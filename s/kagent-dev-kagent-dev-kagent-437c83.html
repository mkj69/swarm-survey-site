**kagent** 是一个用于构建 AI 智能体的 Kubernetes 原生框架。 **kagent** is a Kubernetes native framework for building AI agents. Kubernetes 是最流行的工作负载编排平台，而 **kagent** 使在 Kubernetes 中构建、部署和管理 AI 智能体变得简单。 Kubernetes is the most popular orchestration platform for running workloads, and **kagent** makes it easy to build, deploy and manage AI agents in Kubernetes. **kagent** 框架旨在易于理解和使用，并提供一种灵活而强大的方式来构建和管理 AI 智能体。 The **kagent** framework is designed to be easy to understand and use, and to provide a flexible and powerful way to build and manage AI agents.

技术细节Technical Details
核心概念Core Concepts
**智能体（Agents）**：智能体是 kagent 的主要构建单元。 **Agents**: Agents are the main building block of kagent. Agent 是一种 Kubernetes 自定义资源，将智能体的行为配置与运行时配置整合在一起。 An Agent is a Kubernetes custom resource that brings together an agent's behavior and runtime configuration.
**智能体模板（Agent Templates）**：系统提示词、一组工具和子智能体，以及 LLM 配置共同定义智能体的行为。 **Agent Templates**: A system prompt, a set of tools and subagents, and an LLM configuration define an agent's behavior. 你可以直接在 Agent 中定义这些配置，也可以使用 AgentTemplate 资源在多个智能体之间共享这些配置。 You can define this directly in an Agent or share it across agents using an AgentTemplate resource.
**执行框架（Harnesses）**：Harness 定义智能体的运行方式。 **Harnesses**: A Harness defines how an agent runs. Kagent 支持其自身的 Go 和 Python ADK、Codex、Claude 以及自定义运行时，因此你可以选择适合智能体的运行时。 Kagent supports its own Go and Python ADKs, Codex, Claude, and custom runtimes, so you can choose the runtime that fits your agent.
**LLM 提供商**：Kagent 支持多种 LLM 提供商，包括 [OpenAI](https://kagent.dev/docs/kagent/1.x/setup/model-providers/openai/)、[Azure OpenAI](https://kagent.dev/docs/kagent/1.x/setup/model-providers/azure-openai/)、[Anthropic](https://kagent.dev/docs/kagent/1.x/setup/model-providers/anthropic/)、[Google Vertex AI](https://kagent.dev/docs/kagent/1.x/setup/model-providers/google-vertexai/)、[Ollama](https://kagent.dev/docs/kagent/1.x/setup/model-providers/ollama/)，以及可通过 AI 网关访问的自定义提供商和模型。 **LLM Providers**: Kagent supports multiple LLM providers, including [OpenAI](https://kagent.dev/docs/kagent/1.x/setup/model-providers/openai/), [Azure OpenAI](https://kagent.dev/docs/kagent/1.x/setup/model-providers/azure-openai/), [Anthropic](https://kagent.dev/docs/kagent/1.x/setup/model-providers/anthropic/), [Google Vertex AI](https://kagent.dev/docs/kagent/1.x/setup/model-providers/google-vertexai/), [Ollama](https://kagent.dev/docs/kagent/1.x/setup/model-providers/ollama/) and custom providers and models accessible via AI gateways. 模型通过 ModelConfig 资源进行配置，对提供商的支持取决于所选的 Harness。 Models are configured through the ModelConfig resource, with provider support depending on the chosen Harness.
**MCP 工具**：智能体可以连接到提供工具的 MCP 服务器。 **MCP Tools**: Agents can connect to MCP servers that provide tools. Kagent 自带一个 MCP 服务器，其中包含适用于 Kubernetes、Istio、Helm、Argo、Prometheus、Grafana、Cilium 等的工具。 Kagent comes with an MCP server with tools for Kubernetes, Istio, Helm, Argo, Prometheus, Grafana, Cilium, and others. 智能体通过 RemoteMCPServer 资源进行连接，这些资源可以在多个智能体之间共享。 Agents connect through RemoteMCPServer resources, which can be shared across agents.
**会话（Sessions）**：会话在多次交互之间保留对话和任务历史。 **Sessions**: Sessions keep conversations and task history across interactions. 你可以挂起和恢复智能体，也可以创建检查点，并从该检查点分叉出一个新对话。 You can suspend and resume an agent, or create a checkpoint and fork a new conversation from it.
**可观测性**：Kagent 支持 [OpenTelemetry 追踪](https://kagent.dev/docs/kagent/1.x/observability/tracing/)，使你能够监控智能体和工具的运行情况。 **Observability**: Kagent supports [OpenTelemetry tracing](https://kagent.dev/docs/kagent/1.x/observability/tracing/), which allows you to monitor what's happening with your agents and tools.
核心原则Core Principles
**Kubernetes 原生**：通过 Kubernetes API 和熟悉的 `kubectl` 工作流管理智能体和工具的配置。 **Kubernetes Native**: Manage agent and tool configuration through Kubernetes APIs and familiar `kubectl` workflows.
**可扩展**：添加自定义工具、技能和运行时，将智能体连接到你自己的系统。 **Extensible**: Add custom tools, skills, and runtimes to connect agents to your own systems.
**灵活**：选择适合工作负载的模型和运行时，并在兼容的执行框架之间复用智能体模板。 **Flexible**: Choose the models and runtimes that fit your workload, and reuse agent templates across compatible harnesses.
**可观测**：使用 OpenTelemetry 和现有的可观测性技术栈追踪智能体、模型和工具的执行。 **Observable**: Trace agent, model, and tool execution with OpenTelemetry and your existing observability stack.
**声明式**：使用 YAML 定义智能体，将配置纳入版本控制，并通过 GitOps 工作流进行部署。 **Declarative**: Define agents in YAML, keep configuration in version control, and deploy through GitOps workflows.
**可测试**：通过智能体的公开 API 进行测试，并利用任务历史和追踪记录诊断故障。 **Testable**: Test agents through their public APIs and use task history and traces to diagnose failures.
架构Architecture
flowchart TD
    UI[UI] --> CONTROLLER[kagent Controller]
    CLI[CLI] --> CONTROLLER
    CONFIG[Kubernetes resources] --> CONTROLLER
    CONTROLLER --> DB[(PostgreSQL)]
    CONTROLLER --> SUBSTRATE[Substrate]
    SUBSTRATE --> RUNTIMES[Agent runtimes]
    CONTROLLER -->|A2A| RUNTIMES
Kagent 整合了以下组件： Kagent brings together the following components:
**控制器（Controller）**：控制器监听 kagent 自定义资源，为智能体的运行做好准备，并管理其会话。 **Controller**: The controller watches kagent custom resources, prepares agents to run, and manages their sessions. 它提供 gRPC、A2A 和 MCP API，供客户端与智能体交互。 It exposes gRPC, A2A, and MCP APIs for clients to interact with agents.
**用户界面（UI）**：该界面是一个 Web 用户界面，可用于管理智能体和工具，以及与智能体对话。 **UI**: The UI is a web UI that allows you to manage agents and tools and chat with your agents.
**智能体运行时**：智能体使用由其 Harness 选择的 Go 或 Python ADK、Codex、Claude 或自定义运行时运行。 **Agent Runtimes**: Agents run using the Go or Python ADK, Codex, Claude, or a custom runtime, selected by their Harness.
**Substrate**：Substrate 运行智能体并管理其生命周期，包括挂起、恢复和快照。 **Substrate**: Substrate runs the agents and manages their lifecycle, including suspension, resumption, and snapshots.
**PostgreSQL**：PostgreSQL 存储会话、任务和对话历史，使这些数据能够独立于运行中的智能体持久保存。 **PostgreSQL**: PostgreSQL stores sessions, tasks, and conversation history so they persist independently of the running agents.
**CLI**：CLI 是一种命令行工具，可用于管理智能体和工具，并与智能体交互。 **CLI**: The CLI is a command-line tool that allows you to manage agents and tools and interact with your agents.
有关 v1 架构的更多详细信息，包括资源定义和智能体的运行方式，请参阅[架构指南](docs/architecture/README.md)。 For more details on the v1 architecture, including resource definitions and how agents run, see the [architecture guide](docs/architecture/README.md).
