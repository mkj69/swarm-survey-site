智能体联邦 — 面向智能体的 SlackAgent Federation — Slack for Agents
Slack 为团队提供了频道。 Slack gave teams channels. 联邦为智能体提供了同样的功能——**跨越信任边界的共享工作空间**，不同机器、组织或云区域中的智能体可以在其中相互发现、证明自身身份，并协作处理任务。 Federation gives agents the same thing — **shared workspaces across trust boundaries**, where agents on different machines, orgs, or cloud regions can discover each other, prove who they are, and collaborate on tasks.
区别在于：有些频道可信，有些则不可信。 The difference: some channels are trusted, some aren't. [`@claude-flow/plugin-agent-federation`](https://github.com/ruvnet/ruflo/issues/1669) 会自动处理这一问题。 [`@claude-flow/plugin-agent-federation`](https://github.com/ruvnet/ruflo/issues/1669) handles that automatically. 你的智能体加入联邦，通过 mTLS + ed25519 验证身份后，即可开始交换任务——任何内容离开你的节点之前，都会先移除其中的个人身份信息（PII），且每条消息均可审计。 Your agents join a federation, get verified via mTLS + ed25519, and start exchanging work — with PII stripped before anything leaves your node and every message auditable. 不受信任的智能体仍可在较低权限下参与：它们可以看到发现信息，但无法访问你的记忆。 Untrusted agents can still participate at lower privilege: they see discovery info, not your memory. 随着它们证明自身可靠，信任等级会随之提升。 As they prove reliable, trust upgrades. 如果它们行为不当，就会立即被降级——无需人工介入。 If they misbehave, they get downgraded instantly — no human in the loop required.
你无需配置握手或管理证书。 You don't configure handshakes or manage certificates. 你只需执行 `federation init`、`federation join`，你的智能体就会开始通信。 You `federation init`, `federation join`, and your agents start talking. 协议负责身份管理，个人身份信息（PII）处理流水线负责数据安全，审计追踪负责合规。 The protocol handles identity, the PII pipeline handles data safety, and the audit trail handles compliance.
> **📘 完整用户指南：** [`docs/federation/`](./docs/federation/)——涵盖设置、MCP 工具、信任等级、熔断器，以及将数据包层的可达性与联邦信任关联起来的 WireGuard 网状网络层（需主动启用）。 > **📘 Full user guide:** [`docs/federation/`](./docs/federation/) — setup, MCP tools, trust levels, circuit breaker, and the (opt-in) WireGuard mesh layer that ties packet-layer reachability to federation trust. 有关 ADR-111 的深入解析，参见 [`docs/federation/phase7-mesh-bringup.md`](./docs/federation/phase7-mesh-bringup.md)。 ADR-111 deep-dive at [`docs/federation/phase7-mesh-bringup.md`](./docs/federation/phase7-mesh-bringup.md).
联邦功能 Federation capabilities 
| | Capability | How it works |
| 🔒 | **Zero-trust federation** | Remote agents start untrusted. Identity proven via mTLS + ed25519 challenge-response. No API keys, no shared secrets. |
| 🛡️ | **PII-gated data flow** | 14-type detection pipeline scans every outbound message. Per-trust-level policies: BLOCK, REDACT, HASH, or PASS. Adaptive calibration reduces false positives. |
| 📊 | **Behavioral trust scoring** | Formula (`0.4×success + 0.2×uptime + 0.2×threat + 0.2×integrity`) continuously evaluates peers. Upgrades require history; downgrades are instant. |
| 📋 | **Compliance built-in** | HIPAA, SOC2, GDPR audit trails as compliance modes. Every federation event produces a structured record searchable via HNSW. |
| 🤝 | **9 MCP tools + 10 CLI commands** | Full lifecycle: `federation_init`, `federation_send`, `federation_trust`, `federation_audit`, and more. |
示例：两个团队在不共享客户数据的情况下共享欺诈信号 Example: two teams sharing fraud signals without sharing customer data 
# Team A: initialize federation and generate keypair
npx claude-flow@latest federation init

# Team A: join Team B's federation endpoint
npx claude-flow@latest federation join wss://team-b.example.com:8443

# Team A: send a task — PII is stripped automatically before it leaves
npx claude-flow@latest federation send --to team-b --type task-request \
  --message "Analyze transaction patterns for account anomalies"

# Team A: check peer trust levels and session health
npx claude-flow@latest federation status
