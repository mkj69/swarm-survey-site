一句话

这份访谈摘要将 swarm 扩展的瓶颈从模型能力转向推理预算、人类消化速度与组织治理，但依据主要是个人实践自述。

主要内容

  • Yegge 主张多数工作可由小模型群承担，并称切换后很快改善了质量与吞吐。
  • 软件工厂每周产生 2000—4000 次提交；他建议限制消息和功能产出，把余力用于质量、清理和内部工具。
  • 按 API 价格估算，配置每年约需 150 万美元；采用折扣订阅后，自报支出为 6万—10 万美元。
  • 规则累积也会阻塞执行：他描述约 650 道限制导致系统停摆，而全面撤除又让半成品上线。
  • 摘要还介绍短任务代理与只观察、记录、协调的代理分工。

证据与可信度

这是作者对 Yegge 访谈的二手摘要，未读到访谈全文。提交量、支出和规则数量均为受访者自报，未提供日志、账单或独立核验；150 万美元是 API 价格折算，并非实际付款。提交数不能直接证明有效产出或质量。每人管理 50—100 个代理属于预测；开放网络出现群体智能的说法缺乏可核查证据。

对 swarm scaling 的意义

材料提示，扩大代理数量需要同时约束成本、协调开销和人类接收能力。规则过密与撤除全部门禁的两种失败，也说明治理机制值得单独评估。但它没有代理数量对照、任务成功率或质量测量，尚不能据此确认 swarm 的规模收益。
