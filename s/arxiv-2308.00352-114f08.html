摘要Abstract
通过由基于大语言模型（LLMs）的智能体组成的群体，自动化问题求解已取得显著进展。 Remarkable progress has been made on automated problem solving through societies of agents based on large language models (LLMs). 现有的基于 LLM 的多智能体系统已经能够解决简单的对话任务。 Existing LLM-based multi-agent systems can already solve simple dialogue tasks. 然而，简单地将 LLM 串联起来会引发级联幻觉，进而导致逻辑不一致，使更复杂任务的求解变得困难。 Solutions to more complex tasks, however, are complicated through logic inconsistencies due to cascading hallucinations caused by naively chaining LLMs. 本文提出 MetaGPT，这是一种创新的元编程框架，将高效的人类工作流程融入基于 LLM 的多智能体协作。 Here we introduce MetaGPT, an innovative meta-programming framework incorporating efficient human workflows into LLM-based multi-agent collaborations. MetaGPT 将标准化操作规程（SOPs）编码为提示序列，使工作流程更加精简顺畅，从而让具备类人领域专业知识的智能体能够验证中间结果并减少错误。 MetaGPT encodes Standardized Operating Procedures (SOPs) into prompt sequences for more streamlined workflows, thus allowing agents with human-like domain expertise to verify intermediate results and reduce errors. MetaGPT 采用流水线范式，为不同智能体分配多样化的角色，高效地将复杂任务分解为由多个智能体共同完成的子任务。 MetaGPT utilizes an assembly line paradigm to assign diverse roles to various agents, efficiently breaking down complex tasks into subtasks involving many agents working together. 在协作式软件工程基准测试中，MetaGPT 生成的解决方案比以往基于聊天的多智能体系统更加连贯一致。 On collaborative software engineering benchmarks, MetaGPT generates more coherent solutions than previous chat-based multi-agent systems. 我们的项目地址为 https://github.com/geekan/MetaGPT。 Our project can be found at https://github.com/geekan/MetaGPT.

3.2 通信协议3.2 Communication Protocol
结构化通信接口Structured Communication Interfaces
目前大多数基于 LLM 的多智能体框架（Li et al., 2023; Zhuge et al., 2023; Zhang et al., 2023a; Park et al., 2023）都使用不受约束的自然语言作为通信接口。 Most current LLM-based multi-agent frameworks (Li et al., 2023; Zhuge et al., 2023; Zhang et al., 2023a; Park et al., 2023) utilize unconstrained natural language as a communication interface.
然而，尽管自然语言用途广泛，一个问题随之而来：仅靠纯自然语言通信是否足以解决复杂任务？ However, despite the versatility of natural language, a question arises: does pure natural language communication suffice for solving complex tasks? 例如，在传话游戏（又称 Chinese whispers）22 2 https://en.wikipedia.org/wiki/Chinese_whispers 中，经过几轮传递后，原始信息可能会严重失真。 For example, in the telephone game (or Chinese whispers)22 2 https://en.wikipedia.org/wiki/Chinese_whispers, after several rounds of communication, the original information may be quite distorted. 受人类社会结构的启发，我们提出使用结构化通信来规范智能体之间的通信。 Inspired by human social structures, we propose using structured communication to formulate the communication of agents. 我们为每个角色制定模式（schema）和格式，并要求各个智能体根据自身的具体角色和上下文提供必要的输出。 We establish a schema and format for each role and request that individuals provide the necessary outputs based on their specific role and context.
如图 3 所示，架构师智能体生成两项输出：系统接口设计和时序流程图。 As shown in Figure 3, the Architect agent generates two outputs: the system interface design and a sequence flow diagram. 这些输出包含系统模块设计和交互时序，是提供给工程师的重要交付物。 These contain system module design and interaction sequences, which serve as important deliverables for Engineers. 与 ChatDev（Zhao et al., 2023）不同，MetaGPT 中的智能体通过文档和图表（结构化输出）进行通信，而非通过对话。 Unlike ChatDev (Zhao et al., 2023), agents in MetaGPT communicate through documents and diagrams (structured outputs) rather than dialogue. 这些文档包含所有必要信息，避免出现无关内容或内容缺失。 These documents contain all necessary information, preventing irrelevant or missing content.
发布-订阅机制Publish-Subscribe Mechanism
信息共享在协作中至关重要。 Sharing information is critical in collaboration. 例如，架构师和工程师经常需要参考产品需求文档（PRDs）。 For instance, Architects and Engineers often need to reference PRDs. 然而，如先前工作（Li et al., 2023; Zhao et al., 2023; Zhang et al., 2023a）所示，每次都以一对一的方式传递这些信息，会使通信拓扑复杂化，导致效率低下。 However, communicating this information each time in a one-to-one manner, as indicated by previous work (Li et al., 2023; Zhao et al., 2023; Zhang et al., 2023a), can complicate the communication topology, resulting in inefficiencies.
为应对这一挑战，一种可行的方法是将信息存储在全局消息池中。 To address this challenge, a viable approach is to store information in a global message pool. 如图 2（左）所示，我们引入了一个共享消息池，使所有智能体都能直接交换消息。 As shown in Figure 2 (left), we introduce a shared message pool that allows all agents to exchange messages directly. 这些智能体不仅在消息池中发布自己的结构化消息，还能透明地访问其他实体的消息。 These agents not only publish their structured messages in the pool but also access messages from other entities transparently. 任何智能体都可以直接从共享池中检索所需信息，无须向其他智能体询问并等待其响应。 Any agent can directly retrieve required information from the shared pool, eliminating the need to inquire about other agents and await their responses. 这提高了通信效率。 This enhances communication efficiency.
向每个智能体共享全部信息可能导致信息过载。 Sharing all information with every agent can lead to information overload. 在执行任务时，智能体通常倾向于只接收与任务相关的信息，并避免受到无关细节的干扰。 During task execution, an agent typically prefers to receive only task-related information and avoid distractions through irrelevant details. 有效地管理和传播这些信息至关重要。 Effective management and dissemination of this information play a crucial role. 我们提供了一种简单而有效的解决方案——订阅机制（见图 2（左））。 We offer a simple and effective solution-subscription mechanism (in Figure 2 (left)). 智能体根据各自角色所关注的内容提取相关信息，而不是依赖对话。 Instead of relying on dialogue, agents utilize role-specific interests to extract relevant information. 它们可以根据自身的角色描述选择要关注的信息。 They can select information to follow based on their role profiles. 在实际实现中，智能体只有在收到其所需的全部前置依赖项后，才会启动相应行动。 In practical implementations, an agent activates its action only after receiving all its prerequisite dependencies. 如图 3 所示，架构师主要关注产品经理提供的 PRDs，而对质量保证工程师等角色提供的文档可能关注较少。 As illustrated in Figure 3, the Architect mainly focuses on PRDs provided by the Product Manager, while documents from roles such as the QA Engineer might be of lesser concern.
3.3 基于可执行反馈的迭代编程3.3 Iterative programming with executable feedback
在日常编程任务中，调试和优化过程发挥着重要作用。 In daily programming tasks, the processes of debugging and optimization play important roles. 然而，现有方法往往缺乏自我纠正机制，导致代码生成失败。 However, existing methods often lack a self-correction mechanism, which leads to unsuccessful code generation. 先前的工作引入了不执行代码的代码审查和自我反思（Zhao et al., 2023; Yao et al., 2022; Shinn et al., 2023; Dong et al., 2023）。 Previous work introduced non-executable code review and self-reflection (Zhao et al., 2023; Yao et al., 2022; Shinn et al., 2023; Dong et al., 2023). 然而，这些方法在确保代码可执行性和运行时正确性方面仍面临挑战。 However, they still face challenges in ensuring code executability and runtime correctness.
在 MetaGPT 的最初实现中，由于 LLM 幻觉（Manakul et al., 2023），我们在审查过程中遗漏了某些错误。 Our first MetaGPT implementations overlooked certain errors during the review process, due to LLM hallucinations (Manakul et al., 2023). 为克服这一问题，我们在初步生成代码后引入了可执行反馈机制，以迭代改进代码。 To overcome this, after initial code generation, we introduce an executable feedback mechanism to improve the code iteratively. 更具体地说，如图 2 所示，工程师被要求根据原始产品需求和设计编写代码。 More specifically, as shown in Figure 2, the Engineer is asked to write code based on the original product requirements and design.
这使工程师能够利用自身以往执行和调试的记忆，持续改进代码。 This enables the Engineer to continuously improve code using its own historical execution and debugging memory. 为获取更多信息，工程师编写并执行相应的单元测试用例，随后接收测试结果。 To obtain additional information, the Engineer writes and executes the corresponding unit test cases, and subsequently receives the test results. 如果结果令人满意，则启动额外的开发任务。 If satisfactory, additional development tasks are initiated. 否则，工程师会先调试代码，然后再继续编程。 Otherwise the Engineer debugs the code before resuming programming. 这一迭代测试过程会持续进行，直到测试通过或达到最多 3 次重试的上限。 This iterative testing process continues until the test is passed or a maximum of 3 retries is reached.

评估指标Evaluation Metrics
对于 HuamnEval 和 MBPP，我们采用 (Chen et al., 2021a; Dong et al., 2023) 提出的 $\operatorname{Pass}@k$ 无偏版本，评估排名前 k 的生成代码的功能正确性：$\operatorname{Pass}@k={\mathbb{E}}_{\text{Problems}}\left[1-\frac{{\binom{n-c}{k}}}{{\binom{n}{k}}}\right]$。 For HuamnEval and MBPP, we follow the unbiased version of $\operatorname{Pass}@k$ as presented by (Chen et al., 2021a; Dong et al., 2023), to evaluate the functional accuracy of the top-k generated codes: $\operatorname{Pass}@k={\mathbb{E}}_{\text{Problems}}\left[1-\frac{{\binom{n-c}{k}}}{{\binom{n}{k}}}\right]$ .
对于 SoftwareDev，我们优先考虑实际使用，并通过人工评估 (A, E) 或统计分析 (B, C, D) 来评估性能：(A) 可执行性：该指标对代码的评分范围为 1（失败／无法正常工作）至 4（完美无缺）。 For SoftwareDev, we prioritize practical use and evaluate performance through human evaluations (A, E) or statistical analysis (B, C, D): (A) Executability: this metric rates code from 1 (failure/non-functional) to 4 (flawless). ‘1’ 表示代码无法正常工作，‘2’ 表示可以运行但不完善，‘3’ 表示接近完美，‘4’ 表示完美无缺。 ‘1’ is for non-functional, ‘2’ for runnable but imperfect, ‘3’ for nearly perfect, and ‘4’ for flawless code. (B) 成本：此处的成本评估包括 (1) 运行时间、(2) token 用量和 (3) 费用。 (B) Cost: the cost evaluations here include the (1) running time, (2) token usage, and (3) expenses. (C) 代码统计：包括 (1) 代码文件数、(2) 每个文件的代码行数和 (3) 代码总行数。 (C) Code Statistics: this includes (1) code files, (2) lines of code per file, and (3) total code lines. (D) 生产率：其基本定义为 token 用量除以代码行数，即每行代码消耗的 token 数。 (D) Productivity: basically, it is defined as the number of token usage divided by the number of lines of code, which refers to the consumption of tokens per code line. (E) 人工修改成本：指手动修正代码的次数，这些修正用于解决包导入错误、类名错误或引用路径不完整等问题。 (E) Human Revision Cost: refers to times of manual code corrections, which tackle problems like package import errors, incorrect class names, or incomplete reference paths. 通常，每次修正涉及的代码不超过 3 行。 Typically, each correction involves up to 3 lines of code.

A.1 自我改进机制A.1 Self-Improvement Mechanisms
本文正文中所述 MetaGPT 版本的一个局限在于，每个软件项目都是独立执行的。 One limitation of the MetaGPT version in the main text of this paper is that each software project is executed independently. 然而，通过积极的团队协作，软件开发团队应当从每个项目的开发经验中学习，从而随着时间的推移，配合更加默契，取得更大的成功。 However, through active teamwork, a software development team should learn from the experience gained by developing each project, thus becoming more compatible and successful over time.
这与递归自我改进的思想有一定关联；该思想于 1965 年首次以非正式形式提出 (Good, 1965)，自 1987 年起出现了首批具体实现 (Schmidhuber, 1987; Schmidhuber, 1993b; Schmidhuber et al., 1998)，最终发展为在数学意义上最优的自指式自我改进系统这一概念 (Schmidhuber, 2003; Schmidhuber, 2009)。 This is somewhat related to the idea of recursive self-improvement, first informally proposed in 1965 (Good, 1965), with first concrete implementations since 1987 (Schmidhuber, 1987; Schmidhuber, 1993b; Schmidhuber et al., 1998), culminating in the concept of mathematically optimal self-referential self-improvers (Schmidhuber, 2003; Schmidhuber, 2009). 一般而言，系统应当从现实世界的经验中学习，从学习经验中通过元学习获得更好的学习算法，从元学习经验中通过元元学习获得更好的元学习算法，依此类推，除可计算性和物理规律的限制外，不受任何限制。 Generally speaking, a system should learn from experience in the real world, and meta-learn better learning algorithms from experiences of learning, and meta-meta-learn better meta-learning algorithms from experiences of meta-learning, etc., without any limitations except those of computability and physics.
较近期的一些相关工作利用大语言模型（Large Language Models，LLMs）的推理能力，递归地改进 LLMs 的提示，以提升其在某些下游任务上的表现 (Fernando et al., 2023; Zelikman et al., 2023)；这类似于 2015 年提出的自适应提示工程师 (Schmidhuber, 2015)，其中一个神经网络学习为另一个预训练神经网络生成一系列查询或提示，后者的回答可能帮助前者更快地学习新任务。 More recent, somewhat related work leverages the reasoning ability of Large Language Models (LLMs) and recursively improves prompts of LLMs, to improve performance on certain downstream tasks (Fernando et al., 2023; Zelikman et al., 2023), analogous to the adaptive prompt engineer of 2015 (Schmidhuber, 2015) where one neural network learns to generate sequence of queries or prompts for another pre-trained neural network whose answers may help the first network to learn new tasks more quickly.
在当前工作中，我们还探索了一种自指机制，根据智能体在软件开发过程中观察到的信息，递归地修改其约束提示。 In our present work, we also explore a self-referential mechanism that recursively modifies the constraint prompts of agents based on information they observe during software development. 我们的初步实现如下。 Our initial implementation works as follows. 在每个项目开始之前，软件公司中的每个智能体都会回顾以往的反馈，并对自身的约束提示作出必要的调整。 Prior to each project, every agent in the software company reviews previous feedback and makes necessary adjustments to their constraint prompts. 这使它们能够持续从以往的项目经验中学习，并通过改进公司中的每个个体来增强整个多智能体系统。 This enables them to continuously learn from past project experiences and enhance the overall multi-agent system by improving each individual in the company. 我们首先为每个智能体设置一个交接反馈动作。 We first establish a handover feedback action for each agent. 该动作负责以批判性视角总结在以往项目开发过程中收到的信息，并将这些信息整合到更新后的约束提示中。 This action is responsible for critically summarizing the information received during the development of previous projects and integrating this information in an updated constraint prompt. 总结后的信息存储在长期记忆中，以便未来更新约束提示时能够继承这些信息。 The summarized information is stored in long-term memory such that it can be inherited by future constraint prompt updates. 启动新项目时，每个智能体都首先执行一个 react 动作。 When initiating a new project, each agent starts with a react action. 每个智能体都会评估收到的反馈，并在约束提示中总结自身可以如何改进。 Each agent evaluates the received feedback and summarizes how they can improve in a constraint prompt.
目前的一个局限是，这些基于总结的优化仅修改角色专门化中的约束（第 3.1 节），而不修改通信协议中的结构化通信接口（第 3.2 节）。 One current limitation is that these summary-based optimizations only modify constraints in the specialization of roles (Sec. 3.1) rather than structured communication interfaces in communication protocols (Sec. 3.2). 未来的进一步改进仍有待探索。 Future advancements are yet to be explored.
A.2 多智能体经济体A.2 Multi-Agent Economies
在现实世界的团队协作中，交互过程往往并非硬编码的。 In real-world teamwork, the interaction processes are often not hardcoded. 例如，在软件公司中，协作 SOP 可能会动态变化。 For example, in a software company, the collaboration SOP may change dynamically.
关于“基于自然语言的心智社会”（Natural Language-Based Society of Mind，NLSOM）的论文 (Zhuge et al., 2023) 讨论了此类自组织的一种实现，并提出了“心智经济体”（Economy of Minds，EOM）的思想，这是一个面向由 LLMs 和其他智能体组成的社会的强化学习（Reinforcement Learning，RL）框架。 One implementation of such self-organization is discussed in the paper on a “Natural Language-Based Society of Mind” (NLSOM) (Zhuge et al., 2023), which introduced the idea of an “Economy of Minds” (EOM), a Reinforcement Learning (RL) framework for societies of LLMs and other agents. EOMs 利用自由市场中的供需原则，将功劳（货币）分配给那些为经济成功（奖励）作出贡献的智能体，而非采用标准 RL 技术，通过修改神经网络参数来优化系统的总奖励。 Instead of using standard RL techniques to optimize the total reward of the system through modifications of neural network parameters, EOMs use the principles of supply and demand in free markets to assign credit (money) to those agents that contribute to economic success (reward).
