MapReduce 是一种编程模型及其配套实现，用于在集群上通过并行和分布式算法处理和生成大型数据集。 MapReduce is a programming model and an associated implementation for processing and generating big data sets with a parallel and distributed algorithm on a cluster.
MapReduce 程序由一个 map 过程和一个 reduce 方法组成，前者执行筛选和排序（例如，按学生的名字将其分入队列，每个名字对应一个队列），后者执行汇总操作（例如，统计每个队列中的学生人数，得到各个名字的出现频数）。 A MapReduce program is composed of a map procedure, which performs filtering and sorting (such as sorting students by first name into queues, one queue for each name), and a reduce method, which performs a summary operation (such as counting the number of students in each queue, yielding name frequencies). “MapReduce 系统”（也称为“基础设施”或“框架”）通过调度分布式服务器、并行运行各项任务、管理系统各部分之间的所有通信和数据传输，以及提供冗余和容错机制，来协调处理过程。 The "MapReduce System" (also called "infrastructure" or "framework") orchestrates the processing by marshalling the distributed servers, running the various tasks in parallel, managing all communications and data transfers between the various parts of the system, and providing for redundancy and fault tolerance.
该模型是数据分析中拆分—应用—合并（split-apply-combine）策略的一种特化形式。 The model is a specialization of the split-apply-combine strategy for data analysis.
它受到函数式编程中常用的 map 和 reduce 函数的启发，但这两个函数在 MapReduce 框架中的用途与其原始形式中的用途并不相同。 It is inspired by the map and reduce functions commonly used in functional programming, although their purpose in the MapReduce framework is not the same as in their original forms. MapReduce 框架的关键贡献并非 map 和 reduce 函数本身（例如，它们类似于 1995 年消息传递接口（Message Passing Interface）标准中的 reduce 和 scatter 操作），而是通过并行化为多种应用实现的可扩展性和容错性。 The key contributions of the MapReduce framework are not the actual map and reduce functions (which, for example, resemble the 1995 Message Passing Interface standard's reduce and scatter operations), but the scalability and fault-tolerance achieved for a variety of applications due to parallelization. 因此，MapReduce 的单线程实现通常并不比传统的（非 MapReduce）实现更快；通常只有在多处理器硬件上采用多线程实现时，才能看到性能提升。 As such, a single-threaded implementation of MapReduce is usually not faster than a traditional (non-MapReduce) implementation; any gains are usually only seen with multi-threaded implementations on multi-processor hardware. 只有当 MapReduce 框架中经过优化的分布式混洗（shuffle）操作（可降低网络通信成本）和容错功能发挥作用时，使用该模型才有益处。 The use of this model is beneficial only when the optimized distributed shuffle operation (which reduces network communication cost) and fault tolerance features of the MapReduce framework come into play. 优化通信成本对于设计良好的 MapReduce 算法至关重要。 Optimizing the communication cost is essential to a good MapReduce algorithm.
人们已使用多种编程语言编写了 MapReduce 库，其优化程度各不相同。 MapReduce libraries have been written in many programming languages, with different levels of optimization. Apache Hadoop 包含一种广受欢迎、支持分布式混洗的开源实现。 A popular open-source implementation that has support for distributed shuffles is part of Apache Hadoop. MapReduce 这一名称最初指 Google 的专有技术，但后来已成为通用化商标。 The name MapReduce originally referred to the proprietary Google technology, but has since become a generic trademark. 到 2014 年，Google 已不再将 MapReduce 用作其主要的大数据处理模型，而 Apache Mahout 的开发也已转向功能更强、对磁盘依赖更少的机制，这些机制具备完整的 map 和 reduce 功能。 By 2014, Google was no longer using MapReduce as its primary big data processing model, and development on Apache Mahout had moved on to more capable and less disk-oriented mechanisms that incorporated full map and reduce capabilities.
概述Overview
MapReduce 是一种利用大量计算机（节点）处理大型数据集中的可并行化问题的框架，这些计算机统称为集群（如果所有节点都位于同一局域网内且使用相似的硬件）或网格（如果节点在地理位置和管理上分散的系统之间共享，且使用异构程度更高的硬件）。 MapReduce is a framework for processing parallelizable problems across large datasets using a large number of computers (nodes), collectively referred to as a cluster (if all nodes are on the same local network and use similar hardware) or a grid (if the nodes are shared across geographically and administratively distributed systems, and use more heterogeneous hardware). 处理对象既可以是存储在文件系统中的数据（非结构化数据），也可以是存储在数据库中的数据（结构化数据）。 Processing can occur on data stored either in a filesystem (unstructured) or in a database (structured). MapReduce 可以利用数据局部性，在靠近数据存储位置的地方进行处理，从而尽量减少通信开销。 MapReduce can take advantage of the locality of data, processing it near the place it is stored in order to minimize communication overhead.
MapReduce 框架（或系统）通常由三个操作（或步骤）组成： A MapReduce framework (or system) is usually composed of three operations (or steps):
Map：每个工作节点将 map 函数应用于本地数据，并将输出写入临时存储。 Map: each worker node applies the map function to the local data, and writes the output to a temporary storage. 主节点确保冗余输入数据中只有一个副本被处理。 A master node ensures that only one copy of the redundant input data is processed.
Shuffle：工作节点根据输出键（由 map 函数生成）重新分配数据，使属于同一个键的所有数据都位于同一个工作节点上。 Shuffle: worker nodes redistribute data based on the output keys (produced by the map function), such that all data belonging to one key is located on the same worker node.
Reduce：此时，工作节点按键并行处理各组输出数据。 Reduce: worker nodes now process each group of output data, per key, in parallel.
MapReduce 支持以分布式方式执行映射和归约操作。 MapReduce allows for the distributed processing of the map and reduction operations. 只要各个映射操作彼此独立，就可以并行执行；在实践中，这受到独立数据源数量和/或各数据源附近 CPU 数量的限制。 Maps can be performed in parallel, provided that each mapping operation is independent of the others; in practice, this is limited by the number of independent data sources and/or the number of CPUs near each source. 类似地，一组归约器（reducer）可以执行归约阶段，前提是 map 操作中具有相同键的所有输出同时交给同一个归约器，或者归约函数满足结合律。 Similarly, a set of 'reducers' can perform the reduction phase, provided that all outputs of the map operation that share the same key are presented to the same reducer at the same time, or that the reduction function is associative. 尽管与顺序执行程度更高的算法相比，这一过程往往显得低效（因为必须运行归约过程的多个实例），但 MapReduce 能够处理的数据集规模远超单台“商用”服务器的处理能力——大型服务器群可以使用 MapReduce 在短短几小时内对一拍字节的数据完成排序。 While this process often appears inefficient compared to algorithms that are more sequential (because multiple instances of the reduction process must be run), MapReduce can be applied to significantly larger datasets than a single "commodity" server can handle – a large server farm can use MapReduce to sort a petabyte of data in only a few hours. 这种并行性还使系统在运行过程中有可能从服务器或存储设备的局部故障中恢复：如果某个映射器（mapper）或归约器发生故障，只要输入数据仍然可用，就可以重新调度其工作。 The parallelism also offers some possibility of recovering from partial failure of servers or storage during the operation: if one mapper or reducer fails, the work can be rescheduled – assuming the input data are still available.
也可以将 MapReduce 看作包含 5 个步骤的并行和分布式计算： Another way to look at MapReduce is as a 5-step parallel and distributed computation:
准备 Map() 的输入——“MapReduce 系统”指定 Map 处理器，为每个处理器分配其要处理的输入键 K1，并向该处理器提供与该键关联的所有输入数据。 Prepare the Map() input – the "MapReduce system" designates Map processors, assigns the input key K1 that each processor would work on, and provides that processor with all the input data associated with that key.
运行用户提供的 Map() 代码——对于每个 K1 键，Map() 恰好运行一次，生成按 K2 键组织的输出。 Run the user-provided Map() code – Map() is run exactly once for each K1 key, generating output organized by key K2.
将 Map 输出“混洗”（Shuffle）至 Reduce 处理器——MapReduce 系统指定 Reduce 处理器，为每个处理器分配其应处理的 K2 键，并向该处理器提供 Map 生成的与该键关联的全部数据。 "Shuffle" the Map output to the Reduce processors – the MapReduce system designates Reduce processors, assigns the K2 key each processor should work on, and provides that processor with all the Map-generated data associated with that key.
运行用户提供的 Reduce() 代码——对于 Map 步骤生成的每个 K2 键，Reduce() 恰好运行一次。 Run the user-provided Reduce() code – Reduce() is run exactly once for each K2 key produced by the Map step.
生成最终输出——MapReduce 系统收集所有 Reduce 输出，并按 K2 排序以生成最终结果。 Produce the final output – the MapReduce system collects all the Reduce output, and sorts it by K2 to produce the final outcome.
从逻辑上看，这五个步骤可视为依次执行——每个步骤只有在前一个步骤完成后才开始——但在实践中，只要不影响最终结果，它们就可以交错执行。 These five steps can be logically thought of as running in sequence – each step starts only after the previous step is completed – although in practice they can be interleaved as long as the final result is not affected.
在许多情况下，输入数据可能已经分布（“分片”）在多个不同的服务器上，此时，通过分配 Map 服务器来处理本地已有的输入数据，有时可以大幅简化步骤 1。 In many situations, the input data might have already been distributed ("sharded") among many different servers, in which case step 1 could sometimes be greatly simplified by assigning Map servers that would process the locally present input data. 类似地，通过分配尽可能靠近其所需处理的 Map 生成数据的 Reduce 处理器，有时可以加快步骤 3。 Similarly, step 3 could sometimes be sped up by assigning Reduce processors that are as close as possible to the Map-generated data they need to process.

MapReduce 的 Map 和 Reduce 函数均针对以 (key, value) 键值对形式组织的数据来定义。 The Map and Reduce functions of MapReduce are both defined with respect to data structured in (key, value) pairs. Map 接收一个属于某个数据域、具有相应类型的数据对，并返回另一个数据域中的数据对列表： Map takes one pair of data with a type in one data domain, and returns a list of pairs in a different domain:
Map(k1,v1) → list(k2,v2) Map(k1,v1) → list(k2,v2)
Map 函数并行应用于输入数据集中的每个数据对（以 k1 为键）。 The Map function is applied in parallel to every pair (keyed by k1) in the input dataset. 每次调用都会生成一个数据对列表（以 k2 为键）。 This produces a list of pairs (keyed by k2) for each call.
随后，MapReduce 框架从所有列表中收集具有相同键 (k2) 的全部数据对，并将其归为一组，为每个键创建一个分组。 After that, the MapReduce framework collects all pairs with the same key (k2) from all lists and groups them together, creating one group for each key.
然后，Reduce 函数并行应用于每个分组，进而生成同一数据域中的值的集合： The Reduce function is then applied in parallel to each group, which in turn produces a collection of values in the same domain:
Reduce(k2, list (v2)) → list((k3, v3)) Reduce(k2, list (v2)) → list((k3, v3))
每次 Reduce 调用通常生成一个键值对，或返回空结果，但也允许一次调用返回多个键值对。 Each Reduce call typically produces either one key value pair or an empty return, though one call is allowed to return more than one key value pair. 所有调用的返回结果被收集起来，形成所需的结果列表。 The returns of all calls are collected as the desired result list.
因此，MapReduce 框架将一个 (key, value) 键值对列表转换为另一个 (key, value) 键值对列表。 Thus the MapReduce framework transforms a list of (key, value) pairs into another list of (key, value) pairs. 这种行为不同于函数式编程中典型的 map 与 reduce 组合，后者接收一个任意值的列表，并返回一个将 map 返回的所有值合并而成的单一值。 This behavior is different from the typical functional programming map and reduce combination, which accepts a list of arbitrary values and returns one single value that combines all the values returned by map.
要实现 MapReduce，具备 map 和 reduce 这两种抽象的实现是必要条件，但并非充分条件。 It is necessary but not sufficient to have implementations of the map and reduce abstractions in order to implement MapReduce. MapReduce 的分布式实现需要一种机制，将执行 Map 和 Reduce 阶段的进程连接起来。 Distributed implementations of MapReduce require a means of connecting the processes performing the Map and Reduce phases. 这种机制可以是分布式文件系统。 This may be a distributed file system. 也可以采用其他方案，例如从映射器（mapper）直接向归约器（reducer）流式传输数据，或者由映射处理器向查询它们的归约器提供结果。 Other options are possible, such as direct streaming from mappers to reducers, or for the mapping processors to serve up their results to reducers that query them.

数据流Dataflow
软件框架架构遵循开闭原则（open-closed principle），代码实际上被划分为不可修改的冻结点（frozen spots）和可扩展的热点（hot spots）。 Software framework architecture adheres to open-closed principle where code is effectively divided into unmodifiable frozen spots and extensible hot spots. MapReduce 框架的冻结点是大规模分布式排序。 The frozen spot of the MapReduce framework is a large distributed sort. 由应用程序定义的热点包括： The hot spots, which the application defines, are:
输入读取器 an input reader
Map 函数 a Map function
分区函数 a partition function
比较函数 a compare function
Reduce 函数 a Reduce function
输出写入器 an output writer
输入读取器Input reader
输入读取器将输入划分为大小适当的“分片”（split，实际中通常为 64 MB 至 128 MB），框架为每个 Map 函数分配一个分片。 The input reader divides the input into appropriate size 'splits' (in practice, typically, 64 MB to 128 MB) and the framework assigns one split to each Map function. 输入读取器从稳定存储（通常是分布式文件系统）中读取数据，并生成键值对。 The input reader reads data from stable storage (typically, a distributed file system) and generates key/value pairs.
一个常见的例子是读取一个包含大量文本文件的目录，并将每一行作为一条记录返回。 A common example will read a directory full of text files and return each line as a record.
Map 函数Map function
Map 函数接收一系列键值对，逐一处理，并生成零个或多个输出键值对。 The Map function takes a series of key/value pairs, processes each, and generates zero or more output key/value pairs. map 的输入类型和输出类型可以不同，而且通常确实不同。 The input and output types of the map can be (and often are) different from each other.
如果应用程序执行词频统计，map 函数就会将每一行拆分为单词，并为每个单词输出一个键值对。 If the application is doing a word count, the map function would break the line into words and output a key/value pair for each word. 每个输出键值对都以单词为键，以该单词在该行中出现的次数为值。 Each output pair would contain the word as the key and the number of instances of that word in the line as the value.
分区函数Partition function
应用程序的分区函数将每个 Map 函数的输出分配给特定的归约器（reducer），以实现数据分片。 Each Map function output is allocated to a particular reducer by the application's partition function for sharding purposes. 分区函数接收键和归约器的数量，并返回目标归约器的索引。 The partition function is given the key and the number of reducers and returns the index of the desired reducer.
一种典型的默认做法是对键进行哈希运算，再用哈希值对归约器数量取模。 A typical default is to hash the key and use the hash value modulo the number of reducers. 为了实现负载均衡，选择能使数据在各分片之间近似均匀分布的分区函数非常重要，否则 MapReduce 操作可能会因等待较慢的归约器完成而停滞 It is important to pick a partition function that gives an approximately uniform distribution of data per shard for load-balancing purposes, otherwise the MapReduce operation can be held up waiting for slow reducers to finish
（即在数据分区不均匀时，被分配了较大份额数据的归约器）。 (i.e. the reducers assigned the larger shares of the non-uniformly partitioned data).
在 map 和 reduce 阶段之间，数据会经过混洗（shuffle，即并行排序／节点间交换），以便将数据从生成它们的 map 节点移至将对其进行归约的分片。 Between the map and reduce stages, the data are shuffled (parallel-sorted / exchanged between nodes) in order to move the data from the map node that produced them to the shard in which they will be reduced. 混洗耗时有时会超过计算耗时，这取决于网络带宽、CPU 速度、生成的数据量以及 map 和 reduce 计算所需的时间。 The shuffle can sometimes take longer than the computation time depending on network bandwidth, CPU speeds, data produced and time taken by map and reduce computations.
比较函数Comparison function
每个 Reduce 的输入都从运行 Map 的机器上拉取，并使用应用程序的比较函数进行排序。 The input for each Reduce is pulled from the machine where the Map ran and sorted using the application's comparison function.
Reduce 函数Reduce function
框架按照排序顺序，针对每个不同的键调用一次应用程序的 Reduce 函数。 The framework calls the application's Reduce function once for each unique key in the sorted order. Reduce 可以遍历与该键关联的所有值，并生成零个或多个输出。 The Reduce can iterate through the values that are associated with that key and produce zero or more outputs.
在词频统计示例中，Reduce 函数接收输入值，将其求和，并生成一个包含该单词及最终总和的输出。 In the word count example, the Reduce function takes the input values, sums them and generates a single output of the word and the final sum.
输出写入器Output writer
输出写入器将 Reduce 的输出写入稳定存储。 The Output Writer writes the output of the Reduce to the stable storage.
理论背景Theoretical background
幺半群（monoid）的性质是确保 MapReduce 操作有效性的基础。 Properties of monoids are the basis for ensuring the validity of MapReduce operations.
在 Algebird 软件包中，Map/Reduce 的 Scala 实现明确要求使用幺半群类型类 In the Algebird package a Scala implementation of Map/Reduce explicitly requires a monoid class type

MapReduce 的操作涉及两种类型：被映射的输入数据的类型 A，以及被归约的输出数据的类型 B。 The operations of MapReduce deal with two types: the type A of input data being mapped, and the type B of output data being reduced.
Map 操作接收类型 A 的单个值，并为每个 a:A 生成一个值 b:B；Reduce 操作要求在类型 B 的值上定义一个二元运算 •，其过程是将所有可用的 b:B 折叠为单个值。 The Map operation takes individual values of type A and produces, for each a:A a value b:B; The Reduce operation requires a binary operation • defined on values of type B; it consists of folding all available b:B to a single value.
从基本要求来看，任何 MapReduce 操作都必须能够对被归约的数据任意重新分组。 From a basic requirements point of view, any MapReduce operation must involve the ability to arbitrarily regroup data being reduced. 这一要求等价于运算 • 具备以下两个性质： Such a requirement amounts to two properties of the operation •:
结合律：(x • y) • z = x • (y • z) associativity: (x • y) • z = x • (y • z)
存在单位元 e，使得对于每个 x:B，都有 e • x = x • e = x。 existence of neutral element e such that e • x = x • e = x for every x:B.
第二个性质保证了在多个节点上并行执行时，没有任何数据需要处理的节点不会影响结果。 The second property guarantees that, when parallelized over multiple nodes, the nodes that don't have any data to process would have no impact on the result.
这两个性质意味着，类型 B 的值与运算 • 及单位元 e 共同构成一个幺半群（monoid）(B, •, e)。 These two properties amount to having a monoid (B, •, e) on values of type B with operation • and with neutral element e.
对类型 A 的值没有任何要求；Map 操作可以使用任意函数 A → B。 There's no requirements on the values of type A; an arbitrary function A → B can be used for the Map operation. 这意味着我们有一个折叠态射（catamorphism）A* → (B, •, e)。 This means that we have a catamorphism A* → (B, •, e). 这里的 A* 表示克莱尼星号（Kleene star），也称为 A 上的列表类型。 Here A* denotes a Kleene star, also known as the type of lists over A.
Shuffle 操作本身与 MapReduce 的本质无关；它是将计算分布到云端所必需的。 The Shuffle operation per se is not related to the essence of MapReduce; it's needed to distribute calculations over the cloud.
由上述内容可知，并非所有二元 Reduce 运算都适用于 MapReduce。 It follows from the above that not every binary Reduce operation will work in MapReduce. 以下是一些反例： Here are the counter-examples:
由子树构建一棵树：这一操作不满足结合律，结果会依赖于分组方式； building a tree from subtrees: this operation is not associative, and the result will depend on grouping;
直接计算平均值：avg 也不满足结合律（而且没有单位元）；要计算平均值，需要计算矩。 direct calculation of averages: avg is also not associative (and it has no neutral element); to calculate an average, one needs to calculate moments.
性能考量Performance considerations
MapReduce 程序并不保证运行速度快。 MapReduce programs are not guaranteed to be fast. 这一编程模型的主要优势在于，能够利用平台经过优化的 shuffle 操作，而只需编写程序的 Map 和 Reduce 部分。 The main benefit of this programming model is to exploit the optimized shuffle operation of the platform, and only having to write the Map and Reduce parts of the program.
然而在实践中，MapReduce 程序的编写者必须考虑 shuffle 步骤；尤其是分区函数以及 Map 函数写出的数据量，可能会对性能和可扩展性产生重大影响。 In practice, the author of a MapReduce program however has to take the shuffle step into consideration; in particular the partition function and the amount of data written by the Map function can have a large impact on the performance and scalability. Combiner 函数等附加模块有助于减少写入磁盘和通过网络传输的数据量。 Additional modules such as the Combiner function can help to reduce the amount of data written to disk, and transmitted over the network. 在特定条件下，MapReduce 应用可以获得次线性加速。 MapReduce applications can achieve sub-linear speedups under specific circumstances.
设计 MapReduce 算法时，编写者需要在计算成本与通信成本之间作出合理权衡。 When designing a MapReduce algorithm, the author needs to choose a good tradeoff between the computation and the communication costs. 通信成本往往高于计算成本，而且许多 MapReduce 实现会将所有通信数据写入分布式存储，以便在崩溃后恢复。 Communication cost often dominates the computation cost, and many MapReduce implementations are designed to write all communication to distributed storage for crash recovery.
调优 MapReduce 性能时，必须考虑映射、shuffle、排序（按键分组）和归约的复杂度。 In tuning performance of MapReduce, the complexity of mapping, shuffle, sorting (grouping by the key), and reducing has to be taken into account. 映射器生成的数据量是一个关键参数，它决定了主要计算成本在映射与归约之间的分配。 The amount of data produced by the mappers is a key parameter that shifts the bulk of the computation cost between mapping and reducing. 归约包含排序（对键进行分组），其复杂度是非线性的。 Reducing includes sorting (grouping of the keys) which has nonlinear complexity. 因此，较小的分区可以缩短排序时间，但这需要权衡，因为使用大量归约器可能并不现实。 Hence, small partition sizes reduce sorting time, but there is a trade-off because having a large number of reducers may be impractical. 切分单元大小的影响很小（除非选择得特别不合理，例如 <1MB）。 The influence of split unit size is marginal (unless chosen particularly badly, say <1MB). 平均而言，部分映射器从本地磁盘读取数据所带来的收益很小。 The gains from some mappers reading load from local disks, on average, is minor.
对于能够快速完成、且数据可以容纳在单台机器或小型集群主存中的处理任务，使用 MapReduce 框架通常效果不佳。 For processes that complete quickly, and where the data fits into main memory of a single machine or a small cluster, using a MapReduce framework usually is not effective. 由于这些框架旨在应对计算过程中整个节点失效的情况并从中恢复，因此会将中间结果写入分布式存储。 Since these frameworks are designed to recover from the loss of whole nodes during the computation, they write interim results to distributed storage. 这种崩溃恢复机制成本高昂，只有当计算涉及大量计算机且运行时间较长时，才值得采用。 This crash recovery is expensive, and only pays off when the computation involves many computers and a long runtime of the computation. 对于几秒钟内就能完成的任务，发生错误时直接重新启动即可，而至少有一台机器发生故障的概率会随集群规模的增大而迅速上升。 A task that completes in seconds can just be restarted in the case of an error, and the likelihood of at least one machine failing grows quickly with the cluster size. 对于此类问题，将所有数据保存在内存中并在节点故障时直接重新启动计算的实现，或者在数据量足够小时采用的非分布式解决方案，通常会比 MapReduce 系统更快。 On such problems, implementations keeping all data in memory and simply restarting a computation on node failures or —when the data is small enough— non-distributed solutions will often be faster than a MapReduce system.
分布与可靠性Distribution and reliability
MapReduce 通过将数据集上的若干操作分派给网络中的各个节点来实现可靠性。 MapReduce achieves reliability by parceling out a number of operations on the set of data to each node in the network. 每个节点都应定期回报已完成的工作和最新状态。 Each node is expected to report back periodically with completed work and status updates. 如果某个节点保持静默的时间超过该间隔，主节点（类似于 Google File System 中的主服务器）就会将其标记为失效，并将分配给该节点的工作重新分派给其他节点。 If a node falls silent for longer than that interval, the master node (similar to the master server in the Google File System) records the node as dead and sends out the node's assigned work to other nodes. 各个操作使用原子操作来命名输出文件，以此检查并确保没有相互冲突的线程并行运行。 Individual operations use atomic operations for naming file outputs as a check to ensure that there are not parallel conflicting threads running. 重命名文件时，除了将其命名为任务名称之外，还可以将其复制为另一个名称的文件（从而允许产生副作用）。 When files are renamed, it is possible to also copy them to another name in addition to the name of the task (allowing for side-effects).
reduce 操作的运行方式大致相同。 The reduce operations operate much the same way. 由于 reduce 操作在并行执行方面的特性较差，主节点会尝试将其调度到存有所处理数据的节点上，或调度到与该节点位于同一机架的节点上。 Because of their inferior properties with regard to parallel operations, the master node attempts to schedule reduce operations on the same node, or in the same rack as the node holding the data being operated on. 这一特性是可取的，因为它可以节省数据中心骨干网络的带宽。 This property is desirable as it conserves bandwidth across the backbone network of the datacenter.
具体实现不一定具有很高的可靠性。 Implementations are not necessarily highly reliable. 例如，在较早版本的 Hadoop 中，NameNode 是分布式文件系统的单点故障源。 For example, in older versions of Hadoop the NameNode was a single point of failure for the distributed filesystem. 较新版本的 Hadoop 通过为“NameNode”提供主用/备用故障转移机制，实现了高可用性。 Later versions of Hadoop have high availability with an active/passive failover for the "NameNode."
用途Uses
MapReduce 适用于广泛的应用，包括基于模式的分布式搜索、分布式排序、网页链接图反转、奇异值分解、网页访问日志统计、倒排索引构建、文档聚类、机器学习和统计机器翻译。 MapReduce is useful in a wide range of applications, including distributed pattern-based searching, distributed sorting, web link-graph reversal, singular value decomposition, web access log stats, inverted index construction, document clustering, machine learning, and statistical machine translation. 此外，MapReduce 模型已被改造以适用于多种计算环境，例如多核和众核系统、桌面网格、多集群、志愿计算环境、动态云环境、移动环境以及高性能计算环境。 Moreover, the MapReduce model has been adapted to several computing environments like multi-core and many-core systems, desktop grids, multi-cluster, volunteer computing environments, dynamic cloud environments, mobile environments, and high-performance computing environments.
在 Google，MapReduce 曾被用于完整地重新生成 Google 的万维网索引。 At Google, MapReduce was used to completely regenerate Google's index of the World Wide Web. 它取代了原先用于更新索引和执行各种分析的专用程序。 It replaced the old ad hoc programs that updated the index and ran the various analyses. 此后，Google 的开发工作转向了 Percolator、FlumeJava 和 Google MillWheel 等技术，这些技术提供流式操作和更新，而非批处理，从而能够在无需重建完整索引的情况下整合“实时”搜索结果。 Development at Google has since moved on to technologies such as Percolator, FlumeJava and Google MillWheel that offer streaming operation and updates instead of batch processing, to allow integrating "live" search results without rebuilding the complete index.
MapReduce 的持久化输入和输出通常存储在分布式文件系统中。 MapReduce's stable inputs and outputs are usually stored in a distributed file system. 临时数据通常存储在本地磁盘上，并由 reducer 远程获取。 The transient data are usually stored on local disk and fetched remotely by the reducers.
批评Criticism
缺乏新颖性Lack of novelty
专门研究并行数据库和无共享架构（shared-nothing architectures）的计算机科学家 David DeWitt 和 Michael Stonebraker，对 MapReduce 所能适用的问题范围之广提出了批评。 David DeWitt and Michael Stonebraker, computer scientists specializing in parallel databases and shared-nothing architectures, have been critical of the breadth of problems that MapReduce can be used for. 他们认为其接口过于底层，并质疑它是否真的代表了支持者所宣称的范式转变。 They called its interface too low-level and questioned whether it really represents the paradigm shift its proponents have claimed it is. 他们质疑 MapReduce 支持者关于其新颖性的主张，并以已存在超过二十年的 Teradata 作为现有技术的例子。 They challenged the MapReduce proponents' claims of novelty, citing Teradata as an example of prior art that has existed for over two decades. 他们还将 MapReduce 程序员与 CODASYL 程序员作比较，指出两者都是“使用低级语言编写程序，执行底层记录操作”。 They also compared MapReduce programmers to CODASYL programmers, noting both are "writing in a low-level language performing low-level record manipulation." MapReduce 使用输入文件且缺乏模式（schema）支持，因此无法获得 B 树和哈希分区等常见数据库系统功能所带来的性能提升，不过 Pig（或 PigLatin）、Sawzall、Apache Hive、HBase 和 Bigtable 等项目正在解决其中一些问题。 MapReduce's use of input files and lack of schema support prevents the performance improvements enabled by common database system features such as B-trees and hash partitioning, though projects such as Pig (or PigLatin), Sawzall, Apache Hive, HBase and Bigtable are addressing some of these problems.
Greg Jorgensen 撰文反驳了这些观点。 Greg Jorgensen wrote an article rejecting these views. Jorgensen 断言，DeWitt 和 Stonebraker 的整个分析毫无根据，因为 MapReduce 从未被设计为数据库，也从未打算用作数据库。 Jorgensen asserts that DeWitt and Stonebraker's entire analysis is groundless as MapReduce was never designed nor intended to be used as a database.
DeWitt 和 Stonebraker 随后于 2009 年发表了一项详细的基准测试研究，比较了 Hadoop 的 MapReduce 与关系数据库管理系统（RDBMS）方法在若干具体问题上的性能。 DeWitt and Stonebraker have subsequently published a detailed benchmark study in 2009 comparing performance of Hadoop's MapReduce and RDBMS approaches on several specific problems. 他们得出结论：关系数据库在多种数据使用场景中确实具有优势，尤其是在涉及复杂处理或整个企业范围内使用数据的情况下，但对于简单或一次性的处理任务，用户可能更容易采用 MapReduce。 They concluded that relational databases offer real advantages for many kinds of data use, especially on complex processing or where the data is used across an enterprise, but that MapReduce may be easier for users to adopt for simple or one-time processing tasks.
Danny Hillis 在其 1985 年的学位论文中也描述了用于 Connection Machine 的 MapReduce 编程范式，当时称为“xapping/reduction”，并依靠该机器的专用硬件来加速 map 和 reduce。 The MapReduce programming paradigm was also described in Danny Hillis's 1985 thesis intended for use on the Connection Machine, where it was called "xapping/reduction" and relied upon that machine's special hardware to accelerate both map and reduce. Connection Machine 最终采用的方言是 1986 年的 StarLisp，它提供了并行的 *map 和 reduce!!，而它又基于 1984 年的 Common Lisp，后者内置了非并行的 map 和 reduce。 The dialect ultimately used for the Connection Machine, the 1986 StarLisp, had parallel *map and reduce!!, which in turn was based on the 1984 Common Lisp, which had non-parallel map and reduce built in. Connection Machine 的超立方体架构采用树形方法，在 O(log⁡n) 时间内执行 reduce，这与 Google 论文中作为先前工作提及的方法实质上相同。 The tree-like approach that the Connection Machine's hypercube architecture uses to execute reduce in O(log⁡n) time is effectively the same as the approach referred to within the Google paper as prior work.
2010 年，Google 获授一项被称为 MapReduce 专利的专利。 In 2010 Google was granted what is described as a patent on MapReduce. 这项于 2004 年申请的专利可能涵盖 Hadoop、CouchDB 等开源软件对 MapReduce 的使用。 The patent, filed in 2004, may cover use of MapReduce by open source software such as Hadoop, CouchDB, and others. Ars Technica 的一位编辑承认 Google 在推广 MapReduce 概念方面的作用，但质疑该专利是否有效或具有新颖性。 In Ars Technica, an editor acknowledged Google's role in popularizing the MapReduce concept, but questioned whether the patent was valid or novel. 2013 年，作为其“开放专利不主张权利（OPN）承诺”的一部分，Google 承诺仅将该专利用于防御目的。 In 2013, as part of its "Open Patent Non-Assertion (OPN) Pledge", Google pledged to only use the patent defensively. 该专利预计将于 2026 年 12 月 23 日到期。 The patent is expected to expire on 23 December 2026.
受限的编程框架Restricted programming framework
MapReduce 任务必须编写为无环数据流程序，即先执行一个无状态的映射器（mapper），再执行一个无状态的归约器（reducer），并由批处理作业调度器执行。 MapReduce tasks must be written as acyclic dataflow programs, i.e. a stateless mapper followed by a stateless reducer, that are executed by a batch job scheduler. 这种范式使得对数据集进行反复查询变得困难，并带来了一些限制：在图处理等领域，需要多次访问同一工作集的迭代算法十分常见，因此这些限制尤为明显；而当数据存储在磁盘上、访问延迟较高时，甚至机器学习领域也会受到这些限制，因为即使算法能够容忍每一遍都按顺序访问数据，仍然需要多遍遍历数据。 This paradigm makes repeated querying of datasets difficult and imposes limitations that are felt in fields such as graph processing where iterative algorithms that revisit a single working set multiple times are the norm, as well as, in the presence of disk-based data with high latency, even the field of machine learning where multiple passes through the data are required even though algorithms can tolerate serial access to the data each pass.
