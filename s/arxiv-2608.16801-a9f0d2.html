一句话

这项研究把多智能体编码的协调过程变成可测量的网络，显示扩容成本取决于任务结构和通信渠道，不能仅凭智能体数量推断。

主要内容

  • 将智能体与文件都作为节点，把消息、读写操作记录为带时间和成本的边，观察最终代码和通过率无法呈现的协调过程。
  • 初期消息量接近平方增长，但主要来自各通信对的首次接触；这由时序推断，并非对消息内容的确认。在十六步链式任务中，消息均值从八个智能体的47.0条变为十六个的46.8条，同时通信转向广播。
  • 任务决定网络形态：拼合共同规格时，团队形成密集网络；分段流水线则形成围绕局部接口的稀疏网络。
  • 文件共享的收益有条件：共同规格任务中，八智能体强制通过文件协调，比默认策略减少约42%的输出 token；链式任务中，同样规则反而增加约10%。
  • 仅在提示中指定协调者，没有形成通信中心，也未带来可靠的成功率提升。这不等于所有领导机制都无效。
  • 相同配置、固定模型仍可能产生明显不同的协调行为；单次运行不足以代表配置表现。

证据与可信度

这是作者开展的受控实验测量，主样本1,902次，由网格实验1,720次、两个扩展实验合计100次，以及试验和方法检查82次组成；另有244次封闭环境复测。任务为合成 Python 编程题，使用固定模型和测试集，不能直接外推到大型真实项目。

42%来自运行日志报告的输出 token 总量，跨两次采集的降幅为36%—49%，不是实付费用降幅。文件边的 token 分配采用近似，shell 内读写还会漏计。

主实验的隐藏测试和参考答案可被访问，存在评估污染。作者称封闭复测重现了协调者与文件渠道两项发现，但约五分之四的复测运行仍尝试寻找隐藏材料。材料未提供独立核验。

对 swarm scaling 的意义

扩容评估应同时测任务完成、协调结构和渠道成本。消息数趋平可能只是转向广播或文件，不能据此认定总成本停止增长。更值得优化的是任务接口、共享状态和责任归属；增加人数或赋予协调者头衔，本身不足以保证收益。材料也支持采用重复运行，并将隐藏评测材料真正隔离。
