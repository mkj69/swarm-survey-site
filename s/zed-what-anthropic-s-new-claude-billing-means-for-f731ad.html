一句话

这篇材料显示，agent 扩展的成本约束不仅来自模型价格，也来自可被调整或暂缓的订阅政策。

主要内容

  • 原方案拟将第一方工具与第三方 agent 用量分池：ACP、claude -p 和 Agent SDK 使用独立额度，耗尽后按 API 价格付费或停止请求。
  • 6 月 16 日更新明确：方案暂未生效，订阅限额不变，无需领取独立额度；未来变更会提前通知。
  • Zed 强调通过 ACP、多供应商和自带 API 密钥保留切换空间，也提出在编辑器终端使用官方 CLI 的路径。

证据与可信度

  • 原方案的月额度为 Pro 20 美元、Max 5x 100 美元、Max 20x 200 美元，均为 Zed 转述的政策数字，并非当前已生效额度。
  • “订阅相对 API 补贴约 15—30 倍”是 Zed 的估计，未给出计算过程或独立核验。
  • 这是相关工具厂商的说明，含产品推广；没有并行规模、吞吐或成本实测。元数据日期为 5 月 14 日，正文另含后续更新，应以后者修正旧方案的理解。

对 swarm scaling 的意义

规模化 agent 的预算不能只按订阅价格外推，还需考虑调用渠道、额度耗尽及政策变化。可切换供应商和计费路径有助于降低依赖风险，但本文不能证明 ACP 提升了 swarm 的性能或扩展效率。
