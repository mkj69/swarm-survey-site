一句话

Claude Code 蜂群能否复用缓存，取决于请求前缀是否一致；目录隔离、子代理类型和调度间隔都会影响扩容成本。

主要内容

  • 缓存按请求开头的内容精确匹配，不按文件分别缓存。前缀某处改变，其后的内容就需要重新处理；稳定的系统提示和项目上下文因此放在前面。
  • 文档称，Claude Code 的缓存实际受机器与目录约束：工作目录、自动记忆路径等进入请求，不同目录的会话会形成不同前缀。同目录并行会话可共享匹配部分；顺序启动还要求启动时的 Git 状态快照一致。
  • 普通子代理使用自己的系统提示和工具集，首次请求无法读取父代理缓存，但不破坏父代理缓存。fork 继承父代理前缀，首次请求可复用缓存。
  • TTL 有 5 分钟和 1 小时两档，命中后刷新计时。订阅套餐内的主会话默认请求长档；普通子代理等默认短档，部分服务端控制的辅助请求例外。API、云服务及使用额度付费的请求默认短档，可分别配置。
  • 同前缀工作流扇出时，系统默认让首个代理先行，其余最多等待 5 秒，以便复用首个请求建立的缓存。
  • 切模型、切速度或改变部分工具定义可能失效；压缩主要重建会话层。网关若静默移除缓存标记，可能导致每轮历史都按未缓存输入计费。

证据与可信度

依据所给 Anthropic 官方文档正文。上述时间数字均为文档声明的产品规则或默认配置，属于厂商自述，不是独立实验结果。材料给出缓存读取与写入 token 计数、会话命中率等观测入口，但没有提供实际测量、成本降幅或蜂群规模对照，也没有独立核验。不同提供商、模型、计费方式和版本存在例外。

对 swarm scaling 的意义

  • worktree 隔离可能牺牲跨会话缓存复用。 不同 worktree 使用不同目录，按文档机制会产生不同前缀；这是机制推论，材料没有量化其额外成本。
  • 扩容不能只统计代理数量，还要区分普通子代理与 fork、共享前缀长度、模型和工具配置，以及任务间隔是否超过 TTL。
  • 扇出前先建立公共缓存，可能减少重复处理，但引入启动等待；延长 TTL 则增加写入费用。材料揭示了这些权衡，尚不能证明哪种部署方式的总成本或吞吐最优。
