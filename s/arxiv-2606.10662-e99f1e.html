一句话

DeLM 的核心主张是：多智能体提速取决于共享进展、减少等待和重复劳动，而不只是增加并行数量。

主要内容

  • 用共享上下文和任务队列替代中心主代理。各 agent 异步认领任务、发布中间成果，并在各自工作区整合完整解答。
  • 共享上下文保留发现、失败及完成摘要；文件按需读取和合入，纠错通过追加记录传播。任务归属和运行状态公开，帮助其他 agent 避免重复探索。
  • 长任务实验中，相对最强准确率基线，最高提升 17.5 个百分点；相对所依托的单 agent 框架，最高加速 2.49 倍。两者来自不同设置，不能理解为同一配置同时取得。
  • 扩容存在代价：Terminal-Bench 上从两个增加到四个 agent 后更快，但准确率下降约 3–4 个百分点。作者将其归因于组件整合错误和共享缺陷扩散。
  • 消融实验移除提前共享、同伴状态或共享上下文后，双 agent 的速度退回单 agent 附近，支持“协调机制影响并行收益”的解释。

证据与可信度

未读到全文：提供内容在相关工作处截断，部分表格和附录缺失。以下仅依据所给正文，未经独立核验。

数字属于作者实验测量与轨迹分析。论文称结果取三次运行的均值和标准差；Terminal-Bench、DeepSWE 各选取 10 个长任务，筛选依据是特定单 agent 配置的耗时，因此不能直接推广到完整基准或短任务。

17.5 个百分点来自 DeepSWE 上 90.83% 与 73.33% 的差值；2.49 倍是 Terminal-Bench 的延迟比。示例中的等待占比降至 2%、提速 5.5 倍，仅是单任务轨迹。

成本口径尤其要区分：每任务成本汇总所有 agent，单份提交成本则再除以 agent 数，因为每个 agent 都独立提交。单份提交更便宜不代表解决一个任务的总支出下降，也不代表这些提交相互独立。

对 swarm scaling 的意义

这项工作的价值在于把扩展瓶颈具体化为重复探索、同步等待和中心转述，并给出可检验的协调设计：异步认领、增量共享、状态可见、持续纠错。

证据支持小规模协作的潜力，尚不足以证明大规模 swarm 可持续扩展：实验只覆盖两个和四个 agent，ProgramBench 也仅有两个任务。已有准确率回落提示，扩容时还需关注集成负担与错误传播；评估应同时报告准确率、耗时和总成本。
