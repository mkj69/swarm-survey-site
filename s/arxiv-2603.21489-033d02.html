一句话

CAID 的核心发现是：多智能体协作的收益取决于依赖规划、工作区隔离和可靠集成，增加 agent 数量本身并不保证效果提升。

主要内容

  • CAID 由中央管理者拆解任务、建立依赖图，只分派前置依赖已完成并合入主分支的任务；工程 agent 在独立 git worktree 中异步实现、自测和提交，管理者逐项合并并更新计划。
  • 协作通过结构化 JSON 和版本提交明确责任边界。合并冲突由提交者处理；管理者负责整体调度与最终检查。
  • 摘要报告：相较单 agent，PaperBench 和 Commit0 分别提高 25.6、14.7 个百分点。正文中，MiniMax 在 PaperBench 从 10.5% 升至 36.1%；Claude 在 Commit0-Lite 从 53.1% 升至 59.1%。
  • 工作区隔离具有实际影响：PaperBench 上，共享工作区、仅靠指令约束的方案得分为 55.5%，低于单 agent 的 57.2%；worktree 隔离达到 63.3%。
  • 并行度存在上限：Commit0-Lite 从 2 名工程 agent 增至 4 名时表现改善，增至 8 名反而下降；PaperBench 超过 2 名后收益很小，时间和成本继续增加。
  • 作者承认，多 agent 的 API 成本更高，整体耗时也未显著缩短；串行集成与测试限制了并行加速。

对 swarm scaling 的意义

这篇论文支持的是“让可并行工作可靠汇合”的扩展路径。隔离减少相互覆盖，依赖规划控制启动顺序，测试与合并把局部产出转成可用的整体。

它也展示了扩展瓶颈：关键依赖遗漏、管理者调度能力和集成开销都会抵消更多 agent 的收益。现有证据主要来自少量工程 agent 的软件任务，尚不足以证明大规模 swarm 的扩展规律；更值得追踪的是成功率、总成本和端到端耗时能否同时改善。
