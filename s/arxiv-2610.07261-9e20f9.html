Abstract摘要
A team of coding agents can look fine agent by agent and still fail as a team: each one passes its own tests while the merged result is broken, and single-agent evaluation never catches it. Teams increasingly run several LLM coding agents in parallel on the same codebase, and the agents get in each other’s way: two rewrite the same function, one ships against a contract a teammate just changed, and integration fails after the work is already done. Most coordination tools treat this reactively (watch for a conflict, then warn), but under agent-speed concurrency the warning arrives after the wasted edit. We argue the problem is better posed as scheduling: take each work item’s declared scope, partition the work into disjoint scopes, and order merges along the producer $\rightarrow$ consumer dependency graph, all up front. We build this planner into Nerveplane, a local-first system for coding agents, and evaluate it with NP-Bench, an environment-grounded, three-arm benchmark (no coordination; reactive detection; proactive planning) that verifies integration outcomes off a real git merge, both as a deterministic simulation and with live agents. Deterministically, the planner lifts clean-integration success from 1/9 to 9/9 scenarios and drives merge conflicts from 13 to 0; its advantage grows with the number of agents. With live agents on a breaking contract change, the planner rescues an outcome that both baselines miss on every seed: a clean-integration rate of 0 under no-coordination and under reactive detection rises to 1.0 with the planner on a frontier model, and to 0.6 on a small one, while agents respect their assigned scopes (none of 5 strayed). A separate memory result collapses the repeated-mistake rate from 1.00 to 0.00 on both a strong and a weak model: a decision recorded in one session stops an agent in a later session from repeating it, an information effect no amount of model strength substitutes for. We also report what did not help: at window-fitting scales, routing facts to agents does not rescue retrieval accuracy over long contexts; its value is cost and capacity, not attention. Methodologically, NP-Bench doubles as an environment-grounded verifier for multi-agent coding: each agent passes its own checks, yet the integrated system can still be broken, and a real merge-and-test reveals it. Across the two capability tiers and two vendors we tested, the benefit did not shrink as models got stronger, because it comes from how work is allocated rather than from model reasoning.
一个编程智能体团队中的每个智能体单独看来都可能表现正常，但团队整体仍可能失败：每个智能体都通过了自己的测试，合并后的结果却无法正常工作，而单智能体评估永远无法发现这一点。团队越来越多地让多个 LLM 编程智能体在同一代码库上并行工作，而这些智能体会相互干扰：两个智能体重写同一个函数，一个智能体依据队友刚刚修改的契约交付代码，等工作已经完成后，集成却失败了。大多数协调工具以被动响应的方式处理这一问题（监测冲突，然后发出警告），但在智能体速度的并发作业下，警告到达时，无效的编辑已经发生。我们认为，将这一问题表述为调度问题更为合适：根据每个工作项声明的作用范围，将工作划分为互不重叠的范围，并沿生产者 $\rightarrow$ 消费者依赖图安排合并顺序，所有这些都在开始前完成。我们将这一规划器集成到面向编程智能体的本地优先系统 Nerveplane 中，并使用 NP-Bench 对其进行评估；NP-Bench 是一个立足实际环境、设有三个实验组（无协调、被动检测、主动规划）的基准，通过真实的 git 合并验证集成结果，既支持确定性模拟，也支持真实智能体实验。在确定性实验中，规划器将各场景中无故障集成的成功比例从 1/9 提升至 9/9，并将合并冲突数量从 13 降至 0；其优势随智能体数量的增加而扩大。在涉及破坏性契约变更的真实智能体实验中，规划器挽救了两种基线在每个随机种子下都未能实现的结果：无协调和被动检测下均为 0 的无故障集成率，在使用规划器后，前沿模型上升至 1.0，小型模型上升至 0.6，同时智能体遵守了分配给它们的作用范围（5 个中没有任何一个越界）。另一项关于记忆的结果显示，无论在强模型还是弱模型上，重复犯错率都从 1.00 降至 0.00：在一次会话中记录的决策，能够阻止智能体在后续会话中重犯同样的错误，这种信息效应无法由任何程度的模型能力提升来替代。我们也报告了未能带来帮助的方法：当上下文规模仍能容纳于上下文窗口内时，将事实路由给智能体并不能改善长上下文中的检索准确率；其价值在于成本和容量，而非注意力。在方法论上，NP-Bench 还可作为立足实际环境的多智能体编程验证器：每个智能体都通过了自身检查，集成后的系统却仍可能无法正常工作，而真实的合并与测试能够揭示这一问题。在我们测试的两个能力层级、两家供应商的模型中，这一收益并未随着模型变强而缩小，因为它源于工作分配方式，而非模型推理能力。
1 Introduction1 引言
Running one coding agent is now routine; running several at once is where teams are headed. Worktree multiplexers spin up an agent per branch, CI pipelines fan issues out to a pool of agents, and a single developer can supervise a handful of them at a time. Once that happens, the bottleneck stops being how well any one agent writes code and starts being whether the agents step on each other. Two agents edit the same file and produce a merge conflict; one agent renames a field in an API while another codes against the old shape and integrates to something that merges cleanly but is broken; a decision made in the morning is re-litigated in the afternoon by an agent that never saw it. These are coordination failures, and they scale with the number of agents.
运行一个编程智能体如今已是常态；同时运行多个智能体则是团队正在迈向的方向。工作树多路复用器为每个分支启动一个智能体，CI 流水线将问题分发给智能体池，而单个开发者也可以同时监督数个智能体。一旦如此，瓶颈就不再是某个智能体编写代码的能力有多强，而是这些智能体是否会相互干扰。两个智能体编辑同一个文件，产生合并冲突；一个智能体重命名 API 中的某个字段，另一个却仍依据旧结构编写代码，集成结果虽然能够顺利合并，却无法正常工作；上午做出的决策，下午又被一个从未见过该决策的智能体重新争论。这些都是协调失效问题，并且会随着智能体数量的增加而加剧。
The prevailing response is reactive. A coordination layer watches for trouble (overlapping edits, a changed contract) and warns the affected agent once the change is observed. This is the same idea behind decades of developer “workspace awareness” tools [3], and it is genuinely useful for humans who work on the scale of hours. But agents work on the scale of seconds. By the time a teammate’s edit has been sensed and a warning routed, the warned agent has often already written the conflicting code. The warning then buys a cleanup, not a prevention.
目前主流的应对方式是被动响应。协调层监测潜在问题（重叠的编辑、发生变化的契约），并在观察到变更后向受影响的智能体发出警告。这与数十年来开发者“工作空间感知”工具 [3] 背后的思路相同，而且对于以小时为工作时间尺度的人类而言，确实很有用。但智能体以秒为工作时间尺度。等到队友的编辑被检测到、警告被传递过来时，收到警告的智能体往往已经写出了冲突代码。此时，警告带来的是事后清理，而非事前预防。
This paper takes a different stance: coordination among parallel coding agents is a scheduling problem. Before the agents start, take each work item’s declared scope, partition the work so that concurrently-running agents have disjoint scopes, and order the merges along the producer $\rightarrow$ consumer dependency graph so that whoever changes a contract lands before whoever consumes it. Where a reactive detector can only tell an agent it has a problem after the fact, a schedule prevents the problem by construction.
本文采取了不同的立场：并行编程智能体之间的协调是一个调度问题。在智能体开始工作之前，根据每个工作项声明的作用范围划分工作，使并发运行的智能体具有互不重叠的作用范围，并沿生产者 $\rightarrow$ 消费者依赖图安排合并顺序，确保修改契约的一方先于使用该契约的一方合入代码。被动检测器只能在事后告知智能体它遇到了问题，而调度安排则通过其构造方式预防问题。
There is an obvious objection: “disjoint scopes don’t conflict” is a tautology. But that objection is the research question in disguise. A schedule helps only if (a) its input scopes are accurate and (b) the agents actually respect the scopes they are handed. In this paper the scopes are declared (given by each work item’s stated files and consumed contracts), so we assume (a) and measure (b): an agent told to stay out of a file may edit it anyway, and whether it complies is exactly what the live experiments check. Inferring scopes automatically is an open problem we flag but do not solve. The contribution is the compliance measurement, not the tautology.
一个显而易见的反对意见是：“互不重叠的作用范围不会发生冲突”是一句同义反复。但这一反对意见实际上是研究问题的另一种表述。调度安排只有在以下条件下才有帮助：(a) 输入的作用范围准确；(b) 智能体确实遵守分配给它们的作用范围。本文中的作用范围是声明给出的（由每个工作项列明的文件和所使用的契约确定），因此我们假设 (a) 成立，并测量 (b)：即使被告知不要修改某个文件，智能体仍可能编辑它，而真实智能体实验检验的正是它是否遵守这一要求。自动推断作用域仍是一个开放问题，我们指出了这一问题，但未予以解决。本文的贡献在于衡量遵从程度，而不在于这一同义反复。
There is a verification problem hiding in that measurement. Whether a coordination layer actually helps is not something an agent can self-report, and it is invisible to single-agent evaluation: each agent, checked on its own branch, looks correct; the breakage surfaces only when the branches are integrated. Answering it takes an environment-grounded verifier that reads ground-truth signals (does the merged tree build, does it pass, did the consumer adapt to the new contract) off a real integration rather than trusting any agent’s word. NP-Bench is that verifier, and its three-arm design turns “did coordination help” from an assertion into a measurement.
这一测量中隐藏着一个验证问题。协调层是否确实有帮助，不能由智能体自行报告，也无法通过单智能体评估来观察：在各自分支上单独检查时，每个智能体看起来都没有问题；只有在整合各分支时，问题才会显现。要回答这个问题，需要一个以环境为依据的验证器，从真实的集成过程中读取真实基准信号（合并后的代码树能否构建、能否通过测试、调用方是否已适配新的契约），而不是相信任何智能体的说法。NP-Bench 就是这样的验证器，其三组实验设计将“协调是否有帮助”从一项断言转化为一项测量。
We make four claims and back each with data.
我们提出四项主张，并为每一项提供数据支持。
A verification benchmark. NP-Bench scores three arms (no coordination C0, reactive detection C1-detect, proactive planning C1-plan) both deterministically and with live agents from two model families, reading ground-truth integration signals off a real merge, the coordination axis that single-agent benchmarks like SWE-bench do not measure (Section 5). We present it as a focused study of when coordination helps, not a comprehensive benchmark.
一个验证基准。NP-Bench 采用确定性评测以及来自两个模型家族的实际运行智能体，对三个实验组（无协调 C0、反应式检测 C1-detect、主动式规划 C1-plan）进行评分，从真实的合并过程中读取集成的真实基准信号，衡量 SWE-bench 等单智能体基准未覆盖的协调维度（第 5 节）。我们将其定位为一项聚焦于协调何时有帮助的研究，而非一个综合性基准。
A formulation and a planner. We cast coordination as disjoint-scope partitioning plus topological merge ordering, and implement a small, deterministic static planner (Section 4).
一种形式化表述和一个规划器。我们将协调表述为互不相交的作用域划分与拓扑合并排序的结合，并实现了一个小型、确定性的静态规划器（第 4 节）。
Results with an honest capability analysis. In the evaluated scenarios, the planner strictly dominates both baselines; a vague reactive warning is worth about as much as nothing to a live agent; and we separate the part of the effect that holds across the tested capability tiers from the part that varies with capability (Sections 6 and 8).
实验结果与坦诚的能力分析。在所评估的场景中，该规划器严格优于两个基线；对于实际运行的智能体，模糊的反应式警告几乎等同于没有警告；此外，我们区分了效果中在所测试的各能力层级上均成立的部分，以及随能力变化的部分（第 6 节和第 8 节）。
What did not work. We tried to show that routing facts to agents rescues retrieval accuracy over long contexts and could not; we report that negative result and the measurement bug we caught along the way (Section 7).
未奏效的尝试。我们曾尝试证明，将事实路由给智能体能够挽救长上下文中的检索准确率，但未能成功；我们报告了这一负面结果，以及在此过程中发现的测量缺陷（第 7 节）。
2 Related work2 相关工作
Multi-agent LLM frameworks.多智能体 LLM 框架。
A first wave of systems orchestrates several LLM agents through roles and messages: AutoGen composes conversable agents under a group-chat manager [18]; MetaGPT runs an SOP-driven “software company” of agents [9]; ChatDev structures a chat-driven development organization [17]; CAMEL and AgentVerse study role-play and emergent multi-agent behavior [13, 5]. These divide labor by role and coordinate through dialogue. None offers a scheduling guarantee that concurrently-editing agents will avoid colliding on shared files or stale contracts. The planner here is complementary: it takes the work items such a framework produces and computes a disjoint-scope partition and merge order before execution. We target the substrate (who may touch what, and in what order), not the role or dialogue layer.
第一波系统通过角色和消息来编排多个 LLM 智能体：AutoGen 在群聊管理器的管理下组合可对话智能体 [18]；MetaGPT 运行一个由 SOP 驱动的智能体“软件公司”[9]；ChatDev 构建了一个由聊天驱动的开发组织 [17]；CAMEL 和 AgentVerse 研究角色扮演与涌现的多智能体行为 [13, 5]。这些系统按角色分工，并通过对话进行协调。它们均未提供调度保证，以确保并发编辑的智能体不会因共享文件或过时契约而发生冲突。本文的规划器与这些框架互为补充：它接收此类框架生成的工作项，并在执行前计算互不相交的作用域划分及合并顺序。我们关注的是底层机制（谁可以修改什么，以及按什么顺序修改），而非角色层或对话层。
Coding-agent benchmarks.编码智能体基准。
Evaluation of coding agents is dominated by single-agent, single-repository task success: SWE-bench resolves real GitHub issues [11], SWE-agent studies the agent-computer interface that drives such resolution [19], and execution benchmarks like HumanEval [4] and LiveCodeBench [10] score generated code. None measures whether $N$ agents working in parallel integrate cleanly. NP-Bench adds exactly that axis (clean-merge success, wasted work, and scope compliance for concurrent agents) and is orthogonal to per-task resolution.
编码智能体的评估主要关注单智能体在单个代码仓库中的任务成功情况：SWE-bench 针对真实的 GitHub 问题开展求解评估 [11]，SWE-agent 研究支持此类问题求解的智能体与计算机交互接口 [19]，而 HumanEval [4] 和 LiveCodeBench [10] 等执行基准则对生成的代码进行评分。这些基准均不衡量 $N$ 个并行工作的智能体能否顺利集成其成果。NP-Bench 恰好补充了这一维度（并发智能体的无冲突合并成功率、无效工作量和作用域遵从程度），且与逐任务的问题解决情况相互独立。
Conflict detection and developer coordination.冲突检测与开发者协调。
Proactively predicting merge conflicts by watching parallel edits is a long line in software engineering [3]. This is the intellectual ancestor of the C1-detect arm: valuable, but reactive: the warning fires once a change is observed, which under agent-speed concurrency is frequently after the wasted edit. We show empirically that a proactive schedule dominates reactive detection, and that a vague reactive warning is close to no coordination for a live agent.
通过监测并行编辑来主动预测合并冲突，是软件工程领域一个长期存在的研究方向 [3]。这一方向是 C1-detect 实验组的思想源头：它很有价值，但属于反应式机制：只有在观察到变更后才会触发警告，而在智能体速度下的并发场景中，这往往发生在无效编辑已经完成之后。我们通过实验证明，主动式调度优于反应式检测，而对于实际运行的智能体，模糊的反应式警告近乎等同于没有协调。
Scheduling and dependency-aware ordering.调度与依赖感知排序。
Framing coordination as scheduling connects to classic task-graph work: topological ordering of a dependency DAG [12] and the NP-hardness of the partitioning/coloring subproblem [7]. That software structure mirrors team structure is Conway’s observation [6], and that adding people (or agents) to concurrent work raises coordination cost is Brooks’s [2]. We adapt disjoint-partition-plus-topological-merge to the declared code scopes of LLM agents, where the novel empirical question studied here is whether agents will respect the resulting assignments. Inferring those scopes automatically remains future work.
将协调表述为调度问题，使其与经典的任务图研究建立了联系：依赖关系有向无环图（DAG）的拓扑排序 [12]，以及划分/着色子问题的 NP-hard 性质 [7]。软件结构映射团队结构，是 Conway 的观察 [6]；而向并发工作中增加人员（或智能体）会提高协调成本，则是 Brooks 的观察 [2]。我们将互不相交的划分与拓扑合并相结合的方法应用于 LLM 智能体声明的代码作用域；本文研究的新实证问题在于，智能体是否会遵守由此产生的任务分配。自动推断这些作用域仍有待未来研究。
Agent protocols and memory.智能体协议与记忆。
Agent tooling is standardizing on protocols for model-to-tool and agent-to-agent communication—the Model Context Protocol [1] and Agent2Agent [8]. Nerveplane exposes its coordination surface over MCP but adds the missing piece those protocols leave open: what to route, to whom, and in what order. On memory, systems such as MemGPT [15] and generative agents [16] give an agent long-term recall within its own task. Our memory result is cross-session and cross-agent: a decision recorded by one session prevents an agent in a later session from repeating a mistake, and we isolate it as an information effect that holds equally on strong and weak models.
智能体工具正在围绕模型与工具之间、智能体与智能体之间的通信协议形成标准，即 Model Context Protocol [1] 和 Agent2Agent [8]。Nerveplane 通过 MCP 提供协调接口，同时补充了这些协议尚未解决的缺失环节：路由什么、路由给谁，以及按什么顺序路由。在记忆方面，MemGPT [15] 和生成式智能体（generative agents）[16] 等系统使智能体能够在自身任务范围内进行长期回忆。我们的记忆实验结果具有跨会话和跨智能体的特征：一个会话记录的决策可防止后续会话中的智能体重蹈覆辙；我们将其分离为一种信息效应，该效应在强模型和弱模型上同样成立。

3 The coordination plane3 协调平面
The planner does not run in a vacuum; it needs to know what agents exist, what they are touching, and how services depend on one another. Nerveplane supplies that substrate. It is a local-first system for coding agents: a single per-machine daemon, a SQLite store, and a set of tools exposed over MCP (register, sync, publish, decision, discover, chat, memory, and task); the planner runs inside the daemon and delivers each agent’s assignment through register/sync. It is agent-agnostic: Claude Code, Codex, and OpenCode all connect through the same surface.
规划器并非在真空中运行；它需要知道有哪些智能体、它们正在修改什么，以及各项服务之间如何相互依赖。Nerveplane 提供了这一基础。这是一个面向编程智能体的本地优先系统：每台机器上运行一个守护进程，配备一个 SQLite 存储，以及一组通过 MCP 暴露的工具（register、sync、publish、decision、discover、chat、memory 和 task）；规划器在守护进程内部运行，并通过 register/sync 向各智能体下发任务分配。它不依赖特定智能体：Claude Code、Codex 和 OpenCode 均通过同一接口接入。
The design choice that matters for coordination is that the daemon observes state rather than waiting to be told about it. A passive sensing loop polls each registered agent’s git worktree and emits an event when the changed-file set actually changes, so coordination never depends on an agent remembering to announce its work.[fn1] A routing engine then decides who needs to hear about a given change: the owner of an affected task, other agents in the same repository, and, through a service graph, agents in other repositories that consume a changed API contract. Durable project decisions live in a queryable ledger separate from chat history, and a cross-agent memory (keyword by default, optionally semantic) lets a fact learned in one session resurface in another. Figure 1 sketches the loop.
对协调至关重要的设计选择是：守护进程主动观测状态，而非等待状态上报。一个被动感知循环会轮询每个已注册智能体的 git 工作树（worktree），并在发生变更的文件集合确实发生变化时发出事件，因此协调从不依赖智能体记得主动通报自己的工作。[fn1] 随后，路由引擎会决定哪些智能体需要获知某项变更：受影响任务的负责人、同一代码仓库中的其他智能体，以及通过服务图识别出的、位于其他代码仓库且使用已变更 API 契约的智能体。需要持久保存的项目决策存储在独立于聊天历史的可查询账本中，而跨智能体记忆（默认基于关键词，也可选择语义检索）可使一个会话中学到的事实在另一个会话中再次被检索出来。图 1 概述了这一循环。

4 Coordination as scheduling4 将协调视为调度
Model.模型。
Let $W$ be a set of work items. Each item $w$ has a declared scope $\sigma(w)$ —the set of files (or symbols) it will write—and a set of contracts it consumes. Two items conflict when their scopes intersect, $\sigma(w_{i})\cap\sigma(w_{j})\neq\varnothing$ . Item $w_{j}$ depends on $w_{i}$ (edge $w_{i}\!\rightarrow\!w_{j}$ ) when $w_{j}$ consumes a contract that $w_{i}$ produces, i.e. $w_{i}$ ’s scope overlaps $w_{j}$ ’s consumed set. A plan is a partition of $W$ into batches whose members have pairwise-disjoint scopes, together with a merge order $\pi$ that respects the dependency edges.
设 $W$ 为工作项集合。每个工作项 $w$ 都有一个声明的范围 $\sigma(w)$——即其将写入的文件（或符号）集合——以及一组它所使用的契约。当两个工作项的范围相交，即 $\sigma(w_{i})\cap\sigma(w_{j})\neq\varnothing$ 时，它们便发生冲突。当 $w_{j}$ 使用了 $w_{i}$ 产生的契约，即 $w_{i}$ 的范围与 $w_{j}$ 所使用的集合重叠时，工作项 $w_{j}$ 依赖于 $w_{i}$（边 $w_{i}\!\rightarrow\!w_{j}$）。一个计划由两部分组成：将 $W$ 划分为若干批次，每个批次内各成员的范围两两不相交；以及一个遵循依赖边的合并顺序 $\pi$。
Claim (assumption-scoped).论断（限于所述假设）。
If the declared scopes are accurate and the dependency relation is a DAG, then a disjoint-scope partition plus a topological merge order yields zero structural conflicts by construction: concurrently-running items never touch the same file, and no consumer is merged before its producer. A reactive detector cannot make this guarantee because it acts only after a collision has been sensed. Scope accuracy is assumed through the hand-declared inputs; agent scope-compliance is the empirical unknown measured in Section 6.
如果声明的范围准确，且依赖关系构成有向无环图（DAG），那么，范围互不相交的分组加上拓扑合并顺序，可从构造上保证结构性冲突为零：并发运行的工作项绝不会修改同一文件，且任何使用方都不会先于其提供方被合并。反应式检测器无法提供这一保证，因为它只有在感知到冲突之后才采取行动。范围准确性通过人工声明的输入予以假定；智能体是否遵守范围则是通过第 6 节的实证测量来确定的未知因素。
Algorithm.算法。
Algorithm 1 is the static planner. It builds the dependency graph, marks items that must not take their naive edit (either because they contend for an owned file or because they consume a produced contract), computes a stable topological order by Kahn’s algorithm [12] with deterministic cycle breaking, and greedily colors the scope-overlap graph into parallel batches. Exact minimum coloring is NP-hard [7]; the greedy pass is a documented approximation and is enough for the suite. Every tie breaks on input order, so a given input always yields the same plan, a requirement for reproducible experiments. The item’s assignment (its scope, merge slot, and a human-readable reason when it was reassigned) is delivered to the agent at register/sync time.
算法 1 是静态规划器。它构建依赖图，标记不得按原始方案进行编辑的工作项（原因可能是它们争用已有归属的文件，或使用了其他工作项产生的契约），通过带有确定性环路打破机制的 Kahn 算法 [12] 计算稳定的拓扑顺序，并对范围重叠图进行贪心着色，将工作项划分为可并行执行的批次。求解精确的最小着色是 NP-hard [7]；该贪心过程是一种有文档说明的近似方法，足以满足该测试套件的需要。所有平局均按输入顺序打破，因此给定输入始终产生相同计划，这是实验可复现性的要求。工作项的分配信息（其范围、合并次序位置，以及重新分配时供人阅读的原因）会在 register/sync 时下发给智能体。

The reassigned set $R$ is what the suite ultimately probes. An item lands in $R$ when the planner decides, up front and independent of runtime timing, that its naive scope would collide with a teammate or that it consumes a contract another item produces. That is exactly the information a reactive detector can only deliver after the agent has already edited.
重新分配的工作项集合 $R$ 是该测试套件最终考察的对象。当规划器预先判定某个工作项的原始范围会与协作智能体发生冲突，或它使用了另一工作项产生的契约时，该工作项便被纳入 $R$；这一判定独立于运行时的时序。这恰恰是反应式检测器只有在智能体已经完成编辑后才能提供的信息。
5 NP-Bench5 NP-Bench
NP-Bench compares three arms. C0 is no coordination: agents act blind to one another. C1-detect is reactive coordination: an agent is warned when a teammate’s sensed change touches a file it cares about, and (for live agents) the warning is deliberately vague (“a teammate may be editing $X$ ”), because that is what a realistic just-in-time warning looks like. C1-plan is the proactive planner: before starting, an agent receives either an allowed/forbidden scope or, for a contract consumer, the exact contract migration and an instruction to code against the new shape after the producer merges. The plan also supplies the merge order. Thus the live comparison evaluates the combined effect of timing, information specificity, scope assignment, and merge ordering rather than isolating any one component.
NP-Bench 比较了三个实验组。C0 表示无协调：智能体在行动时对彼此的情况一无所知。C1-detect 表示反应式协调：当感知到的队友变更涉及某个智能体关注的文件时，该智能体会收到警告；对于真实运行的智能体，警告会被刻意设计得较为模糊（“某位队友可能正在编辑 $X$ ”），因为现实中的即时警告就是如此。C1-plan 是主动式规划器：开始工作前，智能体会收到允许或禁止修改的范围；若智能体是契约的消费方，则会收到确切的契约迁移内容，以及在生产方合并后依据新结构编写代码的指令。该计划还提供合并顺序。因此，真实运行对比评估的是时机、信息具体程度、范围分配和合并顺序的综合效果，而非单独考察其中任何一个组成部分。
The suite runs at two tiers. Tier A is a deterministic simulation that drives the real product primitives—agent registration, worktree sensing, conflict detection, and the planner core—over scripted scenarios, and scores the result with a real git integration. An agent takes its coordinated edit exactly when it was warned in time (C1-detect) or reassigned by the planner (C1-plan); otherwise it takes its naive edit. Tier A is CI-gated and reproducible. Tier B replaces the simulated agents with live ones: real coding agents run headless in isolated git worktrees under each arm, their branches are integrated with a real merge, and the outcome is scored. Tier B is nondeterministic and costs money, so it is not a CI gate.
该测试套件分两个层级运行。Tier A 是确定性模拟，在脚本化场景中驱动真实产品的基础功能——智能体注册、工作树感知、冲突检测和规划器核心——并通过真实的 git 集成对结果进行评分。智能体仅在及时收到警告（C1-detect）或被规划器重新分配任务（C1-plan）时执行协调后的编辑；否则执行其朴素编辑。Tier A 被纳入 CI 门禁，且可复现。Tier B 将模拟智能体替换为真实智能体：真实的编程智能体在各实验组的隔离 git 工作树中以无界面模式运行，通过真实合并集成其分支，并对结果进行评分。Tier B 具有非确定性，且需要付费，因此不作为 CI 门禁。
We report the following metrics. CTSR (clean-tree success rate) is the fraction of runs that both merge without conflict and pass a post-integration acceptance check. Merge conflicts and wasted LOC count git conflicts and the lines in conflicting edits that must be reworked. Scope-leakage is the fraction of reassigned C1-plan agents that edited a file they were told not to; 0 means full compliance. Consumer-adaptation rate is the fraction of fan-out consumers whose merged code uses the new contract field. Repeated-mistake rate is one minus adherence to a prior session’s recorded decision. Merge-order correctness checks that every producer is ordered before its consumers.
我们报告以下指标。CTSR（干净工作树成功率，clean-tree success rate）指既能无冲突合并、又能通过集成后验收检查的运行所占的比例。合并冲突数和浪费的代码行数（LOC）分别统计 git 冲突数量，以及冲突编辑中必须返工的代码行数。范围越界率指被重新分配任务的 C1-plan 智能体中，编辑了明确禁止其编辑的文件的智能体所占的比例；0 表示完全遵守要求。消费方适配率指扇出消费方中，合并后的代码使用了新契约字段的消费方所占的比例。重复犯错率等于一减去对先前会话所记录决策的遵循率。合并顺序正确性检查每个生产方是否都排在其消费方之前。
Live runs span two model families: two Claude models of very different capability—a frontier model (Claude Opus 4.8, claude-opus-4-8) and a small one (Claude Haiku 4.5, claude-haiku-4-5)—and OpenAI’s Codex (gpt-5-codex). The two Claude models separate what coordination does from what raw capability does; the second vendor’s model checks that the effect is not a Claude-specific quirk. Live sample sizes are modest ( $K\!=\!3$ – $15$ seeds per cell, the pivotal contract cell at $K{=}15$ ); we report Wilson 95% intervals and treat the smaller cells as pilots (Section 9).
真实运行涵盖两个模型系列：两个能力差异很大的 Claude 模型——一个前沿模型（Claude Opus 4.8, claude-opus-4-8）和一个小型模型（Claude Haiku 4.5, claude-haiku-4-5）——以及 OpenAI 的 Codex（gpt-5-codex）。两个 Claude 模型用于区分协调带来的作用与模型自身能力带来的作用；第二家供应商的模型用于检验该效果是否并非 Claude 特有的现象。真实运行的样本量较小（每个实验单元使用 $K\!=\!3$ – $15$ 个随机种子，关键的契约实验单元使用 $K{=}15$）；我们报告 Wilson 95% 区间，并将样本量较小的实验单元视为预实验（第 9 节）。

6.1 Deterministic three-arm and effect-by- $N$6.1 确定性三组对比及效果随 $N$ 的变化
Across nine scripted scenarios (shared-file, contract, cross-repo fan-out, an independent control, and concurrent/high- $N$ variants), CTSR rises from 1/9 under C0 to 4/9 under C1-detect to 9/9 under C1-plan; total merge conflicts fall 13 $\rightarrow$ 12 $\rightarrow$ 0 and wasted LOC 54 $\rightarrow$ 49 $\rightarrow$ 0. The gap between the two coordination arms is the point. On sequential dependency scenarios the reactive detector and the planner tie: both fix the problem, because the warning has time to land. On concurrent scenarios the detector collapses to the C0 baseline: the warning arrives after the edit. The planner does not, because it never let the collision be scheduled in the first place. On the control scenario (unrelated tasks) all three arms succeed and the plane raises no warnings, so the coordination layer does no harm when there is nothing to coordinate. Cross-repo routing is exact: on the fan-out scenario the two real consumers are warned and the unrelated service is not (100% routing hit, 0% false positives).
在九个脚本化场景（共享文件、契约、跨仓库扇出、一个独立对照场景，以及并发和高 $N$ 变体）中，CTSR 从 C0 下的 1/9 上升到 C1-detect 下的 4/9，再上升到 C1-plan 下的 9/9；合并冲突总数按 13 $\rightarrow$ 12 $\rightarrow$ 0 下降，浪费的代码行数按 54 $\rightarrow$ 49 $\rightarrow$ 0 下降。关键在于两个协调实验组之间的差距。在顺序依赖场景中，反应式检测器与规划器表现持平：两者都能解决问题，因为警告有时间及时送达。在并发场景中，检测器的表现退化至 C0 基线水平：警告在编辑完成后才到达。规划器则不会如此，因为它从一开始就没有允许会发生冲突的操作被调度执行。在对照场景（互不相关的任务）中，三个实验组均成功，且协调平面不发出任何警告，因此在没有协调需求时，协调层不会产生负面影响。跨仓库路由十分精确：在扇出场景中，两个实际消费方均收到警告，而无关服务未收到警告（100% 路由命中率，0% 假阳性率）。

The fan-out version scales that scenario: one producer migrates the contract and $N$ consumers each render in their own file. Adaptation rate is 0.00 under both baselines and 1.00 under the planner at every $N\in\{2,4,8\}$ (frontier, $K{=}3$ ). The rate saturates, so the absolute number of broken consumers under C0 grows linearly with $N$ while the planner holds all of them.
扇出版本扩展了这一场景：一个生产者迁移契约，$N$ 个消费者各自在自己的文件中进行渲染。对于每个 $N\in\{2,4,8\}$，两种基线的适配率均为 0.00，规划器的适配率均为 1.00（前沿模型，$K{=}3$）。适配率已达到极值，因此，C0 下出错的消费者绝对数量随 $N$ 线性增长，而规划器能确保所有消费者均正确适配。
Finally, the make-or-break question for the whole approach: do agents respect the scopes they are assigned? On the shared-file scenario ( $K{=}5$ , frontier), scope-leakage is 0.00: every planner agent put its new work in a separate file and left the owned file untouched, several of them noting that they were doing so “as coordinated.” The disjoint-scope partition is not a tautology defeated by non-compliance; real agents honor it.
最后，决定整个方法成败的问题是：智能体是否遵守分配给它们的作用范围？在共享文件场景中（$K{=}5$，前沿模型），作用范围越界率为 0.00：规划器组的每个智能体都将新增工作放在单独的文件中，并保持已有归属的文件不变，其中几个还指出，它们是“按照协调安排”这样做的。互不相交的作用范围划分并非一种会因不遵守规定而失效的同义反复；真实的智能体确实会遵守这种划分。
6.3 Memory continuity: a capability-independent effect6.3 记忆连续性：一种与能力无关的效应
The results above concern work allocation. A separate experiment concerns knowledge. No model, however strong, can recall a project-specific fact it was never told; if one session discovers a gotcha and records it, an agent in a later session should stop repeating the mistake—but only if memory carries the discovery across sessions. We built a sandbox repository with two symmetric authentication backends that both export the same function, where which one is sanctioned appears nowhere in the code; it is a team decision that lives only in memory. Session 1 records the decision; session 2 (a fresh session) is asked which backend to import. The repeated-mistake rate falls from 1.00 to 0.00 on both the frontier model and Haiku ( $K{=}5$ ). Because the correct choice is not recoverable from the repository, the gap is an information gap, not a reasoning gap, and it closes identically regardless of model strength. The raw replies confirm it: without memory the agents call the two backends “a genuine tie” and guess; with memory they cite the recalled policy and import the sanctioned module.
上述结果涉及工作分配。另一项独立实验涉及知识。无论模型多么强大，都无法回忆起从未被告知的项目特定事实；如果一次会话发现并记录了某个易错点，那么后续会话中的智能体就应当不再重复这一错误——但前提是记忆能将这一发现传递到后续会话。我们构建了一个沙箱代码仓库，其中包含两个对称的身份认证后端，二者都导出同一个函数，但代码中没有任何地方说明哪个后端获得了批准；这是一项仅存于记忆中的团队决策。会话 1 记录该决策；会话 2（一个全新会话）则被要求回答应导入哪个后端。在前沿模型和 Haiku 上，重复犯错率均从 1.00 降至 0.00（$K{=}5$）。由于无法从代码仓库中推断出正确选择，这一差距是信息差距，而非推理差距，并且无论模型能力强弱，该差距都以相同方式得到弥合。原始回复证实了这一点：没有记忆时，智能体称这两个后端“确实不分优劣”，然后进行猜测；有记忆时，它们会引用回忆起的政策，并导入获得批准的模块。
7 What did not work7 未奏效的方法
We initially hypothesized a second result: that routing a needed fact to an agent would rescue its accuracy over a long, distracting context, an “attention rescue” to complement the lost-in-the-middle literature [14]. It did not hold. We report it anyway, because it changes what one should claim for context routing.
我们最初提出了第二个结果假设：将所需事实路由给智能体，可以在冗长且充满干扰的上下文中恢复其准确率，形成一种“注意力挽救”效应，以补充关于“中间信息遗失”（lost-in-the-middle）的文献 [14]。这一假设未能成立。我们仍然报告这一结果，因为它改变了人们应当如何表述上下文路由的作用。
At the modest scales we first tested, a frontier model recalled a fact buried at any position with 100% adherence, with no U-shaped dip. We then built a harder, size-swept test: a single agent must retrieve the current payments contract, buried at $\sim$ 50% depth among four hard-negative money shapes, in a codebase inflated to a target token budget, against routing that delivered the one relevant fact ( $\sim$ 155 tokens). Accuracy did not degrade with dilution: both the frontier model and the small one picked the current contract over the decoys at 10k, 50k, and 100k tokens (and the frontier model up to $\sim$ 280k). A still-harder variant requiring a three-fact join with named traps gave the same answer: no accuracy gap opened, even for the small model.
在最初测试的适中规模下，无论事实埋藏于哪个位置，前沿模型都能回忆起该事实，遵循率为 100%，没有出现 U 形低谷。随后，我们构建了一项更难的、在不同规模下开展的测试：将代码库扩充到目标 token 预算，要求单个智能体从四种高难度负例金额结构中检索出当前的支付契约，该契约埋藏在约 $\sim$ 50% 的深度处；并将其与直接提供唯一相关事实（$\sim$ 155 tokens）的路由方式进行比较。准确率并未随信息稀释而下降：在 10k、50k 和 100k tokens 的规模下，前沿模型和小模型都选择了当前契约，而非干扰项（前沿模型在最高 $\sim$ 280k 的规模下也同样如此）。一个难度更高、要求关联三条事实且包含具名陷阱的变体也得出了相同结论：即使对于小模型，也没有出现准确率差距。
What is real, and large, is cost and capacity. Routing delivers the needed fact in $\sim$ 155 tokens versus 10k–280k dumped into a single agent’s prompt—68 $\times$ to 1296 $\times$ less context per task—and the single-agent prompt that carries an entire microservices world ( $\sim$ 280k tokens) overflows the small model’s 200k window outright (5/5 failures), while the per-agent routed prompt always fits. So per-repo scoping plus routing is a cost-and-feasibility win, not an accuracy rescue; we state it that way rather than the stronger claim we could not support.
真正存在且幅度显著的差异在于成本和容量。路由仅用 $\sim$ 155 tokens 就能提供所需事实，而单个智能体的提示中则被塞入 10k–280k tokens——每项任务所需的上下文减少了 68 $\times$ 到 1296 $\times$——并且，承载整个微服务体系的单智能体提示（$\sim$ 280k tokens）会直接超出小模型的 200k 上下文窗口（5/5 次失败），而经路由分发给各智能体的提示始终能容纳在窗口内。因此，按代码仓库划定范围并结合路由，带来的是成本与可行性上的收益，而非对准确率的补救；我们据此表述，而不采用我们无法支持的更强论断。
One methods note belongs here, because it is the reason we trust the numbers above. An earlier run of the decision-adherence test reported a 70% versus 100% effect on a frontier model. It was a scorer artifact: a regular expression that negated on a substring false-flagged correct replies. Structured output scoring plus raw-reply logging erased the effect, and we retract that number. The lesson—score structured fields and log raw replies rather than pattern-match prose—is now baked into the harness, and it is why the positive results in Section 6 are scored on parsed artifacts (the actual import line, the merged field) rather than on prose mentions.
这里有必要说明一点方法细节，因为它正是我们信任上述数值的原因。较早的一次决策遵循度测试曾报告，某个前沿模型上出现了 70% 对 100% 的效果差异。这是评分器造成的假象：一个根据子字符串匹配作出否定判定的正则表达式，将正确回复误判为了错误。采用结构化输出评分并记录原始回复后，这一效果消失了，因此我们撤回该数值。这一教训——对结构化字段评分并记录原始回复，而不是对文字描述进行模式匹配——现已融入测试框架，这也是第 6 节的正向结果依据解析后的产物（实际的导入语句、合并后的字段）评分，而非依据文字描述中的提及来评分的原因。
8 Discussion8 讨论
The live contract result splits cleanly in two. The coordination signal helps across the tested capability tiers: without it, a frontier model, a small model, and a second vendor’s model all fail at 0.00, because the fact is absent from their context, not beyond their reasoning. Acting on the signal is partly capability-dependent: given the same plan, the frontier models adapt perfectly (1.00) and the small model most of the time (0.60), with the misses tracing to weaker execution (a stray edit, an incomplete migration) rather than to missing information. That split matters for anyone worried that better models will make coordination unnecessary. On the evidence here the information half is not closed by scale; the execution half already benefits from it.
真实运行中的契约结果可以清晰地分为两个方面。协调信号在所测试的各个能力层级上都有帮助：没有这一信号时，前沿模型、小模型以及另一家供应商的模型均告失败，得分为 0.00，因为相关事实不在它们的上下文中，而非超出了它们的推理能力。依据信号采取行动的能力部分取决于模型能力：给定相同的计划，前沿模型能完美完成适配（1.00），小模型则在大多数情况下能够完成（0.60）；失败可归因于较弱的执行能力（一次偏离要求的编辑、一次未完成的迁移），而非信息缺失。对于任何担心更强的模型会使协调变得不再必要的人来说，这一区分都很重要。根据这里的证据，扩大模型规模并未弥合信息方面的缺口；执行方面则已经从中受益。
It also explains when reactive detection is enough and when it is not. In the deterministic timing model, a warning lands in time on sequential dependencies and the detector matches the planner. Under scripted concurrent contention the warning arrives after the edit, so the detector tracks no-coordination and the gap to the planner grows with $N$ . In the live study, where timing and information specificity change together, the evidence supports the combined proactive intervention rather than scheduling alone.
这也解释了何时反应式检测已经足够，何时则不够。在确定性时序模型中，对于顺序依赖关系，警告能够及时送达，检测器的表现与规划器相当。在脚本设定的并发争用条件下，警告在编辑完成后才到达，因此检测器的表现与无协调条件相近，且其与规划器的差距随 $N$ 增大而扩大。在真实运行研究中，时序和信息的具体程度同时发生变化，因此证据支持的是组合式主动干预，而非仅仅调度本身。
Verification is easiest where ground truth is unambiguous—formal proofs, competitive programming, passing test suites. Multi-agent code integration is one more such place: the merged tree either builds and passes its acceptance check or it does not. NP-Bench exploits that to verify coordination end to end—it runs real agents in a real git integration and reads ground-truth signals (clean-merge success, scope compliance, contract adaptation, cross-session decision adherence) directly off the merged tree, rather than trusting each agent’s self-report. Coordination failures are invisible to single-agent verification: each agent, judged alone, did fine; the system still broke on integration. The three-arm design (nothing / reactive / proactive) lets us measure whether the coordination layer helped instead of asserting it, and the negative arm guards against overclaiming.
在真值明确无歧义的场景中，验证最为容易——例如形式化证明、竞赛编程以及测试套件是否通过。多智能体代码集成也是这样的场景之一：合并后的代码树要么能够构建并通过验收检查，要么不能。NP-Bench 利用这一点对协调进行端到端验证——它让真实智能体参与实际的 git 集成，并直接从合并后的代码树中读取真值信号（无冲突合并是否成功、范围遵守情况、契约适配情况、跨会话决策遵循情况），而不是相信各智能体的自我报告。单智能体验证无法发现协调失败：单独评判时，每个智能体都表现良好；系统却仍在集成时发生故障。三组设计（无协调 / 反应式 / 主动式）使我们能够衡量协调层是否起到了帮助，而非直接断言其有效；阴性对照组则防止我们夸大结论。
9 Threats to validity9 有效性威胁
Tier A is a deterministic simulation of agent reaction; it drives the real sensing, detection, routing, and planner, but the agent edits themselves are scripted, so it validates mechanism and routing precision, not agent behavior. That is what Tier B is for. The live cells span two model families (Claude frontier/Haiku and OpenAI Codex), which guards against a single-vendor artifact, and the pivotal contract cell is run at $K{=}15$ , where the planner’s Wilson interval $[0.80,1.00]$ separates cleanly from the baselines’ $[0.00,0.20]$ (Fisher’s exact $p<10^{-4}$ ). The remaining live cells are $K{=}5$ pilots with wider intervals, and the scenarios are hand-constructed; larger $K$ across every cell and a broader scenario set are the obvious next runs.
Tier A 是对智能体反应的确定性模拟；它驱动实际的感知、检测、路由和规划器，但智能体的编辑操作本身由脚本设定，因此它验证的是机制和路由精度，而非智能体行为。后者正是 Tier B 的用途。真实运行的实验单元涵盖两个模型家族（Claude frontier/Haiku 和 OpenAI Codex），这有助于排除单一供应商造成的假象；关键的契约实验单元以 $K{=}15$ 运行，其中规划器的 Wilson 区间 $[0.80,1.00]$ 与基线的 $[0.00,0.20]$ 明确分离（Fisher 精确检验 $p<10^{-4}$）。其余真实运行的实验单元均为 $K{=}5$ 的初步试验，区间更宽，且场景均由人工构建；显然，下一步应在每个实验单元中采用更大的 $K$，并扩展场景集合。
The most important limitation is scope inference. In these experiments the declared scopes are hand-seeded in the harness (each item’s stated files and consumed contracts), not inferred from natural-language tasks. The planner’s guarantee is only as good as those scopes, and inferring them automatically (from a symbol graph or the service graph) is unbuilt work, not a solved component; we claim the scheduling result, not automatic scope inference. Scope-leakage is also measured on the simple shared-file case; leakage could be higher on subtler scopes. Finally, the C1-detect warning is deliberately vague. We argue this is realistic rather than a straw man—a just-in-time “someone may be touching $X$ ” is what reactive systems actually emit—but a specificity-versus-timing ablation (a detailed but late warning) would sharpen the comparison and is future work.
最重要的局限是范围推断。在这些实验中，声明的范围由人工预先设定在测试框架中（每个任务项注明的文件和所使用的契约），而非从自然语言任务中推断得出。规划器的保证取决于这些作用域的准确性，而自动推断作用域（基于符号图或服务图）仍是尚未实现的工作，并非已经解决的组件；我们声称实现的是调度方面的结果，而非作用域的自动推断。作用域越界也是在简单的共享文件情形下测量的；对于更微妙的作用域，越界程度可能更高。最后，C1-detect 的警告被刻意设计得较为模糊。我们认为，这种设计符合现实，而非树立稻草人——反应式系统实际发出的正是“可能有人正在修改 $X$”这类即时提示——但针对具体程度与时机的消融实验（提供详细但延迟的警告）将使比较更有说服力，这属于未来工作。
10 Conclusion10 结论
Parallel coding agents collide at integration, and that collision is a scheduling problem. Given declared scopes, scheduling around them (disjoint scopes for concurrent work, producers merged before their consumers) turns conflict cleanup into conflict prevention. On NP-Bench the planner lifts deterministic clean-integration from 1/9 to 9/9 and, with live agents from two vendors, rescues a breaking contract change that no-coordination and reactive detection both miss (0.00/0.00 $\rightarrow$ 1.00 on the frontier models, 0.60 on a small one), while agents respect their assigned scopes. A cross-session memory closes a repeated-mistake gap identically on strong and weak models. Routing facts to agents, which we expected to rescue long-context accuracy, does not at window-fitting scales; its value is cost and capacity. The benefit held across the models we tested because it comes from how work is allocated, not from model reasoning. What remains open is inferring scopes automatically rather than hand-seeding them, re-planning as work changes, and moving from advisory scopes to enforced ones.
并行编码智能体在集成时发生冲突，而这种冲突是一个调度问题。在给定已声明作用域的情况下，围绕这些作用域进行调度（使并发工作的作用域互不相交，并先合并生产者的更改，再合并其消费者的更改），就能将冲突清理转变为冲突预防。在 NP-Bench 上，规划器将确定性的无冲突集成表现从 1/9 提升至 9/9；在使用两家供应商的实际运行智能体时，它还成功处理了无协调和反应式检测两种方式均未能处理的破坏性契约变更（前沿模型上的表现从 0.00/0.00 $\rightarrow$ 1.00，小型模型上达到 0.60），同时智能体遵守了各自分配到的作用域。跨会话记忆在强模型和弱模型上以相同的效果弥补了重复犯错方面的不足。我们原本预期，将事实路由给智能体能够改善长上下文准确率，但在内容可容纳于上下文窗口的规模下并未如此；其价值在于成本和容量。这一收益在我们测试的各个模型上都得以保持，因为它源于工作分配方式，而非模型推理。尚待解决的问题包括：自动推断作用域，而非手动预先指定；随着工作变化重新规划；以及从建议性作用域转向强制执行的作用域。
