一句话

Brown 将多智能体视为用额外计算换取更短等待时间的方法，但明确表示，现有证据不足以证明万级 agent 的规模收益。

主要内容

  • 多智能体把串行推理转为并行工作，代价是上下文分散和协作开销。收益依任务而变：资料检索较易并行，数学也适合，小说创作则被他判断为较难受益。
  • Brown 称，部分基准上，4 个 agent 能将完成时间减半；按数量乘运行时间估算，总计算成本约翻倍。扩至 16 个仍有收益，但效率下降。
  • 主持人提到，一个系统以 10,000 个 agent、1300 亿 token、88 小时完成了 Navier–Stokes 相关千禧年难题。Brown 强调，这只是单个案例，未做单 agent 对照，也无法确定 10,000 相对 1,000 的增益。他认为，多智能体应得的功劳不到一成，核心是基础模型能力。
  • 协作设计倾向少设固定流程，给 agent 相互发消息的工具，让其自行协调。但这种组织能力并非自然出现：系统容易退化为各自独立解题，消息也会打断推理。
  • 对 AI 研究自动化，Brown 认为实验时长、串行依赖和 GPU 供给仍会限制加速，不能直接从数学任务推导出研究速度暴涨。

“功劳不到一成”是参与者的主观归因，不是消融实验测得的贡献比例。Brown 也明确承认缺少大规模对照，因此这些内容属于内部参与者陈述与经验判断，不能视为已建立的 scaling law。

对 swarm scaling 的意义

这份材料最有价值的是划清证据边界：成功运行万级 swarm，不等于证明增加 agent 带来了相应收益。评估应同时比较答案质量、完成时间和总计算成本，并控制基础模型与任务条件。

它还提示，规模收益取决于任务可拆分程度、通信干扰和模型的协作能力。万级案例可作为可行性线索，但不足以判断最优规模，更不能单凭数量认定 agent 已比人类更善于大规模组织。
