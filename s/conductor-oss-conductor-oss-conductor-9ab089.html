Conductor——面向工作流和智能体的持久执行平台 Conductor - Durable Execution for Workflows and Agents
构建能够自适应的智能体。运行可持久执行的图。Build agents that adapt. Run graphs that endure.
Conductor 是一个开源持久执行平台，面向微服务、AI 智能体和自适应工作流图。 Conductor is an open-source durable execution platform for microservices, AI agents, and adaptive workflow graphs. 它将运行时的各种选择——循环、分支、扇出、工具调用、审批、重试和取消——转化为可持久保存、可检查的执行过程。 It turns runtime choices—loops, branching, fan-out, tool calls, approvals, retries, and cancellation—into durable, inspectable execution. 它起源于 [Netflix](https://netflixtechblog.com/netflix-conductor-a-microservices-orchestrator-2e8d4771bf40)，目前由 [Orkes](https://orkes.io) 和[社区](https://join.slack.com/t/orkes-conductor/shared_invite/zt-3dpcskdyd-W895bJDm8psAV7viYG3jFA)积极维护。 It originated at [Netflix](https://netflixtechblog.com/netflix-conductor-a-microservices-orchestrator-2e8d4771bf40) and is actively maintained by [Orkes](https://orkes.io) and the [community](https://join.slack.com/t/orkes-conductor/shared_invite/zt-3dpcskdyd-W895bJDm8psAV7viYG3jFA).

为什么 Conductor 是开发者首选的工作流引擎Why Conductor is the workflow engine of choice for developers
| **Durable execution** | Every step is persisted. Survives crashes, restarts, and network failures with configurable retries and timeouts. |
| **Explicit orchestration** | Keep orchestration as a versioned, inspectable graph while workers and built-in tasks perform business logic and side effects. |
| **AI agent orchestration** | Native LLM tasks, MCP tool calling, human approval, and vector workflows for RAG. |
| **Durable adaptive graphs** | Govern runtime-selected paths, bounded fan-out, tool calls, approvals, retries, cancellation, and recovery. |
| **Dynamic at runtime** | Dynamic forks, tasks, and sub-workflows can be resolved at runtime. Validate generated workflow definitions before starting them. |
| **Execution recovery** | Inspect an execution, then restart, rerun, retry, pause, resume, or terminate it according to the workflow's policy. |
| **Operate at your scale** | Scale servers and workers independently, then use task domains, rate limits, concurrency limits, and metrics for control. |
| **Polyglot workers** | Workers in Java, Python, Go, JavaScript, C#, Ruby, or Rust. Workers poll, execute, and report — run them anywhere. |
| **Self-hosted, no lock-in** | Apache 2.0. 5 persistence backends, 6 message brokers. Runs anywhere Docker or a JVM runs. |
交付可持久执行的自适应图，而非框架代码Ship Durable Adaptive Graphs, Not Framework Code
Conductor 的工作节点就是普通代码——可使用任意语言、任意库和任意 I/O。编排层采用声明式形式，且可供机器读取，因此开发者可以继续使用自己偏好的 SDK 或框架，同时运维人员仍能保有持久状态、策略边界、重放、版本管理和可审计性。 Conductor workers are plain code — any language, any library, any I/O. The orchestration layer is declarative and machine-readable, so developers can keep their preferred SDK or framework while operators retain durable state, policy boundaries, replay, versioning, and auditability.
从[受治理的自适应图](https://docs.conductor-oss.org/devguide/ai/dynamic-workflows.html)开始：规划 → 验证已获批准的能力 → 有界扇出或人工审批 → 评估 → 继续或结束。 Start with the [governed adaptive graph](https://docs.conductor-oss.org/devguide/ai/dynamic-workflows.html): plan → validate approved capabilities → bounded fan-out or human approval → evaluate → continue or finish.

常见问题FAQ
这与 Netflix Conductor 是同一个项目吗？ Is this the same as Netflix Conductor?
能。 Yes. Conductor OSS 是原始 [Netflix Conductor](https://github.com/Netflix/conductor) 仓库的延续，Netflix 此前已将该项目捐赠给开源基金会。 Conductor OSS is the continuation of the original [Netflix Conductor](https://github.com/Netflix/conductor) repository after Netflix contributed the project to the open-source foundation.
Conductor 是开源的吗？ Is Conductor open source?
能。 Yes. Conductor 是一个完全开源的工作流引擎，采用 Apache 2.0 许可证。 Conductor is a fully open-source workflow engine licensed under Apache 2.0. 您可以在自己的基础设施上自行部署，并可选用 5 种持久化后端和 6 种消息代理。 You can self-host on your own infrastructure with 5 persistence backends and 6 message brokers.
该项目是否仍在积极维护？ Is this project actively maintained?
能。 Yes. [Orkes](https://orkes.io) 是主要维护者，并提供覆盖所有主流云服务提供商的 Conductor 企业级 SaaS 平台。 [Orkes](https://orkes.io) is the primary maintainer and offers an enterprise SaaS platform for Conductor across all major cloud providers.
Conductor 能否通过扩展来处理我的工作负载？ Can Conductor scale to handle my workload?
Conductor 服务器和工作进程（worker）可独立扩展。 Conductor servers and workers scale independently. 通过任务域、并发限制、持久化配置和指标，使吞吐量与隔离程度适应您的环境。 Use task domains, concurrency limits, persistence configuration, and metrics to match throughput and isolation to your environment.
Conductor 是否支持持久执行（durable execution）？ Does Conductor support durable execution?
能。 Yes. Conductor 会持久化工作流和任务的状态，支持在工作进程和基础设施发生故障后恢复，并提供重试、超时、暂停、恢复和终止控制。 Conductor persists workflow and task state, supports recovery after worker and infrastructure failure, and exposes retries, timeouts, pause, resume, and termination controls.
工作流完成或失败后，我能否重放它？ Can I replay a workflow after it completes or fails?
Conductor 支持重启、重新运行和重试控制。 Conductor supports restart, rerun, and retry controls. 执行历史的保留取决于配置，而 keepLastN 会按设计移除较早的循环迭代记录。 Execution-history retention depends on configuration, and keepLastN intentionally removes older loop iterations.
Conductor 能否编排 AI 智能体和 LLM？ Can Conductor orchestrate AI agents and LLMs?
能。 Yes. Conductor 提供原生 LLM 任务、MCP 工具发现与调用、人工审批，以及用于 RAG 的向量工作流。 Conductor provides native LLM tasks, MCP tool discovery and calls, human approval, and vector workflows for RAG. 有关提供商和功能的详细信息，请参阅持续维护的 LLM 编排指南。 See the maintained LLM orchestration guide for provider and capability details.
Conductor 为什么将编排与代码分离？ Why does Conductor separate orchestration from code?
Conductor 将编排保存为具有版本管理的机器可读图，而由工作节点和内置任务执行业务逻辑及产生副作用的操作。 Conductor keeps orchestration as a versioned, machine-readable graph while workers and built-in tasks perform business logic and side effects. 这使得执行路径、输入、策略和任务结果均可检查，同时不限制工作节点所使用的编程语言。 This makes paths, inputs, policy, and task outcomes inspectable without constraining the language used for workers.
用代码编写工作流不是比使用 JSON 更强大吗？ Isn't writing workflows as code more powerful than JSON?
JSON 使编排图保持机器可读，并支持版本管理。 JSON keeps the orchestration graph machine-readable and versioned. 工作节点仍使用普通代码实现，而内置任务涵盖常见的集成和控制流行为。 Workers remain ordinary code, and built-in tasks cover common integration and control-flow behavior. 当服务或 LLM 需要在运行时选择已批准的计划时，应使用经过验证的运行时定义。 Use validated runtime definitions when a service or LLM needs to select an approved plan at runtime.
JSON 工作流能处理分支、循环和错误处理等复杂逻辑吗？ Can JSON workflows handle complex logic like branching, loops, and error handling?
能。 Yes. Conductor 支持 `SWITCH`（条件分支）、`DO_WHILE`（可配置迭代清理的循环）、`FORK_JOIN`（支持动态扇出的并行执行）、`SUB_WORKFLOW`（组合）以及在运行时解析的 `DYNAMIC` 任务。 Conductor supports `SWITCH` (conditional branching), `DO_WHILE` (loops with configurable iteration cleanup), `FORK_JOIN` (parallel execution with dynamic fanout), `SUB_WORKFLOW` (composition), and `DYNAMIC` tasks resolved at runtime. 这些结构可以组合使用——你可以在并行分支中嵌套条件分支，再在条件分支中嵌套循环。 These are composable — you can nest loops inside branches inside forks. 在错误处理方面，每个任务都支持可配置的重试、超时，以及可选任务或补偿任务。 For error handling, every task supports configurable retries, timeouts, and optional/compensating tasks. 声明式模型不会限制复杂性，而是使复杂性可见且可调试。 The declarative model doesn't limit complexity — it makes complexity visible and debuggable.
Conductor 如何管理工作流版本？ How does Conductor handle workflow versioning?
工作流定义通过数字编号进行版本管理。 Workflow definitions are versioned by number. 正在运行的执行实例会继续使用启动时的版本——部署新版本绝不会破坏运行中的工作流。 Running executions continue on the version they started with — deploying a new version never breaks in-flight workflows. 由于 Conductor 不会重放你的代码，因此不存在重放兼容性问题。 There's no replay compatibility problem because Conductor doesn't replay your code. 编排图是权威依据，每个执行实例都固定使用其对应的定义版本。 The orchestration graph is the source of truth, and each execution is pinned to its definition version. 更新编排逻辑时，无须重新部署工作节点，也无须担心破坏正在运行的工作流。 Update orchestration logic without redeploying workers and without worrying about breaking running workflows.
开发者体验如何——是否支持 IDE、类型检查和调试？ What about developer experience — IDE support, type checking, debugging?
Conductor 提供内置的可视化 UI，用于设计、运行和调试工作流。 Conductor provides a built-in visual UI for designing, running, and debugging workflows. 每个执行实例都具有完整的可观测性：你可以检查每个任务的输入、输出、时间信息和重试历史。 Every execution is fully observable: you can inspect the input, output, timing, and retry history of every task. 为保障类型安全，Conductor 会依据 JSON Schema 验证工作流输入以及任务的输入和输出。 For type safety, Conductor validates workflow inputs and task I/O against JSON Schema. 工作节点使用你所选语言的普通代码编写——你的业务逻辑可以获得完整的 IDE 支持、类型检查和调试功能。 Workers are plain code in your language of choice — you get full IDE support, type checking, and debugging for your business logic. 编排层在 UI 中清晰可见，而非隐藏在框架内部。 The orchestration layer is visible in the UI, not hidden inside a framework.
Conductor 能处理长时间运行的工作流（持续数天、数周或数月）吗？ Can Conductor handle long-running workflows (days, weeks, months)?
能。 Yes. Conductor 专为长时间运行的工作流而设计。 Conductor is designed for long-running workflows. 执行状态会被完整持久化——工作流可以暂停数月，等待人工审批、外部信号或预设定时器触发，然后从暂停处准确恢复执行。 Executions are fully persisted — a workflow can pause for months waiting for a human approval, an external signal, or a scheduled timer, and resume exactly where it left off. 不存在可能丢失的内存状态。 There's no in-memory state to lose. 同样的机制也为 AI 智能体循环提供了持久性保障：如果第 12 次迭代等待人工审核达三周之久，第 13 次迭代仍能从先前中断的位置接续执行。 This is the same mechanism that makes AI agent loops durable: if iteration 12 waits for a human review for three weeks, iteration 13 picks up right where it left off.
不用代码实现编排，难道不会损失灵活性吗？ Don't I lose flexibility by not having orchestration in code?
你反而会获得更高的灵活性。 You gain flexibility. 由于工作流采用 JSON 表示，LLM 可以在运行时生成和修改工作流——无须经历编译和部署周期。 Because workflows are JSON, LLMs can generate and modify them at runtime — no compile/deploy cycle. 动态并行分支允许你将执行扇出到数量可变的并行任务，这一数量在运行时确定。 Dynamic forks let you fan out to a variable number of parallel tasks determined at runtime. 动态子工作流允许一个工作流按名称组合其他工作流。 Dynamic sub-workflows let one workflow compose others by name. 而且，由于工作节点与编排解耦，你可以独立更新工作流图或替换工作节点的实现。 And because workers are decoupled from orchestration, you can update the workflow graph or swap worker implementations independently. 代码优先的引擎将二者耦合在一起，因此更改编排就意味着重新部署代码并为其创建新版本。 Code-first engines couple these together, so changing orchestration means redeploying and re-versioning your code.
Conductor 为自适应智能体提供了哪些功能？ What does Conductor provide for adaptive agents?
Conductor 将原生 AI 和 MCP 任务与持久化循环、分支、扇出、审批、重试、取消以及可检查的执行历史结合起来。 Conductor combines native AI and MCP tasks with durable loops, branches, fan-out, approval, retry, cancellation, and an inspectable execution history. 从受治理的自适应图开始。 Start with the governed adaptive graph.
