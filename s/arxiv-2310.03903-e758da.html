在 Hanabi (Bard et al., 2020) 中，玩家的目标是按升序（1 至 5）组成五组牌序列，每组对应一种不同的颜色：紫色、红色、蓝色、黄色和绿色。 In Hanabi (Bard et al., 2020), players aim to assemble five sequences of cards in ascending order (1 through 5), each sequence dedicated to a different color: purple, red, blue, yellow, and green. 该游戏的一个独特之处在于，玩家只能看到搭档的牌，而看不到自己的牌。 A unique aspect of the game is that the players can only view their partner’s cards, not their own. 这要求玩家协同合作，使用提示标记（reveal tokens）来提供有关搭档手牌的提示。 This requires players to work collaboratively, utilizing reveal tokens to provide hints about the cards in their partner’s hand. 这些提示可以涉及牌的颜色或点数。 These hints can be about either the color or the rank of the cards. 例如，玩家使用一个提示标记，就可以指出搭档手中某一点数的所有牌。 For instance, using a single reveal token, a player can indicate all cards of a certain rank in their partner’s hand. 当玩家对自己持有的某张牌有所了解后，就可以选择将该牌打到牌堆上。 Once a player has an idea about which card they have, they can choose to play the card on the stack. 如果出牌正确，玩家就获得一分。 If the card is correct, they get a point. 否则，玩家会失去一个共享的生命标记。 Otherwise, players lose a collective life token. 全部 3 个生命标记耗尽后，游戏结束。 The loss of all 3 life tokens leads to the end of the game. 4.1.1 LLM 智能体4.1.1 LLM Agents
为使 LLM 能够参与多轮游戏，我们基于语言智能体认知架构（Cognitive Architectures for Language Agents）Sumers et al. (2023)，为其搭建了一个智能体框架。 To allow LLMs to play multi-turn games, we scaffold them with an agentic framework based on Cognitive Architectures for Language Agents Sumers et al. (2023). 该框架包含三个部分：记忆、推理和落地。 The framework includes three parts: Memory, Reasoning, and Grounding.
记忆包括：(1) 长期记忆，用于存储游戏描述，包括游戏规则、惯例、目标和动作空间；(2) 工作记忆，由当前观测的文本描述组成；(3) 情景记忆，即智能体此前所选动作的列表。 Memory includes (1) Long-Term Memory for storing the Game Description, including the game’s rules, conventions, objectives, and action space, (2) Working memory, which consists of a textual description of the current observation, and (3) Episodic Memory which is a list of previous actions selected by the agent.
推理是将大语言模型（LLM）接入该框架的环节。 Reasoning is where the Large Language Model (LLM) is plugged into the framework. 它以记忆中的文本描述为输入，并根据上下文生成下一步动作。 It takes the textual description from the Memory as input and generates the next action based on the context. LLM 对当前状态进行推理，然后以自然语言从可用动作列表中选择一个动作。 The LLM reasons about the current state and then selects an action from the list of available actions in natural language.
自我验证：协调游戏 Hanabi 的容错空间很小，因为任何误操作都会导致生命标记损失，而全部三个生命标记耗尽后，游戏就会结束。 Self-Verification: For the coordination game Hanabi, there is a low margin for error as any misplays lead to the loss of life tokens, and the loss of all three life tokens subsequently results at the end of the game. 因此，我们在 Hanabi 的推理过程中加入了答案验证（Answer-Verification）Weng et al. (2023)，即再次向 LLM 提示，要求其确认所生成的动作是否恰当，以及是否会导致致命错误。 We thus supplement the reasoning process in Hanabi with Answer-Verification Weng et al. (2023), where the LLM is re-prompted to confirm that the action it generated is appropriate and does not lead to fatal errors.
ToM 推理：我们还展示了在为 Hanabi 和 CollabEscape 生成下一步动作之前加入心智理论推理步骤的积极作用，这两款游戏都能从这一中间步骤中受益。 ToM-Reasoning: We also demonstrate the positive impact of a Theory of Mind Reasoning step prior to generating the next action for Hanabi and CollabEscape, which benefit from this intermediate step. 在 ToM 推理步骤中，LLM 在生成下一步动作之前，先对搭档的动作或当前位置作出解释，以显式体现信念推断过程。 In the ToM reasoning step, the LLM generates an interpretation of their partner’s actions or current position before generating the next action to explicitly capture the belief inference process. 由于延迟和成本方面的显著限制，且收益有限，我们未在 Overcooked 上测试额外的 ToM 推理。 We do not test with additional ToM reasoning on Overcooked due to significant latency and cost constraints, with marginal benefits.
最后，落地过程将推理模块生成的自然语言动作转换为与游戏兼容的一个或多个动作。 Finally, the Grounding process translates the natural language action generated by the reasoning module into game-compatible action(s). 具象化模块（grounding module）的具体实现取决于所讨论的游戏；例如，在 Overcooked-AI 中，具象化模块需要将“从 o0 拿起洋葱。”这样的高层动作转换为低层动作序列。 The exact implementation of the grounding module depends on the game in question; for example, in Overcooked-AI, the grounding module needs to convert high-level actions like "pick up onion from o0." into sequences of lower-level actions. 另一方面，在 Hanabi 这样的游戏中，具象化模块需要将“揭示 Bob 的红色牌”这样的动作匹配到其低层表示。 On the other hand, in games like Hanabi, the Grounding needs to match actions like "Reveal Bob’s Red Color Cards" to their lower-level representations. 具象化过程还负责根据游戏情境过滤掉不可行的动作（更多细节见附录 A、B）。 The Grounding process is also responsible for filtering out infeasible actions based on the context of the game (See Appendices A, B for more details.)
LLM 智能体的提示或设置不会因交叉对弈（Cross-play）或自我对弈（Self-play）而有所不同。 There are no prompt or setup differences for LLM Agents based on Cross-play or Self-play. 我们使用 gpt-4-0125-preview、GPT-3.5-turbo-0125、Mixtral 8x7B 和 GPT-4o 这些 LLM 进行智能体评估研究。 We use the LLMs gpt-4-0125-preview, GPT-3.5-turbo-0125, Mixtral 8x7B, and GPT-4o for agentic evaluation studies.

8 局限性8 Limitations
延迟与计算需求：如第 5 节所强调的，有效的协调推理主要依靠 GPT-4-turbo 等规模较大的 LLM 实现。 Latency and Compute Requirements: As highlighted in Section 5, effective reasoning for coordination is achievable primarily with larger LLMs like GPT-4-turbo. 然而，这些模型存在显著延迟，且需要大量计算资源，因此不太适合需要快速决策的实时应用。 However, these models are associated with significant latency and require substantial computational resources, making them less suitable for real-time applications where rapid decision-making is crucial.
初始提示配置：要实现最佳推理性能，需要仔细地手动配置描述游戏的初始提示（程序性记忆）。 Initial Prompt Configuration: Achieving optimal reasoning performance necessitates careful manual configuration of the initial prompts that describe the game (Procedural Memory). 尽管该提示可以从游戏手册或现有资源中提取，但仍需针对 LLM 智能体进行格式编排和设计。 While this prompt could be extracted from game manuals or existing resources, it still needs to be formatted and designed with the LLM agent in mind. 此外，还可以通过让 LLM 生成更多文本以及优化提示来改善其在各个游戏中的表现。 Furthermore, the results for individual games could be improved by letting the LLM generate more text and engineering the prompt. 不过，我们将这些优化留给未来侧重于性能提升而非基准评测的研究。 However, we leave these optimizations to future works focused on performance improvement rather than benchmarking.
人工筛选边界案例：CoordinationQA 套件需要人工筛选协调博弈中无歧义的边界案例，以构建数据集。 Manual Curation of Edge Cases: The CoordinationQA suite involves manually curating unambiguous edge cases in coordination games to construct the dataset. 这可能会限制该基准扩展以涵盖新场景的能力。 This can hinder the ability to scale the benchmark to accommodate new scenarios. 然而，为了开展更可靠的研究，精心筛选这些样例十分重要。 Yet, it is important to curate these examples for more reliable studies.
