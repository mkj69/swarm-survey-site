一句话

这篇综述把 swarm 扩展问题从“增加多少 agent”转向“谁与谁连接、如何交换信息，以及谁能承担核验”。

主要内容

  • 作者以记忆、注意力和推理为共同框架，连接人类群体、纯 AI 多智能体与人机混合团队研究；混合系统既有节点能力差异，也有通信带宽、延迟和信任差异。
  • 两组权衡贯穿全文：探索与利用、效率与冗余。快速传播有利于共享已有解法，也可能加速错误共识；保留独立搜索和交叉核验则需要额外成本。
  • 文中归纳的既有研究表明，复杂任务中，适度稀疏、具有跨群连接的网络可能优于密集互联；先独立探索、再逐步增加连接，也可能改善结果。这些结论依赖任务环境。
  • agent 数量不等于有效多样性。复制相近模型可能扩大规模，却让答案、偏差和信息来源更加同质化。
  • 混合团队中，人的位置和职责尤其重要：枢纽可能提供异常识别与责任承担，也可能成为注意力瓶颈；信息把关控制流入流出，监督则检查输出错误，两者解决的问题不同。

这是一篇跨领域综合性章节，当前片段主要引用既有实验、模拟和理论，并非报告一套新的规模测试。关于规模与多样性的倒 U 型关系、稀疏拓扑优势等，属于作者对已有研究的归纳；混合结构的部分效果则明确作为预测或待验证问题提出。

片段没有给出可复算的性能曲线、样本量、通信预算或最优 agent 数，因此无法据此确定规模阈值，也不能确认所谓协作扩展规律的具体形式。本文及其引用研究均未在此独立核验。

对 swarm scaling 的意义

它提供的是解释扩展成败的框架，而非“越多越强”的实证定律。评估 swarm 时，应同时观察连接结构、错误相关性、有效多样性和核验负担，不能只统计 agent 数。

对人类调度大量子 agent 的系统，尤其值得检验：产出增加后，人是否仍有能力识别错误；递归委派是否伴随信息漂移和责任稀释。适度稀疏连接、分阶段汇合、明确接口职责可作为实验方向，但当前材料不足以证明存在通用最优架构。
