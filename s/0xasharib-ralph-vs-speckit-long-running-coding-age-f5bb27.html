一句话

这篇二手综述把长期编码代理分为“测试驱动的循环执行”和“规格驱动的分阶段协作”，对 swarm scaling 的价值在于提示任务、记忆和验收如何组织，而非证明增加代理数量能提升产出。

主要内容

  • Ralph：以小任务为单位反复执行。 按文章描述，它从 PRD 中选择未完成事项，启动新的代理实例，读取代码和持久化记录，完成实现后通过测试决定是否提交、重试。对话上下文被清空，进度和经验留在文件及 Git 中。
  • SpecKit：先明确意图，再推进实现。 文章将其概括为原则、规格、计划、任务、实现五个阶段，通过文档保存需求和架构决策，并让开发者在关键环节审阅。
  • 两者承担不同成本。 Ralph 的代价是反复读取上下文，以及局部任务可能偏离整体设计；SpecKit 的代价是文档与审阅负担，以及长会话的上下文压力。
  • 作者提出混合流程。 先用 SpecKit 形成计划和任务清单，再交给 Ralph 循环实现。文中没有给出该组合的实际案例或效果数据。

对 swarm scaling 的意义

  • 先解决可验收性。 Ralph 的模式说明，扩大执行规模需要颗粒度合适的任务和可靠反馈；否则循环可能只是在重复错误。
  • 外部记忆提供跨实例衔接。 文件、规格和提交记录可作为代理接续工作的依据，但文章没有验证多代理同时读写时的冲突与协调问题。
  • 规划与执行可以分工。 混合方案提供了先统一约束、再分派实现的思路；其并行收益、协调成本和适用规模仍待验证。
