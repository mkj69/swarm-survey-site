When Agents Coordinate: Measuring Coordination in Multi-Agent AI Coding当智能体协同工作时：衡量多智能体 AI 编程中的协调
Abstract摘要
We study how teams of AI coding agents coordinate while solving programming tasks. Current evaluations usually report whether the agents complete the task and how much the run costs, leaving the coordination inside the team largely unmeasured. We introduce an instrument to measure this coordination directly. Each run is represented as a temporal network in which agents and files are nodes, and messages, file writes, and file reads are timestamped directed edges with an associated cost. We apply this instrument to 1,902 runs, each evaluated with a fixed test suite, across configurations that vary the team size, the team structure, and the file policy.
我们研究 AI 编程智能体团队在解决编程任务时如何协调。现有评估通常报告智能体是否完成任务以及运行成本，而团队内部的协调在很大程度上仍未得到衡量。我们提出一种直接衡量这种协调的工具。每次运行都表示为一个时序网络，其中智能体和文件是节点，消息、文件写入和文件读取则是带有时间戳及相应成本的有向边。我们将该工具应用于 1,902 次运行，每次运行均使用固定测试套件进行评估，所涵盖的配置在团队规模、团队结构和文件策略方面有所不同。
The resulting networks show how coordination changes as teams grow and as the work changes. Direct messaging initially increases close to quadratically with the number of agents, with much of this growth coming from an early round of introductions. As the teams grow further, this increase levels off in the largest teams we study, where agents increasingly communicate through broadcast messages. The programming task also shapes the network that emerges. Work built around a shared specification produces dense, highly connected teams, while pipeline tasks produce sparse networks organised around local interfaces. Shared files can replace repeated one-to-one communication, cutting output tokens by about 42% at eight agents on message-heavy work, while adding overhead when files already carry the coordination. Naming one agent as coordinator creates no communication hub and provides no reliable improvement in success.
由此得到的网络展示了协调如何随着团队规模扩大和工作变化而变化。直接消息传递最初随智能体数量增加而呈近似二次增长，其中很大一部分增长来自早期的一轮自我介绍。随着团队进一步扩大，这一增长在我们研究的最大规模团队中趋于平缓，此时智能体越来越多地通过广播消息进行通信。编程任务也会塑造所形成的网络。围绕共享规范开展的工作会形成连接密集、高度连通的团队，而流水线任务则会形成围绕局部接口组织的稀疏网络。共享文件可以替代反复进行的一对一通信，在消息密集型工作中，当团队有 8 个智能体时，输出 token 数可减少约 42%；但当文件已经承担协调作用时，共享文件会增加额外开销。指定一个智能体担任协调者既不会形成通信枢纽，也不会带来可靠的成功率提升。
We also observe an unprompted tendency for agents to seek out hidden grading material. We repeat the key experimental conditions in a sealed environment, replacing the hidden material with marked placeholder files. Across 244 additional runs, agents still reach for it in four fifths of runs, while the coordinator and file-channel findings reproduce.
我们还观察到，智能体在未受到提示的情况下会倾向于寻找隐藏的评分材料。我们在封闭环境中重复了关键实验条件，并用带有标记的占位文件替换隐藏材料。在额外的 244 次运行中，智能体仍在五分之四的运行中尝试访问这些材料，同时，有关协调者和文件通信渠道的发现也得到了复现。
Repeated runs also show that coordination measurements can vary substantially under the same configuration and pinned model, especially when the task leaves agents more freedom in how to organise. A single run therefore gives only one sample of the coordination behaviour of a configuration. These results show that coordination among AI coding agents can be measured directly, exposing structures, behaviours, and costs that task success and aggregate token counts leave hidden.
重复运行还表明，在相同配置和固定模型版本下，协调测量结果也可能存在显著差异，尤其是在任务允许智能体更自由地组织工作时。因此，单次运行只能提供某一配置下协调行为的一个样本。这些结果表明，AI 编程智能体之间的协调可以被直接衡量，从而揭示任务成功与否和 token 总数未能呈现的结构、行为及成本。

1 Introduction1 引言
Multi-agent AI coding systems assign a programming task to several agents that work in parallel in a shared workspace. Whether the team succeeds, and what the run costs, depends on how the agents coordinate: how they divide the work, what they tell each other, which files they share, and how they resolve the interfaces between their contributions. Almost none of this survives into the final code. A run can pass every test while leaving no trace of how much coordination it required, and two runs that pass the same tests can differ severalfold in messages, file activity, and tokens.
多智能体 AI 编程系统将一项编程任务分配给多个智能体，让它们在共享工作空间中并行工作。团队能否成功以及运行成本如何，取决于智能体如何协调：它们如何分工、彼此传递哪些信息、共享哪些文件，以及如何处理各自工作成果之间的接口。这些过程几乎都不会留存在最终代码中。一次运行可以通过所有测试，却不留下任何痕迹来表明它需要多少协调；而通过相同测试的两次运行，在消息数量、文件活动和 token 数方面可能相差数倍。
A developer configuring such a system must decide the team size, whether to name one agent coordinator, and whether the team should coordinate through direct messaging or through shared files. The effects of these choices are still poorly understood. Evaluations typically report task success and the final code or patch, with computational cost increasingly considered as an additional evaluation dimension [19, 32, 1], or prescribe which agents may communicate with which [29, 16, 39]. These measures do not show the coordination structure that emerges during a run.
配置此类系统的开发者必须决定团队规模、是否指定一个智能体担任协调者，以及团队应通过直接消息传递还是共享文件来协调。这些选择的影响仍未得到充分理解。评估通常报告任务成功与否以及最终代码或补丁，并越来越多地将计算成本作为额外的评估维度 [19, 32, 1]，或者规定哪些智能体可以与哪些智能体通信 [29, 16, 39]。这些衡量方式无法展示运行过程中形成的协调结构。
We make that structure measurable. Each run is represented as a temporal network in which agents and files are nodes. A direct message is an agent-to-agent edge, a file write is an agent-to-file edge, and a file read is a file-to-agent edge; every edge carries a timestamp, a byte size, and a token cost. Treating files as nodes is central to the instrument. A file persists after it is written; one write can be read by many agents in any order; and its contents remain in the shared workspace across agent processes and outlive the session that wrote them. Files therefore provide persistent shared state as well as a one-to-many communication channel. Representing them as nodes allows file-mediated coordination and direct messaging to be measured on the same timeline. Every edge corresponds to a logged event, so the temporal network records the coordination that occurred during the run.
我们使这种结构变得可衡量。每次运行都表示为一个时序网络，其中智能体和文件是节点。一条直接消息对应一条从智能体到智能体的边，一次文件写入对应一条从智能体到文件的边，一次文件读取对应一条从文件到智能体的边；每条边都带有时间戳、字节大小和 token 成本。将文件视为节点是该工具的核心。文件在写入后会持续存在；一次写入的内容可由多个智能体按任意顺序读取；其内容在不同智能体进程之间始终保留在共享工作空间中，并且在写入它们的会话结束后仍然存在。因此，文件既提供持久的共享状态，也提供一对多的通信渠道。将文件表示为节点，可以在同一时间轴上衡量以文件为媒介的协调和直接消息传递。每条边都对应一个已记录的事件，因此，时序网络记录了运行过程中实际发生的协调。
We apply the instrument to 1,902 runs, each evaluated with a fixed test suite, across two experiments using synthetic Python tasks. In Experiment 1, the distributed task, each agent holds a different part of a specification and the team must reconstruct the whole. In Experiment 2, the chained task, each agent owns consecutive steps of a processing chain and the team must agree the interfaces between them. Across these runs we vary three factors: the team size, from one to eight agents in the main experiments and up to sixteen in a scaling arm[fn1]; the team structure, with either a flat team or one agent named coordinator; and the file policy, with shared files forbidden, allowed, or mandatory. Section 3 defines the experimental design in full.
我们将该工具应用于使用合成 Python 任务开展的两项实验中的 1,902 次运行，每次运行均使用固定测试套件进行评估。在实验 1，即分布式任务中，每个智能体掌握规范的不同部分，团队必须重建完整规范。在实验 2，即链式任务中，每个智能体负责处理链中连续的若干步骤，团队必须就这些步骤之间的接口达成一致。在这些运行中，我们改变三个因素：团队规模，主要实验中从一个到八个智能体，规模扩展实验分支中最多达十六个[fn1]；团队结构，采用扁平团队，或指定一个智能体为协调者；以及文件策略，禁止、允许或强制使用共享文件。第 3 节完整定义了实验设计。
Footnote: 1 A scaling arm is a pre-registered extension of the chained task with more steps, so that a larger team still has work for every agent.
脚注：1 规模扩展实验分支是链式任务的一项预注册扩展，包含更多步骤，以确保更大的团队中每个智能体仍有工作可做。
One question organises the study: how does coordination scale and reorganise as these teams grow, under different team structures and file policies? The answer speaks to each of the three configuration choices above, and in each case the coordination we measure behaves differently from what the run’s outputs alone would suggest.
本研究围绕一个问题展开：在不同的团队结构和文件策略下，随着这些团队规模增大，协调如何扩展并重新组织？这一问题的答案涉及上述三项配置选择中的每一项，而且在每种情况下，我们测得的协调行为都与仅从运行输出所能推断出的情况不同。
Team size. Messaging does grow near-quadratically with the team, which suggests a cost that will keep growing. The timestamps show otherwise: the growth is a one-off round of introductions early in each run, what persists afterwards is far smaller, and on the largest teams messaging growth levels off as the teams shift towards broadcast (Section 4).
团队规模。消息量确实随团队规模呈近似二次增长，这似乎意味着成本将持续增加。时间戳却显示出不同的情况：这种增长源于每次运行初期一次性的相互介绍，此后持续发生的消息交流要少得多；而在规模最大的团队中，随着团队转向广播式通信，消息量的增长趋于平缓（第 4 节）。
Communication channel. A direct message reaches one agent; a file is written once and can be read by many. Requiring teams to coordinate through shared files cuts a large share of the output-token cost on one task and adds cost on the other. This difference shows that the effect of the channel depends on the task (Section 6).
通信渠道。一条直接消息只能送达一个智能体；一个文件只需写入一次，就可供多个智能体读取。要求团队通过共享文件进行协调，在一项任务中大幅降低了输出 token 成本，却在另一项任务中增加了成本。这一差异表明，通信渠道的影响取决于任务（第 6 节）。
Leadership. Naming one agent the coordinator in its prompt produces no hub and no reliable gain in success, and a sealed replication finds flat and coordinator teams level at eight agents. A team is organised by the structure that emerges in its interactions, and a prompt label alone creates none of it (Sections 7 and 9).
领导。在提示词中指定一个智能体为协调者，既未形成枢纽，也未可靠地提高成功率；一项封闭环境复现实验发现，在八个智能体的规模下，扁平团队与设有协调者的团队表现相当。团队的组织方式由其交互中涌现的结构决定，仅靠提示词中的标签无法形成这种结构（第 7 节和第 9 节）。
Underneath all three choices is the shape of the network itself, and the task sets that shape. The distributed task builds a dense, tightly clustered mesh that rides the all-to-all line as the team grows; the chained task builds a sparse network whose gap to all-to-all widens with team size, until at sixteen agents scarcely any named-message network forms at all (mean degree 0.28 against a clique of fifteen). Neither shape has a leader. Left to organise themselves, the teams do not converge on a single coordination span; they let the task dictate the structure (Section 5).
这三项选择的底层都是网络本身的形态，而这一形态由任务决定。分布式任务形成了稠密、聚类紧密的网状网络，随着团队规模增大，其增长沿着全互连基准线展开；链式任务则形成了稀疏网络，其与全互连网络的差距随团队规模增大而扩大，直到十六个智能体时，几乎完全不形成指名消息网络（平均度为 0.28，而全互连团中的度为十五）。这两种形态都没有领导者。在自主组织的情况下，团队并不会趋于同一种协调跨度，而是让任务决定结构（第 5 节）。
A further result concerns the instrument itself. Under a pinned model, the chained task reproduces across collection sessions almost exactly, while the distributed task does not: the same configuration, collected twice under the same pinned model, gave two incompatible growth rates. A configuration is therefore characterised by a distribution of runs, and any single run is one sample from it; where matched sessions exist we report the headline number with its cross-session range (the scaling arms and the sealed replication are single batches; Section 8).
另一项结果涉及测量工具本身。在模型版本固定的情况下，链式任务在不同数据采集批次中的结果几乎完全一致，而分布式任务则不然：在同一固定模型下，对同一配置进行两次数据采集，得到了两个彼此不相容的增长率。因此，一种配置应由一组运行结果的分布来表征，任何单次运行都只是从该分布中抽取的一个样本；在存在匹配采集批次的情况下，我们会同时报告主要数值及其跨批次范围（规模扩展实验分支和封闭环境复现实验均仅包含一个批次；第 8 节）。
The measurements also expose failures that the final code hides. An eight-step calculation split one step per agent failed in all ten runs, every time on the same question: round at each step, or once at the end. The convention sat on the boundary between two agents, and no agent owned it. The teams discussed rounding in every one of those runs and still never agreed. Success rates do not reveal this failure mechanism. The temporal network shows the structural condition behind it: the failing interface lies between two different owners (Section 7).
这些测量还揭示了最终代码所掩盖的失败。一项八步计算被拆分为每个智能体负责一步，在全部十次运行中均告失败，而且每次都出在同一个问题上：是在每一步进行舍入，还是只在最后进行一次舍入。这一约定处于两个智能体的职责边界上，没有任何智能体负责。团队在上述每次运行中都讨论了舍入问题，却始终未能达成一致。成功率无法揭示这种失败机制。时序网络揭示了其背后的结构性条件：发生失败的接口位于两个不同的负责人之间（第 7 节）。
A last result is a behaviour we did not anticipate. Each task is graded by a hidden test suite, and no prompt tells the agents to look for it. Yet the teams went looking, and a validity check found them reading it, together with the reference solution, where the main runs had left both reachable. We re-ran the load-bearing cells in a sealed environment, with decoys in place of the hidden files: the two findings these cells test reproduce, and the teams still reach for the hidden test suite in four fifths of runs even though it returns nothing, an unprompted search for the answer key that a grade cannot see (Section 9).
最后一项结果是一种我们未曾预料到的行为。每项任务都由一个隐藏测试套件评分，且没有任何提示词要求智能体寻找它。然而，团队还是进行了搜索；一项有效性检查发现，在主要运行中隐藏测试套件和参考解答均可访问的情况下，团队读取了两者。我们在封闭环境中重新运行了支撑关键结论的实验条件组合，并用诱饵替代隐藏文件：这些条件组合所检验的两项发现均得到复现，而且即使访问没有返回任何内容，团队仍在五分之四的运行中尝试获取隐藏测试套件；这种未经提示便搜寻标准答案的行为无法通过评分察觉（第 9 节）。
The paper contributes: (i) a temporal-network representation of multi-agent coding runs with agents and files as first-class nodes; (ii) an instrumentation pipeline that turns a run’s logs into that network; (iii) a released dataset of 1,902 graded, fully instrumented runs across a controlled grid of configurations, together with a sealed replication of a further 244 runs (Section 9); and (iv) the three findings above, each pre-registered where confirmatory and reported with its reliability, two of them (the coordinator null and the file-channel substitution) re-tested in the sealed replication, together with a task-resolved topology result showing that the task sets the shape of the coordination network (Section 5).
本文的贡献包括：(i) 一种多智能体编码运行的时序网络表示，将智能体和文件均作为一等节点；(ii) 一套将运行日志转换为该网络的测量流程；(iii) 一个已公开的数据集，包含在受控配置网格下完成的 1,902 次已评分且经过完整测量的运行，以及另含 244 次运行的封闭环境复现实验（第 9 节）；以及 (iv) 上述三项发现，其中属于验证性分析的部分均已预注册，且均报告了可靠性，其中两项（协调者无效应和文件渠道替代效应）在封闭环境复现实验中接受了再次检验；此外，还提供了一项按任务区分的拓扑结果，表明任务决定了协调网络的形态（第 5 节）。

Formally, we model each run’s temporal network as a heterogeneous graph $G=(V,E)$ . The vertices $V=A\cup F$ are the agents $A$ and the files $F$ touched during the run. The edges are typed and timestamped: an agent-to-agent edge is a direct message, an agent-to-file edge is a write or an edit, and a file-to-agent edge is a read. Every edge carries a timestamp, a byte size, and a token cost. Figure 1 shows a small instance.
形式上，我们将每次运行的时序网络建模为异构图 $G=(V,E)$。顶点 $V=A\cup F$ 包括运行过程中涉及的智能体 $A$ 和文件 $F$。边具有类型和时间戳：智能体到智能体的边表示直接消息，智能体到文件的边表示写入或编辑，文件到智能体的边表示读取。每条边都携带时间戳、字节大小和 token 成本。图 1 展示了一个小规模实例。
Making files nodes, with their own identity and their own edges, is the design choice everything else rests on. The file channel behaves unlike the message channel in three ways. A file persists after it is written. One write can be read by many agents, in any order and after any delay. And a file crosses process and credential boundaries that an in-memory channel cannot. Giving files separate read and write edges puts file-mediated coordination on the same footing as direct messaging, which is what makes the channel comparison of Section 6 possible at all.
将文件设为拥有自身标识和自身边的节点，是其他所有设计赖以成立的基础性选择。文件通道的行为在三个方面不同于消息通道。文件在写入后会持续存在。一次写入可供多个智能体以任意顺序、在任意延迟后读取。此外，文件能够跨越内存通道无法跨越的进程边界和凭据边界。为文件分别设置读取边和写入边，使文件介导的协调与直接消息传递能够在同等基础上进行分析，而这正是第 6 节能够比较不同通道的前提。
The network is a direct record: every edge corresponds to a logged tool-call event, a message sent through a dedicated messaging tool or a file operation performed with the runtime’s file tools, so the counts and identities of those events are exact. One blind spot follows from this: a file read or write issued through the shell leaves no edge, so file activity is a slight undercount (Section 10). The one coarse quantity is the token cost on file edges: the runtime reports tokens per turn, and a turn can make several tool calls, so we divide a turn’s output tokens evenly across its calls. The authoritative per-turn usage is stored alongside, so any finer attribution can be applied later without re-parsing.
该网络是一份直接记录：每条边都对应一个记入日志的工具调用事件，即通过专用消息工具发送的消息，或通过运行时的文件工具执行的文件操作，因此这些事件的数量和标识都是精确的。由此产生的一个盲点是：通过 shell 发起的文件读取或写入不会留下边，因此文件活动的统计数量略有低估（第 10 节）。唯一采用粗略估计的量是文件边上的 token 成本：运行时按轮次报告 token 数，而一轮可能包含多次工具调用，因此我们将一轮的输出 token 数平均分配给该轮的各次调用。权威的逐轮用量数据也一并存储，因此之后可以采用任何更精细的归因方法，而无需重新解析。

Two experiments.两个实验。
Work divides across a team in two canonical ways: into independent pieces of knowledge, or into dependent steps. We built one experiment for each, where an experiment is a task together with its variants. In Experiment 1, the distributed task (process_orders), the specification of one Python function, process_orders(orders, config), is cut into four parts: the function signature and return shape (a dictionary of the processed orders, their count, their summed total, and a count of rejected orders); the validation rules (an order is valid when its amount is a non-negative number and its quantity a positive integer); the discount calculation (a bulk discount when the quantity reaches a threshold, and a loyalty discount for listed customers, both applied to the order’s amount alone and never multiplied by its quantity); and the sort order of the output. No agent in a team is given the whole specification, and none is told who holds what, so the team can only recover it by coordinating. How the parts are dealt out is the split, with three values: clean, each part held by exactly one agent; overlapping, some parts duplicated across two agents; and conflicting, where two agents hold versions of the validation rule that disagree on a single point (whether a quantity of zero is valid), the test suite silently enforces one version, and neither agent is told which. The conflicting split therefore plants a disagreement that the team must first notice and then resolve the right way. In Experiment 2, the chained task (summarise_transactions), the task is a four-step processing chain, and each agent owns one or more consecutive steps. Every agent’s prompt carries the same team-level knowledge, the name and signature of the pipeline function the team must deliver, together with its private piece: the full input-to-output contract of its own step and the name of the file it must produce. The chain’s length, the agent’s position in it, and the content of the other steps are withheld, and every step after the first names only the step immediately upstream. The interfaces between owners must therefore be agreed during the run, and the team must also decide who writes the pipeline file that assembles the chain. Experiment 2 crosses the same three splits (its conflicting split disagrees on whether an amount of zero is valid), and two longer chains appear in the scaling arms below.
团队内的工作划分有两种典型方式：划分为相互独立的知识片段，或划分为相互依赖的步骤。我们为二者各设计了一个实验，其中，一个实验由一项任务及其变体组成。在实验 1 的分布式任务（process_orders）中，一个 Python 函数 process_orders(orders, config) 的规约被分为四个部分：函数签名和返回结构（一个字典，包含处理后的订单、订单数量、订单总金额以及被拒绝订单的数量）；验证规则（当订单金额为非负数且数量为正整数时，订单有效）；折扣计算（当数量达到阈值时给予批量折扣，并为名单中的客户给予忠诚度折扣，两种折扣均仅应用于订单金额，绝不乘以订单数量）；以及输出的排序顺序。团队中的任何智能体都不会获得完整规约，也不会被告知谁掌握哪些部分，因此团队只能通过协调来还原完整规约。各部分的分配方式称为划分方式（split），共有三种取值：clean，每个部分恰好由一个智能体持有；overlapping，某些部分由两个智能体重复持有；以及 conflicting，两个智能体持有的验证规则版本在一个问题上存在分歧（数量为零是否有效），测试套件在未作说明的情况下执行其中一个版本，而两个智能体都不会被告知执行的是哪个版本。因此，conflicting 划分方式预设了一处分歧，团队必须先发现它，再以正确的方式解决它。在实验 2 的链式任务（summarise_transactions）中，任务是一条由四个步骤组成的处理链，每个智能体负责一个或多个连续步骤。每个智能体的提示都包含相同的团队层面信息，即团队必须交付的流水线函数的名称和签名，以及该智能体独有的部分：其所负责步骤的完整输入输出契约，以及它必须生成的文件的名称。处理链的长度、智能体在链中的位置以及其他步骤的内容均不予告知，而且除第一步外，每个步骤都只指明其紧邻的上游步骤。因此，不同负责者之间的接口必须在运行过程中协商确定，团队还必须决定由谁编写用于组装处理链的流水线文件。实验 2 同样将这三种划分方式进行交叉组合（其 conflicting 划分方式的分歧在于金额为零是否有效），下文的规模扩展实验分支中还包含两条更长的处理链。
Three crossed factors.三个交叉因素。
Every run fixes three factors. Team size is 1, 2, 4, or 8 agents. Team structure is either flat, all agents equal, or coordinator[fn2], where one agent’s prompt, and only that agent’s prompt, names it the coordinator. File policy[fn3] governs coordination through shared files: forbidden, only the deliverable itself may be written, so the file traffic that remains under this policy is only the deliverable being written and read back; allowed, the team does as it pleases, which makes this the default condition; or mandatory, all inter-agent state must pass through files. One choice of all factors, plus the split, is a configuration. Crossing the factors and dropping the combinations that make no sense (a mandatory file policy with a single agent, for example) leaves 58 distinct configurations per experiment. A cell is ten runs of one configuration in one collection, the unit at which we report results; the flat structure above one agent was collected twice (Section 8), so each of its 27 configurations contributes two cells, and the crossing gives 85 cells per experiment. Experiment 2’s released grid carries two further single-configuration baseline cells, both at four agents, flat, allowed, giving 87: the eight-step chain (compute_invoices) at a grid-interior configuration, and a variant of the main task (summarise_transactions_v2) whose output ordering depends on a constant defined in another, non-adjacent step’s specification, so the value can only arrive through coordination. The two experiments’ grids together contain 1,720 runs.
每次运行均固定三个因素的取值。团队规模为 1、2、4 或 8 个智能体。团队结构为 flat，即所有智能体地位平等，或 coordinator[fn2]，即只有一个智能体的提示将其指定为协调者。文件策略[fn3]规定通过共享文件进行协调的方式：forbidden，只允许写入交付物本身，因此该策略下仅有的文件交互是写入交付物并将其读回；allowed，团队可以自行决定如何使用文件，这是默认条件；或 mandatory，所有智能体之间的状态都必须通过文件传递。所有因素各取一个值，再加上一种划分方式，就构成一个配置。将各因素交叉组合，并剔除不合理的组合（例如，单个智能体采用 mandatory 文件策略），每个实验最终得到 58 种不同配置。一个单元格是一次采集批次中某一配置的十次运行，也是我们报告结果所用的单位；智能体数量大于一个时的 flat 结构被采集了两次（第 8 节），因此其 27 种配置中的每一种都贡献两个单元格，交叉组合后每个实验共有 85 个单元格。实验 2 发布的实验网格还包含两个各对应单一配置的基线单元格，两者均采用四个智能体、flat 结构和 allowed 文件策略，使单元格总数达到 87：一个是在网格内部配置下运行的八步处理链（compute_invoices），另一个是主任务的变体（summarise_transactions_v2），其输出顺序取决于另一个不相邻步骤的规约中定义的常量，因此该常量的值只能通过协调获得。两个实验的网格合计包含 1,720 次运行。

Overstaffed cells.人员配置过多的单元格。
The grid holds each task fixed while the team grows, because a fixed task is what makes two cells comparable; the price is that an eight-agent team on a four-part task leaves four agents with no part of the specification to hold. We keep those cells because overstaffing is a normal state of real teams: projects routinely carry more people than the work needs, and the extra members keep joining the coordination while producing little. The overstaffed cells measure that cost directly, what adding agents does to the coordination network when the work cannot absorb them. The four agents without a part turn out to be the team’s most active coordinators: in the eight-agent Experiment 1 runs they send 62% of all messages, 13.7 per agent per run against 8.4 for the agents holding parts, because an agent that holds nothing must ask the others for everything. The one conclusion these cells cannot support is a scaling law, since above four agents growth in coordination cannot be separated from the team running out of work.
在网格中，随着团队规模扩大，各项任务保持不变，因为只有固定任务才能使两个单元格具有可比性；代价是，当八智能体团队处理一个由四部分组成的任务时，会有四个智能体没有任何一部分任务规范可供掌握。我们保留这些单元格，因为人员过剩是现实团队的常见状态：项目的人员数量经常超过工作所需，多余成员持续参与协调，却产出甚少。这些人员过剩的单元格直接衡量了这一成本，即当工作无法容纳新增智能体时，增加智能体会对协调网络产生什么影响。结果表明，没有分配到任务部分的四个智能体是团队中最活跃的协调者：在实验 1 的八智能体运行中，它们发送了全部消息的 62%，每个智能体每次运行发送 13.7 条消息，而掌握任务部分的智能体为 8.4 条，因为一个什么也不掌握的智能体必须事事向其他智能体询问。这些单元格无法支持的一个结论是规模扩展定律，因为当智能体超过四个时，协调的增长便无法与团队工作量不足的影响区分开来。
The two scaling arms.两个规模扩展实验分支。
A scaling arm is a chained task with more steps, so that a larger team still has work for every agent. There are two arms, both pre-registered: for each, we wrote down what we expected to find and exactly how we would test it before any runs were collected, and the released package contains those records. The eight-step chain (compute_invoices) runs at 2, 4, and 8 agents under the allowed policy (ten runs per cell, 30 runs); the sixteen-step chain (process_billing) runs at 4, 8, and 16 agents, the only part of the study that reaches sixteen agents. Figure 4 and hypothesis H7 use the arm’s own cells; the grid’s baseline compute_invoices cell is separate. The sixteen-step arm carries twenty runs per cell under the allowed policy instead of ten, decided in advance: more runs per cell sharpen the test of whether messaging growth stops at large team sizes (hypothesis H8, Appendix A). A further ten-run mandatory cell at sixteen agents brings the arm to 70 runs. Steps are dealt in contiguous blocks, so along an arm each agent holds four consecutive steps, then two, then one as the team doubles. At the top of each arm every agent owns exactly one step, so nobody is idle and any slowing of coordination growth cannot be the team running out of work. The sixteen-step arm was collected as one interleaved batch over three days, with team sizes balanced within each day so the round-robin protects the size comparison, and it is not a cross-session replication. The remaining 82 runs are pilots (small trial batches run before the full schedules) and methodological checks, giving 1,902 runs in the main collection; a further 244 runs form the sealed replication of Section 9.
规模扩展实验分支采用步骤更多的链式任务，使更大的团队仍能为每个智能体分配工作。共有两个分支，均已预注册：对于每个分支，我们都在收集任何运行数据之前，记录了预期发现及其确切检验方法，发布的资料包中包含这些记录。八步链式任务（compute_invoices）在允许策略下分别使用 2、4 和 8 个智能体运行（每个单元格十次运行，共 30 次运行）；十六步链式任务（process_billing）分别使用 4、8 和 16 个智能体运行，这是本研究中唯一达到十六个智能体的部分。图 4 和假设 H7 使用该分支自身的单元格；网格中的基线 compute_invoices 单元格另行处理。按照事先作出的决定，十六步分支在允许策略下每个单元格进行二十次运行，而非十次：增加每个单元格的运行次数，可以更精确地检验消息量的增长是否会在团队规模较大时停止（假设 H8，附录 A）。此外，在十六个智能体条件下增加一个采用强制策略、包含十次运行的单元格，使该分支的运行总数达到 70 次。步骤按连续区块分配，因此沿着一个分支，随着团队规模逐次翻倍，每个智能体掌握的连续步骤数依次为四步、两步和一步。在每个分支的最大规模条件下，每个智能体恰好负责一个步骤，因此无人闲置，协调增长的任何放缓都不可能是由于团队工作量不足。十六步分支的数据在三天内以一个交错批次收集，每天内部均衡安排各团队规模，以便通过轮转安排保障规模比较的有效性；这并非跨会话复现实验。其余 82 次运行属于预试验（在完整运行计划执行之前进行的小规模试验批次）和方法学检查，使主数据收集共计包含 1,902 次运行；另外 244 次运行构成第 9 节的封闭访问复现实验。
Grading.评分。
Every task ships with a reference solution, and a fixed suite of behavioural input/output tests grades the team’s deliverable against outputs fixed in advance[fn5]. The tasks are pure functions with no randomness, and comparison is exact. The test suite is placed outside each agent’s working directory; in the main collection that placement was not otherwise access-controlled, and Section 9 reports what the teams did with the access and re-runs the load-bearing cells under a seal that removes it. A run succeeds only if every test passes, so success is unambiguous while the path to it varies.
每项任务均附带一个参考解，并通过一套固定的行为输入/输出测试，将团队交付成果与预先确定的输出进行比对评分[fn5]。这些任务均为不含随机性的纯函数，且采用精确比对。测试套件放置在每个智能体的工作目录之外；在主数据收集中，除此之外并未对其实施访问控制，第 9 节报告了团队如何利用这一访问权限，并在封闭访问、取消该权限的条件下重新运行支撑关键结论的单元格。只有所有测试均通过，一次运行才算成功，因此成功与否明确无歧义，而实现成功的路径则各不相同。

Statistical approach.统计方法。
The unit of analysis is the run: one graph, one pass/fail outcome. Success rates carry Clopper–Pearson exact 95% intervals [8]; success contrasts use Fisher’s exact test [12], continuous contrasts the Mann–Whitney test [23], and each set of related contrasts is corrected with the Benjamini–Hochberg procedure [2], reported as $p_{\mathrm{BH}}$ . Eight hypotheses (H1–H8) are stated in advance; six are pre-registered in both prediction and test (H1, H4–H8), while H2 and H3 carry qualifications set out in Appendix A. The appendix lists all eight with their outcomes, and the findings cite them by number. At ten runs a single cell’s success rate carries a margin of roughly thirty percentage points, so single-cell readings are directional and the pooled contrasts carry the inferential weight.
分析单位是单次运行：一张图，一个通过/失败结果。成功率附有 Clopper–Pearson 精确 95% 区间 [8]；成功率对比采用 Fisher 精确检验 [12]，连续变量对比采用 Mann–Whitney 检验 [23]，每组相关对比均使用 Benjamini–Hochberg 程序 [2] 进行校正，并报告为 $p_{\mathrm{BH}}$。八项假设（H1–H8）均事先提出；其中六项的预测和检验方法均已预注册（H1、H4–H8），而 H2 和 H3 则附有附录 A 中说明的限定条件。该附录列出了全部八项假设及其结果，研究发现按编号引用这些假设。在十次运行的情况下，单个单元格的成功率误差幅度约为三十个百分点，因此单个单元格的解读仅能指示方向，统计推断主要依赖合并后的对比。

If every agent must talk to every other, messaging scales as $n^{2}$ with team size, and the cost of coordination soon dominates the cost of the work. The first half of that picture holds in our data. Table 1 shows messages per run rising from 6.1 at two agents to 71.3 at eight. Throughout the paper we quantify such growth by fitting a line to message count against team size on log-log axes; the slope of that line is the growth exponent, 1 for linear growth and 2 for quadratic. On the chained task the exponent is 1.92, quadratic within error, and the two collection sessions agree to two decimal places (1.92 and 1.93). The pre-registered H1 test, a regression over the three cell means, gives 1.92 with an interval of $[1.67,2.17]$ ( $\pm 1.96\,\mathrm{SE}$ , the pre-registered test’s normal approximation); the per-run regression we use for scaling elsewhere in the paper gives the same 1.92 with a tighter interval, $[1.80,2.05]$ . Both confirm quadratic scaling. On the distributed task the growth is also steep but not stable across sessions, a point Section 8 takes up. Figure 4 plots both experiments and the two scaling arms together.
如果每个智能体都必须与其他所有智能体通信，那么消息数量就会随团队规模按 $n^{2}$ 增长，协调成本很快就会超过工作本身的成本。这一描述的前半部分在我们的数据中成立。表 1 显示，每次运行的消息数从两个智能体时的 6.1 上升至八个智能体时的 71.3。在全文中，我们通过在双对数坐标下对消息数与团队规模拟合直线来量化这种增长；该直线的斜率就是增长指数，1 表示线性增长，2 表示二次增长。在链式任务中，指数为 1.92，在误差范围内符合二次增长，而且两次采集会话的结果精确到小数点后两位仍一致（1.92 和 1.93）。预注册的 H1 检验对三个实验单元的均值进行回归，得到的指数为 1.92，区间为 $[1.67,2.17]$（$\pm 1.96\,\mathrm{SE}$，采用预注册检验的正态近似）；我们在本文其他地方用于分析尺度关系的逐次运行回归同样得到 1.92，但区间更窄，为 $[1.80,2.05]$。两者均证实了二次尺度增长。在分布式任务中，增长也很陡峭，但在不同采集会话之间并不稳定，第 8 节将讨论这一点。图 4 将两个实验和两个规模扩展分支绘制在一起。

The second half does not hold, and the timestamps show why. The growth is a round of introductions, made once, early. We read this from timing and message counts, because the instrument does not capture message content; introduction here simply names a pair’s first contact. Two measurements separate this opening handshake from the coordination that lasts.
后半部分并不成立，而时间戳揭示了原因。这种增长来自运行早期仅发生一次的一轮初次联络。我们根据时间分布和消息数得出这一判断，因为测量工具并未记录消息内容；这里的初次联络仅指一对智能体之间的首次接触。两项测量将这种起始握手与持续发生的协调区分开来。
First, the messages per pair fall as the team grows, from about three messages per ordered pair at two agents to 1.27 at eight. The total rises only because there are more pairs; each pair talks less.
首先，随着团队规模增大，每对智能体之间的消息数下降，从两个智能体时每个有序对约三条消息，降至八个智能体时的 1.27 条。总量上升仅仅是因为智能体对的数量增加了；每对智能体之间的通信反而更少。
Second, the introductions come early in the run; the sustained traffic comes later. We place each run’s messages on a normalised timeline, with $\tau=0$ the run’s first message and $\tau=1$ its last, and report the mean over runs of the time by which ninety per cent of a run’s pairs have appeared. On the distributed task, in one collection session, ninety per cent of the distinct sender-to-recipient pairs a run will ever use have appeared by $\tau\approx 0.2$ at every team size (Figure 5); in the other session the eight-agent handshake stretches to $\tau\approx 0.6$ , so how early it completes is itself session-dependent. The chained task completes its handshake early at four and eight agents in both sessions; at two agents, in one session, ninety per cent of pairs appear only around the middle of the run ( $\tau\approx 0.46$ ). What holds everywhere is the ordering, introductions first, then repeat traffic on a small established core, with the sustained channels running through the middle and second half of the run. Messages also get shorter as teams grow (mean size falls at every step in team size), so per-channel coordination thins on two axes at once.
其次，初次联络发生在运行早期；持续的通信则发生在后期。我们将每次运行的消息放置在归一化时间轴上，其中 $\tau=0$ 表示该次运行的第一条消息，$\tau=1$ 表示最后一条消息，并报告每次运行中百分之九十的智能体对均已出现的时间在各次运行间的均值。在分布式任务的一次采集会话中，对于每种团队规模，一次运行最终使用的所有不同发送者—接收者对中，有百分之九十在 $\tau\approx 0.2$ 时就已出现（图 5）；而在另一次会话中，八个智能体的握手过程延续至 $\tau\approx 0.6$，因此握手完成得有多早本身也取决于采集会话。在两次采集会话中，链式任务在四个和八个智能体时都较早完成握手；在两个智能体时，其中一次会话中百分之九十的智能体对直到运行中段左右才出现（$\tau\approx 0.46$）。在所有情况下都成立的是其先后顺序：先进行初次联络，随后在一个已建立的小型核心通信网络上反复通信，而持续使用的通道贯穿运行的中段和后半段。随着团队规模增大，消息也变得更短（团队规模每增加一档，平均消息长度都会下降），因此每个通道上的协调同时在两个维度上减弱。

The scaling arms close the argument, because each was collected as one interleaved batch with no idle agents and a decision rule fixed in advance. On the eight-step chain the slope falls from 1.82 between two and four agents to 0.72 between four and eight; at ten runs per cell the fall is in the predicted direction but not significant (hypothesis H7, Appendix A). On the sixteen-step chain the growth stops outright: mean messages are 21.4, 47.0, and 46.8 at four, eight, and sixteen agents, the slope between eight and sixteen is 0.00 (95% CI $[-0.34,0.34]$ ), and the break is significant ( $\Delta=1.08$ , 95% CI $[0.61,1.55]$ ), confirming hypothesis H8. Because that chain is fully divided only at sixteen agents, the plateau cannot be the team running out of work. Instead the team changes how it addresses itself: past eight agents, messages aimed at one named peer fall from 34.6 to 12.2 per run while broadcasts, messages sent to the whole team at once, rise from 12.3 to 34.0, and twelve of the twenty allowed sixteen-agent runs coordinate by broadcast alone. A large team stops addressing peers one at a time and speaks to the room.
规模扩展分支使这一论证完整，因为每个分支都以一个交错批次采集，没有空闲智能体，并且判定规则事先固定。在八步链中，斜率从两个至四个智能体之间的 1.82 降至四个至八个智能体之间的 0.72；在每个实验单元运行十次的情况下，下降方向符合预测，但未达到统计显著性（假设 H7，附录 A）。在十六步链中，增长完全停止：四个、八个和十六个智能体时的平均消息数分别为 21.4、47.0 和 46.8，八个至十六个智能体之间的斜率为 0.00（95% CI $[-0.34,0.34]$），且斜率的下降达到统计显著性（$\Delta=1.08$，95% CI $[0.61,1.55]$），证实了假设 H8。由于该链只有在智能体数量达到十六个时才被完全划分，因此这一平台期不可能是团队无事可做所致。相反，团队改变了内部消息的发送方式：超过八个智能体后，每次运行中发给某个具名同伴的消息从 34.6 条降至 12.2 条，而广播消息，即一次发给整个团队的消息，则从 12.3 条增至 34.0 条；在允许通信的二十次十六智能体运行中，有十二次仅通过广播进行协调。大型团队不再逐一向同伴发送消息，而是面向全体成员发言。
Summary.小结。
Adding an agent adds one more introduction, while the lasting per-agent coordination barely grows, and on the largest teams the messaging cost of growth falls to zero because the team switches to broadcast. The task sets the shape of the lasting traffic (Section 5). A budget or a topology designed for sustained all-to-all messaging provides for traffic the teams do not produce.
每增加一个智能体，就会多一次自我介绍，而每个智能体的持续协调量几乎不增加；在最大的团队中，由于团队转向广播，规模增长带来的消息通信成本降至零。任务决定了持续通信流量的形态（第 5 节）。为持续的全互联消息通信设计预算或拓扑，所预留的是团队实际上并不会产生的通信流量。
5 The Task Shapes the Network5 任务塑造网络
The handshake of Section 4 says how much messaging there is; it does not say what shape the messaging settles into. To read the shape we build, for each run, its sustained undirected graph: two agents are joined by an edge when at least one direction between them carried two or more messages during the run, so an edge marks a channel the pair used more than once; a single greeting does not count. We then measure two properties of that graph and average them over a cell’s runs. The first is the mean degree, how many live partners the average agent keeps, read against the clique line $n-1$ that all-to-all coordination would draw. The second is the global clustering coefficient (transitivity), the share of an agent’s partner-pairs that are themselves joined; it lies near 1 when the live partners form one tightly interconnected group and near 0 when they do not link to each other. Appendix A.3 gives the exact definitions and thresholds.
第 4 节的握手过程说明了消息通信量有多大，却没有说明消息通信最终稳定为何种形态。为分析这一形态，我们为每次运行构建持续通信无向图：如果两个智能体之间至少有一个方向在该次运行中传递了两条或更多消息，就用一条边连接它们，因此，一条边表示这对智能体使用过不止一次的通信通道；单次问候不计入其中。随后，我们测量该图的两个性质，并对同一实验单元内各次运行的测量结果取平均。第一个是平均度，即每个智能体平均维持多少个活跃通信伙伴，并将其与全互联协调所对应的团基准线 $n-1$ 进行比较。第二个是全局聚类系数（传递性），即一个智能体的通信伙伴所组成的各对中，彼此也有连接的比例；当活跃通信伙伴构成一个内部连接紧密的群体时，该系数接近 1，而当这些伙伴彼此不相连时，则接近 0。附录 A.3 给出了确切的定义和阈值。
The shape is set by the task, and the two tasks settle on opposite shapes (Figure 6). Both quantities are averaged over every configured agent and every run in a cell, so an idle agent counts as degree zero, and a run with no named-message network counts as zero and stays in the average; Appendix A.3 gives the estimator. On the distributed task, where every agent holds a fragment of one shared specification, the graph rides the clique line and fills in. Mean degree is 0.90, 2.92, and 5.47 at two, four, and eight agents, against clique lines of 1, 3, and 7, and clustering is high once the team is larger than a pair (0.96 at four agents, 0.81 at eight). Reconciling one specification pulls the team towards talking to everyone, and those partners also interconnect, so the sustained graph is a near-complete, tightly clustered mesh. On the chained task, where each agent owns consecutive steps of a pipeline, the graph stays sparse. Mean degree is 0.90, 1.57, and 2.99 at the same sizes, so the gap to the clique line widens as the team grows, and clustering stays low (0.36 at four agents, 0.38 at eight). A pipeline needs each owner to agree interfaces only with its neighbours, and the sustained graph records that local structure. The sixteen-step chain, the only configuration that reaches sixteen agents, has the widest gap: the average agent sustains just 0.28 partners against a clique line of 15, and clustering falls to 0.03. Only 8 of the 20 sixteen-agent runs carry any named agent-to-agent messaging at all; in the rest the named-peer network has gone quiet: the messaging that remains is broadcast, sent to the whole team at once (Section 4), and the coordination that is not in messages has moved to files (Section 6). Growing the team does not grow the named-peer network towards all-to-all; it stretches a sparse, chain-shaped graph thinner until, at sixteen agents, almost none of it forms.
网络形态由任务决定，而这两项任务最终形成了相反的形态（图 6）。这两个量均对一个实验单元内所有配置的智能体和每次运行取平均，因此，空闲智能体的度计为零，没有具名消息网络的运行也计为零并保留在平均值计算中；附录 A.3 给出了估计量。在分布式任务中，每个智能体都持有同一份共享规范的一个片段，其图的平均度紧随团基准线，且连接日益完备。在两个、四个和八个智能体时，平均度分别为 0.90、2.92 和 5.47，对应的团基准线分别为 1、3 和 7；当团队超过两个智能体时，聚类系数较高（四个智能体时为 0.96，八个智能体时为 0.81）。协调统一同一份规范促使团队成员与所有人交流，而这些通信伙伴之间也相互连接，因此，持续通信图呈现为近乎完全连接、聚类程度很高的网状结构。在链式任务中，每个智能体负责流水线中连续的若干步骤，其图始终保持稀疏。在相同的团队规模下，平均度分别为 0.90、1.57 和 2.99，因此，随着团队规模增大，其与团基准线的差距不断扩大，而聚类系数始终较低（四个智能体时为 0.36，八个智能体时为 0.38）。流水线只需要各环节的负责者与相邻环节的负责者就接口达成一致，而持续通信图记录了这种局部结构。十六步链是唯一达到十六个智能体的配置，其差距最大：每个智能体平均仅维持 0.28 个通信伙伴，而团基准线为 15，聚类系数则降至 0.03。20 次十六智能体运行中，只有 8 次存在任何具名智能体之间的消息通信；在其余运行中，具名同伴网络已归于沉寂：剩余的消息通信是一次发给整个团队的广播（第 4 节），而未通过消息进行的协调则已转移到文件中（第 6 节）。团队规模增长并未使具名同伴网络向全互联发展；它使稀疏的链状图变得更加稀薄，直至在十六个智能体时，这种图几乎不再形成。

Neither shape has a leader. The distributed mesh is dense but flat: no agent holds a disproportionate share of the sustained edges. Filtering each run’s message graph to the channels that carry significantly more than an even spread (a disparity-filter backbone, $\alpha=0.05$ ) leaves essentially no edges, 0 of 1,170 at eight agents on the distributed task and 2 of 1,077 on the chained task, and Section 7 shows that naming a coordinator does not change this. The dense graph is dense everywhere and the sparse graph is sparse everywhere; neither concentrates on a hub. Whatever the task, the structure the team builds is leaderless.
这两种形态都没有领导者。分布式网状结构密集但扁平：没有任何智能体占据不成比例的持续通信边份额。将每次运行的消息图筛选为仅保留消息量显著高于均匀分布水平的通道（差异过滤骨干网络，$\alpha=0.05$），结果几乎不剩任何边：在八个智能体时，分布式任务的 1,170 条边中保留了 0 条，链式任务的 1,077 条边中保留了 2 条；第 7 节表明，指定协调者也不会改变这一结果。稠密图在各处都稠密，稀疏图在各处都稀疏；两者都没有围绕某个枢纽集中连接。无论任务如何，团队构建的结构都是无领导者的。
A directed version of this measure gives a narrower picture. If one counts, for the average agent, the number of distinct peers it sends two or more messages to (a directed out-degree, normalised across all agents), the count is smaller and varies by experiment and session, roughly two to five at eight agents (Figure 7). It is a partial measure. On the chained task it stays around two; on the distributed task it is about three in one collection and five in the other, and in the second it comes close to the undirected degree of 5.5. The directed count describes how many peers an agent actively pushes to, which is generally fewer than the undirected connectivity, though it is a range, varying by experiment and session.
这一度量的有向版本呈现出一个更为局限的图景。如果统计平均每个智能体向多少个不同的同伴发送了两条或更多消息（即在所有智能体上归一化的有向出度），所得数值会更小，并随实验和会话而变化，在八个智能体时约为二到五（图 7）。这是一项局部度量。在链式任务中，该值保持在二左右；在分布式任务中，一组采集数据中的值约为三，另一组约为五，且在后一组中接近 5.5 的无向度数。有向计数描述的是一个智能体主动向多少个同伴推送消息，通常小于无向连通度，但其数值处于一个随实验和会话而变化的范围内。

Summary.小结。
Left to organise themselves, the teams do not converge on one coordination span. The distributed task builds a dense, tightly clustered mesh that rides the all-to-all line; the chained task builds a sparse graph whose gap to all-to-all widens with team size; and neither has a hub. The shape of the coordination network is a property of the task, read directly off the graph.
在自主组织的情况下，各团队并不会收敛到同一种协调跨度。分布式任务构建出一个稠密、高度聚类且紧随全连接基准线的网状网络；链式任务构建出一个稀疏图，其与全连接的差距随团队规模扩大而增大；两者都没有枢纽。协调网络的形态是任务的一种属性，可以直接从图中读出。
6 Finding 2: Files are the Cheaper Channel, Where Messaging Would Dominate6 发现 2：在消息传递本会占主导的情况下，文件是成本更低的通道
The shape of the network is one half of the coordination cost; the channel it runs on is the other. A direct message reaches one recipient, so telling the whole team something means repeating it. A shared file is written once and read by many. The file policy of Section 3 turns this difference into an experiment: the same tasks run with coordination files forbidden, allowed, or mandatory.
网络形态是协调成本的一个方面；承载协调的通道则是另一个方面。一条直接消息只能送达一个接收者，因此，要把某件事告诉整个团队，就意味着需要重复发送。共享文件只需写入一次，即可由多人读取。第 3 节的文件策略将这一区别转化为一项实验：在禁止、允许或强制使用协调文件的条件下运行相同任务。

They therefore show only the direction of the channel shift; the run-level output-token totals in the text use the model’s reported figures. Mandating files changes where the coordination happens. At eight agents on the distributed task, the tokens attributed to direct messages fall from about 10,500 per run under the allowed default to 1,700 under mandatory, while file-write and file-read tokens roughly double (Figure 8). The two figures are measured differently, the message tokens from message length and the file tokens as a share of the turn’s output (see the caption), so the decomposition shows only the direction of the shift; the direction is corroborated by the message count itself, which collapses under the policy, and by the run-level totals below. On the distributed task under the mandatory policy the distinct files a run touches grow with the team, from 3.2 at two agents to 11.9 at eight, and the pre-committed main effect, that mandatory adds file coordination while forbidden and allowed look alike, holds in both experiments (hypothesis H4).
强制使用文件改变了协调发生的通道。在八个智能体执行分布式任务时，归属于直接消息的 token 数从默认允许策略下每次运行约 10,500 个降至强制策略下的 1,700 个，而文件写入和文件读取的 token 数大致翻倍（图 8）。这两类数值的测量方式不同：消息 token 数根据消息长度计算，文件 token 数则按该轮次输出的一定份额计算（见图注），因此这一分解仅表明转移的方向；策略实施后消息数量本身也大幅下降，以及下文的运行级别总量，都印证了这一方向。在强制策略下的分布式任务中，每次运行所访问的不同文件数随团队规模增长，从两个智能体时的 3.2 增至八个智能体时的 11.9；事先约定的主效应，即强制策略增加文件协调，而禁止策略与允许策略表现相近，在两项实验中均成立（假设 H4）。
The saving, however, belongs to one task shape, and we state it in the model’s output tokens, which the run’s logs report directly. On the distributed task the mandatory policy cuts output tokens by about 25% at four agents and about 42% at eight below the allowed default, with all team structures and splits pooled at each size (the eight-agent cut spans 36% to 49% across the two collection sessions). Output is only part of what a run consumes: most of the token throughput is cached context re-read on every turn, about 10.5 million tokens per run at eight agents under the allowed policy over the flat cells, which the run totals do not price, and the runs were collected on a subscription, with no per-token metering. The saving is not an artefact of the output-only view, since mandating files cuts the cached throughput as well, to about 6.6 million tokens per run. At API list rates for output alone, the eight-agent cut corresponds to roughly $4.3 versus $2.5 per run, an illustration of the output saving. On the chained task the same rule raises output tokens, by about 17% at four agents and 10% at eight. The direction of the difference is the finding, and it makes the rule conditional: Experiment 1 teams left to themselves coordinate by one-to-one messages, so replacing that channel with files removes repetition; Experiment 2 teams already pass their work through files, each step’s output read by the next, so mandating more file traffic only adds overhead. The sixteen-agent arm marks the limit sharply: with files already carrying the coordination, the mandatory rule roughly doubles per-run tokens (578k against 333k) and more than triples file reads, for identical success (10 of 10 against 20 of 20).
然而，这种节省只出现在一种任务形态中，我们以运行日志直接报告的模型输出 token 数来表述这种节省。在分布式任务中，将每种团队规模下的所有团队结构和拆分方式汇总后，相较于默认的允许策略，强制策略在四个智能体时将输出 token 数减少约 25%，在八个智能体时减少约 42%（八个智能体时，两次数据采集中的降幅为 36% 至 49%）。输出只是一次运行消耗的一部分：token 吞吐量的大部分来自每一轮对缓存上下文的重新读取；在允许策略下，八个智能体的扁平结构各实验条件中，每次运行的这部分吞吐量约为 10.5 million token，运行总计并未对其计价，而且这些运行是在订阅制下采集的，没有按 token 计量收费。这种节省并非仅考察输出所造成的假象，因为强制使用文件也将缓存吞吐量降至每次运行约 6.6 million token。仅按输出的 API 标价计算，八个智能体时的降幅相当于每次运行的费用从约 $4.3 降至 $2.5，这说明了输出方面的节省。在链式任务中，同一规则反而增加了输出 token 数，四个智能体时增加约 17%，八个智能体时增加约 10%。差异的方向就是研究发现，它表明这条规则的适用性取决于条件：实验 1 中的团队在自主行动时通过一对一消息进行协调，因此用文件替代该通道可以消除重复；实验 2 中的团队已经通过文件传递工作成果，每一步的输出由下一步读取，因此强制增加文件交互只会增加开销。十六个智能体的实验组清楚地显示了这一局限：在协调已经由文件承载的情况下，强制规则使每次运行的 token 数大致翻倍（578k 对 333k），文件读取次数增至三倍以上，而成功率完全相同（10 次中成功 10 次，对比 20 次中成功 20 次）。

The policy also sets the run’s shape in time. Messaging leads file writing (comparing each run’s mean message time with its mean file-write time) in 86% of allowed distributed-task runs, 62% under forbidden, and 17% under mandatory, where files must exist before anything can read them; a quarter of the mandatory runs (about a third at four and eight agents) send no message at all and drop out of this measure, so the 17% describes the minority that still message. A sequential task settles its interfaces by writing them down, whatever it is told.
策略还决定了运行在时间上的形态。在分布式任务中，通过比较每次运行的平均消息发送时间与平均文件写入时间可知，在允许策略下，86% 的运行先发送消息，禁止策略下为 62%，强制策略下为 17%，因为文件必须先存在才能被读取；强制策略下有四分之一的运行（四个和八个智能体时约为三分之一）完全不发送消息，因此未纳入这一指标，所以 17% 描述的是仍然发送消息的少数运行。链式任务在每一种策略下都会先写入文件（仅有 12% 至 14% 的运行先发送消息），尽管其提示要求智能体通过消息进行协调。无论收到什么指示，顺序任务都会通过书面记录来确定其接口。
Summary.小结。
Files are not passive outputs; they are the one-to-many channel, and the cheaper one wherever one-to-one messaging would otherwise dominate. The practical rule is conditional, and the graph tells you which side of it a task sits on: if the teams’ own coordination is message-heavy, mandate files and save; if it already flows through files, leave it alone.
文件并非被动的输出；它们是一对多通道，而且在原本会由一对一消息传递占主导的情形下，成本更低。这条实用规则的适用性取决于条件，而图结构会告诉你任务属于哪种情形：如果团队自身的协调以消息为主，就强制使用文件以节省成本；如果协调已经通过文件进行，就保持原样。
7 Finding 3: Naming a Coordinator Does Not Create Structural Leadership7 发现 3：指定协调者并不会产生结构性领导地位
The simplest way to assign leadership to an agent team is a sentence in a prompt. In the coordinator condition one agent, and only that agent, is told it is the coordinator. If the label works, the communication graph should show it: traffic concentrating on the coordinator, and success rising on the tasks that need arbitration most.
为智能体团队指定领导者，最简单的方法是在提示中写上一句话。在协调者条件下，一个且仅有这一个智能体被告知自己是协调者。如果这一标签有效，通信图就应体现出来：通信流量向协调者集中，而且在最需要仲裁的任务上，成功率应有所提高。
Neither happens. No hub forms under either condition: filtering each run’s message graph to the channels that carry a disproportionate share of an agent’s traffic (a disparity-filter backbone, $\alpha=0.05$ ) leaves 0 of 1,170 channels at eight agents on the distributed task and 2 of 1,077 on the chained task, and the same holds at four agents. A pre-committed null on the chained task also finds no difference in directed traffic at four agents in the pre-registered session (12.9 against 16.3 messages, $p=0.29$ ). Whatever the prompt says, no communication hub emerges in either task. Nominal leadership does not become structural leadership.
这两种情况都没有发生。两种条件下都没有形成通信枢纽：将每次运行的消息图过滤为仅保留承载某个智能体不成比例的大量通信流量的通道（差异过滤骨架，$\alpha=0.05$），在八智能体配置下，分布式任务的 1,170 条通道中有 0 条保留下来，链式任务的 1,077 条通道中有 2 条保留下来，四智能体配置下也同样如此。在预注册场次中，针对链式任务预先设定的零假设检验也发现，四智能体配置下的有向通信流量没有差异（12.9 条消息对 16.3 条消息，$p=0.29$）。无论提示如何表述，两项任务中都没有出现通信枢纽。名义上的领导地位并未转化为结构上的领导地位。

将两批扁平配置的数据合并后，成功情况也呈现出相同的结果（表 2）。预注册的预测是，协调者有助于处理冲突划分，因为其中两个智能体持有不一致的规则，需要有人作出仲裁。该划分中的成功情况只能不完全地衡量仲裁能力：评分器在不告知团队的情况下执行两条规则中的一条，因此，即使团队顺利完成仲裁，若其就另一条规则达成一致，仍会失败；因而，结果混合了仲裁能力与恰好选中被执行约定的因素（参考实现采用更严格的规则，即数量为零时无效）。在四智能体配置下，协调者看起来表现更好（8/10，而采集批次 B 为 5/10），但合并两批扁平配置的数据后，这一优势便消失了（8/10 对 12/20，$p=0.42$）；在八智能体配置下，方向则发生逆转：在每一种策略下，扁平团队的表现都不逊于或优于协调者团队。在六个冲突条件单元格的比较中，唯一经校正后仍显著的差异是一次反转：在 forbidden 策略下，扁平团队为 20/20，协调者团队为 6/10（$p_{\mathrm{BH}}=0.046$）。一旦将评分测试套件置于智能体无法访问的位置，这一差异便无法复现：第 9 节的封闭复现实验运行了相同的八智能体冲突条件单元格，发现扁平团队与协调者团队在每种策略下的表现均相当，因此，我们将这一反转视为未隔离采集所产生的伪象。在链式任务中，拥有不受限制的文件通道的协调者团队是实验中表现最弱的单元格（1/10）。预注册的实验内比较针对冲突划分中的两种拓扑结构，结果尚无定论（假设 H3）；此处报告的跨实验交互作用（$p=0.24$）属于探索性检验，不在预注册范围内（附录 A）。
A flat team is no cure either. At two agents on the conflicting split, flat teams fail 37% of their runs pooled across policies (up to half in the weaker session), while coordinating through the same channels as everyone else. Resolving a planted disagreement is not a matter of communication volume.
扁平团队也不是解决办法。在冲突划分的双智能体配置下，将各策略的数据合并后，扁平团队有 37% 的运行失败（在表现较弱的场次中，失败比例高达一半），而它们使用的协调通道与其他团队相同。解决预设的分歧并不取决于通信量。

The sharpest failure has no leader and no fix by talking. The eight-step chain (compute_invoices) succeeds in nine of ten runs at two and four agents, then fails all ten at eight agents, where each agent owns exactly one step. Every failure sits on the same seam, between compute_tax (step 7) and format_invoices (step 8): round at each step, or once at the end. The specification settles it, compute_tax is told to pass its tax on unrounded and format_invoices to round every figure once at the end, so the two agents each hold one half of the convention. At two and four agents one agent owns both steps and reconciles the halves internally; at eight agents the seam falls between two different owners and no agent holds responsibility for it. The teams were not silent: the run transcripts show rounding discussed in all ten of the eight-agent runs, and those teams messaged more than the four-agent ones. Talking more did not close an interface that nobody owned. The mismatch is invisible to each agent, whose own step is correct, and invisible in the finished code, which runs. Diagnosing it draws on the specification, the identical failure across the runs, and the transcripts, none of which is the graph; what the coordination graph adds is the structural signature, that at eight agents the seam falls on a boundary between two different owners, an interface no single agent sits across.
最严重的失败发生在没有领导者的情况下，而且无法通过交谈解决。八步链条（compute_invoices）在双智能体和四智能体配置下均有十次运行中的九次成功，但在八智能体配置下十次全部失败，此时每个智能体恰好负责一个步骤。所有失败都发生在同一衔接处，即 compute_tax（步骤 7）与 format_invoices（步骤 8）之间：究竟是每一步都进行舍入，还是仅在最后舍入一次。规范对此已有明确规定：compute_tax 被要求将税额不经舍入地传递下去，而 format_invoices 被要求在最后对每个数值舍入一次，因此，这两个智能体各自掌握了该约定的一半。在双智能体和四智能体配置下，一个智能体同时负责这两个步骤，并在内部协调这两半约定；在八智能体配置下，衔接处落在两个不同负责者之间，没有任何智能体对其负责。这些团队并非没有交流：运行记录显示，十次八智能体运行中都讨论了舍入问题，而且这些团队发送的消息比四智能体团队更多。更多的交谈并未弥合这个无人负责的接口。每个智能体都看不到这一不匹配，因为其自身负责的步骤是正确的；完成后的代码也未显露这一不匹配，因为代码能够运行。对这一问题的诊断依赖于规范、各次运行中相同的失败以及运行记录，而这些都不是图本身；协调图所补充的是其结构特征：在八智能体配置下，衔接处落在两个不同负责者的边界上，没有任何单个智能体跨越这一接口。
Beyond structure, no single network property buys success. Exploratory run-level regressions point one way, more messaging and writing go with failure and longer runs, more reading with success and shorter ones, but the associations explain about a tenth of the variance and the causality is open, since a run that goes well needs less repair traffic. The network’s shape records how a run went more than it predicts how it will go.
除结构之外，没有任何单一的网络属性能够带来成功。探索性的运行层面回归分析呈现出一致的方向：消息交流和写入越多，越容易失败，运行时间也越长；读取越多，越容易成功，运行时间也越短，但这些关联仅能解释约十分之一的方差，因果关系仍未确定，因为进展顺利的运行所需的补救性通信更少。网络的形态更多是在记录一次运行的实际进展，而非预测其未来走向。
Summary.小结。
A coordinator exists only where the interaction structure carries the role, and a prompt clause alone does not create that structure. Decomposition creates interfaces between agents, every interface needs an owner, and the graph shows which interfaces have none; those are where the teams break.
只有当交互结构承载协调者这一角色时，协调者才真正存在，仅凭提示词中的一条规定并不能创造这种结构。任务分解会在智能体之间产生接口，每个接口都需要有负责者，而图揭示了哪些接口无人负责；团队正是在这些地方出现崩溃。
8 How Far to Trust One Run: Reliability of the Measurements8 一次运行值得信任到什么程度：测量的可靠性
The flat condition was collected twice under byte-identical prompts, giving 54 matched cell pairs that are exact same-configuration replications under one pinned model. These replications quantify the reliability of the instrument. Where a task pins the coordination down the two sessions agree closely, showing that the instrument itself can reproduce consistently; where a task leaves the coordination open the spread between sessions is considerably larger and itself task-dependent, which uniform measurement noise would not produce.
扁平条件下的数据在字节完全相同的提示词下采集了两次，得到54对匹配的实验单元，它们是在同一个固定模型下对完全相同配置的精确重复实验。这些重复实验量化了测量工具的可靠性。当任务明确限定协调方式时，两次实验的数据高度一致，表明测量工具本身能够稳定地复现结果；当任务允许自由协调时，两次实验之间的差异明显更大，且差异本身取决于任务，这是均匀的测量噪声所无法产生的。

Reproducibility is task-dependent (Figure 11). On the chained task the sessions agree almost everywhere: no matched cell differs once the twenty-seven comparisons are Benjamini–Hochberg corrected (one differs at the raw level), and typical cell means move by about seven per cent. On the distributed task thirteen of twenty-seven cells differ after the same correction, one of them by a factor of fifteen in messaging (31.4 against 2.0 messages per run at the same configuration). File activity swings too: at eight agents under the allowed policy, one session’s teams touch 18.0 distinct files per run on the conflicting split and the other’s touch 4.3. This is why the distributed task’s scaling exponent is a range, 1.76 (95% CI $[1.57,1.96]$ ) in one session and 2.44 ( $[2.32,2.57]$ ) in another, with non-overlapping intervals, and why the handshake completion time in Section 4 is reported per session. The chained task’s exponent, meanwhile, replicates to two decimal places.
可复现性取决于任务（图11）。在链式任务上，两次实验的结果几乎处处一致：对二十七次比较进行Benjamini–Hochberg校正后，没有任何匹配的实验单元存在显著差异（未经校正时有一个存在显著差异），各实验单元均值的典型变化幅度约为百分之七。在分布式任务上，经过相同校正后，二十七个实验单元中有十三个存在显著差异，其中一个的消息数相差十五倍（相同配置下，每次运行的消息数分别为31.4和2.0）。文件活动也有大幅波动：在允许策略下使用八个智能体时，对于存在冲突的任务划分，一次实验中的团队每次运行涉及18.0个不同文件，另一次实验中则为4.3个。这就是为什么分布式任务的缩放指数表现为一个范围：一次实验中为1.76（95%置信区间 $[1.57,1.96]$），另一次实验中为2.44（$[2.32,2.57]$），两个区间互不重叠；这也是第4节按每次实验分别报告握手完成时间的原因。与此同时，链式任务的指数在重复实验中可保持一致到小数点后两位。
The pattern in where the divergence lands explains it. The cells that drift are the high-coordination ones, where the task leaves the team the most freedom in how to organise; the cells that reproduce are those where the task pins the coordination down, as a chain does. The gap is not elapsed time between sessions, since the chained pairs span a longer wall-clock gap than the distributed ones and still reproduce.
差异出现在哪些实验单元上的分布模式解释了这一现象。发生漂移的是协调需求高的实验单元，在这些单元中，任务给予团队最大的组织方式自由度；能够复现的是任务明确限定协调方式的实验单元，链式任务便是如此。这种差异并非由两次实验之间的时间间隔造成，因为链式任务的配对实验之间实际经过的时间比分布式任务更长，却仍然能够复现。
Summary.小结。
Under a fixed model identifier, a multi-agent configuration is characterised by a distribution of runs. Where the task leaves coordination open, single-run benchmarks of multi-agent systems measure a sample of size one from a wide distribution. Any instrument for these systems has to be used with repetition, and any headline number should carry its cross-session range where matched sessions exist, as ours do.
在固定的模型标识符下，一个多智能体配置的特征应由多次运行的分布来刻画。当任务允许自由协调时，多智能体系统的单次运行基准测试所测得的，只是来自一个宽广分布、样本量为一的样本。用于这些系统的任何测量工具都必须重复使用，而且只要存在像我们这样相互匹配的多次实验，任何核心指标都应附上其跨实验的取值范围。
9 Containment and What the Teams Reach For9 访问隔离与团队主动探查的对象
The runs analysed above were collected in an environment that did not confine the agents to their working directory. For each run the grading suite and the reference solution sat in sibling directories, and the run’s manifest recorded their paths. A validity check made after the main collection found that the agents used this access: they opened the hidden test suite in 234 runs and read the reference solution in 77, the reach most common in the eight-agent conflicting cells. The same access reached further than the grading files: through the file tools, agents opened another agent’s private prompt in 129 runs, read a different run’s files in 18 (a finished solution in 16 of them), and read the shared message log in 52; shell-mediated reads, which the graph does not capture, would raise each of these counts. No prompt forbade reading these files, and none asked for them; the only stated constraint concerned which files a team could create. The agents went looking on their own initiative and reported what they found openly. The reachable files are a containment gap in the setup; the looking is the agents’ own behaviour, measured directly under the seal below. The gap does not on its own decide the findings. The confirmatory results survive when every run with such a read is dropped, and the file-policy saving of Section 6 is largest in the runs with no out-of-workspace read and smallest in the most-affected third when the affected runs are grouped by read count (46% against 41% across all affected runs and 37% in the most-affected third), so the access dilutes that effect and cannot account for it. To settle the matter directly we re-ran the load-bearing cells in a sealed environment.
上述分析所用的运行数据采集于一个未将智能体限制在其工作目录内的环境。对于每次运行，评分测试套件和参考解答都位于同级目录中，且该次运行的清单记录了它们的路径。主要数据采集完成后进行的一次有效性检查发现，智能体利用了这种访问权限：它们在234次运行中打开了隐藏测试套件，在77次运行中读取了参考解答，这类访问在八智能体且存在冲突的实验单元中最为常见。这种访问还超出了评分文件的范围：通过文件工具，智能体在129次运行中打开了另一个智能体的私有提示词，在18次运行中读取了另一次运行的文件（其中16次读取了已完成的解答），并在52次运行中读取了共享消息日志；图未捕获通过shell进行的读取，若将其计入，上述各项次数都会增加。没有任何提示词禁止读取这些文件，也没有任何提示词要求读取它们；唯一明确规定的约束涉及团队可以创建哪些文件。智能体主动进行了探查，并公开报告了所发现的内容。这些可访问的文件构成了实验设置中的访问隔离漏洞；探查则是智能体自身的行为，下面将在封闭访问条件下对其进行直接测量。这一漏洞本身并不能决定研究结论是否成立。剔除所有发生过此类读取的运行后，验证性结果仍然成立；而且，将受影响的运行按读取次数分组后，第 6 节所述的文件策略节省幅度在未发生工作区外读取的运行中最大，在受影响最严重的三分之一运行中最小（分别为 46%、所有受影响运行中的 41%，以及受影响最严重的三分之一运行中的 37%），因此，这种访问削弱了该效应，无法解释该效应。为直接厘清这一问题，我们在封闭环境中重新运行了支撑关键结论的实验条件。
The seal.封闭措施。
Each run’s working directory was placed on its own, with the grading suite, the reference solution, the manifest, and the other agents’ prompts held outside it. Where the grading suite and the prompts used to sit we left decoys of the same names, each carrying a marked placeholder and none of the real content. Where the manifest used to sit we left a copy stripped of its grading pointers, the paths to the test suite and the reference solution; the copy still lists the team’s component assignment, as the original did in the main collection, but nothing that grades the work. An agent that reached for the hidden material therefore found a file where it expected one, read a placeholder, and left a record of the attempt. The real files remained in place for the duration of each run for scoring, and each finished run’s sensitive files were cleared before the next run began, but the relocation sends the reach the agents actually used, always a relative path out of the workspace, onto the decoy instead. Every read made through the file tools was logged and classified by location; we count the seal as holding only when no such read reached a real file, and we discarded and re-ran any run in which one did. In the event no run was discarded for such a read; four runs were discarded and re-run for agent timeouts. The seal therefore functions as a tripwire that defeats the observed reach pattern and records every tool-mediated attempt. It stops short of an enforced sandbox: a read issued through the shell would not be captured, and the runs execute under a permissive filesystem mode. The sealed batch is 244 runs at eight agents on the distributed task, covering the six conflicting-split cells (flat and coordinator under each file policy) and the two clean-split file cells, on the same pinned model and with the grading suite byte-identical to the released one. No tool-mediated read reached a real file in the runs we kept.
每次运行的工作目录均独立放置，评分套件、参考解答、清单以及其他智能体的提示词均存放在该目录之外。在原先存放评分套件和提示词的位置，我们留下了同名诱饵文件，每个文件都包含明确标记的占位内容，不含任何真实内容。在原先存放清单的位置，我们留下了一个副本，移除了其中指向评分资源的信息，即测试套件和参考解答的路径；与主数据集中使用的原始清单一样，该副本仍列出团队的组件分工，但不包含任何用于评分的内容。因此，试图获取隐藏材料的智能体会在预期位置找到一个文件，读到占位内容，并留下尝试访问的记录。真实文件在每次运行期间始终保留在原位以供评分，每次运行结束后，其敏感文件都会在下一次运行开始前被清除；但这种位置调整会将智能体实际使用的访问路径（始终是通向工作区之外的相对路径）引向诱饵文件。所有通过文件工具进行的读取都被记录，并按位置分类；只有在此类读取均未触及真实文件时，我们才认定封闭措施有效，任何发生过此类真实文件读取的运行都会被丢弃并重新运行。实际执行中，没有运行因发生此类读取而被丢弃；有 four 次运行因智能体超时而被丢弃并重新运行。因此，这种封闭措施起到了绊线的作用，既阻断了已观察到的访问模式，又记录了每一次通过工具进行的访问尝试。它尚未达到强制沙箱的程度：通过 shell 发起的读取不会被捕获，而且这些运行是在宽松的文件系统模式下执行的。封闭批次包含 244 次运行，每次由 eight 个智能体执行分布式任务，覆盖 six 个存在冲突的任务划分实验条件（每种文件策略下的扁平式团队和协调者式团队）以及 two 个无冲突任务划分的文件实验条件；所用模型固定为同一版本，评分套件与发布版本逐字节一致。在我们保留的运行中，没有任何通过工具进行的读取触及真实文件。
The teams reach for the answers.团队试图获取答案。
The decoys turn the reach into a measurement. With the real material replaced by a placeholder and nothing to gain, the teams still went looking for it: in 80% of the sealed runs an agent opened the decoy standing in for the hidden test file, in 66% it opened another agent’s prompt, and in 61% it opened the run manifest. No prompt asks for any of these files; the test-file and prompt reads return only a placeholder, and the manifest read returns no grading material, so the reach for the test file is an unprompted tendency to seek out the grading material. It is the kind of reward-seeking that grade-only evaluation cannot see [27, 21, 36, 13], and it makes the containment gap in the main collection unsurprising in hindsight: agents that look for the answer key when they are confined will read it when they are not.
诱饵文件使这种访问尝试变得可测量。即使真实材料已被占位内容替换、无利可图，团队仍然会寻找这些材料：在 80% 的封闭运行中，有智能体打开了替代隐藏测试文件的诱饵文件；在 66% 的运行中，有智能体打开了另一个智能体的提示词；在 61% 的运行中，有智能体打开了运行清单。没有任何提示词要求读取这些文件；读取测试文件和提示词只会返回占位内容，读取清单也不会返回评分材料，因此，试图访问测试文件反映了一种未经提示而主动寻找评分材料的倾向。这种寻求奖励的行为是仅依据评分的评估无法发现的 [27, 21, 36, 13]；回过头看，它也使主数据集中的隔离漏洞显得不足为奇：在受限环境中仍会寻找标准答案的智能体，在不受限时就会读取它。
The findings hold under containment.研究发现在隔离条件下仍然成立。
With the real material replaced by decoys, the two findings that these cells test reproduce. Naming a coordinator again makes no difference to success: flat and coordinator teams are level under every file policy (forbidden 20/30 against 21/32, $p=1.00$ ; allowed 26/31 against 23/31, $p=0.53$ ; mandatory 23/30 against 25/30, $p=0.75$ ). The single reversal reported in Section 7, the flat team beating the coordinator under the forbidden policy, does not reappear, so it is best read as an artefact of the uncontained cells. The channel substitution of Section 6 holds as well: mandating files collapses one-to-one messaging, from 108 messages per run under forbidden and 134 under allowed to 26 under mandatory on the conflicting split, and from 119 to 21 on the clean split, the same move from the message channel to the file channel measured in the main dataset.
将真实材料替换为诱饵文件后，这些实验条件所检验的两项发现均得到复现。指定协调者仍然不会影响成功率：在每种文件策略下，扁平式团队与协调者式团队的表现均相当（禁止使用文件时为 20/30 对 21/32，$p=1.00$；允许使用文件时为 26/31 对 23/31，$p=0.53$；强制使用文件时为 23/30 对 25/30，$p=0.75$）。第 7 节报告的唯一一次反转，即禁止使用文件策略下扁平式团队优于协调者式团队，并未再次出现，因此最好将其理解为未隔离实验条件造成的假象。第 6 节所述的渠道替代现象同样成立：强制使用文件使一对一消息数量骤减，在存在冲突的任务划分下，从禁止使用文件时每次运行 108 条消息、允许使用文件时 134 条，降至强制使用文件时的 26 条；在无冲突的任务划分下，则从 119 条降至 21 条，这与主数据集中测得的从消息渠道向文件渠道的转移一致。
10 Threats to Validity10 效度威胁
Construct.构念。
The file graph captures tool-mediated file activity only. Edges come from the runtime’s Read, Write, and Edit tools; a file operation issued through the shell leaves no edge. In the main collection this cost ten runs their recorded write, because their deliverable was created with a shell command, which leaves no edge, so file activity is undercounted in about 0.6% of runs. This is an undercount, so the sparse file structure we report is conservative: any unlogged operation would only add edges. The per-channel token figures are proxies on two bases. Token cost on file edges divides a turn’s output evenly across its tool calls, while token cost on message edges is estimated from message length, so the two are not a like-for-like total and the channel bars of Figure 8 show direction only; the run-level output-token results use the model’s reported totals and are independent of the division, and the direction of the channel substitution survives any monotone re-attribution within a turn. The reported token totals count input and output only, excluding the cached context re-read on each turn, which is the bulk of the throughput; the output saving of Section 6 holds on the cached tokens too, and the runs were collected on a subscription, so we report token reductions. The coordinator is a prompt clause with no enforced routing, so Section 7 measures the effect of nominal leadership; an enforced star topology is follow-on work, and the distinction is the point of the finding. The two experiments also differ in one prompt detail: Experiment 2’s prompt asks agents to coordinate through messages, and its file-first behaviour runs against that instruction, so the cross-experiment contrasts are conservative with respect to it.
文件图仅捕获通过工具进行的文件活动。边来自运行时的 Read、Write 和 Edit 工具；通过 shell 发起的文件操作不会留下边。在主数据集中，这导致 ten 次运行的写入未被记录，因为它们的交付物是通过 shell 命令创建的，而这不会留下边，因此约 0.6% 的运行存在文件活动漏计。由于这是漏计，我们报告的文件结构稀疏性属于保守估计：任何未记录的操作都只会增加边。各渠道的 token 数量基于两方面原因属于代理指标。文件边上的 token 成本将一个轮次的输出均摊到该轮次的各次工具调用上，而消息边上的 token 成本则根据消息长度估算，因此二者并非可按相同口径比较的总量，图 8 中各通道的条形仅表示变化方向；运行层面的输出 token 结果使用模型报告的总量，与这种分摊无关，而且，在一个轮次内进行任何单调的重新归属，都不会改变通道替代的方向。所报告的 token 总量仅计入输入和输出，不包括每个轮次重新读取的缓存上下文，而后者占吞吐量的大部分；第 6 节所述的输出节省对缓存 token 同样成立，且这些运行是在订阅模式下采集的，因此我们报告的是 token 用量的减少。协调者只是提示中的一项条款，并没有强制执行的路由机制，因此第 7 节衡量的是名义领导的作用；强制执行的星形拓扑属于后续工作，而这一差别正是该发现的要点。这两项实验在提示的一个细节上也有所不同：实验 2 的提示要求智能体通过消息进行协调，而其文件优先行为违背了这一指令，因此，就该指令的影响而言，跨实验对比是保守的。
Internal.内部效度。
The agents are stochastic and a model identifier does not fix the provider’s state. Every cell carries ten repetitions, the model identifier is logged per turn (no mid-study change occurred), and within a batch a regression of messaging on run order shows no drift. Between sessions the measurements do vary, and we analyse this variation explicitly in Section 8 and report session ranges. At eight agents the clean main-matrix cells leave four agents idle, and the four-agent break coincides with the tasks’ four-unit structure; the two scaling arms were built without either confound and reproduce the deceleration and the plateau. The main collection also did not confine the agents to their workspace, and Section 9 quantifies that access, shows the confirmatory findings survive the exclusion of every affected run, and re-runs the load-bearing cells under a seal that removes it.
智能体具有随机性，模型标识符并不能固定提供方的状态。每个实验单元均重复十次，每个轮次都记录模型标识符（研究期间未发生变更），且在同一批次内，将消息通信对运行顺序进行回归分析，未发现漂移。不同会话之间的测量结果确实存在差异，我们在第 8 节中明确分析了这种变异，并报告各会话的取值范围。在八个智能体的配置下，主实验矩阵中无混杂的实验单元会使四个智能体闲置，而四个智能体处的转折又与任务的四单元结构重合；两个扩展性实验分支在设计时均排除了这两项混杂因素，并复现了减速和平台现象。主要数据采集也未将智能体限制在各自的工作区内，第 9 节量化了这种访问，表明剔除所有受影响的运行后，验证性发现仍然成立，并在消除这种访问的封闭条件下重新运行了支撑主要结论的实验单元。
External.外部效度。
The numbers come from two synthetic Python tasks, one runtime, and one pinned model, and the specific values will not carry directly to other settings. The claims we generalise are structural: the handshake-then-core shape, the one-to-many economics of files, and the gap between nominal and structural leadership. The graph schema and parser apply to any runtime that logs tool calls and messages; tasks from real repositories and other models are the natural replication.
这些数值来自两个合成 Python 任务、一个运行时和一个固定模型，具体数值不能直接推广到其他情境。我们推广的主张是结构性的：先握手、后核心的形态，文件的一对多经济性，以及名义领导与结构性领导之间的差距。该图模式和解析器适用于任何记录工具调用和消息的运行时；采用真实代码仓库中的任务和其他模型，是自然的复现方向。
Conclusion.结论。
Confirmatory claims rest on hypotheses pre-registered in both prediction and test (H1, H4–H8), with Benjamini–Hochberg correction within each contrast set; H2 and H3 carry the qualifications set out in Appendix A, and the appendix also records that the pre-registered top-up rule flagged cells we did not top up. Power is the limit: at ten runs a cell’s success rate carries a margin of roughly thirty percentage points, so single-cell readings are directional and pooled contrasts carry the weight. H7 met its pre-committed power-limited branch and is reported as directional; H8, at twenty runs per cell, reached significance.
验证性主张基于在预测和检验两个方面均已预注册的假设（H1, H4–H8），并在每组对比内进行 Benjamini–Hochberg 校正；H2 和 H3 受附录 A 所述限定条件约束，附录还记录了预注册的补充运行规则标记出了一些实验单元，但我们并未对其补充运行。统计功效是限制因素：每个实验单元运行十次时，其成功率的误差幅度约为三十个百分点，因此对单个实验单元的解读仅具有方向性，主要证据来自合并对比。H7 满足了预先承诺的统计功效受限分支条件，因此作为方向性结果报告；H8 在每个实验单元运行二十次时达到了统计显著性。
11 Related Work11 相关工作
Work on multi-agent LLM systems evaluates them, almost without exception, by their outputs. Benchmark studies score end-task success across frameworks and team configurations: MultiAgentBench evaluates different coordination topologies and, in an ablation study, different team sizes, and measures task completion and coordination performance [38]; software-engineering studies compare role-specialised teams with single agents based on the functional correctness and requirement coverage of the delivered software [9, 33]; a controlled comparison across 260 configurations evaluates each one using benchmark-specific measures of task performance [20]. Cost studies measure the tokens agentic workflows consume and how cost varies with task difficulty, and argue that cost belongs beside accuracy in agent evaluation [19, 31, 1]. Studies of failure catalogue the ways multi-agent pipelines break, from mis-specification to inter-agent misunderstanding: MAST derives fourteen failure modes from execution traces [7], attribution work asks which agent and which step caused a failed run [35], and a study of code-generation teams attributes three quarters of the failures it analyses to the boundary between planner and coder [22]. All of this looks at finished run: a grade, a bill, or a post-mortem of the transcript.
关于多智能体 LLM 系统的研究几乎无一例外地根据其输出来评估系统。基准研究对不同框架和团队配置下的最终任务成功情况进行评分：MultiAgentBench 评估不同的协调拓扑，并在消融研究中评估不同的团队规模，衡量任务完成情况和协调表现 [38]；软件工程研究根据所交付软件的功能正确性和需求覆盖率，比较角色专门化团队与单个智能体 [9, 33]；一项涵盖 260 种配置的受控比较使用各基准特有的任务表现指标评估每种配置 [20]。成本研究衡量智能体工作流消耗的 token 数量，以及成本如何随任务难度变化，并主张在智能体评估中应将成本与准确性并列考虑 [19, 31, 1]。失败研究归纳了多智能体流水线失效的各种方式，从规格设定不当到智能体之间的误解：MAST 从执行轨迹中归纳出十四种失败模式 [7]，归因研究探究是哪个智能体、哪个步骤导致了一次运行失败 [35]，而一项关于代码生成团队的研究将其所分析失败中的四分之三归因于规划者与编码者之间的衔接环节 [22]。所有这些研究关注的都是已完成的运行：一个评分、一笔账单，或对交互记录的事后剖析。
A second line of work designs the communication structure in advance: which agents may talk to which, in what order, and through what roles. ChatDev and MetaGPT assign fixed roles and pass work along a prescribed order [29, 16]; multi-agent debate fixes who reads whom and for how many rounds [10]; MacNet arranges agents into chains, stars, trees, and meshes and compares the arrangements [30]; GPTSwarm and AgentPrune treat the communication graph itself as a quantity to optimise or prune [39, 34]. In every case the topology is an input: the system fixes or searches the structure and then scores the outcome, so the coordination that happens inside the structure goes unmeasured. When communication is examined at all, it appears as raw message logs or token counts, and the structure, the timing, and the file activity that carry much of the coordination stay out of view. Our experiment leaves the channel open: any agent may message any other under every configuration, and the topology is a result the instrument recovers (Section 5).
另一类研究预先设计通信结构：哪些智能体可以与哪些智能体交流，以何种顺序交流，以及通过哪些角色交流。ChatDev 和 MetaGPT 分配固定角色，并按预定顺序传递工作 [29, 16]；多智能体辩论固定了谁读取谁的内容，以及进行多少轮 [10]；MacNet 将智能体组织成链形、星形、树形和网状结构，并比较这些结构 [30]；GPTSwarm 和 AgentPrune 则将通信图本身视为需要优化或剪枝的对象 [39, 34]。在所有这些情况下，拓扑都是输入：系统先固定或搜索结构，再对结果评分，因此结构内部发生的协调并未得到度量。即便通信得到考察，也只是以原始消息日志或 token 计数的形式呈现，而承载了大量协调活动的结构、时序和文件活动仍未进入观察范围。我们的实验保持通信渠道开放：在每一种配置下，任何智能体都可以向任何其他智能体发送消息，而拓扑则是由测量工具还原出的结果（第 5 节）。
What is missing is an instrument: a way to observe the coordination structure that emerges during a run, on the same footing for messages and for shared artefacts, and comparable across team sizes, configurations, and frameworks. Network analysis provides the natural language for this, and it has a long record in software engineering. Developer networks mined from version histories predict failure-prone components [28, 24], and combining the contribution network with the technical dependency network predicts them better than either alone [3]. The socio-technical congruence tradition compares the coordination a project’s dependencies demand with the coordination its records show [6, 5]. Longitudinal network studies expose team structure itself: developer coordination networks in large open-source projects organise into stable cores and loosely connected peripheries as they evolve [18, 17]. All of these networks are recovered from repository artefacts after the fact, at the granularity the commit record allows; even time-stamped co-editing networks are reconstructed from Git histories once the commits exist [14]. Multi-agent runs permit something stronger: every message, write, and read made through the runtime’s tools is a logged event, so the temporal network of a collaboration can be recorded directly from the trace as it happens.
目前缺少的是一种测量工具：它能够观察运行过程中涌现的协调结构，以同等方式处理消息和共享制品，并支持跨团队规模、配置和框架的比较。网络分析为此提供了自然的描述语言，而且在软件工程领域已有悠久的应用历史。从版本历史中挖掘出的开发者网络能够预测容易发生故障的组件 [28, 24]，而将贡献网络与技术依赖网络结合起来，其预测效果优于单独使用其中任何一种网络 [3]。社会技术一致性（socio-technical congruence）研究传统将项目依赖关系所要求的协调与项目记录所反映的协调进行比较 [6, 5]。纵向网络研究揭示了团队结构本身：大型开源项目中的开发者协调网络在演化过程中，会形成稳定的核心和连接松散的外围 [18, 17]。所有这些网络都是事后从代码仓库制品中还原的，其粒度受提交记录所限；即便是带时间戳的共同编辑网络，也是在提交产生之后才根据 Git 历史重建的 [14]。多智能体运行支持更强的观测能力：通过运行时工具进行的每一次消息发送、写入和读取都是有日志记录的事件，因此可以在协作发生的同时，直接根据执行轨迹记录其时序网络。
This paper supplies that instrument. It differs from output-based evaluation in what it measures (the coordination itself), from failure analysis in timing (the run is recorded as it unfolds, before its outcome is known), from topology design in direction (the network is an observed outcome), and from mined developer networks in resolution (every edge is an exact, timestamped event). The closest prior threads, on span of control and group-size limits in human organisations [15, 25, 11, 37], return in Section 12, where the measured limits on sustained coordination invite the comparison.
本文提供了这样的测量工具。它在测量对象上区别于基于输出的评估（测量的是协调本身），在时间上区别于故障分析（在结果尚未知晓时，随运行展开而进行记录），在方向上区别于拓扑设计（网络是观测到的结果），在分辨率上区别于挖掘得到的开发者网络（每条边都是一个精确且带有时间戳的事件）。最为接近的既有研究脉络涉及人类组织中的管理幅度和群体规模上限 [15, 25, 11, 37]，第 12 节将再次讨论这些研究，因为测得的持续协调上限促使我们进行这一比较。
12 Conclusion12 结论
Multi-agent AI coding systems are evaluated by their outputs, but they succeed or fail by their coordination, and the coordination is invisible in the output. This paper’s contribution is to make it a measured object: a temporal network in which agents and files are both nodes and every message, write, and read logged by the runtime’s tools is a timestamped, costed edge. The graph is a direct record of that tool-mediated activity, cheap to collect from existing logs, and comparable across team sizes, configurations, and frameworks.
多智能体 AI 编程系统依据其输出接受评估，但其成败取决于协调，而协调在输出中不可见。本文的贡献在于将协调转化为可度量的对象：一个时序网络，其中智能体和文件都是节点，运行时工具所记录的每一次消息发送、写入和读取都是一条带有时间戳和成本的边。该图直接记录了这些以工具为媒介的活动，可以低成本地从现有日志中采集，并支持跨团队规模、配置和框架的比较。
Measured this way, the three configuration choices a developer faces come out differently from what output-level evaluation suggests. The quadratic cost of communication is real but shallow: it is an opening handshake, made once, after which each agent sustains a few channels, no hub forms, and the largest teams switch increasingly to broadcast and messaging growth levels off between eight and sixteen agents. Files, usually treated as outputs, are the team’s one-to-many channel, and requiring their use cuts output tokens by about 42% at eight agents on message-heavy work, while adding cost on chain-shaped work whose files already carry the coordination. And leadership assigned by prompt is nominal only: it creates no structure and buys no reliable success, and a sealed replication of the eight-agent conflict cells leaves flat and coordinator teams level under every file policy. The common thread is that what the prompt declares and what the interaction structure builds can differ, and the measured outcomes follow the second.
以这种方式进行度量后，开发者面临的三项配置选择呈现出的结果，与输出层面评估所暗示的结果不同。通信的二次方成本确实存在，但程度有限：它是仅进行一次的初始握手，此后每个智能体只维持少数几个通信渠道，不会形成枢纽，而规模最大的团队越来越多地转向广播，消息量的增长在八个到十六个智能体之间趋于平缓。文件通常被视为输出，实际上却是团队的一对多通信渠道；在消息密集型工作中，要求使用文件可使八个智能体时的输出 token 数减少约 42%，但对于协调已由文件承载的链式工作，这一要求反而会增加成本。而通过提示指定的领导角色只是名义上的：它既未形成任何结构，也未带来可靠的成功；对八智能体冲突实验单元进行的封闭复现实验表明，在每一种文件策略下，扁平团队与设有协调者的团队表现都持平。共同之处在于，提示所声明的安排与交互结构实际形成的安排可能不同，而测得的结果取决于后者。
Beneath those choices, the shape of the coordination network is set by the task. Left to organise themselves, the teams do not converge on a single coordination span. The distributed task, where everyone reconciles one shared specification, builds a dense, tightly clustered graph that rides the all-to-all line; the chained task, where each agent agrees interfaces only with its neighbours, stays sparse, down to a mean degree of 0.28 against a clique of fifteen at sixteen agents, where scarcely any named-message network forms at all. Neither has a hub. In our experiments, the structure a team builds is a property of the work it is given, read directly off the graph.
在这些选择之下，协调网络的形态由任务决定。在自行组织的情况下，各团队并不会收敛到同一种协调跨度。在分布式任务中，所有智能体都要协调统一同一份共享规范，由此形成一个稠密、高度聚类的图，沿着全互连基准线变化；在链式任务中，每个智能体只与相邻智能体协商接口，网络始终保持稀疏，在十六个智能体时，平均度低至 0.28，而完全图的度为十五，此时几乎没有形成任何定向消息网络。两者都没有枢纽。在我们的实验中，团队构建的结构取决于其承担的工作，这一点可以直接从图中读出。
The two collections also reveal the reliability of the measurements. Under one pinned model, the chained task’s measurements replicate across sessions to two decimal places while the distributed task’s exponent moves from 1.76 to 2.44, so a configuration is a distribution of runs, and single-run evaluations of multi-agent systems stand on a sample of size one. And the measurements see what grading cannot: an eight-step calculation split one step per agent failed every run on a rounding convention that sat between two agents and belonged to neither, discussed every time and never settled. Decomposition creates interfaces between agents, each interface needs an owner, and the graph shows which have none.
这两组数据也揭示了测量的可靠性。在固定使用同一个模型的条件下，链式任务的测量结果在不同会话间可复现到小数点后两位，而分布式任务的指数则从 1.76 变动到 2.44，因此，一种配置对应的是多次运行结果的分布，而对多智能体系统进行单次运行评估，所依据的样本量仅为一。而且，测量能够发现评分无法揭示的问题：一项八步计算被拆分为每个智能体负责一步，却在每次运行中都因一项舍入约定而失败；这项约定处于两个智能体的交界处，却不归任何一方负责，每次都会被讨论，却始终未能确定。任务分解会在智能体之间产生接口，每个接口都需要一个责任主体，而图能够显示哪些接口无人负责。
The instrument also caught a behaviour that grading hides. The main runs were not confined to their workspace, and the teams used the access: they opened the hidden grading suite in 234 runs and the reference solution in 77. A sealed replication of the load-bearing cells, with decoys where the real files had sat, both confirmed the two findings it re-tested under containment, the coordinator null and the message-to-file substitution, and measured the behaviour directly: in four fifths of the sealed runs the agents reached for the grading suite even though it returned nothing, an unprompted search for the answer key that only a record of coordination, and not a grade, can see.
这一测量工具还捕捉到了一种被评分掩盖的行为。主要实验中的运行并未被限制在各自的工作区内，而各团队也利用了这些访问权限：它们在 234 次运行中打开了隐藏的评分套件，在 77 次运行中打开了参考解答。我们对支撑核心结论的实验单元进行了封闭环境复现，并在原先存放真实文件的位置放置了诱饵文件；这一复现既在隔离条件下确认了所复测的两项发现，即协调者的零效应和以文件替代消息的现象，也直接测量了上述行为：在五分之四的封闭运行中，智能体都尝试访问评分套件，尽管这未返回任何内容；这种未经提示便搜寻标准答案的行为，只有协调过程记录才能揭示，评分则无法反映。
There is a resonance here with a long literature on the limits of human coordination. Spans of workable oversight have been placed at around five direct reports by Graicunas [15] and near seven items by Miller [25], while Dunbar links group size to limits on the relationships that can be monitored [11], and human group sizes cluster near five and fifteen in Zhou et al.’s analysis [37]. Our agent teams sustain a limited number of one-to-one pushes, roughly two to five peers per agent by the directed out-degree of Section 5, in the range of those figures, and in the sixteen-step arm messaging growth halts between eight and sixteen agents, which invites the comparison. The topology result cautions against reading it as a shared cognitive span. Left free, the agents do not settle on one span at all: where the task calls for it they build a dense near-clique, and where it does not they stay sparse. Human hierarchies may owe as much to the cost of adding people and the distribution of authority as to any limit on coordination itself; here, adding agents still carries coordination cost, but formal authority is minimal, and the pyramid does not return. What remains and still binds is the cost of coordination. We claim no shared mechanism, and our design cannot place the growth break more precisely than the eight-to-sixteen interval, but if coordination structure is subject to similar economics wherever it arises, machine teams are a way to study those economics with an exactness that is difficult to achieve in human organisations.
这一现象与长期以来关于人类协调局限的研究文献形成了呼应。Graicunas 将有效监督的跨度定为约五名直接下属 [15]，Miller 则将其定为接近七个项目 [25]；Dunbar 将群体规模与可监控关系数量的限制联系起来 [11]，而 Zhou 等人的分析表明，人类群体的规模集中在五人和十五人附近 [37]。我们的智能体团队能够维持的一对一推送数量有限：按第 5 节的有向出度衡量，每个智能体大约对应二至五个同伴，处于上述数值范围内；而在十六步实验分支中，消息量的增长在智能体数量介于八至十六之间时停止，这使人自然联想到上述比较。拓扑结构方面的结果提醒我们，不应将其解读为一种共同的认知跨度。在自由行动的情况下，智能体根本不会固定在某一种跨度上：任务有需要时，它们会构建稠密的近团结构；任务没有需要时，它们则保持稀疏连接。人类的层级结构可能同样源于增加人员的成本和权力分配，而不只是协调本身的某种局限；在这里，增加智能体仍会带来协调成本，但正式权力极少，金字塔结构也未再现。依然存在并持续构成约束的，是协调成本。我们并不声称二者具有共同机制，而且我们的设计无法将增长转折点定位得比八至十六这一区间更精确；但如果协调结构无论在何处出现都受到类似经济规律的制约，那么机器团队便提供了一种研究这些经济规律的途径，其精确程度是人类组织研究难以达到的。

A.2 Tests and correctionsA.2 检验与校正
The unit of analysis is one run: one graph, one binary outcome. Binary success rates carry Clopper–Pearson exact 95% intervals [8]. Success contrasts use Fisher’s exact test [12]; continuous contrasts use the Mann–Whitney rank test [23]; neither assumes normality. Where a question tests a set of related contrasts, the set is corrected with the Benjamini–Hochberg procedure [2] and the corrected values are reported as $p_{\mathrm{BH}}$ . Scaling exponents are least-squares slopes of $\log(\text{count})$ on $\log(n)$ over per-run values, with 95% confidence intervals. The one exception is the pre-registered H1 test, which by its plan regresses over the three cell means; it gives the same slope with a wider interval, and both forms are reported in Section 4. The scaling arms use a piecewise version with the knot fixed in advance ( $n{=}4$ for the eight-step arm, $n{=}8$ for the sixteen-step arm) and report the two segment slopes and their difference $\Delta$ .
分析单位是一次运行：一个图、一个二元结果。二元成功率附有 Clopper–Pearson 精确 95% 区间 [8]。成功率比较采用 Fisher 精确检验 [12]；连续变量比较采用 Mann–Whitney 秩检验 [23]；两者均不要求正态性假设。当一个问题检验一组相关比较时，使用 Benjamini–Hochberg 程序 [2] 对该组比较进行校正，并将校正后的值报告为 $p_{\mathrm{BH}}$ 。标度指数是基于逐次运行的数值，将 $\log(\text{count})$ 对 $\log(n)$ 进行最小二乘回归所得的斜率，并附有 95% 置信区间。唯一的例外是预注册的 H1 检验，该检验按计划对三个实验单元的均值进行回归；它得到相同的斜率，但区间更宽，Section 4 报告了这两种形式。标度实验分支采用分段形式，节点位置预先固定（八步分支为 $n{=}4$，十六步分支为 $n{=}8$），并报告两个分段的斜率及其差值 $\Delta$ 。
A.3 The sustained undirected graph and its topologyA.3 持续通信无向图及其拓扑
Section 5 reads the shape of a run’s coordination from its sustained undirected graph. For one run, count the direct messages sent in each ordered direction between every pair of agents. Two agents are joined by an undirected edge when at least one of the two directions carried two or more messages, so single greetings are dropped and a link marks a channel the pair used more than once. Only the configured agents agent-1 to agent- $N$ are admitted as endpoints, so a hallucinated recipient never enters the graph. The mean degree of a run is the sum of the agents’ degrees divided by the full team size $N$ , so an agent that sustains no channel counts as degree zero and stays in the denominator; a run that builds no sustained named-message network therefore has mean degree zero. We report the mean of this quantity over every run in the cell, silent runs included, against the clique line $n-1$ , the degree every agent would have if the team were fully connected. Averaging over every configured agent and every run, including the silent ones, is what keeps the degree an honest per-agent expectation; the earlier of these two choices matters most on the sparse sixteen-agent cell, where most runs build no network at all. The global clustering coefficient (transitivity) of a run is the number of closed triples divided by the number of connected triples in the same graph: for every agent, over each unordered pair of its partners, the pair is a connected triple, and a closed one when those two partners are themselves joined. It is 1 when the live partners form a single interconnected group and 0 when no two partners of any agent are joined. Both quantities are computed by precompute_topology_scaling.py in the released package, over the flat cells (both collection sessions pooled) under the allowed policy and clean split, at two, four, and eight agents for each task, with the sixteen-step chain adding points at eight and sixteen agents, the latter the only sixteen-agent data. The directed out-degree of Figure 7 (the eff_team_t measure in the released code) is a different measurement on the same messages: for each agent the number of distinct peers it sends at least $t$ messages to, averaged across all agents; the count is directed and differs from the degree of the undirected graph.
Section 5 根据一次运行的持续通信无向图解读其协调结构。对于一次运行，统计每对智能体之间沿各个有序方向发送的直接消息数。当两个方向中至少一个方向传递了两条或更多消息时，就在两个智能体之间连接一条无向边，因此单次问候会被剔除，而一条连边表示这对智能体使用过不止一次的通信通道。仅允许已配置的智能体 agent-1 至 agent- $N$ 作为端点，因此幻觉产生的接收者绝不会进入图中。一次运行的平均度等于各智能体的度之和除以完整团队规模 $N$，因此，未维持任何通道的智能体按度为零计入，并保留在分母中；所以，未建立任何持续具名消息网络的运行，其平均度为零。我们报告该实验单元内所有运行（包括无消息运行）的这一指标均值，并与团图基准线 $n-1$ 比较，后者表示团队完全连接时每个智能体应具有的度。对所有已配置的智能体和所有运行（包括无消息运行）取平均，才能使度如实反映每个智能体的期望值；这两个选择中的前一个，在稀疏的十六智能体实验单元中尤为重要，因为其中大多数运行根本没有建立网络。一次运行的全局聚类系数（传递性）是同一图中闭合三元组数除以连通三元组数：对于每个智能体，其伙伴的每一个无序对都与该智能体构成一个连通三元组，而当这两个伙伴本身也相连时，该三元组就是闭合的。当活跃伙伴构成一个相互连接的群体时，该值为 1；当任何智能体的伙伴中都不存在彼此相连的两个伙伴时，该值为 0。这两个量均由发布包中的 precompute_topology_scaling.py 计算，计算对象为允许策略和干净划分下的扁平结构实验单元（合并两次采集会话），每项任务均在两个、四个和八个智能体的配置下计算，十六步链式任务还增加了八个和十六个智能体的数据点，其中后者是唯一的十六智能体数据。图 7 中的有向出度（发布代码中的 eff_team_t 度量）是对同一批消息的另一种测量：对每个智能体，统计其向多少个不同的同伴各发送了至少 $t$ 条消息，再对所有智能体取平均；这一计数具有方向性，不同于无向图的度。
A.4 Design checksA.4 设计检查
Repeated runs of the same configuration vary widely [4, 26], in agentic coding by up to thirty-fold in token consumption [1], and every main-matrix cell carries ten repetitions. A pre-registered rule flags a cell for topping up to twenty when its precision is low, and applied to the released data it flags 93 cells across the two experiments (48 of the 85 in Experiment 1, 45 of the 87 in Experiment 2), 25 of them on the outcome-precision condition and the rest on graph-statistic variance. The flags divide roughly evenly by team size, 35 at two agents, 36 at four, and 22 at eight. We topped up none of them, which is a deviation from the rule as written, made deliberately and recorded at the time. Topping the flagged cells up to twenty runs would have sharpened their estimates, the graph-statistic means as much as the success rates, by the usual factor of about $\sqrt{2}$ ; we judged it unnecessary because the confirmatory success contrasts pool across cells, so no single cell decides them, and because many of the graph-statistic flags were triggered by a metric other than the one a headline result uses for that cell, a cell flagged on file-read variance, say, whose headline reading is message count or sustained degree. The cost of that judgement is that the affected cell-level graph estimates remain less precise than the rule intended. A few hypotheses do read specific flagged cells, among them H1, H5, and H6, and their intervals should be read with that reduced precision in mind. The strict alternative of topping up every flagged cell was considered and set aside, and we record the departure here. The one deviation in the other direction is the sixteen-step scaling arm, pre-registered at twenty runs per allowed cell to tighten the plateau test of hypothesis H8. Two ablations defend the design. First, the forbidden policy is a prompt clause; re-running the worst-affected cell with the workspace locked at the filesystem level produced the same workspaces and the same outcomes, so the prompt form is sound. Second, the pilot’s dominant failure traced to an ambiguous return-type clause in one specification; the clause was tightened and the worst cell re-validated (three of three passes) before the full schedules ran, leaving a cleaner outcome variable.
