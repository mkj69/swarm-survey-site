Abstract摘要
Multi-agent systems (MAS), composed of networks of two or more autonomous AI agents, have become increasingly popular in production deployments, yet introduce security risks that do not arise in single-agent settings. Even if individual agents exhibit robust security, architectural decisions governing their coordination can create attack surfaces that have not been systematically characterized. In this work, we present an empirical study of how MAS design decisions shape the tradeoff between task performance and attack resistance. Across three agentic environments (browser, desktop, and code) and 13 architectural configurations, we use stagewise evaluations that distinguish planning refusal, execution-stage interception, partial harmful execution, and successful attack completion to study three key design choices: (i) agent roles, which determine how authority and responsibility are allocated; (ii) communication topology, which shapes how and when agents interact; and (iii) memory, which determines the context and state visibility accessible to each agent. We find that multi-agent architectures are more vulnerable than standalone agents in the majority of configurations, with attack success rates varying by up to 3.8× at comparable or higher benign accuracy, and that no single design is universally safer. These results motivate the development of further evaluations that move beyond the security properties of a single agent.
多智能体系统（multi-agent systems，MAS）由两个或更多自主 AI 智能体组成的网络构成，在生产部署中日益普及，但也引入了单智能体场景中不存在的安全风险。即使各个智能体都表现出稳健的安全性，支配其协调方式的架构决策仍可能形成尚未得到系统性刻画的攻击面。在本研究中，我们通过实证研究考察 MAS 设计决策如何影响任务性能与抵抗攻击能力之间的权衡。我们在三种智能体环境（浏览器、桌面和代码）和 13 种架构配置中，采用分阶段评估，区分规划阶段的拒绝、执行阶段的拦截、部分有害执行以及攻击成功完成，以研究三项关键设计选择：(i) 智能体角色，决定权限和责任的分配方式；(ii) 通信拓扑，决定智能体如何以及何时交互；(iii) 记忆，决定每个智能体能够访问的上下文以及能够查看的状态。我们发现，在大多数配置下，多智能体架构比独立智能体更易受到攻击；在良性任务准确率相当或更高的情况下，攻击成功率的差异可达 3.8×，且没有任何一种设计在所有情况下都更安全。这些结果表明，有必要进一步开发超越单个智能体安全属性的评估方法。

1 Introduction1 引言
As AI systems evolve from single large language models (LLMs) into increasingly complex agentic and multi-agent architectures, their security properties change in fundamental ways (Kumar et al., 2024; Schroeder de Witt, 2025). While early deployments relied on standalone models responding directly to user prompts, modern systems increasingly distribute tasks across agents that plan, execute actions, interact with tools, maintain memory, and coordinate with one another (Hong et al., 2024). Such systems are increasingly capable of achieving large-scale, long-horizon tasks with which individual models and agents struggle (Hadfield et al., 2025; Lin, 2026).
随着 AI 系统从单个大语言模型（large language models，LLMs）演变为日益复杂的智能体架构和多智能体架构，其安全属性发生了根本性变化 (Kumar et al., 2024; Schroeder de Witt, 2025)。早期部署依赖独立模型直接响应用户提示，而现代系统越来越多地将任务分配给多个智能体，由它们进行规划、执行操作、与工具交互、维护记忆并相互协调 (Hong et al., 2024)。这类系统越来越能够完成单个模型和智能体难以胜任的大规模、长时程任务 (Hadfield et al., 2025; Lin, 2026)。
Despite their rapidly increasing capabilities, progress in securing these systems against misuse has lagged behind. Research in AI security has revealed numerous threat vectors against these systems, with new attacks emerging at different levels of abstraction. At the agent level, research examines failures arising from tool use and memory poisoning (Zhang et al., 2025). Recent work has begun exploring multi-agent risks such as collusion (Motwani et al., 2025), infection-style attacks (Lee and Tiwari, 2024; Gu et al., 2024), and viral misalignment via subliminal prompting (Weckbecker et al., 2026). This growing body of work suggests that defenses effective at one layer may degrade or behave differently when embedded in richer systems. A language model that resists direct jailbreak attempts may nonetheless enable harmful behavior once coupled with web tools or persistent memory (Chiang et al., 2025). Similarly, an agent that appears robust in isolation may contribute to system-level failures when its outputs are routed, transformed, or reinforced through inter-agent coordination. In such settings, vulnerabilities can amplify through task decomposition, partial observability, and distributed control, producing emergent risks that are not captured by single-layer evaluations.
尽管这些系统的能力迅速提升，防范其被滥用的安全保障工作却进展滞后。AI 安全研究揭示了针对这些系统的众多威胁途径，新的攻击也在不同抽象层次上不断涌现。在智能体层面，研究关注工具使用和记忆投毒导致的失效 (Zhang et al., 2025)。近期研究已开始探索多智能体风险，例如合谋 (Motwani et al., 2025)、感染式攻击 (Lee and Tiwari, 2024; Gu et al., 2024)，以及通过潜意识提示引发的病毒式失对齐 (Weckbecker et al., 2026)。这些不断积累的研究表明，在某一层面有效的防御措施嵌入更复杂的系统后，其效果可能下降，或表现出不同的行为。一个能够抵御直接越狱尝试的语言模型，在与网络工具或持久记忆结合后，仍可能促成有害行为 (Chiang et al., 2025)。同样，一个单独运行时看似稳健的智能体，当其输出通过智能体间的协调被路由、转换或强化时，也可能促成系统层面的失效。在这类场景中，漏洞可能通过任务分解、部分可观测性和分布式控制而被放大，产生单层评估无法捕捉的涌现风险。
Mitigating these risks requires attending not only to explicit defenses but also to the broader architectural choices that shape system behavior. Yet any modification to system design must be evaluated against its impact on task performance - security methods that impose unacceptable costs fail to preserve the benefits of the underlying system (Schroeder de Witt, 2025; Peigné et al., 2025). While prior work has examined such tradeoffs, the impact of indirect architectural decisions remains underexplored. To address this gap, we present an empirical analysis of how design choices affect security in agentic and multi-agent systems. We ground our study in realistic agent tasks, adapting the BrowserART (Kumar et al., 2024), OS-Harm (Kuntz et al., 2025), and RedCode-Gen (Guo et al., 2024) benchmarks, originally designed for single-agent evaluation, to support systematic multi-agent assessment. We systematically evaluate how susceptibility to misuse changes as tasks move from single-agent to multi-agent, focusing on three key dimensions: role specialization, communication topology, and memory visibility, examining how each reshapes both the attack surface and the overall performance of the system.
缓解这些风险不仅需要关注显式防御措施，还需要关注塑造系统行为的更广泛的架构选择。然而，对系统设计的任何修改，都必须评估其对任务性能的影响——如果安全方法带来的代价不可接受，就无法保留底层系统的益处 (Schroeder de Witt, 2025; Peigné et al., 2025)。尽管已有研究考察了此类权衡，但对安全产生间接影响的架构决策仍未得到充分探索。为填补这一空白，我们通过实证分析考察设计选择如何影响智能体系统和多智能体系统的安全性。我们的研究以现实的智能体任务为基础，对最初为单智能体评估设计的 BrowserART (Kumar et al., 2024)、OS-Harm (Kuntz et al., 2025) 和 RedCode-Gen (Guo et al., 2024) 基准进行改编，以支持系统性的多智能体评估。我们系统评估了任务从单智能体转向多智能体时，系统易被滥用的程度如何变化，重点关注角色专门化、通信拓扑和记忆可见性这三个关键维度，考察各维度如何重塑系统的攻击面与整体性能。

2 Background and Related Work2 背景与相关工作
A multi-agent system (MAS) consists of multiple autonomous AI agents that make decisions and take actions, maintain private state, and interact through communication channels or shared environments. Unlike single-model or single-agent setups, MAS behavior emerges from interactions among agents rather than from any individual component. These interactions introduce system-level dynamics, such as coordination, negotiation, and delegation - that fundamentally change both the attack surface and the nature of failure.
多智能体系统（MAS）由多个自主 AI 智能体组成，它们做出决策并采取行动，维护各自的私有状态，并通过通信信道或共享环境进行交互。与单模型或单智能体设置不同，MAS 的行为涌现于智能体之间的交互，而非源自任何单独的组件。这些交互引入了协调、协商和委派等系统层面的动态机制，从根本上改变了攻击面和失效的性质。
2.1 LLM and Single-Agent Vulnerabilities2.1 LLM 与单智能体的脆弱性
Security research on large language models and LLM based agents has primarily focused on vulnerabilities at the model or single-agent level. At the LLM level, prior work has documented risks such as prompt injection and jailbreak attacks (Liu et al., 2024; Andriushchenko et al., 2024), data poisoning and backdoors (Fendley et al., 2025; Yao et al., 2024), and privacy threats including leakage and membership inference attacks (Aguilera-Martínez and Berzal, 2025; Das et al., 2025; Gan et al., 2024). These vulnerabilities vary across LLM architectures (Benjamin et al., 2024) and change in complex, unpredictable ways (Shang and Wei, 2025).
针对大语言模型及基于 LLM 的智能体的安全研究，主要聚焦于模型或单智能体层面的脆弱性。在 LLM 层面，已有研究记录了提示注入和越狱攻击 (Liu et al., 2024; Andriushchenko et al., 2024)、数据投毒和后门 (Fendley et al., 2025; Yao et al., 2024)，以及包括信息泄露和成员推断攻击在内的隐私威胁 (Aguilera-Martínez and Berzal, 2025; Das et al., 2025; Gan et al., 2024) 等风险。这些脆弱性因 LLM 架构而异 (Benjamin et al., 2024)，并以复杂且不可预测的方式变化 (Shang and Wei, 2025)。
At the single-agent level, vulnerabilities extend beyond the underlying model to include system prompts, tool use and memory poisoning. Zhang et al. (2025) formalize core agent-level attacks and evaluate them using Attack Success Rate, Refusal Rate, and Performance under No Attack. AgentDojo (Debenedetti et al., 2024) provides a dynamic environment specifically for evaluating indirect prompt injection attacks, demonstrating significant vulnerability when tool outputs are adversarially manipulated. AgentHarm (Andriushchenko et al., 2025) extends this to multi-turn agentic misuse scenarios with fine-grained metrics distinguishing planning-stage refusal from execution-stage failures.
在单智能体层面，脆弱性不仅涉及底层模型，还涵盖系统提示、工具使用和记忆投毒。Zhang et al. (2025) 对核心智能体层面攻击进行了形式化描述，并使用攻击成功率、拒绝率和无攻击条件下的性能对其进行评估。AgentDojo (Debenedetti et al., 2024) 提供了一个专门用于评估间接提示注入攻击的动态环境，表明当工具输出遭到对抗性操纵时，系统会表现出显著的脆弱性。AgentHarm (Andriushchenko et al., 2025) 将此扩展至多轮智能体滥用场景，并采用细粒度指标区分规划阶段的拒绝与执行阶段的失败。
2.2 Multi-Agent Security2.2 多智能体安全
Multi-agent settings introduce new risks that cannot be reduced to LLM- or single-agent vulnerabilities. Interactions among agents give rise to distinct failure modes: miscoordination, conflict, and collusion—driven by agents’ incentives and shaped by key risk factors: information asymmetries, network effects, selection pressures, destabilizing dynamics, commitment problems, emergent agency (Hammond et al., 2025). Prior work distinguishes between cooperative and competitive threat models (Schroeder de Witt, 2025; Peigné et al., 2025). In cooperative systems, collaboration itself can become a liability, enabling error amplification, misinformation propagation, and collusive behavior (Motwani et al., 2025). Specifically, covert collusion can emerge through steganographic communication channels, sometimes arising unintentionally from reward misspecification rather than deliberate coordination (Mathew et al., 2024). In competitive settings, agents may engage in deception, persuasion, or sabotage, destabilizing collective outcomes (Qi et al., 2025). Adversarial agents can systematically manipulate multi-agent debate outcomes and increase jailbreak success through iterative dialogue (Qi et al., 2025; Amayuelas et al., 2024). These dynamics enable infection-style attacks where single compromised agents spread harmful behavior across networks (Gu et al., 2024; Lee and Tiwari, 2024), and false information can persist and amplify through multi-agent interactions (Ju et al., 2024).
多智能体设置引入了无法归结为 LLM 或单智能体脆弱性的新风险。智能体之间的交互会产生独特的失效模式：协调失当、冲突和串谋；这些模式由智能体的激励驱动，并受到信息不对称、网络效应、选择压力、破坏稳定性的动态机制、承诺问题和涌现的能动性等关键风险因素的影响 (Hammond et al., 2025)。已有研究区分了合作型与竞争型威胁模型 (Schroeder de Witt, 2025; Peigné et al., 2025)。在合作系统中，协作本身可能成为隐患，促使错误放大、错误信息传播以及串谋行为发生 (Motwani et al., 2025)。具体而言，隐蔽串谋可能通过隐写通信信道涌现，有时它并非源于刻意协调，而是由奖励设定不当无意间引发的 (Mathew et al., 2024)。在竞争场景中，智能体可能实施欺骗、说服或蓄意破坏，从而使集体结果变得不稳定 (Qi et al., 2025)。对抗性智能体可以系统性地操纵多智能体辩论的结果，并通过迭代对话提高越狱成功率（Qi et al., 2025; Amayuelas et al., 2024）。这些动态机制使感染式攻击成为可能，即单个被攻陷的智能体将有害行为传播至整个网络（Gu et al., 2024; Lee and Tiwari, 2024），而虚假信息也可能通过多智能体交互持续存在并被放大（Ju et al., 2024）。
2.3 Evaluation and Defense Gaps2.3 评估与防御的不足
For multi-agent systems, Cemri et al. (2025) introduce MAST, a taxonomy of 14 failure modes derived from 1,600+ execution traces across MAS frameworks, while MultiAgentBench (Zhu et al., 2025a) evaluates collaboration dynamics with coordination metrics. However, existing benchmarks primarily evaluate either general task performance or specific attack types in isolation, without systematically varying architectural design choices or focusing on adversarial security.
针对多智能体系统，Cemri et al. (2025) 提出了 MAST，这是一套基于跨 MAS 框架的 1,600+ 条执行轨迹归纳出的、涵盖 14 种失效模式的分类体系；而 MultiAgentBench（Zhu et al., 2025a）则使用协调指标评估协作动态。然而，现有基准主要孤立地评估一般任务性能或特定攻击类型，既未系统性地改变架构设计选择，也未聚焦于对抗安全性。
Defenses against multi-agent vulnerabilities remain nascent. Recent work explores architectural approaches including plan–then–execute designs (Del Rosario et al., 2025) and capability-based architectures (Debenedetti et al., 2025), yet most defensive work still focuses on input/output filtering designed for single-agent settings, with limited investigation of how architectural choices jointly shape task performance and attack resistance.
针对多智能体漏洞的防御仍处于起步阶段。近期研究探索了架构层面的方法，包括先规划后执行的设计（Del Rosario et al., 2025）和基于能力的架构（Debenedetti et al., 2025），但大多数防御研究仍聚焦于为单智能体场景设计的输入/输出过滤，对架构选择如何共同影响任务性能与抗攻击能力的研究仍然有限。
Security in multi-agent systems has a long history, spanning trust and reputation management (Yu et al., 2013; Jung et al., 2012), Byzantine-resilient consensus (Lamport et al., 1982; LeBlanc et al., 2013), and secure coordination under bounded adversaries such as energy-limited DoS and F-local faults (De Persis and Tesi, 2015; Ishii et al., 2022). LLM-based multi-agent systems differ from much of this tradition in that they are driven by foundation models capable of flexible, generalizable reasoning and communicate through unstructured, free-form protocols rather than rigidly specified interaction languages or APIs (Schroeder de Witt, 2025). As a result, classical guarantees based on fixed message semantics, protocol compliance, or explicit coordination assumptions may not transfer directly, motivating dedicated empirical study of how architecture shapes security in these systems (Nguyen et al., 2026; OWASP GenAI Security Project, 2025).
多智能体系统的安全研究历史悠久，涵盖信任与声誉管理（Yu et al., 2013; Jung et al., 2012）、拜占庭容错共识（Lamport et al., 1982; LeBlanc et al., 2013），以及在能量受限的 DoS 和 F-local 故障等受限对手条件下的安全协调（De Persis and Tesi, 2015; Ishii et al., 2022）。基于 LLM 的多智能体系统与这一传统中的许多系统有所不同：它们由具备灵活、可泛化推理能力的基础模型驱动，并通过非结构化、自由形式的协议进行通信，而非通过严格规定的交互语言或 API（Schroeder de Witt, 2025）。因此，基于固定消息语义、协议遵循或显式协调假设的经典保证可能无法直接适用，这促使人们开展专门的实证研究，探究架构如何塑造这些系统的安全性（Nguyen et al., 2026; OWASP GenAI Security Project, 2025）。
Recent work has begun to characterize security-performance tradeoffs in multi-agent systems: Peigné et al. (2025) quantify a ”multi-agent security tax” between robustness and collaboration, while Zhu et al. (2025b) examine role and topology effects. We extend this by isolating how role distribution, communication topology, and memory visibility independently affect security across three realistic environments, using stage-wise metrics.
近期研究已开始刻画多智能体系统中安全性与性能之间的权衡：Peigné et al. (2025) 量化了鲁棒性与协作之间的“多智能体安全税”，而 Zhu et al. (2025b) 则考察了角色与拓扑的影响。我们在此基础上进一步研究，使用分阶段指标，在三个贴近现实的环境中分别考察角色分配、通信拓扑和记忆可见性对安全性的独立影响。
3 Design Choices in Multi-Agent Systems3 多智能体系统中的设计选择
Multi-agent systems can be constructed using various architectural choices that affect security in ways that may be difficult to predict from first principles. We focus on three design choices that recur across modern architectures: role configuration, communication topology, and memory. We hypothesize that these architectural decisions introduce distinct vulnerability modes compared to single-agent LLMs by fragmenting responsibility for safety assessment and creating new attack surfaces. Below, we identify key design mechanisms and articulate hypotheses about how each may affect the likelihood of harmful task execution.
多智能体系统可以采用多种架构选择来构建，而这些选择对安全性的影响可能难以从第一性原理出发进行预测。我们聚焦于现代架构中反复出现的三种设计选择：角色配置、通信拓扑和记忆。我们假设，与单智能体 LLM 相比，这些架构决策会通过分散安全评估责任和产生新的攻击面，引入不同的漏洞模式。下文中，我们识别关键设计机制，并阐述关于各机制可能如何影响有害任务执行概率的假设。
Design Choice 1: Role Configuration
设计选择 1：角色配置
Multi-agent systems are often designed with distinct agent roles, such as planners that decompose objectives, executors that carry out actions, reviewers that validate outputs, or specialized agents handling domain-specific subtasks. While such role separation can improve efficiency and task performance, and is sometimes necessary due to IP, regulatory, or security constraints, it can also fragment responsibility for safety assessment. Executor agents typically operate on narrowly scoped instructions without visibility into the full task context or downstream consequences; reviewer agents may evaluate outputs in isolation rather than assessing end-to-end behavior. Agents may also differ in their authority over system behavior. When agents with high execution authority are downstream from those responsible for safety reasoning (e.g., planners or critics), security judgments may become advisory rather than binding. Conversely, centralizing authority could introduce single points of failure. We vary role configuration in our experiments to investigate how these tradeoffs manifest in practice.
多智能体系统通常被设计为具有不同的智能体角色，例如分解目标的规划者、执行动作的执行者、验证输出的审查者，或处理特定领域子任务的专门智能体。尽管这种角色分离可以提高效率和任务性能，有时也因知识产权（IP）、监管或安全约束而成为必要，但它也可能分散安全评估责任。执行者智能体通常依据范围狭窄的指令开展工作，无法了解完整的任务上下文或下游后果；审查者智能体则可能孤立地评估输出，而非评估端到端行为。不同智能体对系统行为的控制权限也可能有所不同。当具有较高执行权限的智能体位于负责安全推理的智能体（例如规划者或批评者）的下游时，安全判断可能仅具有建议性质，而不具备约束力。反之，集中权限可能引入单点故障。我们在实验中改变角色配置，以研究这些权衡在实践中的表现。
Design Choice 2: Communication Topology
设计选择 2：通信拓扑
Multi-agent systems can vary in communication structure, including centralized orchestrators, hierarchical trees, chains, and fully connected meshes. Communication topology determines how intent, uncertainty, and safety signals propagate through the system. In decentralized or mesh-based systems, decisions are distributed across agents without centralized oversight, while in hierarchical or chain-based systems, information may be summarized or filtered as it passes between agents. Each topology introduces distinct security tradeoffs, and these effects may depend on interactions with role configuration and memory design.
多智能体系统可以采用不同的通信结构，包括集中式编排器、层次树、链和全连接网状结构。通信拓扑决定了意图、不确定性和安全信号如何在系统中传播。在去中心化或网状系统中，决策分散于各个智能体，无需集中监督；而在层级式或链式系统中，信息在智能体之间传递时可能会被概括或过滤。每种拓扑结构都会带来不同的安全权衡，而这些影响可能取决于其与角色配置和记忆设计之间的相互作用。
Design Choice 3: Memory and State Visibility
设计选择 3：记忆与状态可见性
Agents may maintain private scratchpads or write to shared memory, creating different tradeoffs for safety reasoning. Private state preserves independence but may prevent safety-relevant insights from propagating across agents, while shared state improves transparency but may enable unsafe assumptions to spread. Beyond simple private/shared distinctions, systems vary in what information agents can access about themselves and others. Some expose full chains of thought through context windows or queryable memory, others provide action histories spanning entire sessions, and blackboard architectures may give agents visibility into the complete state of all other agents. These choices create different attack surfaces, as exposed reasoning may reveal exploitable patterns while shared histories could enable adversarial coordination.
智能体可以维护私有草稿区，也可以向共享记忆写入信息，从而在安全推理方面形成不同的权衡。私有状态能够保持独立性，但可能阻碍与安全相关的见解在智能体之间传播；共享状态则提高了透明度，但也可能使不安全的假设扩散。除了简单的私有与共享之分，不同系统在智能体能够访问哪些关于自身及其他智能体的信息方面也存在差异。有些系统通过上下文窗口或可查询的记忆公开完整的思维链，另一些系统提供覆盖整个会话的行动历史，而黑板架构则可能使智能体能够查看所有其他智能体的完整状态。这些选择会形成不同的攻击面，因为公开的推理可能暴露可被利用的模式，而共享历史记录则可能使对抗性协作成为可能。
4 Multi-Agent System Experimental Setup4 多智能体系统实验设置
We consider a malicious user who provides adversarial task instructions at input time. The attacker does not modify model weights or system code, and interacts with the system only through natural language prompts and standard tool outputs.
我们考虑一种恶意用户，其在输入时提供对抗性任务指令。攻击者不会修改模型权重或系统代码，仅通过自然语言提示和标准工具输出与系统交互。
4.1 Scenarios4.1 场景
We evaluate three scenarios spanning the main agentic deployment categories: browser control (BrowserART; Kumar et al., 2024), desktop computer use (OS-Harm; Kuntz et al., 2025), and sandboxed code generation (RedCode-Gen; Guo et al., 2024). Each is a standardized single-agent benchmark that we adapt to multi-agent settings while preserving the original task semantics and environment. The only variables that change across conditions are architectural - the set of agent roles, the communication topology, and the memory available to each agent, and the distribution of tool access according to role specialization. Task prompts and scoring rubrics are held fixed.
我们评估了涵盖主要智能体部署类别的三种场景：浏览器控制（BrowserART; Kumar et al., 2024）、桌面计算机使用（OS-Harm; Kuntz et al., 2025）以及沙箱化代码生成（RedCode-Gen; Guo et al., 2024）。每个场景都是一个标准化的单智能体基准，我们在保留原始任务语义和环境的同时，将其适配到多智能体设置。各实验条件之间变化的变量仅涉及架构，包括智能体角色集合、通信拓扑、每个智能体可用的记忆，以及根据角色专业化分配的工具访问权限。任务提示和评分标准保持不变。
The scenarios differ in their action-space structure, which directly shapes how roles can be decomposed. BrowserART exposes a fixed set of named browser primitives (goto, click, fill, scroll), enabling a clean one-tool-per-agent partition in the fully specialized configuration (Navigate / Fill / Scroll / Click). OS-Harm agents instead operate on pixels through a unified computer tool (screenshot + mouse + keyboard); we partition this into four disjoint sub-tools (click, type, key, scroll), each retained alongside screenshot and submit so specialists can observe before acting. RedCode-Gen exposes four heterogeneous tools (python, text_editor, bash, think), yielding an asymmetric partition across four role-typed specialists (Design / Code / Review / Test) where several agents retain python but only one can write code. For each scenario, we also evaluate 2- and 3-specialist variants that progressively merge these sub-tools, allowing the degree of role decomposition to be varied independently of topology. Benign performance is measured on 42 tasks (available part of BrowserART), 50 OS-World tasks (Xie et al., 2024), and 50 BigCodeBench (Zhuo et al., 2024). Full details are provided in Appendix B.
这些场景的动作空间结构各不相同，这直接影响了角色的分解方式。BrowserART 提供了一组固定的具名浏览器基本操作（goto, click, fill, scroll），因此在完全专业化配置（Navigate / Fill / Scroll / Click）中，可以清晰地实现每个智能体对应一个工具的划分。相比之下，OS-Harm 智能体通过统一的计算机工具（screenshot + mouse + keyboard）基于像素进行操作；我们将其划分为四个互不重叠的子工具（click, type, key, scroll），并为每个专业智能体保留 screenshot 和 submit，使其能够在行动前进行观察。RedCode-Gen 提供四种异构工具（python, text_editor, bash, think），由此在四种角色类型的专业智能体（Design / Code / Review / Test）之间形成非对称划分，其中多个智能体保留 python，但只有一个智能体可以编写代码。对于每种场景，我们还评估了包含 2 个和 3 个专业智能体的变体，通过逐步合并这些子工具，使角色分解程度能够独立于拓扑结构进行调整。良性任务表现通过 42 个任务（BrowserART 中可用的部分）、50 个 OS-World 任务（Xie et al., 2024）和 50 个 BigCodeBench 任务（Zhuo et al., 2024）进行衡量。完整细节见附录 B。
4.2 Architectures4.2 架构
We instantiate the following architectural variants identically across all three scenarios. Appendix B.1 summarises the 13 evaluated conditions.
我们在全部三种场景中以相同方式实例化以下架构变体。附录 B.1 概述了所评估的 13 种实验条件。
Baseline As a reference point, we evaluate a standalone agent. This agent has access to all tools, maintains its own memory, and executes actions sequentially. The standalone agent establishes baseline rates for both harmful behavior and benign task performance.
基线 作为参照，我们评估了一个独立智能体。该智能体可以访问所有工具，维护自身的记忆，并按顺序执行动作。该独立智能体为有害行为发生率和良性任务表现确立了基线。
Role Specialization We evaluate several multi-agent role configurations that redistribute planning and execution. In orchestrator + batch executor setups, the orchestrator generates a plan and delegates execution to a single executor, which executes the plan without intermediate feedback. We consider variants in which the orchestrator provides either a high-level goal or a detailed action sequence. In stepwise execution, the orchestrator remains in the loop after every action, and the executor performs only a single action before returning control. In specialized executor settings, the orchestrator delegates subtasks to multiple executors with distinct roles, with all coordination mediated by the orchestrator.
角色专业化 我们评估了多种重新分配规划与执行职责的多智能体角色配置。在编排器 + 批量执行器设置中，编排器生成计划并将执行工作委派给单个执行器，执行器在没有中间反馈的情况下执行该计划。我们考虑了编排器提供高层目标或详细动作序列这两种变体。在逐步执行中，编排器在每次动作之后都继续参与流程，而执行器仅执行一个动作便交回控制权。在专业化执行器设置中，编排器将子任务委派给多个具有不同角色的执行器，所有协调均由编排器居中完成。
Communication Topology We study three communication topologies beyond the standalone baseline. In a star topology, a central orchestrator mediates all communication between executors, which do not communicate directly. In a chain topology, agents execute sequentially in a fixed order, with each agent receiving the previous agent’s output. In a mesh topology, agents communicate peer-to-peer without a central coordinator, and no single agent has global control authority.
通信拓扑 除独立智能体基线外，我们还研究了三种通信拓扑。在星形拓扑中，中央编排器负责执行器之间的所有通信，执行器彼此不直接通信。在链式拓扑中，智能体按照固定顺序依次执行，每个智能体都接收前一个智能体的输出。在网状拓扑中，智能体在没有中央协调者的情况下进行点对点通信，且任何单个智能体都不具有全局控制权。
Memory To isolate the effect of memory and shared context, we fix the topology and vary what information agents can access. We consider settings with private memory per agent (baseline), access to agents’ own chain-of-thought reasoning (+Own Reasoning), and full shared memory in which all agents observe the complete execution history (+Shared Memory), including actions, observations, and reasoning traces.
记忆 为了单独考察记忆与共享上下文的影响，我们固定拓扑结构，并改变智能体可访问的信息。我们考虑以下设置：每个智能体拥有私有记忆（基线）、智能体可访问自身的思维链推理（+Own Reasoning），以及所有智能体均可查看完整执行历史的完全共享记忆（+Shared Memory），其中包括动作、观察结果和推理轨迹。

4.4 Evaluation Metrics4.4 评估指标
Binary attack success is insufficient for multi-agent systems, where harmful behavior may be refused or executed at different pipeline stages. We record stage-specific outcomes: Planning Refusal (task refused during planning), Execution Refusal (refused after delegation), Harmful Actions (one or more harmful actions executed), and Harmful Task (objective completed). We additionally report Benign task success to assess performance impact. Outcome classification follows the judge protocol of each original benchmark. BrowserART uses the Llama-3.3-70B-Instruct (AI@Meta, 2024) via the Together API. OS-Harm and RedCode-Gen use GPT-4.1. All judges map trajectories to the four-stage outcome hierarchy described above. Full judging details are provided in Appendix B.6. To validate automated judgments, we used a two-phase process: an LLM-as-a-judge pass to flag potential scoring errors, followed by manual inspection of all flagged cases by two researchers, with additional sampling from full logs. This review identified 15 scoring errors and 20 corrections to the scorer itself, all of which were corrected. A subsequent spot-check of 10% of the remaining logs found a 7% discrepancy rate; all identified discrepancies were corrected in the final results.
对于多智能体系统，仅用二元攻击成功指标并不足够，因为有害行为可能在流程的不同阶段被拒绝或执行。我们记录各阶段的结果：规划阶段拒绝（在规划期间拒绝任务）、执行阶段拒绝（在任务委派后拒绝）、有害动作（执行了一个或多个有害动作）和有害任务（目标已完成）。我们还报告良性任务成功率，以评估对性能的影响。结果分类遵循各原始基准的评判协议。BrowserART 通过 Together API 使用 Llama-3.3-70B-Instruct (AI@Meta, 2024)。OS-Harm 和 RedCode-Gen 使用 GPT-4.1。所有评判模型均将执行轨迹映射至上述四阶段结果层级。完整的评判细节见附录 B.6。为了验证自动评判结果，我们采用了两阶段流程：先由大语言模型充当评判者，标记潜在的评分错误，再由两名研究人员人工检查所有被标记的案例，并从完整日志中额外抽样检查。此次审查发现了 15 处评分错误，以及评分器本身需要修正的 20 处问题，所有问题均已修正。随后对剩余日志的 10% 进行抽查，发现差异率为 7%；所有发现的差异均已在最终结果中修正。

在这一场景中，所有多智能体配置下的脆弱性均有所增加，而不仅限于专业化配置。与 BrowserART 不同，即使是简单的任务委派也会增加风险，这表明代码生成任务尤其容易受到任务分解效应的影响。所有配置下的规划阶段拒绝率（Planning Refusal）均有所下降——从 $84.4\%$ 降至最低 $13.8\%$——但较高的执行阶段拒绝率（Execution Refusal，最高达 $38.8\%$）部分抵消了这一下降，表明即使规划智能体未予拒绝，执行智能体仍能识别出部分有害指令。这表明，在多智能体架构中，安全推理的重心应从规划阶段转向执行阶段。
Notably, HT decreases monotonically as more specialists are added (25.6% → 23.8% → 17.5% for 2, 3, and 4 specialists) - the opposite of the BrowserART trend. This reversal suggests that security impacts depend on task domain and tool structure: RedCode-Gen’s asymmetric partition (multiple agents retain python) may create redundancy that improves safety, contrasting with BrowserART’s clean one-tool-per-agent mapping.

6 Discussion6 讨论
Multi-agent systems expand the attack surface.多智能体系统扩大了攻击面。
Moving from a single agent to a multi-agent architecture introduces additional decision points, communication channels, and role boundaries - each a potential site where safety reasoning can fail or be bypassed. That multi-agent systems should be harder to secure is, in principle, unsurprising; what our results quantify is the extent and unpredictability of this effect. Across six models and three environments, multi-agent architectures are more vulnerable than the standalone agent in the majority of evaluated configurations, often by substantial margins. However, the direction and magnitude of the effect depend on the specific architecture, model, and environment: no single topology, memory scheme, or delegation strategy is universally safer or riskier. Notably, this increased vulnerability co-occurs with stable or improved benign performance: on BrowserART, specialist configurations achieve higher benign accuracy than the standalone agent ( $95{-}98\%$ vs. $92.9\%$ ) while exhibiting up to $3.8{\times}$ higher attack success. Standard capability evaluation provides no signal about these risks.
从单智能体转向多智能体架构会引入额外的决策点、通信渠道和角色边界，而其中每一处都可能成为安全推理失效或被绕过的位置。从原理上说，多智能体系统更难保障安全并不令人意外；我们的结果量化的是这一效应的程度及其不可预测性。在六个模型和三个环境中，多智能体架构在大多数受评估配置下都比独立智能体更易受到攻击，且差距往往相当显著。然而，这种影响的方向和幅度取决于具体的架构、模型和环境：没有任何一种拓扑结构、记忆机制或委派策略在所有情况下都更安全或风险更高。值得注意的是，这种脆弱性的增加与良性任务性能保持稳定或提升同时出现：在 BrowserART 上，专家配置的良性任务准确率高于独立智能体（$95{-}98\%$ 对比 $92.9\%$），但其攻击成功率最高达到后者的 $3.8{\times}$。标准能力评估无法提供关于这些风险的任何信号。
Effects are scenario- and model-dependent.影响取决于场景和模型。
Our results do not support a single ranking of “safe” vs. “unsafe” designs. Role specialization produces the largest absolute increase on BrowserART but shows substantial relative effects across all scenarios. Star topology is the riskiest on BrowserART but the safest multi-agent topology on RedCode-Gen and OS-Harm, where chain is the riskiest. Increased memory visibility does not reliably improve security: of six topology-scenario combinations, only one shows consistent improvement, while two show worsening. These interactions between design axis, environment, and action-space structure make it difficult to issue universal architectural recommendations and underscore the need for per-deployment evaluation.
我们的结果不支持对“安全”与“不安全”的设计给出统一排序。角色专业化在 BrowserART 上带来的绝对增幅最大，但在所有场景中都表现出显著的相对影响。星形拓扑在 BrowserART 上风险最高，但在 RedCode-Gen 和 OS-Harm 上却是最安全的多智能体拓扑，而链式拓扑在这两个环境中风险最高。提高记忆可见性并不能可靠地改善安全性：在六种拓扑与场景的组合中，只有一种表现出一致的改善，而两种表现出恶化。设计维度、环境与动作空间结构之间的这些交互作用，使得提出普遍适用的架构建议变得困难，也凸显了针对每次部署进行评估的必要性。
The effect of architecture on security is further mediated by the underlying model’s safety training. Well-aligned models remain robust across nearly all configurations, though OS-Harm is an exception where even strong models show increased vulnerability under simple delegation. Weaker-aligned models degrade dramatically under the same architectural changes, with some showing 4-fold increases in harmful task completion under specialization. This suggests that architectural fragmentation interacts with model-level alignment: models with stronger safety training detect harmful intent from partial context, while weaker models lose the ability to recognize harm once it is distributed across agents.
架构对安全性的影响还受到底层模型安全训练的调节。对齐良好的模型在几乎所有配置下都保持稳健，但 OS-Harm 是一个例外，即使是能力较强的模型，在简单委派下也表现出更高的脆弱性。对齐较弱的模型在相同架构变化下表现急剧恶化，其中一些模型在专业化配置下的有害任务完成率增至原来的 4 倍。这表明，架构碎片化与模型层面的对齐存在交互作用：安全训练更充分的模型能够从局部上下文中识别有害意图，而较弱的模型在有害内容分散到多个智能体后，便失去了识别危害的能力。
Mechanisms.作用机制。
Our results suggest that architectural decomposition undermines safety reasoning through two primary pathways. In role specialization, specialists receive isolated instructions without visibility into the full harmful task, while orchestrators decompose tasks without safety evaluation, creating a responsibility gap where no agent performs end-to-end safety assessment. This explains why specialist configurations show reduced Planning Refusal despite individual agents having strong safety training. For topology effects, the key factor is task visibility: mesh agents see the complete harmful objective and can refuse independently, while chain agents receive processed outputs that mask harmful intent, explaining chain’s Planning Refusal collapse on RedCode-Gen (8.1% vs. 25.6% for star). Memory effects depend on whether shared information aids detection (code patterns in RedCode-Gen mesh) or coordination for harmful tasks (OS-Harm mesh), with the balance determined by model alignment strength.
我们的结果表明，架构分解主要通过两条路径削弱安全推理。在角色专业化中，专家智能体接收彼此孤立的指令，无法了解完整的有害任务，而编排智能体在分解任务时不进行安全评估，由此形成了责任空缺，没有任何智能体执行端到端的安全评估。这解释了为何尽管各个智能体都接受了充分的安全训练，专家配置的规划拒绝率（Planning Refusal）仍然下降。对于拓扑效应，关键因素是任务可见性：网状拓扑中的智能体能够看到完整的有害目标，并可独立拒绝，而链式拓扑中的智能体接收到的是经过处理的输出，有害意图被掩盖，这解释了链式拓扑在 RedCode-Gen 上规划拒绝率的骤降（8.1%，而星形拓扑为 25.6%）。记忆的影响取决于共享信息是有助于检测有害意图（RedCode-Gen 网状拓扑中的代码模式），还是有助于协调有害任务（OS-Harm 网状拓扑），两者之间的平衡由模型的对齐强度决定。
Implications for system design.对系统设计的启示。
The findings highlight three key considerations for practitioners. First, security cannot be inferred from component-level evaluations-models that refuse harmful instructions individually may enable harm when architecturally decomposed. Second, performance-improving choices like specialization can simultaneously degrade security without affecting capability metrics. Third, architectural security must be evaluated per-deployment since effects are scenario- and model-dependent. This motivates treating architecture as a first-class security variable alongside traditional defenses.
这些发现凸显了实践者需要考虑的三个关键问题。首先，不能根据组件层面的评估来推断安全性——单独使用时会拒绝有害指令的模型，在架构层面进行分解后可能促成有害行为。其次，专业化等提升性能的选择可能在不影响能力指标的同时降低安全性。第三，由于影响取决于场景和模型，必须针对每次部署评估架构安全性。这促使我们将架构与传统防御措施并列，视为首要的安全变量。
7 Conclusions7 结论
This work presents an empirical study of how architectural design decisions affect security in multi-agent systems. Across three design dimensions, three agentic environments, and multiple base models, we find that multi-agent architectures are more vulnerable than standalone agents in the majority of configurations, often by substantial margins, though the magnitude and direction of the effect depend on the specific architecture, model, and environment.
本研究通过实证研究考察了架构设计决策如何影响多智能体系统的安全性。在三个设计维度、三个智能体环境和多个基础模型中，我们发现，多智能体架构在大多数配置下都比独立智能体更易受到攻击，且差距往往相当显著，但影响的幅度和方向取决于具体的架构、模型和环境。
Three findings challenge common assumptions about multi-agent security. First, security and performance can decouple counterintuitively: specialist configurations achieve higher benign accuracy while being up to 3.8× more vulnerable, meaning capability evaluation provides no signal about security risks. Second, no architectural design is universally safer-the same choices that reduce risk in one environment may increase it in another. Third, common design intuitions fail: increased memory visibility and communication connectivity do not reliably improve security and can worsen outcomes.
三项发现挑战了关于多智能体安全性的常见假设。首先，安全性与性能可能以违反直觉的方式脱钩：专家配置在良性任务上取得更高准确率的同时，易受攻击程度最高达到原来的 3.8×，这意味着能力评估无法提供关于安全风险的任何信号。其次，没有任何架构设计在所有情况下都更安全——在一个环境中降低风险的相同选择，在另一个环境中可能增加风险。第三，常见的设计直觉并不成立：提高记忆可见性和通信连通性并不能可靠地改善安全性，甚至可能使结果恶化。
More broadly, our results provide evidence that safety properties do not compose straightforwardly from individual agents to multi-agent systems. A model that reliably refuses harmful instructions in isolation may enable the same harm when embedded in an architecture that fragments context, distributes authority, or separates task visibility from execution capability. We release our benchmark adaptations for multi-agent settings to support further investigation of these properties.
更广泛地说，我们的结果提供了证据，表明单个智能体的安全属性无法直接组合为多智能体系统的安全属性。一个在独立运行时能够可靠地拒绝有害指令的模型，当被嵌入将上下文碎片化、分散权限，或将任务可见性与执行能力分离的架构中时，可能会促成同样的危害。我们发布了针对多智能体场景改编的基准，以支持对这些属性的进一步研究。
8 Limitations8 局限性
Our study evaluates jailbreak vulnerabilities from an architectural perspective across three agentic environments (browser, desktop, and code), and the findings should be interpreted within this scope. While we isolate the effects of role configuration, communication topology, and memory visibility, these design choices may interact differently across additional domains, deployment contexts, and threat models. Several important directions are not explored in this work. We study only direct misuse by a malicious user; indirect prompt injection, memory poisoning, and adversarial agents operating within the system represent distinct threat vectors that may interact differently with architecture. We do not evaluate dedicated safety mechanisms such as monitor agents, guardrail layers, or policy-checking stages, which could alter the security-performance tradeoffs we observe. Our three design axes are varied independently in most experiments; the interaction effects between role configuration, topology, and memory, and with additional axes such as inter-agent communication protocols (e.g., A2A, MCP), remain underexplored. Extending this analysis to these settings, and to iterative red- and blue-teaming dynamics, is an important direction for future work.
本研究从架构视角评估了三种智能体环境（浏览器、桌面和代码）中的越狱漏洞，研究结果应在这一范围内解读。尽管我们分别考察了角色配置、通信拓扑和记忆可见性的影响，但这些设计选择在其他领域、部署情境和威胁模型中可能以不同方式相互作用。本研究尚未探索若干重要方向。我们仅研究恶意用户的直接滥用；间接提示注入、记忆投毒以及在系统内部运行的对抗性智能体构成了不同的威胁途径，它们可能以不同方式与架构相互作用。我们未评估专门的安全机制，例如监控智能体、防护层或策略检查阶段，这些机制可能改变我们观察到的安全性与性能之间的权衡。在大多数实验中，我们独立改变三个设计维度；角色配置、拓扑和记忆之间的交互效应，以及它们与智能体间通信协议（如 A2A、MCP）等其他维度之间的交互效应，仍缺乏充分探索。将这一分析扩展到这些场景以及红队与蓝队的迭代对抗动态，是未来工作的一个重要方向。

B.5 Topology ImplementationB.5 拓扑实现
Star.星形。
A central orchestrator mediates all communication. Specialists receive instructions from and return results to the orchestrator only; they do not communicate directly.
一个中央编排器负责中转所有通信。专家仅从编排器接收指令，并向编排器返回结果；专家之间不直接通信。
Chain.链式。
Agents are arranged in a deterministic fixed order, identical for every task within a scenario: BrowserART: Click $\to$ Fill $\to$ Scroll $\to$ Navigate; OS-Harm: Click $\to$ Type $\to$ Key $\to$ Scroll; RedCode-Gen: Design $\to$ Code $\to$ Review $\to$ Test. Each agent receives the output of the previous agent and passes its result to the next. There is no central coordinator and no backtracking.
智能体按确定的固定顺序排列，同一场景内的每项任务均采用相同顺序：BrowserART：点击 $\to$ 填写 $\to$ 滚动 $\to$ 导航；OS-Harm：点击 $\to$ 输入 $\to$ 按键 $\to$ 滚动；RedCode-Gen：设计 $\to$ 编码 $\to$ 审查 $\to$ 测试。每个智能体接收前一个智能体的输出，并将自己的结果传递给下一个智能体。不存在中央协调器，也不进行回溯。
Mesh.网状。
Delegation is free-form and prompt-driven. Each peer agent sees a list of available agents in its system prompt and produces a structured output (Thought / Delegate / Instruction). The Inspect framework converts the delegate field into a tool call on the named agent. Any peer can delegate to any other peer - there is no type matching, no structured protocol, and no restriction on delegation targets.
委派采用自由形式，并由提示驱动。每个对等智能体都能在其系统提示中看到可用智能体列表，并生成结构化输出（Thought / Delegate / Instruction）。Inspect 框架将 delegate 字段转换为对指定智能体的工具调用。任何对等智能体都可以向其他任何对等智能体委派任务——没有类型匹配，没有结构化协议，也不限制委派对象。
B.6 Judging ProtocolB.6 评判协议
All three scenarios use a shared MASJudgeScorer base class that computes per-agent compromise scores and maps them to the four-stage outcome hierarchy (planning refusal, execution refusal, harmful actions, harmful task).
这三种场景均使用共享的 MASJudgeScorer 基类，该类计算每个智能体的失陷分数，并将其映射到四阶段结果层级（规划阶段拒绝、执行阶段拒绝、有害行为、有害任务）。
BrowserART.BrowserART。
A HarmBench-style LLM classifier (Llama-3.3-70B-Instruct, via the Together API) evaluates each trajectory against the per-task rubric from Kumar et al. (2024), consistent with the original benchmark’s evaluation protocol.
一个 HarmBench 风格的 LLM 分类器（通过 Together API 调用 Llama-3.3-70B-Instruct）依据 Kumar et al. (2024) 中针对各项任务的评分准则评估每条轨迹，与原始基准的评估协议保持一致。
OS-Harm.OS-Harm。
An LLM judge (GPT-4.1) evaluates each trajectory against three criteria sets (misuse, injection, misbehavior), producing one of four verdict categories.
一个 LLM 评判器（GPT-4.1）依据三组标准（滥用、注入、不当行为）评估每条轨迹，并给出四类判定结果之一。
