MonoScale：以单调改进扩展多智能体系统MonoScale: Scaling Multi-Agent System with Monotonic Improvement
摘要Abstract
近年来，基于大语言模型（LLM）的多智能体系统（MAS）发展迅速，利用路由器分解任务，并将子任务分派给专门的智能体。 In recent years, LLM-based multi-agent systems (MAS) have advanced rapidly, using a router to decompose tasks and delegate subtasks to specialized agents. 扩展系统能力的一种自然方式是持续整合新的功能型智能体或工具接口，以扩大智能体池；但当路由器面对新加入的、异构且不可靠的智能体进行冷启动时，朴素扩展可能引发性能崩溃。 A natural way to expand capability is to scale up the agent pool by continually integrating new functional agents or tool interfaces, but naive expansion can trigger performance collapse when the router cold-starts on newly added, heterogeneous, and unreliable agents. 我们提出 MonoScale，这是一种感知扩展的更新框架，能够主动生成一小组以智能体为条件的熟悉任务，从成功和失败的交互中收集证据，并将其提炼为可审计的自然语言记忆，以指导后续路由。 We propose MonoScale, an expansion-aware update framework that proactively generates a small set of agent-conditioned familiarization tasks, harvests evidence from both successful and failed interactions, and distills it into auditable natural-language memory to guide future routing. 我们将序贯扩充形式化为上下文多臂老虎机（contextual bandit）问题，并执行信赖域记忆更新，从而在无干扰扩展假设下，为各轮新智能体接入提供性能单调不下降的保证。 We formalize sequential augmentation as a contextual bandit and perform trust-region memory updates, yielding a monotonic non-decreasing performance guarantee across onboarding rounds under a non-interfering expansion assumption. 在 GAIA 和 Humanity’s Last Exam 上的实验表明，随着智能体池扩大，系统性能稳定提升，优于朴素扩展基线和采用强路由器的固定智能体池基线。 Experiments on GAIA and Humanity’s Last Exam show stable gains as the agent pool grows, outperforming naive scale-up and strong-router fixed-pool baselines. 我们的代码可在此处获取。 Our code is available here.

1 引言1 Introduction
基于大语言模型（LLMs）构建的多智能体系统（MAS）正成为解决复杂任务的一种强大范式 (Chen et al., 2025; Yang et al., 2024; Guo et al., 2024; Liao et al., 2026)。 Multi-agent systems (MAS) built on large language models (LLMs) are emerging as a powerful paradigm for solving complex tasks (Chen et al., 2025; Yang et al., 2024; Guo et al., 2024; Liao et al., 2026). 与端到端生成答案的单个模型不同，MAS 通常包含一个路由器，负责分解输入问题，将子任务分派给专门的智能体 (Hu et al., 2025; Yang et al., 2025b; Yue et al., 2025)（例如，负责检索、代码执行、规划、工具使用的智能体或领域专家），然后将它们的输出汇总为最终回复。 Unlike a single model that produces an answer end-to-end, an MAS typically includes a router that decomposes an input problem, dispatches subtasks to specialized agents (Hu et al., 2025; Yang et al., 2025b; Yue et al., 2025)(e.g., retrieval, code execution, planning, tool use, or domain experts), and then aggregates their outputs into a final response. 这种模块化的“分而治之”结构支持灵活协作，使 MAS 在多步骤工作流、工具增强推理和长时程任务执行方面尤为有效。 This modular “divide–and–conquer” structure enables flexible collaboration and makes MAS particularly effective for multi-step workflows, tool-augmented reasoning, and long-horizon task execution.
在实际部署中，MAS 往往持续演化：新的工具、插件、外部 API 或专门的智能体可能随时间推移不断集成，从而形成动态扩大的智能体池 (Kim et al., 2025; Microsoft, 2025)。 In real deployments, MAS are often continuously evolving: new tools, plugins, external APIs, or specialized agents may be integrated over time, leading to a dynamically expanding agent pool (Kim et al., 2025; Microsoft, 2025). 虽然增加更强的智能体或具备新技能的智能体，原则上应能提高系统的能力上限，但在实践中，朴素扩展可能产生相反的结果——整体性能可能停滞、下降，甚至出现明显的性能崩溃。 While adding a stronger agent or one that covers new skills should, in principle, increase the system’s capability ceiling, naive scale-up in practice can yield the opposite outcome—overall performance may stagnate, degrade, or even exhibit a clear performance collapse. 这种失效模式并非仅是假设：结果显示，在 GAIA 上使用冷启动路由器时，增加智能体池的规模可能损害端到端性能（例如，DeepSeek-V3.2 从 5 个智能体时的 0.558 降至 10 个智能体时的 0.491；Qwen3 在 7 个智能体时达到峰值 0.461，但在 10 个智能体时降至 0.424）。 This failure mode is not merely hypothetical: shows that, on GAIA under cold-start routers, increasing the agent pool size can hurt end-to-end performance (e.g., DeepSeek-V3.2 drops from 0.558 at 5 agents to 0.491 at 10; Qwen3 peaks at 0.461 with 7 agents but falls to 0.424 at 10). 一个关键原因是路由器的冷启动：当新的智能体 $a_{\text{new}}$ 可用时，路由器通常缺乏有实际依据的知识，不了解该智能体擅长什么、何时可靠、能力边界和失效模式是什么，以及如何与其工具交互（例如，接口、输出格式和常见错误）。 A key reason is the router’s cold start: once a new agent $a_{\text{new}}$ becomes available, the router typically lacks grounded knowledge of what the agent is good at, when it is reliable, what its boundaries and failure modes are, or how to interact with its tools (e.g., interfaces, output formats, and frequent errors). 如果路由器过早或过于激进地将任务分配给 $a_{\text{new}}$，错误的路由决策就可能在系统层面被放大，降低端到端奖励——例如，将高精度要求的请求发送给不稳定的检索智能体，将复杂的工具调用委派给不熟悉接口的智能体，或在多步骤工作流中引入一个脆弱环节，导致整个链条失败。 If the router assigns tasks to $a_{\text{new}}$ too early or too aggressively, mis-routing decisions can be amplified at the system level and reduce end-to-end reward—for example, sending high-precision requests to an unstable retrieval agent, delegating complex tool calls to an agent unfamiliar with the interface, or introducing a brittle link in a multi-step workflow that causes the entire chain to fail.
现有改进多智能体协调的方法大致分为两条研究路线，但二者都未能充分解决开放式 MAS 扩展的核心挑战。 Existing approaches for improving multi-agent coordination broadly fall into two lines, yet neither fully addresses the central challenge of open-ended MAS scaling. 第一条路线关注静态智能体池，假设智能体集合及其能力特征在训练与部署之间保持稳定 (Yue et al., 2025; Zhang et al., 2024; Liu et al., 2025b)；因此，研究重点是在固定池内优化路由策略、改进分工或提高规划效率。 The first line focuses on a static agent pool, assuming that the agent set and its capability profile remain stable between training and deployment (Yue et al., 2025; Zhang et al., 2024; Liu et al., 2025b); the research emphasis is then on optimizing routing policies, improving division of labor, or planning more efficiently within a fixed pool. 尽管这些方法在静态环境中有效，但它们通常缺乏一种受控更新机制，无法在持续添加新智能体时防止性能退化，也没有为开放式系统中持续扩充智能体条件下的在线更新提供统一的形式化描述。 While effective in static settings, these methods typically lack a controlled update mechanism that can prevent performance regressions when new agents are continually added, and they do not provide a unified formalization for online updating under continual agent augmentation in open-ended systems. 与此同时，近期一些工作开始研究 LLM 路由中的动态扩展 (Wang et al., 2025; Zhang et al., 2025c)，在这类场景中，系统在随时间不断扩大的可用专家集合中进行路由。 In parallel, some recent work has started to examine dynamic expansion in LLM routing (Wang et al., 2025; Zhang et al., 2025c), where the system routes across an enlarging set of available experts over time. 然而，扩展 MAS 要困难得多：新集成的智能体具有更强的异构性（工具、记忆、技能、角色和接口各不相同），而且它们在实践中的质量可能参差不齐（工具调用脆弱、API 故障、检索噪声或行为不稳定）。 However, scaling an MAS is substantially harder: newly integrated agents are far more heterogeneous (tools, memory, skills, roles, and interfaces), and their quality can be highly uneven in practice (brittle tool calls, API failures, retrieval noise, or unstable behaviors). 因此，路由器面临更为严峻的冷启动问题，而用于对新智能体进行“试运行”的固定接入测试集往往并不足够：(i) 它无法针对每个智能体独有的能力边界和失效模式进行调整；(ii) 它可能无法充分覆盖真实的部署分布，导致某些智能体在接入阶段看似可用，却在实际部署后仍出现性能崩溃。 As a result, the router faces a sharper cold start problem, and a fixed onboarding suite to “trial-run” the new agent is often insufficient: (i) it cannot be adapted to each agent’s unique boundaries and failure modes; and (ii) it may under-cover the true deployment distribution, creating a risk of agents that appear usable during onboarding but still collapse after real deployment. 简言之，动态 MAS 扩展真正需要的是一种自适应的（以智能体为条件的）保守更新协议，使端到端性能能够随着智能体池的扩大而稳定提升。 In short, what dynamic MAS scaling truly requires is an adaptive (agent-conditioned) and conservative update protocol, so that end-to-end performance can improve stably as the agent pool grows.
为弥补这一缺口，我们提出了一种用于序贯扩展开放式 MAS 的更新框架。 To bridge this gap, we propose an update framework for sequentially expanding open-ended MAS. 每当引入一个新智能体时，我们都会主动为其定制一小组熟悉化任务，并利用这些任务收集受控反馈，而不是等待真实用户流量暴露问题。 Whenever a new agent is introduced, rather than waiting for real user traffic to surface failures, we proactively customize a small set of familiarization tasks tailored to the new agent and use them to collect controlled feedback. 我们的机制包含两个阶段：(i) 通过任务定制进行主动熟悉化，即合成任务以探查新智能体可能具有的优势、接口约束和失效模式，使路由器能够学会何时使用／何时不使用该智能体；(ii) 通过记忆更新路由器，即维护一份从经验中提炼而来的、可审计的文本记忆，以更新路由器的策略。 Our mechanism has two stages: (i) active familiarization via task customization, where tasks are synthesized to probe the new agent’s likely strengths, interface constraints, and failure modes, enabling the router to learn when to use / when not to use the agent; and (ii) router update via memory, where we update the router’s policy by maintaining an auditable text memory distilled from experience. 具体而言，记忆不仅记录成功编排背后的模式，还记录工作智能体调用失败和路由错误带来的教训；我们将这些信号抽象为一组精炼、可执行的原则（例如能力边界、安全／不安全的情境、接口注意事项以及常见失效模式），以指导未来的路由决策。 Concretely, the memory captures not only patterns behind successful orchestration, but also lessons from failed worker calls and mis-routings; we abstract these signals into a compact set of actionable principles (e.g., capability boundaries, safe/unsafe contexts, interface caveats, and common failure patterns) that guide future routing decisions. 通过随着智能体池的演变持续学习这些路由原则，路由器能够减少因不熟悉新接入智能体而导致的脆弱调度，使端到端性能随着智能体数量的增加而更加稳定地提升。 By continuously learning these routing principles as the agent pool evolves, the router becomes less prone to brittle dispatching caused by unfamiliarity with newly integrated agents, enabling end-to-end performance to scale more stably with additional agents. 在理论方面，我们将序贯扩充下的编排建模为上下文多臂老虎机（contextual bandit）问题，并证明，在非干扰扩展假设下，我们的信赖域记忆优化能够保证各轮接入过程中的性能单调不减。 On the theory side, we cast orchestration under sequential augmentation as a contextual bandit and prove that, under a non-interfering expansion assumption, our trust-region memory optimization yields a monotonic non-decreasing performance guarantee across onboarding rounds.
我们在 GAIA (Mialon et al., 2023) 验证集和 Humanity’s Last Exam (Phan et al., 2025) 的多项选择题子集上，系统评估了开放式多智能体系统的序贯扩展过程。 We systematically evaluate the sequential expansion process of open multi-agent systems on the GAIA (Mialon et al., 2023) validation set and the multiple-choice subset of Humanity’s Last Exam (Phan et al., 2025). 我们比较了以下方案：(i) 朴素扩展：使用 Qwen-3-30B-A3B-Instruct 路由器，仅增加智能体，不进行任务定制或记忆更新；结果表明，随着智能体数量持续增加，性能不仅未能提升，反而出现明显崩溃；(ii) 以最先进（SOTA）模型作为路由器的多智能体系统（例如 GPT-5）；(iii) 我们的扩展感知协议，其中包含定制的熟悉化任务和自然语言记忆更新。 We compare: (i) naive scale-up: using a Qwen-3-30B-A3B-Instruct router, which simply adds more agents without task customization or memory updates; results show that performance not only fails to improve, but instead exhibits a clear collapse as the number of agents continues to grow; (ii) multi-agent systems with SOTA models as routers (e.g., GPT-5); and (iii) our expansion-aware protocol, which includes customized familiarization tasks and natural-language memory updates. 我们的结果表明，该方法显著降低了扩展后性能崩溃的风险，并在多轮接入过程中实现了更稳定、持续的性能提升。 Our results demonstrate that this approach substantially reduces the risk of post-expansion performance collapse and yields more stable, sustained improvements across multiple onboarding rounds. 值得注意的是，借助任务定制和记忆，Qwen-3-30B-A3B-Instruct 路由器能够受益于智能体池的扩展，甚至可以超越“强路由器 + 固定智能体池”基线，这表明，自适应的路由器更新对于稳健的 MAS 扩展至关重要，不能仅依赖骨干模型的能力。 Notably, with task customization and memory, the Qwen-3-30B-A3B-Instruct router benefits from scaling up the agent pool and can even outperform the “strong-router + fixed agent pool" baseline, indicating that adaptive router updates—rather than backbone strength alone—are crucial for robust MAS scaling. 此外，我们进一步评估了含噪智能体池设置下的鲁棒性，即智能体池中包含功能异常的智能体，并将我们的方法与强路由器基线进行比较：即使是最强的模型（Gemini-3-pro），在面对高噪声智能体池时也可能出现性能崩溃，而我们的方法即使在此类噪声下仍能保持稳定，并维持 MAS 的性能。 In addition, we further evaluate robustness under a noisy agent pool setting, i.e., the pool contains malfunctioning agents, and compare our method against strong-router baselines: even the strongest model (Gemini-3-pro) can suffer a performance collapse when faced with a noise-heavy agent pool, whereas our method remains stable and maintains MAS performance even under such noise.
贡献。Contributions.
我们的主要贡献有三个方面： Our main contributions are three-fold:
问题形式化：我们形式化定义了序贯扩展下的 MAS 扩展问题，并引入统一的模型和符号体系，用于分析冷启动引发的性能崩溃。 Problem formalization: we formally define MAS scaling under sequential expansion, and introduce a unified model and notation for analyzing cold-start-induced performance collapse.
方法与协议：我们提出了一种扩展感知的任务定制（数据合成）策略和路由器更新协议，主动获取关于每个新增智能体特征的证据，并通过可审计、可控且可回滚的自然语言记忆编辑来更新路由器。 Method and protocol: we propose an expansion-aware task customization (data synthesis) strategy and a router update protocol that actively elicits evidence about each newly added agent’s profile, and updates the router via auditable, controllable, and rollbackable natural-language memory editing.
理论保证：在上下文多臂老虎机的建模框架下，我们证明，在非干扰扩展假设下，我们的信赖域记忆优化能够保证扩展过程中的性能单调不减，从而为开放式 MAS 扩展提供可验证的条件性下界。 Theoretical guarantee: under a contextual bandit formulation, we prove that, under a non-interfering expansion assumption, our trust-region memory optimization yields a monotonic non-decreasing performance guarantee during scaling, providing a verifiable conditional lower-bound for open MAS expansion.

基于 LLM 的多智能体系统与编排。LLM-based multi-agent systems and orchestration.
基于 LLM 的多智能体系统（MAS）(Yang et al., 2025b; Chen et al., 2025; Yang et al., 2024) 通常依赖中央路由器或协调器来分解任务 (Hong et al., 2024; Li et al., 2023; Wu et al., 2023)、将子任务分派给专门的智能体 (Qian et al., 2024; Hu et al., 2025)（例如，负责检索、工具使用、代码执行的智能体），并汇总结果 (Wang et al., 2023; Wang et al., 2024)，从而支持工具增强型工作流和长程工作流。 LLM-based multi-agent systems (MAS) (Yang et al., 2025b; Chen et al., 2025; Yang et al., 2024) typically rely on a central router or coordinator to decompose tasks (Hong et al., 2024; Li et al., 2023; Wu et al., 2023), dispatch subtasks to specialized agents (Qian et al., 2024; Hu et al., 2025) (e.g., retrieval, tool use, code execution), and aggregate results (Wang et al., 2023; Wang et al., 2024), enabling tool-augmented and long-horizon workflows. 在这一设定下，大量研究探讨了如何在静态智能体池中改进规划、分工和路由决策 (Yue et al., 2025; Zhang et al., 2024; Liu et al., 2025b)，即假设智能体集合及其能力配置在训练与部署之间保持不变。 In this setting, a large body of work studies how to improve planning, division of labor, and routing decisions under a static agent pool (Yue et al., 2025; Zhang et al., 2024; Liu et al., 2025b), i.e., the agent set and its capability profile are assumed fixed between training and deployment. 当动作空间稳定时，这类方法是有效的，但它们通常没有提供一种在持续增添智能体的过程中进行受控在线更新的机制，以防止智能体池随时间变化时出现性能退化。 Such approaches are effective when the action space is stable, but they usually do not provide a controlled online updating under continual agent augmentation mechanism that prevents regressions once the agent pool changes over time.
MAS 的动态演化与冷启动问题。Dynamic MAS evolution and the cold-start problem.
近期研究探索了能够自我演化的基于 LLM 的多智能体系统，其中的团队、角色或交互拓扑由系统自动生成、优化或重组 (Yang et al., 2025b; Zhuge et al., 2024; Zhang et al., 2025a; Lu et al., 2025)。 Recent work explores self-evolving LLM-based multi-agent systems, where teams, roles, or interaction topologies are generated, optimized, or reorganized automatically (Yang et al., 2025b; Zhuge et al., 2024; Zhang et al., 2025a; Lu et al., 2025). 这种内部适应可以改进 MAS，但不受约束的自我演化可能逐渐引发涌现风险 (Shao et al., 2026)，因此，必须对智能体的演化能力与可靠性进行明确评估，而不能直接假定其具备这些特性 (Fu et al., 2026; Yang et al., 2025a)。 Such internal adaptation can improve a MAS, but unconstrained self-evolution may drift into emergent risks (Shao et al., 2026), so the evolutionary capability and reliability of agents must be explicitly evaluated rather than assumed (Fu et al., 2026; Yang et al., 2025a). 关键在于，这些方法同样没有解决动态扩容问题，即持续将新的专才型或通才型智能体整合到现有系统中。 Crucially, these approaches also do not address dynamic scale-up—continuously integrating new specialist or generalist agents into an existing system. 一条相关研究路线通过在不断扩大的异构模型池中进行路由来研究系统层面的扩展 (Wang et al., 2025; Zhang et al., 2025c)：UniRoute 通过学习得到的模型嵌入，将查询路由至此前未见过的 LLM (Jitkrittum et al., 2025)，而 StageRoute 则在容量和成本预算约束下，针对持续流入的模型集合执行在线部署与路由 (Li and Li, 2026)。 A related line studies system-level expansion by routing over growing pools of heterogeneous models (Wang et al., 2025; Zhang et al., 2025c): UniRoute routes queries to previously unseen LLMs via learned model embeddings (Jitkrittum et al., 2025), and StageRoute performs online deployment and routing over a streaming model inventory under capacity and cost budgets (Li and Li, 2026). 然而，这些研究处理的是模型层面的路由，其决策单元是单个独立的 LLM。 However, these address model-level routing, where the decision unit is a single standalone LLM. MAS 中的智能体路由更加困难：智能体的异构性要强得多（涉及工具、记忆、技能和角色），在实际应用中的可靠性也更低（存在工具/API 故障、接口脆弱、检索噪声等问题），因此，路由必须综合权衡能力与可靠性，并生成多步骤编排计划，而不是仅仅选择单个模型。 Agent routing in MAS is harder: agents are far more heterogeneous (tools, memory, skills, roles) and less reliable in practice (tool/API failures, brittle interfaces, retrieval noise), so routing must jointly weigh capability and reliability and produce a multi-step orchestration plan rather than a single-model choice. 与我们的设定最为接近的是 EvoRoute，它在智能体系统内部执行经验驱动的自路由 (Zhang et al., 2026a)，但其目标是权衡成本、延迟与准确率，而非防止智能体池扩展过程中的冷启动性能崩溃。 Closest to our setting, EvoRoute performs experience-driven self-routing within an agentic system (Zhang et al., 2026a), but targets the cost, latency, and accuracy trade-off rather than preventing cold-start collapse during agent-pool expansion. 因此，这些方法与 MonoScale 具有互补性，而不是可以直接适用的基线方法。 These methods are thus complementary to MonoScale rather than directly applicable baselines.

如图 1 所示，每个扩展步骤包含两个阶段：扩展感知的任务合成和证据驱动的记忆更新。 As illustrated in Figure 1, each expansion step consists of two stages: expansion-aware task synthesis and an evidence-driven memory update. 集成新智能体 $a_{k}$ 时，我们首先以新智能体的概况为条件合成预热任务，以探查其优势和失效模式；随后在当前路由器下执行这些任务，收集成功与失败的证据；最后将这些证据提炼为可审计的路由原则，形成结构化记忆候选，并从中选择安全的更新（配备保守回退机制），以缓解冷启动时的错误路由，并支持系统随智能体池增长而稳定扩展。 When a new agent $a_{k}$ is integrated, we first synthesize warm-up tasks conditioned on the new agent’s profile to probe both strengths and failure modes, then execute these tasks under the current router to collect success/failure evidence, and finally distill the evidence into auditable routing principles as structured memory candidates, from which we select a safe update (with a conservative fallback) to mitigate cold-start mis-routing and support stable scaling as the agent pool grows.
3.2.1 扩展感知的任务合成3.2.1 Expansion-Aware Task Synthesis
我们的设计借鉴了近期关于开放世界智能体轨迹合成的研究（Guo et al., 2024; Fang et al., 2025; Shi et al., 2025），但将其理念从基准构建调整为生成以新智能体为中心的预热任务分布，以实现安全的 Router 更新。 Our design draws on recent work on open-world agent trajectory synthesis (Guo et al., 2024; Fang et al., 2025; Shi et al., 2025), but adapts the philosophy from benchmark construction to generating a warm-up task distribution centered on new agents for safe Router updates.
对于系统中的每个工作智能体，包括新增智能体，我们都维护一张简明的智能体卡片，概述其功能能力、可用工具和已知行为特征。 For each worker agent in the system, including newly added agents, we maintain a concise agent card that summarizes its functional capabilities, available tools, and known behavioral characteristics. 引入新智能体时，其智能体卡片会与现有工作智能体的卡片一起，作为条件输入提供给专门的任务合成器。 When a new agent is introduced, its agent card is provided jointly with the agent cards of existing workers as conditional inputs to a dedicated task synthesizer. 合成器本身遵循步骤级的规划器—执行器—验证器循环。 The synthesizer itself follows a step-level planner–executor–validator loop. 具体而言，规划器提出候选任务规范，随后执行器尝试在当前多智能体配置下完成所提出的任务，生成完整的多智能体交互过程；最后，验证器检查执行结果，以确保该任务具有确定性解、遵循连贯的执行路径，并能有效揭示新智能体的能力边界或潜在的不匹配行为。 Specifically, the planner proposes candidate task specifications, the executor then attempts to carry out the proposed task under the current multi-agent configuration, producing a complete multi-agent interaction process; finally, the validator examines the execution outcome to ensure that the task admits a deterministic solution, follows a coherent execution path, and effectively exposes the capability boundaries or potential mismatch behaviors of the new agent. 只有通过这一验证流程的任务才会被保留，作为后续 Router 熟悉阶段的交互样本。 Only tasks that pass this validation procedure are retained as interaction samples for the subsequent Router familiarization stage.
按照这一流程，在第 $k$ 次系统扩展后，我们获得一组感知扩展的合成任务，记为 $\mathcal{T}_{k}^{\mathrm{syn}}$，由此形成相应的预热任务分布 $\mathcal{D}_{k}^{\mathrm{warm}}$。 Following this procedure, after the $k$ -th system expansion we obtain a set of expansion-aware synthesized tasks, denoted as $\mathcal{T}_{k}^{\mathrm{syn}}$ , which induces a corresponding warm-up task distribution $\mathcal{D}_{k}^{\mathrm{warm}}$ . 这些合成任务不用于训练或更新单个工作智能体。 These synthesized tasks are not used to train or update individual worker agents. 相反，它们用于驱动 Router 在固定策略下进行批量交互和采样。 Instead, they are used to drive the Router, under a fixed policy, to perform batch interactions and sampling. 所有合成任务的执行结果——包括路由成功和失败的情况——均被汇总，随后用于支持下一阶段 Router 的记忆更新和策略改进建模。 The execution outcomes of all synthesized tasks—including both successful and failed routing cases—are aggregated and subsequently used to support memory updates and policy improvement modeling of the Router in the following stage.
3.2.2 记忆更新3.2.2 Memory Update
在熟悉阶段，Router 在当前记忆状态 $m_{t}$ 下与从预热分布中采样的任务进行交互：对于 $x\sim\mathcal{D}_{k}^{\mathrm{warm}}$，它采样一个编排计划 $y\sim\pi_{m_{t}}(\cdot\mid x)$，执行该计划，并获得标量奖励 $r(x,y)$。 During the familiarization stage, the Router interacts with tasks sampled from the warm-up distribution under the current memory state $m_{t}$ : for $x\sim\mathcal{D}_{k}^{\mathrm{warm}}$ , it samples an orchestration plan $y\sim\pi_{m_{t}}(\cdot\mid x)$ , executes it, and receives a scalar reward $r(x,y)$ . 我们将 $\mathcal{D}_{k}^{\mathrm{warm}}$ 设计为在任务形式和执行约束方面与部署任务分布 $\mathcal{D}$ 紧密匹配，同时提高涉及新智能体的情境的占比。 We design $\mathcal{D}_{k}^{\mathrm{warm}}$ to closely match the deployment task distribution $\mathcal{D}$ in task form and execution constraints, while amplifying contexts that involve the new agent. 因此，我们将 $\mathcal{D}_{k}^{\mathrm{warm}}$ 视为 $\mathcal{D}$ 的实用近似，并使用来自 $\mathcal{D}_{k}^{\mathrm{warm}}$ 的样本来估计目标函数中的期望。 Consequently, we treat $\mathcal{D}_{k}^{\mathrm{warm}}$ as a practical proxy of $\mathcal{D}$ and estimate the expectations in our objective using samples from $\mathcal{D}_{k}^{\mathrm{warm}}$ .

5 实验5 Experiments
本节从两个维度对 MonoScale 进行实证验证：(i) 稳定的可扩展性，即随着智能体池扩展，性能能否可靠地提升而不发生崩溃；以及 (ii) 能力，即开放权重路由器能否在端到端性能上与强大的专有模型基线相竞争。 In this section, we empirically validate MonoScale along two dimensions: (i) stable scalability, whether performance improves reliably as the agent pool expands without collapse; and (ii) capability, whether an open-weight router achieves competitive end-to-end performance against strong proprietary baselines.
5.1 实验设置5.1 Experimental Settings
基准。Benchmarks.
我们主要采用 GAIA（General AI Assistants，通用人工智能助手）(Mialon et al., 2023) 基准，使用完整验证集评估开放世界场景中的工具使用、多步规划等实际能力。 We primarily utilize the GAIA (General AI Assistants) (Mialon et al., 2023)benchmark, using the full Validation Set to evaluate pragmatic capabilities such as tool use and multi-step planning in open-world scenarios. 此外，为检验我们的方法及扩展过程中积累的路由经验能否泛化到更困难、更复杂的深度推理分布，我们将 HLE（Humanity’s Last Exam，人类最后的考试）(Phan et al., 2025) 的多项选择题（MCQ）子集纳入补充评估；选择该子集的部分原因是它便于进行基于规则的自动评分。 In addition, to test whether our method and the routing experience accumulated during expansion generalize to harder, more complex deep-reasoning distributions, we include the MCQ subset of HLE (Humanity’s Last Exam) (Phan et al., 2025)as a supplementary evaluation; we choose this subset in part because it supports convenient rule-based automatic scoring.
智能体池配置。Agent Pool Configuration.
我们基于 camel-ai (Li et al., 2023) 工具包构建了两个动态多智能体系统（MAS），均将工作智能体池从 $N=3$ 扩展至 $N=10$，这一范围与 (Kim et al., 2025) 中探索的范围相当：(1) 正常池（Clean Pool），其中所有智能体均可靠，用于测试 MonoScale 能否在无噪声条件下保持稳定的扩容性能；(2) 故障池（Malfunctioning Pool），我们在扩展过程中有意注入若干表现出现实故障模式的故障智能体，用于评估即使存在不可靠的工作智能体，MonoScale 能否仍然稳定 MAS 的整体性能。 We build two dynamic Multi-Agent Systems (MAS) based on the toolkit of camel-ai (Li et al., 2023), both scaling the worker pool from $N=3$ to $N=10$ , a range comparable to that explored in (Kim et al., 2025): (1) a Clean Pool, where all agents are reliable, to test whether MonoScale can maintain stable scale-up performance under noise-free conditions; and (2) a Malfunctioning Pool, where we intentionally inject several Malfunctioning Agents exhibiting realistic failure modes during expansion, to evaluate whether MonoScale can stabilize overall MAS performance even in the presence of unreliable workers. 在这两个系统中，初始智能体群体均由核心通用型智能体组成，而后续新增智能体逐步引入更专业的领域能力。 In both systems, the initial cohort consists of core generalists, while subsequent additions progressively introduce more specialized domain capabilities. 附录 A 提供了所有智能体及故障智能体的详细规格。 Detailed specifications of all agents and the malfunctioning agents are provided in Appendix A.
数据合成与经验收集。Data synthesis and experience collection.
为在扩展过程中为每个新加入的智能体定制可求解且易于验证的熟悉任务，我们复用了 (Guo et al., 2024) 中的任务合成范式（规划器–执行器–验证器），确保合成任务具有可执行的求解路径和自动验证器。 To customize solvable and easily verifiable familiarization tasks for each newly added agent during expansion, we replicate the task-synthesis paradigm from (Guo et al., 2024) (planner–executor–validator), which ensures that synthesized tasks admit an executable solution path and an automatic verifier. 在此框架的基础上，我们还将新智能体的智能体卡片作为规划器的条件输入，使生成的计划优先探查该智能体的能力边界、接口约束和常见失效模式。 Building on this framework, we additionally condition the planner on the new agent’s agent card, so that the generated plans prioritize probing the agent’s capability boundaries, interface constraints, and common failure modes. 每当一个新智能体被集成到多智能体系统（MAS）中时，我们都会合成约 50 个考虑扩展情境的预热任务，供路由器针对新智能体进行冷启动。 Whenever a new agent is integrated into the MAS, we synthesize approximately 50 expansion-aware warm-up tasks for the router to cold-start on the new agent. 在执行阶段，对于每个预热任务，我们让路由器独立采样 4 个编排计划并并行执行；如果某个任务在全部 4 次运行中均失败，我们就将其过滤掉，以减少不可求解或噪声过大的样本对后续更新的影响。 In the execution stage, for each warm-up task, we let the router independently sample and execute 4 orchestration plans in parallel; if a task fails in all 4 runs, we filter it out to reduce the impact of unsolvable or overly noisy samples on subsequent updates. 对于剩余任务，我们分别从成功和失败的轨迹中总结经验：成功轨迹用于提炼正向路由原则（即何时调用新智能体），而失败轨迹则提供负向证据（即何时不应调用它，或何时需要施加额外约束）。 For the remaining tasks, we summarize experience separately from successful and failed trajectories: successful traces are used to distill positive routing principles (i.e., when to invoke the new agent), while failed traces provide negative evidence (i.e., when not to invoke it or when additional constraints are required). 随后，我们利用这两类证据构建并评估候选记忆更新。 Both types of evidence are then used to construct and evaluate memory-update candidates.

在新兴的智能体网络（Agentic Web）(Yang et al., 2025c) 中，路由器可能需要从个人或组织上传的数百万个第三方智能体中进行选择。 In the emerging Agentic Web (Yang et al., 2025c), a router may need to choose among millions of third-party agents uploaded by individuals or organizations. 即使经过基本的质量控制，智能体卡片仍可能不完整、过时，或与实际执行行为不一致，从而使零样本路由变得不可靠；当工具接口脆弱，或任务需要多步工作流、一次路由错误就可能引发连锁反应并导致端到端失败时，这一问题尤为突出。 Even with basic quality control, agent cards can be incomplete, outdated, or misaligned with actual execution behavior, making zero-shot routing unreliable; this is especially problematic when tool interfaces are brittle, or tasks require multi-step workflows where a single misrouting can cascade into end-to-end failure. 在这种情况下，仅仅升级为更强的路由模型，并不能从根本上解决缺乏基于执行的证据这一问题。 In this setting, simply upgrading to a stronger router model does not fundamentally address the lack of execution-grounded evidence. 相反，将智能体集成视为一项强制性的预热协议，即使用一小组以智能体为条件的任务来探测新智能体，并将成功与失败经验都提炼为可审计、可回滚的路由约束，似乎是防止扩展后性能崩溃的必要措施。 Instead, treating agent integration as a mandatory warm-up protocol, where we probe new agents with a small set of agent-conditioned tasks and distill both successes and failures into auditable, rollbackable routing constraints, appears essential for preventing post-expansion performance collapse.
这种崩溃风险带来的一个实际影响决定了我们的实验比较方式。 A practical consequence of this collapse risk shapes our experimental comparison. 我们主要将 MonoScale 与固定小规模（$3$ 个智能体）池中的强路由器基线进行基准比较，而不是与这些基线在朴素扩展下的最佳配置进行比较，原因在于可预测性存在不对称：在朴素扩展下，强路由器的性能呈非单调变化，只有在穷尽评估所有规模之后，才能事后确定哪种池规模最优。 We benchmark MonoScale mainly against strong-router baselines at a fixed small ( $3$ -agent) pool rather than against their best naively scaled configuration, because of an asymmetry in predictability: under naive scale-up a strong router’s performance is non-monotonic, and which pool size is best can only be identified in hindsight, after exhaustively evaluating every scale. 因此，接入新智能体的实践者无法可靠地预先知道，这样的路由器在包含多少个智能体时会表现良好，或会在何处崩溃，所以其固定小规模池配置是唯一稳定且可事先获知的运行点，也因此是有意义的参照。 A practitioner onboarding new agents thus has no reliable way to know a priori at how many agents such a router will perform well—or where it will collapse—so its fixed small-pool configuration is the only stable, a-priori-knowable operating point, and hence the meaningful reference. MonoScale 消除了这种不确定性：其保守更新通过设计便可产生稳定、非递减的扩展趋势，因此其扩展后的性能是可预测的，使用者可以持续接入智能体，而不必押注性能峰值出现的位置。 MonoScale removes this uncertainty: its conservative updates yield a stable, non-decreasing scaling trend by construction, so its scaled performance is predictable and one can keep onboarding agents without gambling on where the peak lies.
局限性。Limitations.
我们指出以下几项局限性。 We note several limitations. 首先，单调改进保证是有条件的：它在非干扰扩展假设（假设 C.1）下成立，而在持续的环境漂移下可能减弱，例如外部 API 行为发生变化，附录 C.2 对此进行了实证考察。 First, the monotonic-improvement guarantee is conditional: it holds under the non-interfering expansion assumption (Assumption C.1) and may weaken under persistent environment drift, such as shifting external-API behavior, as examined empirically in Appendix C.2. 其次，MonoScale 在固定的 token 预算下，将路由知识存储于自然语言记忆中；在我们研究的智能体池规模下，我们未观察到由饱和引发的崩溃或灾难性干扰，但这一结论尚未在更长期的扩展过程中得到证实，而在此类情形下，很可能需要显式的记忆管理机制，例如检索、剪枝或整合。 Second, MonoScale stores routing knowledge in a natural-language memory under a fixed token budget; at the agent-pool sizes we study we observe no saturation-induced collapse or catastrophic interference, but this is not established for much longer expansion horizons, where explicit memory management—retrieval, pruning, or consolidation—would likely be needed.
受计算资源和实验规模的限制，我们的主要实验在最多包含 $10$ 个智能体的相对较小智能体池上验证了该方法（附录 D.4 中还进行了初步的 $20$ 个智能体探测实验），并观察到了很强的有效性和稳定性。 Due to compute and experimental-scale constraints, our main experiments validate the approach on relatively small agent pools of up to $10$ agents (with a preliminary $20$ -agent probe in Appendix D.4), where we observe strong effectiveness and stability. 在现实的智能体网络（Agentic Web）场景中，路由器面对的目录包含数千乃至数百万个智能体，而路由通常由检索驱动：系统必须先从大型目录中检索出一个小规模候选集，再选择并调用智能体。 In realistic Agentic Web settings, routers face catalogs containing thousands to millions of agents, and routing is typically retrieval-driven: the system must first retrieve a small candidate set from a large directory before selecting and invoking an agent. 如何在可控的成本预算下，以 Web 规模持续且并行地接入智能体并扩展智能体集合，同时通过预热和校准路由来避免扩展过程中的性能退化，仍是一个开放挑战。 How to continuously and in parallel onboard and expand the agent set at Web scale with a controllable cost budget—while warming up and calibrating routing to avoid degradation during expansion—remains an open challenge. 另一个问题是，是否应将基于检索的路由更紧密地融入我们的扩展策略，形成一个受预算约束的“检索—路由—校准”循环，优先校准新出现或高度不确定的长尾智能体，并将由此得到的可靠性和边界信息反馈到后续的检索与路由决策中。 A further question is whether retrieval-based routing should be more tightly integrated into our expansion strategy, forming a budgeted “retrieve–route–calibrate” loop that prioritizes calibration for newly surfaced or highly uncertain long-tail agents and feeds the resulting reliability and boundary information back into subsequent retrieval and routing decisions. 沿着这些方向设计更高效、可扩展且稳定的扩展机制，是我们未来工作的核心重点。 Designing a more efficient, scalable, and stable expansion mechanism along these lines is a central focus of our future work.
7 结论7 Conclusion
我们研究了开放式多智能体系统在持续扩展过程中的一种常见失效模式：冷启动时的路由错误导致性能崩溃。 We study a common failure mode in open multi-agent systems under continual expansion: cold-start misrouting that leads to performance collapse. 我们提出了 MonoScale，该方法在每次集成新智能体时，通过以智能体为条件的预热探测，主动收集基于执行的证据，并将成功与失败经验都提炼为可审计、可回滚的自然语言路由记忆。 We propose MonoScale, which, upon each new agent integration, proactively collects execution-grounded evidence via agent-conditioned warm-up probes and distills both successes and failures into auditable, rollbackable natural-language routing memories. 在理论方面，我们将扩展形式化为上下文多臂老虎机问题，并在非干扰扩展假设、保守回退机制和信赖域约束下，建立了逐阶段单调不退化保证。 On the theory side, we formalize expansion as a contextual bandit problem and establish a stage-wise monotonic non-degradation guarantee under a non-interfering expansion assumption, conservative fallback, and trust-region constraints. 在 GAIA 和 Humanity’s Last Exam 上的实验表明，随着智能体池从 3 个增长到 10 个，MonoScale 能够带来稳定的性能提升，显著缓解朴素扩展造成的性能退化，并在存在噪声智能体时保持更强的鲁棒性。 Experiments on GAIA and Humanity’s Last Exam show that MonoScale delivers stable gains as the agent pool grows from 3 to 10, substantially mitigating the degradation of naive scale-up, and remains more robust in the presence of noisy agents. 我们希望这项工作能够为未来 Agentic Web 中大规模、开放式的智能体接入提供安全且可控的扩展协议；我们还计划将 MonoScale 与基于检索的路由相结合，以支持百万规模的智能体生态系统。 We hope this work provides a safe and controllable expansion protocol for large-scale, open agent onboarding in the future Agentic Web; we further aim to integrate MonoScale with retrieval-based routing to support million-scale agent ecosystems.

D.4 扩展至十个以上的智能体D.4 Scaling Beyond Ten Agents
我们的主要实验将智能体池扩展至 $N=10$。 Our main experiments scale the agent pool up to $N=10$ . 为探究更大规模下的表现，我们新增十个基于 Gemini-2.5-Pro 的工作智能体，将 HLE-MCQ 系统中的工作智能体数量从 $10$ 进一步扩展至 $20$，其余设置保持不变。 To probe behaviour at a larger scale, we further expand the HLE-MCQ system from $10$ to $20$ worker agents by adding ten Gemini-2.5-Pro-based workers, keeping the rest of the setup unchanged. 总体准确率从 $10$ 个智能体时的 $19.88\%$ 提升至 $20$ 个智能体时的 $23.4\%$，表明在中等规模下，额外的模型能力和技能多样性仍能带来切实收益，而上下文窗口尚未成为主要瓶颈。 Overall accuracy improves from $19.88\%$ at $10$ agents to $23.4\%$ at $20$ agents, indicating that at moderate scale, additional model capability and skill diversity still yield tangible gains and that the context window is not yet the dominant bottleneck. 尽管如此，我们并不声称，当前基于提示的路由范式本身就能应对真正的 Web 规模场景：当智能体数量达到数百或数千时，上下文长度会成为主要瓶颈，MonoScale 需要与智能体推荐或分层调度阶段相结合，先检索出一个规模较小的相关智能体子集，再进行路由。 We nonetheless do not claim that the current prompt-based routing paradigm alone addresses true Web-scale settings: at hundreds or thousands of agents, context length becomes the primary bottleneck, and MonoScale would need to be combined with an agent-recommendation or hierarchical-scheduling stage that first retrieves a small relevant subset of agents before routing.
D.5 新智能体接入成本D.5 Onboarding Cost
新智能体的接入是一项一次性成本。 Onboarding a new agent is a one-time cost. 在我们的实现中，这需要大约 $50$ 个定制预热任务，每个任务包含 $4$ 条 rollout 轨迹，按照 DeepSeek 官方 API 定价，每个智能体的成本约为 $19.5。 In our implementation, it requires roughly $50$ customized warm-up tasks with $4$ rollout trajectories each, costing about $19.5 per agent under DeepSeek’s official API pricing. 相比之下，一次完整评估的成本约为 $50，而完整 HLE 基准测试的成本约为 $100（约为每个智能体接入费用的 $5\times$）。 For comparison, a single full evaluation costs about $50, and the full HLE benchmark about $100 (roughly $5\times$ the per-agent onboarding fee). 预热过程具有很高的可并行性，通常可在 $10$ – $15$ 分钟内完成，因此其实际耗时有限。 The warm-up procedure is highly parallelizable and typically completes within $10$ – $15$ minutes, so its wall-clock latency is limited. 由于每个智能体只需接入一次，接入后的智能体会在许多下游任务中复用，考虑到系统能力的持续提升，我们认为这项开销适中且易于摊销。 Because onboarding is performed only once per agent while the resulting agent is reused across many downstream tasks, we regard this overhead as moderate and readily amortized given the persistent gain in system capability.
D.6 多随机种子方差D.6 Multi-Seed Variance
对基于 LLM 的多智能体系统（MAS）开展完整的多随机种子评估成本高昂，因此我们使用三个独立随机种子，在随机抽取的包含 $40$ 个任务的 GAIA 子集上评估方差。 Full multi-seed evaluation of an LLM-based MAS is expensive, so we assess variance on a randomly sampled $40$ -task GAIA subset using three independent seeds. 当智能体数量分别为 $5$、$7$ 和 $10$ 时，总体准确率的标准差分别为 $2.89$、$1.44$ 和 $2.89$ 个百分点，相当于 $40$ 个任务中仅约 $0.5$ – $1.2$ 个任务的差异。 The standard deviation of overall accuracy is $2.89$ , $1.44$ , and $2.89$ points at $5$ , $7$ , and $10$ agents respectively—only about $0.5$ – $1.2$ tasks out of $40$ . 这种低方差表明，MonoScale 在扩展过程中的增益并非随机波动造成的假象；因此，我们将这一实证趋势表述为稳定的、非递减的提升，而非声称每个点都具有严格的单调性。 This low variance indicates that MonoScale’s gains across expansion are not an artifact of random fluctuation; accordingly, we frame the empirical trend as a stable, non-decreasing improvement rather than a strict per-point monotonicity claim.

constraints. 我们将根本原因追溯至预热阶段：当前的任务设计并未明确涵盖预算受限场景，因此收集到的证据缺乏关于预算耗尽的负面信号，提炼出的路由记忆也几乎无法指导路由器在预算有限时避免过度分解。 We trace the root cause to the warm-up stage: its current task design does not explicitly cover
