一句话

Anthropic 官方文档称，队友处于计划模式时，Claude Code agent teams 的 token 用量约为普通会话的 7 倍；这是特定使用条件下的成本提示，不能直接当作 swarm 的普遍扩展规律。

主要内容

  • 多个队友分别运行 Claude 实例，各自维护上下文；总 token 用量随活跃队友数量及运行时长增长，文档将其描述为与团队规模大致成正比。
  • 控制团队成本的建议包括：缩小团队、明确任务边界、精简启动提示，并在任务结束后关闭队友。队友还会自动加载项目说明、MCP 服务和技能，存在上下文负担。
  • 子代理可把测试、日志、文档等冗长内容留在自己的上下文，只向主会话返回摘要；但子代理请求仍计入总用量，主会话变短不代表整体更省。
  • 成本还受模型、上下文长度、缓存命中和后台请求影响。因此，token 总量与最终账单不能简单等同。

证据与可信度

  • “约 7 倍”来自 Anthropic 产品文档，限定条件是队友运行于计划模式。材料未披露任务集、队友数量、普通会话基线、重复次数或误差范围，属于厂商给出的近似数字，缺少可复现实验及独立核验。
  • “与团队规模大致成正比”是官方机制说明，材料没有提供不同规模的实测曲线，也未报告成功率或耗时收益。
  • 文档中的缓存统计明确只覆盖主会话，不含子代理；订阅用量归因则来自本机历史的近似计算。评估多代理成本时，需要先确认统计口径是否覆盖全部代理。
  • 抓取文本末尾截断于网站配置，正文包含相关成本段落；发布日期未提供，无法据此确定这些数字的版本适用范围。

对 swarm scaling 的意义

这份材料提供的是扩容的成本约束，而非扩容有效性的证据。增加代理会增加独立上下文与请求，但材料没有证明这些开销能换来多少质量或速度收益。

对调研最有用的启示是：同时记录团队规模、运行时长、全体代理 token、缓存及模型配置，再与任务成功率和完成时间比较。“约 7 倍”可作为试点预算的参考，不能据此推算任意规模 swarm 的成本或收益。
