概述Overview
Swarm 致力于使智能体的**协调**与**执行**保持轻量、高度可控且易于测试。 Swarm focuses on making agent **coordination** and **execution** lightweight, highly controllable, and easily testable.
它通过两种基本抽象实现这一目标：`Agent` 和**交接（handoff）**。 It accomplishes this through two primitive abstractions: `Agent`s and **handoffs**. 一个 `Agent` 包含 `instructions` 和 `tools`，并且可以在任何时候选择将对话交接给另一个 `Agent`。 An `Agent` encompasses `instructions` and `tools`, and can at any point choose to hand off a conversation to another `Agent`.
这些基本抽象足以表达工具与智能体网络之间丰富的动态交互，使你能够构建可扩展的实际应用解决方案，同时避免陡峭的学习曲线。 These primitives are powerful enough to express rich dynamics between tools and networks of agents, allowing you to build scalable, real-world solutions while avoiding a steep learning curve.
> [!NOTE] > [!NOTE]
> Swarm 智能体与 Assistants API 中的 Assistants 无关。 > Swarm Agents are not related to Assistants in the Assistants API. 它们只是为了方便而采用了相似的名称，除此之外完全没有关联。 They are named similarly for convenience, but are otherwise completely unrelated. Swarm 完全由 Chat Completions API 驱动，因此在调用之间不保留状态。 Swarm is entirely powered by the Chat Completions API and is hence stateless between calls.
为什么选择 SwarmWhy Swarm
Swarm 探索的是在设计上就具备轻量、可扩展和高度可定制特性的模式。 Swarm explores patterns that are lightweight, scalable, and highly customizable by design. 类似 Swarm 的方法最适合需要处理大量独立能力和指令、且难以将它们编码到单个提示中的场景。 Approaches similar to Swarm are best suited for situations dealing with a large number of independent capabilities and instructions that are difficult to encode into a single prompt.
对于希望获得完全托管的对话线程以及内置内存管理和检索功能的开发者而言，Assistants API 是一个很好的选择。 The Assistants API is a great option for developers looking for fully-hosted threads and built in memory management and retrieval. 而 Swarm 则是面向有兴趣了解多智能体编排的开发者的教育资源。 However, Swarm is an educational resource for developers curious to learn about multi-agent orchestration. Swarm（几乎）完全在客户端运行，并且与 Chat Completions API 非常相似，不会在调用之间存储状态。 Swarm runs (almost) entirely on the client and, much like the Chat Completions API, does not store state between calls.

运行 SwarmRunning Swarm
首先实例化一个 Swarm 客户端（其内部只是实例化一个 `OpenAI` 客户端）。 Start by instantiating a Swarm client (which internally just instantiates an `OpenAI` client). 
from swarm import Swarm

client = Swarm()
`client.run()``client.run()`
Swarm 的 `run()` 函数类似于 Chat Completions API 中的 `chat.completions.create()` 函数——它接收 `messages` 并返回 `messages`，且不在调用之间保存任何状态。 Swarm's `run()` function is analogous to the `chat.completions.create()` function in the Chat Completions API – it takes `messages` and returns `messages` and saves no state between calls. 不过，重要的是，它还会处理智能体的函数执行、交接（handoff）和上下文变量引用，并且可以在向用户返回结果之前进行多轮交互。 Importantly, however, it also handles Agent function execution, hand-offs, context variable references, and can take multiple turns before returning to the user.
Swarm 的 `client.run()` 核心实现了以下循环： At its core, Swarm's `client.run()` implements the following loop:
从当前智能体获取一次补全结果 Get a completion from the current Agent
执行工具调用并追加结果 Execute tool calls and append results
必要时切换智能体 Switch Agent if necessary
必要时更新上下文变量 Update context variables, if necessary
如果没有新的函数调用，则返回 If no new function calls, return

`client.run()` 完成后（期间可能多次调用智能体和工具），将返回一个 `Response`，其中包含所有相关的已更新状态。 Once `client.run()` is finished (after potentially multiple calls to agents and tools) it will return a `Response` containing all the relevant updated state. 具体而言，包括新的 `messages`、最后调用的 `Agent`，以及最新的 `context_variables`。 Specifically, the new `messages`, the last `Agent` to be called, and the most up-to-date `context_variables`. 你可以将这些值（连同新的用户消息）传入下一次 `client.run()` 调用，从上次停止的位置继续交互——这与 `chat.completions.create()` 非常相似。 You can pass these values (plus new user messages) in to your next execution of `client.run()` to continue the interaction where it left off – much like `chat.completions.create()`. （`/swarm/repl/repl.py` 中的 `run_demo_loop` 函数实现了一个完整执行循环的示例。） (The `run_demo_loop` function implements an example of a full execution loop in `/swarm/repl/repl.py`.)

智能体Agents
一个 `Agent` 只是将一组 `instructions` 与一组 `functions`（以及下文所述的一些附加设置）封装在一起，并具备将执行权移交给另一个 `Agent` 的能力。 An `Agent` simply encapsulates a set of `instructions` with a set of `functions` (plus some additional settings below), and has the capability to hand off execution to another `Agent`.
虽然人们很容易将 `Agent` 拟人化为“执行 X 的某个人”，但它也可以用来表示由一组 `instructions` 和 `functions` 定义的非常具体的工作流或步骤（例如一组步骤、一次复杂检索、数据转换中的单个步骤等）。 While it's tempting to personify an `Agent` as "someone who does X", it can also be used to represent a very specific workflow or step defined by a set of `instructions` and `functions` (e.g. a set of steps, a complex retrieval, single step of data transformation, etc). 这使得多个 `Agent` 可以组合成一个由“智能体”“工作流”和“任务”构成的网络，所有这些都由同一种基本构件表示。 This allows `Agent`s to be composed into a network of "agents", "workflows", and "tasks", all represented by the same primitive.
`Agent` 字段`Agent` Fields
| Field            | Type                     | Description                                                                   | Default                      |
| **name**         | `str`                    | The name of the agent.                                                        | `"Agent"`                    |
| **model**        | `str`                    | The model to be used by the agent.                                            | `"gpt-4o"`                   |
| **instructions** | `str` or `func() -> str` | Instructions for the agent, can be a string or a callable returning a string. | `"You are a helpful agent."` |
| **functions**    | `List`                   | A list of functions that the agent can call.                                  | `[]`                         |
| **tool_choice**  | `str`                    | The tool choice for the agent, if any.                                        | `None`                       |
指令Instructions
`Agent` 的 `instructions` 会直接转换为对话的 `system` 提示词（作为第一条消息）。 `Agent` `instructions` are directly converted into the `system` prompt of a conversation (as the first message). 在任何给定时刻，都只会存在当前活动 `Agent` 的 `instructions`（例如，如果发生 `Agent` 交接，`system` 提示词会改变，但聊天历史不会改变）。 Only the `instructions` of the active `Agent` will be present at any given time (e.g. if there is an `Agent` handoff, the `system` prompt will change, but the chat history will not.) 
agent = Agent(
   instructions="You are a helpful agent."
)
`instructions` 可以是普通的 `str`，也可以是返回 `str` 的函数。 The `instructions` can either be a regular `str`, or a function that returns a `str`. 该函数可以选择接收一个 `context_variables` 参数，其值由传入 `client.run()` 的 `context_variables` 填充。 The function can optionally receive a `context_variables` parameter, which will be populated by the `context_variables` passed into `client.run()`. 
def instructions(context_variables):
   user_name = context_variables["user_name"]
   return f"Help the user, {user_name}, do whatever they want."

agent = Agent(
   instructions=instructions
)
response = client.run(
   agent=agent,
   messages=[{"role":"user", "content": "Hi!"}],
   context_variables={"user_name":"John"}
)
print(response.messages[-1]["content"])
Hi John, how can I assist you today?
函数Functions
Swarm 的 `Agent` 可以直接调用 Python 函数。 Swarm `Agent`s can call python functions directly.
函数通常应返回 `str`（系统会尝试将返回值转换为 `str`）。 Function should usually return a `str` (values will be attempted to be cast as a `str`).
如果函数返回一个 `Agent`，执行权将转移给该 `Agent`。 If a function returns an `Agent`, execution will be transferred to that `Agent`.
如果函数定义了一个 `context_variables` 参数，其值将由传入 `client.run()` 的 `context_variables` 填充。 If a function defines a `context_variables` parameter, it will be populated by the `context_variables` passed into `client.run()`. 
def greet(context_variables, language):
   user_name = context_variables["user_name"]
   greeting = "Hola" if language.lower() == "spanish" else "Hello"
   print(f"{greeting}, {user_name}!")
   return "Done"

agent = Agent(
   functions=[greet]
)

client.run(
   agent=agent,
   messages=[{"role": "user", "content": "Usa greet() por favor."}],
   context_variables={"user_name": "John"}
)
Hola, John!
如果 `Agent` 的函数调用出现错误（函数缺失、参数错误、执行出错），则会向聊天记录追加一条错误响应，以便 `Agent` 能够妥善恢复。 If an `Agent` function call has an error (missing function, wrong argument, error) an error response will be appended to the chat so the `Agent` can recover gracefully.
如果 `Agent` 调用了多个函数，这些函数将按调用顺序执行。 If multiple functions are called by the `Agent`, they will be executed in that order.
交接与上下文变量更新Handoffs and Updating Context Variables
`Agent` 可以通过在 `function` 中返回另一个 `Agent`，将控制权移交给该 `Agent`。 An `Agent` can hand off to another `Agent` by returning it in a `function`. 
sales_agent = Agent(name="Sales Agent")

def transfer_to_sales():
   return sales_agent

agent = Agent(functions=[transfer_to_sales])

response = client.run(agent, [{"role":"user", "content":"Transfer me to sales."}])
print(response.agent.name)
Sales Agent
它还可以通过返回一个更完整的 `Result` 对象来更新 `context_variables`。 It can also update the `context_variables` by returning a more complete `Result` object. 该对象还可以包含 `value` 和 `agent`，以便在需要时通过单个函数返回值、更新智能体并更新上下文变量（或执行这三项操作的任意子集）。 This can also contain a `value` and an `agent`, in case you want a single function to return a value, update the agent, and update the context variables (or any subset of the three). 
sales_agent = Agent(name="Sales Agent")

def talk_to_sales():
   print("Hello, World!")
   return Result(
       value="Done",
       agent=sales_agent,
       context_variables={"department": "sales"}
   )

agent = Agent(functions=[talk_to_sales])

response = client.run(
   agent=agent,
   messages=[{"role": "user", "content": "Transfer me to sales"}],
   context_variables={"user_name": "John"}
)
print(response.agent.name)
print(response.context_variables)
Sales Agent
{'department': 'sales', 'user_name': 'John'}
> [!NOTE] > [!NOTE]
> 如果一个 `Agent` 调用多个函数以将控制权移交给某个 `Agent`，则只会使用最后一个移交函数。 > If an `Agent` calls multiple functions to hand-off to an `Agent`, only the last handoff function will be used.
函数模式（Function Schemas）Function Schemas
Swarm 会自动将函数转换为 JSON Schema，并将其传入 Chat Completions 的 `tools`。 Swarm automatically converts functions into a JSON Schema that is passed into Chat Completions `tools`.
文档字符串会转换为函数的 `description`。 Docstrings are turned into the function `description`.
没有默认值的参数会被设为 `required`。 Parameters without default values are set to `required`.
类型提示会映射为参数的 `type`（默认为 `string`）。 Type hints are mapped to the parameter's `type` (and default to `string`).
目前尚未明确支持为每个参数提供描述，但只要将这些描述添加到文档字符串中，应该也能起到类似的作用。 Per-parameter descriptions are not explicitly supported, but should work similarly if just added in the docstring. （未来可能会增加对文档字符串中参数信息的解析。） (In the future docstring argument parsing may be added.) 
def greet(name, age: int, location: str = "New York"):
   """Greets the user. Make sure to get their name and age before calling.

   Args:
      name: Name of the user.
      age: Age of the user.
      location: Best place on earth.
   """
   print(f"Hello {name}, glad you are {age} in {location}!")
{
   "type": "function",
   "function": {
      "name": "greet",
      "description": "Greets the user. Make sure to get their name and age before calling.\n\nArgs:\n   name: Name of the user.\n   age: Age of the user.\n   location: Best place on earth.",
      "parameters": {
         "type": "object",
         "properties": {
            "name": {"type": "string"},
            "age": {"type": "integer"},
            "location": {"type": "string"}
         },
         "required": ["name", "age"]
      }
   }
}
流式传输Streaming
stream = client.run(agent, messages, stream=True)
for chunk in stream:
   print(chunk)
使用与 [Chat Completions API 流式传输](https://platform.openai.com/docs/api-reference/streaming)相同的事件。 Uses the same events as [Chat Completions API streaming](https://platform.openai.com/docs/api-reference/streaming). 示例请参见 `/swarm/repl/repl.py` 中的 `process_and_print_streaming_response`。 See `process_and_print_streaming_response` in `/swarm/repl/repl.py` as an example.
新增了两种事件类型： Two new event types have been added:
`{"delim":"start"}` 和 `{"delim":"end"}`，用于标记 `Agent` 每次处理单条消息（响应或函数调用）的开始和结束。 `{"delim":"start"}` and `{"delim":"end"}`, to signal each time an `Agent` handles a single message (response or function call). 这有助于识别不同 `Agent` 之间的切换。 This helps identify switches between `Agent`s.
为便于使用，`{"response": Response}` 会在流结束时返回一个 `Response` 对象，其中包含汇总后的完整响应。 `{"response": Response}` will return a `Response` object at the end of a stream with the aggregated (complete) response, for convenience.
