一句话

多 agent 的扩展上限可能在人的审查与判断能力：并发产出增加，未必带来更多可靠交付。

主要内容

  • Osmani 将“编排税”归因于启动与验收成本的不对称：派发任务很容易，但理解结果、处理冲突和合并修改仍消耗人的注意力。
  • 他借阿姆达尔定律和单线程锁作类比：当人工判断成为串行瓶颈，继续增加 agent 主要会拉长待审队列。
  • 负担还来自反复恢复上下文，以及担心后台任务出错。疲劳可能导致草率审查、放弃独立判断，继而积累技术债与认知债。
  • 建议按实际审查速率控制并发；把隔离、可异步验收的任务与高度依赖判断的复杂任务分开；集中审查，并让测试、截图等自动验证承担基础检查。
  • 人的完整思考时间也需要保护，避免全部被检查 agent 状态占据。

对 swarm scaling 的意义

这篇文章把扩展目标从“同时运行多少 agent”转向“单位时间能审查并交付多少可靠成果”。对需要人工验收的 swarm，任务隔离、自动验证与按审查能力施加背压，比单纯扩大数量更值得关注。其适用边界也很明确：文章讨论的是人参与判断与合并的开发流程，不能据此外推所有自主 swarm 的规模上限。
