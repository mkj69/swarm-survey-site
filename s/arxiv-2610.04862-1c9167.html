摘要Abstract
长时程问题求解与科学研究需要计算在连续的尝试中不断积累。 Long-horizon problem solving and scientific research require computation to accumulate across successive attempts. 部分解、实验发现，甚至未成功的方法，都可能对后续工作有用，但大多数推理时计算都是围绕单条轨迹或单个候选方案组织的，而非围绕持久保存、可复用的工作成果集合。 Partial solutions, experimental findings, and even unsuccessful approaches can become useful to later work, yet most inference-time computation is organized around individual trajectories or candidates rather than a persistent body of reusable work. 我们将这一范式称为累积式推理（compounding 1 引言1 Introduction
扩大推理时计算规模，可通过重复采样、更长的推理轨迹、搜索和多智能体协作来提升语言模型的性能 (Brown et al., 2024; Snell et al., 2024; Du et al., 2023)。 Scaling inference-time computation improves language model performance through repeated sampling, longer reasoning trajectories, search, and multi-agent collaboration (Brown et al., 2024; Snell et al., 2024; Du et al., 2023). 这些方法主要关注应如何使用额外的计算。 These approaches largely ask how additional computation should be spent. 长时程问题求解与科学研究提出了一个互补的挑战：有用的计算还必须在多次尝试之间不断积累。 Long-horizon problem solving and scientific research pose a complementary challenge: useful computation must also accumulate across attempts.
中间工作成果的价值在产生时往往尚不明确。 The value of intermediate work is often unknown when it is produced. 一次未成功的实验可能揭示一个有前景的方向；一个部分解可能确立某个很久以后才会用到的要素；相互竞争的方法中可能包含只有在组合后才有用的想法。 An unsuccessful experiment may reveal a promising direction; a partial solution may establish an ingredient used much later; competing approaches may contain ideas that become useful only when combined. 如果这些工作成果在一个回合结束时就消失，后续计算可能需要重新发现它们。 If such work disappears when an episode terminates, later computation may need to rediscover it. 将其保存下来，则能让后续智能体在累积的已有工作成果基础上继续推进。 Preserving it instead allows subsequent agents to build on an accumulated body of prior work. 我们将这一范式称为累积式推理：将推理时计算组织为一个持久保存、持续演进且可复用的工作成果集合。 We call this paradigm compounding inference: organizing inference-time computation into a persistent, evolving body of reusable work.
现有方法支持这一过程中的不同环节。 Existing approaches support different parts of this process. 独立采样探索多样化的候选方案，更长的推理轨迹在单个回合内保留工作成果，而多智能体系统则通常通过预定义角色、集中式规划或共享对话来实现协作 (Hong et al., 2024; Chen et al., 2024; Wang et al., 2025; Wu et al., 2023)。 Independent sampling explores diverse candidates, longer reasoning trajectories retain work within an episode, and multi-agent systems enable collaboration, often through predefined roles, centralized planning, or shared conversations (Hong et al., 2024; Chen et al., 2024; Wang et al., 2025; Wu et al., 2023). 另一些方法将先前尝试提炼为摘要，以指导后续推理 (Madaan et al., 2025; Venkatraman et al., 2025; Kim et al., 2026)。 Other approaches distill earlier attempts into summaries that guide subsequent inference (Madaan et al., 2025; Venkatraman et al., 2025; Kim et al., 2026). 我们研究一种不同的组织方式：独立工作智能体保留相互竞争的工作路线及其依赖关系，同时自主决定扩展哪些已有贡献。 We investigate a different organization: independent workers preserve competing lines of work and their dependencies, while deciding for themselves which previous contributions to extend.
我们在 GitSwarm 中实现了累积式推理，该系统使用一个共享且支持分支的 Git 仓库作为结构化持久记忆。 We instantiate compounding inference in GitSwarm, which uses a shared, branchable Git repository as structured persistent memory. 同质工作智能体异步运行，检查已有贡献，并独立决定是开展探索、实验、验证、改进，还是组合现有工作成果。 Homogeneous workers operate asynchronously, inspect previous contributions, and independently decide whether to explore, experiment, verify, refine, or combine existing work. 每项贡献均以原子提交的形式发布。 Each contribution is published as an atomic commit. 重要的是，GitSwarm 区分了工作智能体开始工作时所基于的仓库状态，以及其工作所依赖的其他已有贡献。 Importantly, GitSwarm distinguishes the repository state from which a worker begins from the additional prior contributions that its work depends on. 因此，显式语义依赖使工作智能体能够在扩展一个分支的同时，借鉴其他分支上的发现。 Explicit semantic dependencies therefore allow a worker to extend one branch while drawing on discoveries from others. 这既保留了相互竞争的方法，也保留了它们之间的联系。 This preserves competing approaches without losing the connections between them. 没有中央智能规划者分配任务或角色；执行框架负责调度和验证，而工作智能体则提名候选方案，供最终选择。 No central intellectual planner assigns tasks or roles; an execution harness manages scheduling and validation, while workers nominate candidates for final selection.
我们的评估涵盖两种场景。 Our evaluation spans two settings. 第一种是长时程问题求解，其中任务具有明确的目标和可验证的结果。 The first is long-horizon problem solving, where tasks have well-defined objectives and verifiable outcomes. 我们研究数学证明和程序重建。 We study mathematical proof and program reconstruction. 在 IMOProofBench-Advanced (Luong et al., 2025) 上，GitSwarm 使用 Codex (GPT-5.5-High) 工作智能体，以略低于一百万个输出 token 的用量，在一次运行中解决了全部 30 道题。 On IMOProofBench-Advanced (Luong et al., 2025), GitSwarm solves all 30 problems in one run using Codex (GPT-5.5-High) workers and slightly under one million output tokens. 在 ProgramBench (Yang et al., 2026) 上，使用 Codex (GPT-5.5-High) 工作智能体时，其平均得分达到 79.39%，而在相当的计算预算下，Forced Codex 的平均得分为 65.12%；Forced Codex 是一个被反复提示继续工作的单个 Codex (GPT-5.5-High) 智能体。 On ProgramBench (Yang et al., 2026), with Codex (GPT-5.5-High) workers, it achieves a 79.39% mean score, as compared to 65.12% for Forced Codex - a single Codex (GPT-5.5-High) agent repeatedly prompted to continue, at a comparable compute budget. 在所测试的范围内，平均性能随推理时计算量的增加而提升。 Mean performance improves with inference-time computation over the tested ranges.
第二种场景是持续性实验研究，其中智能体必须决定开展哪些实验，并从实验结果中学习。 The second setting is sustained experimental research, where agents must decide which experiments to run and learn from their outcomes. 我们在 Residual Matrix Transformer (Mak and Flanigan, 2025)、Looped Transformer (Geiping et al., 2025) 和 NanoChat 上评估 GitSwarm。 We evaluate GitSwarm on Residual Matrix Transformer (Mak and Flanigan, 2025), Looped Transformer (Geiping et al., 2025), and NanoChat. 在全部三个任务中，GitSwarm 均在各自的初始基线之上取得了改进。 GitSwarm improves upon the respective starting points in all three tasks. 在 Residual Matrix Transformer 上，使用相同的 1.3B-token 训练预算，两种配置在留出集上的损失分别达到 2.890 和 2.894，而参考配置为 3.147。 On Residual Matrix Transformer, two configurations achieve held-out losses of 2.890 and 2.894, compared with 3.147 for the reference, using the same 1.3B-token training budget. 由此形成的研究历程表明，工作智能体会结合在不同分支上开发的架构改动，并重新审视最初未成功的实验。 The resulting research histories show workers combining architectural changes developed on separate branches and revisiting initially unsuccessful experiments.
除了最终性能，我们还考察先前的计算是否确实得到了积累。 Beyond final performance, we examine whether earlier computation actually accumulates. 在所分析的 ProgramBench 运行中，94.7% 的贡献随后被引用；在各预算下，所选解的传递祖先平均覆盖贡献图的 81.6–92.6%，这主要通过显式声明的跨分支依赖实现。 Across the analyzed ProgramBench runs, 94.7% of contributions are subsequently referenced, and the selected solution’s transitive ancestry covers 81.6–92.6% of the contribution graph on average across budgets, largely through declared cross-branch dependencies. 执行轨迹提供了独立的证据，表明工作智能体确实使用了先前的产物。 Execution traces provide separate evidence that workers consume earlier artifacts. 数学证明呈现出不同的模式：即使先前工作没有进入所选证明的祖先集合，工作智能体也经常复用这些工作来验证和比较候选方案。 Mathematical proof exhibits a different pattern: workers frequently reuse previous work to verify and compare candidates even when that work does not enter the selected proof’s ancestry. 这些结果共同表明，持久化记忆既能支持对先前贡献的综合，也能支持证据的积累，以指导后续计算。 Together, these results show that persistent memory can support both the synthesis of earlier contributions and the accumulation of evidence that guides subsequent computation.
因此，我们的贡献有三个方面：将复合推理（compounding inference）表述为一种跨工作轮次积累可复用的推理时计算的范式；提出 GitSwarm，作为一种基于持久化、可分支且具有显式跨分支依赖的贡献的具体实现；并在问题求解和持续性实验研究中，同时评估任务性能与积累过程本身。 Our contributions are therefore threefold: we formulate compounding inference as a paradigm for accumulating reusable inference-time computation across episodes; we introduce GitSwarm as a concrete realization based on persistent, branchable contributions with explicit cross-branch dependencies; and we evaluate both task performance and the accumulation process itself across problem solving and sustained experimental research.
2 GitSwarm2 GitSwarm
GitSwarm 通过在共享 Git 仓库上协作的异步、同质工作智能体实现复合推理。 GitSwarm implements compounding inference through asynchronous, homogeneous workers collaborating over a shared Git repository. 工作智能体独立决定如何推进任务，而执行框架负责管理并发、隔离、验证和发布。 Workers independently decide how to advance the task, while an execution harness manages concurrency, isolation, validation, and publication. 仓库以可分支计算图的形式保存中间工作成果。 The repository preserves intermediate work as a branchable computation graph.
2.1 设计原则2.1 Design Principles
我们希望在不预先规定智能体应如何组织工作的情况下积累计算。 We seek to accumulate computation without prescribing how agents should organize their work. 这要求共享记忆具备三个属性：持久性，使中间发现能够在其创建者结束工作后继续保留；可分支性，使相互竞争的方法能够发展，而不必过早确定单一解；以及可归因性，使后续工作智能体能够识别贡献之间的依赖关系，包括跨分支的依赖关系。 This requires three properties of the shared memory: persistence, so intermediate discoveries survive their authors; branchability, so competing approaches can develop without prematurely committing to a single solution; and attribution, so subsequent workers can identify dependencies between contributions, including across branches. 这些属性支持自适应的去中心化控制：工作智能体根据不断演变的共享状态，独立选择要探索、验证、改进或组合的内容。 These properties support adaptive, decentralized control: workers independently choose what to explore, verify, refine, or combine based on the evolving shared state. 执行框架协调执行，但不分配智力工作角色，也不规定问题求解阶段的先后顺序。 The harness coordinates execution but does not assign intellectual roles or prescribe a sequence of problem-solving stages.

2.3 异步工作智能体协议2.3 Asynchronous Worker Protocol
一次运行的预算为 $B$ 个计入预算的工作智能体执行轮次，最大并发数为 $C$。 A run has a budget of $B$ charged worker episodes and maximum concurrency $C$ . 运行框架维持最多 $C$ 个活跃工作智能体，并在并发槽位空出时启动新的工作智能体进行补充。 The harness maintains up to $C$ active workers, launching replacements as slots become available. 所有工作智能体使用相同的模型并遵循相同的行为约定，不预设角色。 All workers use the same model and behavioral contract, without predefined roles.
每个工作智能体都在独立的 Git 工作树中运行。 Each worker operates in an isolated Git worktree. 它检查代码仓库，选择一个起始提交，并自主决定如何推进任务。 It inspects the repository, selects a starting commit, and independently decides how to advance the task. 每个执行轮次均以下列三种操作之一结束： Each episode ends with one of three actions:
贡献：发布一个经过验证的原子提交，其中包含部分解决方案、实验、测试或改进等新工作。 Contribute: Publish one validated, atomic commit containing new work, such as a partial solution, experiment, test, or refinement. 验证用于落实特定任务的发布要求，而非确保解决方案的正确性。 Validation enforces task-specific publication requirements, not solution correctness.
提名：选择一个现有候选方案，发布一条独立的提名记录并说明理由，不修改该候选方案。 Nominate: Select an existing candidate and publish a separate nomination record with a rationale, without modifying the candidate.
弃权：在未发现有用的额外工作，或同等工作已在进行时，不发布任何内容便结束执行。 Abstain: Terminate without publication when no useful additional work is identified or equivalent work is already underway.
自愿弃权会触发工作智能体的补充，且不消耗 $B$，但会产生推理成本；其他执行轮次结果则会消耗预算。 Voluntary abstentions trigger replacement without consuming $B$ , although they incur inference costs; other episode outcomes consume the budget. 因此，工作智能体可以在探索、改进、实验、验证、整合和选择之间自适应地分配精力。 Workers may therefore allocate effort adaptively among exploration, refinement, experimentation, verification, integration, and selection.
2.4 实时群体状态：仪表板与进行中的活动2.4 Live Swarm State: Dashboard and In-Flight Activity
工作智能体还可以通过两个接口了解当前运行状态及其他工作智能体正在开展的工作；这两个接口只报告状态，不分配工作（图 2）。 Workers also see the current state of the run and what their peers are doing, through two interfaces that report state but do not assign work (Figure 2).
仪表板。 Dashboard. 每个工作智能体在启动时都会收到一份仪表板快照，并可通过 gs_dashboard 查询实时状态。 Every worker receives a dashboard snapshot at spawn time and can query the live state with gs_dashboard. 仪表板报告剩余的工作智能体预算、正在运行的工作智能体以及提名票数统计，并注明票数并非正确性的证据。 It reports the remaining worker budget, the workers in flight, and the nomination tally, noting that votes are not evidence of correctness. 对于采用实际运行时间预算并依据验证分数选择最终模型的研究任务，预算和提名字段被替换为共享 GPU、CPU 和作业的使用情况、GPU 利用率偏低时的警告，以及最佳验证分数及其对应的提交。 For research tasks, which use a wall-clock budget and select the final model by validation score, the budget and nomination fields are replaced by shared GPU, CPU, and job usage, a warning when GPU utilization is low, and the best validation score with its commit.
进行中的活动。 In-flight activity. 由于未提交的工作在代码仓库中不可见，每个工作智能体都通过 gs_inflight 维护一份公开的活动日志。 Since uncommitted work is invisible in the repository, each worker keeps a public activity log via gs_inflight. 它在编辑前声明工作范围（待填补的空缺、交付成果、成功标准和中止标准），并发布进度更新。 It announces its scope (gap, deliverable, success and abort criteria) before editing and posts progress updates. 其他工作智能体可以列出活跃的工作智能体，或查看某个工作智能体的日志和未提交的更改，但无法修改这些内容。 Peers can list active workers or inspect a worker’s log and uncommitted changes, but cannot modify them. 此举旨在帮助工作智能体避免接手其他正在运行的工作智能体已经开展的工作。 This is meant to help workers avoid taking up work which is already being undertaken by their in-flight peers.

4 讨论与局限性4 Discussion and Limitations
我们的结果揭示了复利式推理（compounding inference）的不同形式。 Our results reveal different forms of compounding inference. 在程序重建中，工作智能体反复整合来自不同分支的发现，形成能力不断增强的解决方案。 In program reconstruction, workers repeatedly integrate discoveries from different branches into increasingly capable solutions. 在数学证明中，工作智能体经常利用先前工作来验证和比较候选证明，而不延伸所选证明的谱系。 In mathematical proof, workers often use previous work to verify and compare candidates without extending the selected proof’s lineage. 架构研究实验既展示了跨分支综合的作用，也体现了重新审视早期失败的价值：RMT 架构融合了在不同分支上开发的机制，而 Looped Transformer 运行则通过进一步评估重新采用了一个最初被否决的想法。 The architecture research experiments illustrate both cross-branch synthesis and the value of revisiting earlier failures: the RMT architecture incorporates mechanisms developed on separate branches, while the Looped Transformer run recovers an initially rejected idea through further evaluation. 因此，有用的计算不一定直接体现在最终候选方案的祖先谱系中；它也可能为追求、否决或选择哪些方向提供依据。 Useful computation therefore need not appear directly in the final candidate’s ancestry; it may also inform which directions are pursued, rejected, or selected.
因果归因。 Causal attribution. 我们的依赖关系分析和执行轨迹分析证实，工作智能体会查阅、复用并积累先前工作，但未能分离出由此带来的性能增益。 Our dependency and execution-trace analyses establish that workers inspect, reuse, and accumulate previous work, but do not isolate the resulting performance gains. 必填的 informed_by= 字段记录了工作智能体自行声明的依赖关系，而观测到的产物使用行为提供的是使用证据，而非因果影响的证据。 The mandatory informed_by= field records worker-declared dependencies, while observed artifact consumption provides evidence of use rather than causal influence. 反过来，所选解决方案的祖先谱系会遗漏可能有用的验证和候选方案比较工作。 Conversely, selected-solution ancestry omits potentially useful verification and candidate comparison. 一种直接的干预方法是从同一个候选方案恢复相互匹配的运行，在剩余计算资源相同的条件下，分别允许和禁止访问该候选方案之前的研究历史。 A direct intervention would resume matched runs from the same candidate, with and without access to its preceding research history, under equal remaining compute. 要分离持久性、可分支性和跨分支依赖关系的影响，还需要分别进行干预。 Separate interventions would be needed to isolate the effects of persistence, branchability, and cross-branch dependencies. 我们的合成实验展示了它们在运行层面的益处，但未能确立它们各自对基准性能的贡献。 Our synthetic experiments demonstrate their operational benefits but do not establish their individual contributions to benchmark performance.
评估范围。 Evaluation scope. 我们的结果以所评估的任务和预算为条件。 Our results are conditional on the evaluated tasks and budgets. ProgramBench 性能是在总计 200 个任务中的一个固定的 50 个任务子集上测得的。 ProgramBench performance is measured on a fixed 50-task subset out of a total of 200 tasks. IMOProofBench-Advanced 的满分结果来自单次运行；一些独立采样基线和 Forced 基线也达到了该基准的性能上限，而且部分证明比较的执行条件存在差异。 The perfect IMOProofBench-Advanced result is a single run; some independent-sampling and Forced baselines also reach the benchmark ceiling, and execution conditions differ across some proof comparisons. 在 AutoResearch 中，RMT 群体模型与参照模型采用相同的 1.3B 训练词元预算，而用于比较的单智能体模型使用了更多训练词元。 In AutoResearch, the RMT swarm models and reference share the same 1.3B-token training budget, whereas the compared single-agent models use more training tokens. 以既有研究为种子的 RMT 运行还继承了更早的研究成果。 The seeded RMT run additionally inherits earlier research. 所记录的 Looped Transformer 运行当时仍在进行中，而 NanoChat 各比较实验的起始检查点和 GPU 分配有所不同。 The recorded Looped Transformer runs were still in progress, and NanoChat comparisons vary in starting checkpoint and GPU allocation. GitSwarm 在所有三个研究任务中都相较于起点取得了改进，但这些结果并不能确立其优于所有单智能体配置。 GitSwarm improves upon the starting points across all three research tasks, but the results do not establish superiority over every single-agent configuration.

5 结论5 Conclusion
我们提出了复利式推理，其中中间工作得以持久保存，并可在独立的智能体执行轮次之间继续扩展。 We introduced compounding inference, in which intermediate work persists and can be extended across independent agent episodes. GitSwarm 通过异步工作智能体、共享的可分支代码仓库以及显式跨分支依赖关系，为这一过程提供了基础设施，无需中央智能规划者。 GitSwarm provides a substrate for this process through asynchronous workers, a shared branchable repository, and explicit cross-branch dependencies, without a central intellectual planner. 在问题求解和依托 GPU 的研究中，我们观察到先前工作被广泛复用，包括综合独立发现，以及重新采用最初未获成功的想法。 Across problem solving and GPU-backed research, we observe extensive reuse of earlier work, including the synthesis of independent discoveries and the recovery of initially unsuccessful ideas. 我们将这一基础设施视为长时间跨度发现过程的基础。 We view this substrate as a foundation for long-horizon discovery. 它支持一个持续循环：智能体提出想法、开展实验、保存发现，并利用先前证据指导新的研究。 It supports a continuing loop in which agents propose ideas, run experiments, preserve their findings, and use earlier evidence to guide new research. 一个自然的下一步是在这一环境中，针对多种任务通过强化学习训练智能体。 A natural next step is to train agents with reinforcement learning across diverse tasks within this environment. 这种训练可以激励那些价值通过后续工作才显现出来的贡献，而不只是奖励单个执行轮次的结果，从而使智能体不仅学会解决问题，还学会推动集体发现过程。 Rather than rewarding only the outcome of an individual episode, such training could incentivize contributions whose value emerges through subsequent work, enabling agents to learn not just to solve problems, but to advance a collective process of discovery.

(2022) 将这一思想引入现代神经架构，使学习得到的专门化模块能够通过容量有限的共享工作空间进行通信。 Shanahan developed computational realizations of this principle in cognitive and neural architectures based on competition and global broadcast (Shanahan, 2006; Shanahan, 2008), and Goyal et al. (2022) brought the idea to modern neural architectures, allowing learned specialist modules to communicate through a capacity-limited shared workspace.
GitSwarm 继承了共享工作空间原则，但改变了工作空间在时间和结构上的作用。 GitSwarm inherits the shared-workspace principle but changes the temporal and structural role of the workspace. GitSwarm 并非维护一种临时的公共状态，以协调认知周期或神经网络前向传播过程中的计算，而是跨智能体运行轮次保留明确的贡献历史。 Rather than maintaining a transient common state for coordinating computation within a cognitive cycle or neural forward process, GitSwarm preserves an explicit history of contributions across agent episodes. 该工作空间具有持久性且可创建分支，并明确记录各项贡献之间的依赖关系，使相互竞争的工作路线能够持续保留，并在之后重新组合。 The workspace is durable and branchable, and dependencies between contributions are recorded explicitly, allowing competing lines of work to persist and later recombine. 因此，我们关注的不仅是通过共享状态进行协调，还包括在较长时间跨度内积累可复用的计算成果。 Our focus is therefore not only coordination through shared state, but the accumulation of reusable computation over long horizons.
自主实验与进化搜索。 Autonomous experimentation and evolutionary search. Karpathy 的 AutoResearch 在单智能体循环中反复修改、训练和评估 NanoChat 模型 (Karpathy, 2026)。 Karpathy’s AutoResearch repeatedly modifies, trains, and evaluates a NanoChat model in a single-agent loop (Karpathy, 2026). The AI Scientist 将从创意生成到论文撰写的各个阶段自动化 (Lu et al., 2024)，而 AI Scientist-v2 则采用由实验管理器指导的渐进式智能体树搜索 (Yamada et al., 2025)。 The AI Scientist automates stages from idea generation to paper writing (Lu et al., 2024), while AI Scientist-v2 uses progressive agentic tree search directed by an experiment manager (Yamada et al., 2025). Agent Laboratory 将文献综述、实验和写作组织为分阶段的研究工作流程 (Schmidgall et al., 2025)。 Agent Laboratory organizes literature review, experimentation, and writing into a staged research workflow (Schmidgall et al., 2025).
AlphaEvolve 维护一个经过评估的程序种群，并利用进化选择来发现算法 (Novikov et al., 2025)。 AlphaEvolve maintains an evaluated population of programs and uses evolutionary selection for algorithm discovery (Novikov et al., 2025). AIRA2 将智能体实验、一致的评估和异步多 GPU 执行相结合 (Hambardzumyan et al., 2026)。 AIRA2 combines agentic experimentation, consistent evaluation, and asynchronous multi-GPU execution (Hambardzumyan et al., 2026). 这些系统展示了实验反馈、持久保留的候选池和并行研究的价值。 These systems demonstrate the value of experimental feedback, persistent candidate pools, and parallel research.
我们的问题是：在没有中央智能体选择每个后续实验的情况下，独立的研究轮次如何进一步将假设、失败的实验、代码和支持证据保存在可审计的贡献图中。 Our question is how independent research episodes can additionally preserve hypotheses, failed experiments, code, and supporting evidence in an auditable contribution graph, without a central agent selecting each next experiment. 第 3.3 节中的研究历史展示了跨分支的架构综合，以及对最初被否决结果的后续重新考量。 The research histories in Section 3.3 illustrate cross-branch architectural synthesis and the later reconsideration of initially rejected results. 这些观察结果展示了复用现象，但其本身并不能确立复用对性能的因果影响。 These observations demonstrate reuse, but do not by themselves establish its causal effect on performance.
此前关于自主研究的工作确立了组织实验搜索的互补方法。 Earlier work on autonomous research establishes complementary ways to organize experimental search. AIRA (Toledo et al., 2025) 研究搜索策略与算子在机器学习研究中如何相互作用，而 AI Co-Scientist (Gottweis et al., 2025) 则利用异步智能体和基于锦标赛的迭代改进来形成科学假设。 AIRA (Toledo et al., 2025) studies how search policies and operators interact in machine learning research, while AI Co-Scientist (Gottweis et al., 2025) uses asynchronous agents and tournament-based refinement to develop scientific hypotheses. Darwin Gödel Machine (Zhang et al., 2025) 维护一个不断扩展的编码智能体档案库，并通过实证验证能够改进智能体自身的修改。 The Darwin Gödel Machine (Zhang et al., 2025) maintains an expanding archive of coding agents, empirically validating modifications that improve the agents themselves. ARTS (Juneja et al., 2026) 使用中央推理模型检查先前实验的日志，并选择扩展搜索树中的哪个节点，将薄弱的假设与有缺陷的实现区分开来，而不是按得分对节点排序。 ARTS (Juneja et al., 2026) uses a central reasoning model to inspect the logs of earlier experiments and choose which node of a search tree to expand, separating weak hypotheses from flawed implementations rather than ranking nodes by score. 由于这个科学家智能体承担整个搜索过程，ARTS 将不断增长的历史压缩为简短的书面见解，并在一种变体中通过测试时训练将其融入模型权重，最终返回经过验证的最佳节点。 Because this scientist carries the entire search, ARTS condenses the growing history into short written insights and, in a variant, into the model’s weights via test-time training, and it returns the best validated node. GitSwarm 没有中央科学家智能体：独立的工作智能体每次都从全新的上下文开始，从一个共享、受版本控制且从不被摘要化或剪枝的持久仓库中检索所需内容；它们可以将不同分支合并为一项贡献，并在不存在可靠验证得分时，通过去中心化提名选择最终解决方案。 GitSwarm has no central scientist: independent workers, each starting with a fresh context, retrieve what they need from a shared version-controlled persistent repository that is never summarized or pruned, can combine separate branches into a single contribution, and select the final solution through decentralized nomination when no reliable validation score exists. GitSwarm 则保持工作智能体的模型固定，并积累针对外部研究任务的贡献。 GitSwarm instead keeps the worker model fixed and accumulates contributions to an external research task. 其仓库保留相互竞争的实验，包括未成功的实验，并明确记录各项贡献之间的依赖关系。 Its repository preserves competing experiments, including unsuccessful ones, with explicit dependencies between contributions.
Meta-Harness (Lee et al., 2026) 使用单个负责提出候选方案的编码智能体，对 LLM 运行框架（harness）的代码进行搜索；该智能体从文件系统中读取所有先前候选方案的源代码、得分和执行轨迹。 Meta-Harness (Lee et al., 2026) searches over the code of LLM harnesses with a single coding-agent proposer that reads the source code, scores, and execution traces of all prior candidates from a filesystem. 与 GitSwarm 一样，它提供完整、未经压缩的历史以供选择性检索，而不是对历史进行摘要。 Like GitSwarm, it exposes the full, uncompressed history for selective retrieval rather than summarizing it. 然而，它的搜索按顺序迭代进行，存储的每个候选方案都是一个完整的运行框架，在固定的搜索集上接受评估，并记录在为各候选方案预定义的目录中。 Its search, however, proceeds in sequential iterations, and every stored candidate is a complete harness, evaluated on a fixed search set and logged in a predefined per-candidate directory. 相比之下，GitSwarm 的贡献可以是范围有限的局部工作，由后续工作智能体继续扩展，从而提供更高的分支因子，允许开展更多探索。 GitSwarm contributions can instead be bounded partial work that later workers extend, providing a higher branching factor and thus allowing more exploration. 分支和显式依赖关系使多个异步工作智能体能够在版本控制下并发地基于彼此的工作继续构建；除少量核心目录结构外，工作智能体自行选择保留哪些产物。 Branches and explicit dependencies let many asynchronous workers build on one another concurrently under version control, and beyond a small core layout, workers choose which artifacts to leave. GitSwarm 还应用于程序重建、证明搜索和架构研究，而非仅针对单一类别的产物。 GitSwarm is also applied across program reconstruction, proof search, and architecture research rather than to a single class of artifact.

C.1 持久性：隐藏规则集C.1 Persistence: Hidden Rulebook

C.2 可分支性：隐藏迷宫C.2 Branchability: Hidden Maze
任务生成。Task generation.
迷宫是一棵随机生成的、最大深度为 $D$ 的有根树。 The maze is a randomly generated rooted tree of maximum depth $D$ . 在广度优先生成过程中，每个深度小于 $D$ 的房间都会随机采样零到 $N$ 个子节点；我们保留达到深度 $D$ 的树，并将宝藏放置在从最深层叶节点中均匀随机选取的一个节点上。 During breadth-first generation, each room at depth less than $D$ samples between zero and $N$ children; we retain trees that reach depth $D$ and place the treasure at a uniformly sampled deepest leaf. 房间和出口的 ID 均不透露其含义。 Room and exit IDs are opaque. 工作者始终无法看到整棵树的全貌：其当前状态仅显示当前房间、可见出口、返回前一个房间的出口，以及该房间是否为死胡同或是否包含宝藏。 A worker never sees the tree globally: its current state reveals only the current room, its visible exits, the exit returning to the preceding room, and whether the room is a dead end or contains the treasure. 通过任何可见出口移动都消耗一步，包括沿先前探索过的路线折返的移动。 A move through any visible exit costs one step, including moves that retrace previously explored routes. 因此，工作智能体可以实际回溯，但这样做也会消耗其有限的预算（图 13）。 Thus a worker may backtrack physically, but doing so also spends its limited budget (Figure 13).
图 13：Hidden Maze 示例。 Figure 13: Hidden Maze example. 可恢复的端点使新的工作智能体能够探索从 B 出发的另一个出口，而无需再次承担从入口到该端点的路径成本。 A restorable endpoint lets a new worker explore another exit from B without paying again for the path from the entrance. 嵌套目录记录了每条轨迹是从哪个端点延伸的。 Nested directories record which endpoint each trajectory extended.
接口与记忆处理条件。Interface and memory treatments.
每个工作智能体都有一个受限的 bash(command) 工具和一个可写的 current_state.json。 Every worker has a restricted bash(command) tool and a writable current_state.json. 调用 move(exit_id, rationale) 会从该文件中存储的房间出发进行移动，消耗一步，并将文件内容替换为新的房间状态。yield_worker(summary) 会结束本轮运行。 The call move(exit_id, rationale) moves from the room stored in this file, costs one step, and replaces it with the new room state. yield_worker(summary) ends the episode. 在允许恢复已保存状态的处理条件中，只能在第一次移动之前将检查点复制到 current_state.json；此后，工作智能体沿一条连续的实际轨迹移动。 Where a treatment makes saved states restorable, a checkpoint can be copied to current_state.json only before the first move; afterward, the worker follows one continuous physical trajectory. 运行框架会验证每个恢复的检查点，并在本轮运行结束后提交最终状态，因此工作智能体无法伪造状态或修改先前的工作。 The harness validates every restored checkpoint and commits the final state after the episode, so workers cannot fabricate states or modify previous work. 我们比较了三种文件系统记忆组织方式： We compare three filesystem memory organizations:
扁平持久记忆将此前的所有移动存储在 memory/paths.jsonl 中，但每个工作智能体都从入口出发，且任何已保存状态都无法恢复，因此工作智能体必须实际重走任何已知的路径前缀。 Flat persistent memory stores all earlier moves in memory/paths.jsonl, but every worker starts at the entrance and no saved state is restorable, so a worker must physically retrace any known prefix.
非结构化可续接记忆将端点文件存储在 memory/nodes/ 下；工作智能体可以将其中一个文件复制到 current_state.json，但其提示词并未提及这一可能性。 Unstructured resumable memory stores endpoint files under memory/nodes/; a worker can copy one to current_state.json, but its prompt does not mention this possibility.
分支原生记忆将每条已完成的轨迹存储为其续接端点下的一个子目录，从而形成一棵检查点树。 Branch-native memory stores every completed trajectory as a child directory beneath the endpoint it resumed, forming a tree of checkpoints. 其提示词明确要求工作智能体查看这棵树、选择一个端点，并在继续探索之前恢复该端点的 checkpoint.json。 Its prompt explicitly asks the worker to inspect the tree, select an endpoint, and restore its checkpoint.json before continuing exploration. 选择叶节点会延续一条分支，而选择已有子节点的端点则会创建一条兄弟分支。 Selecting a leaf continues a branch, while selecting an endpoint with existing children creates a sibling branch. 因此，分支原生记忆使后续探索能够直接利用先前的端点及其相互关系。 Branch-native memory thus makes both earlier endpoints and their relationships directly available for subsequent exploration.
在所有处理条件中，先前的记忆均为只读。 Previous memory is read-only in all treatments.

E.2.1 任务细节E.2.1 Task Details
架构。Architecture.
残差矩阵 Transformer（RMT；Mak and Flanigan, 2025）用外积记忆矩阵取代 transformer 的残差向量：每一层通过学习得到的读取键从矩阵中检索其输入，并将其输出以学习得到的写入键与值的外积形式存回矩阵。 The Residual Matrix Transformer (RMT; Mak and Flanigan, 2025) replaces the transformer’s residual vector with an outer-product memory matrix: each layer retrieves its input from the matrix through learned read keys and stores its output back as outer products of learned write keys and values. 这使得残差流的规模能够独立于参数量和计算量进行扩展。 This lets the residual stream be scaled independently of parameters and compute.
任务规范。Task specification.
智能体群必须从作者的 JAX 实现出发，开发一种架构经过改进的 RMT，保留矩阵值残差流，参数量不超过 350M，并在提供的 6.5B-token OpenWebText 数据流上从头训练。 Starting from the authors’ JAX implementation, the swarm must develop an architecturally improved RMT that retains a matrix-valued residual stream and has at most 350M parameters, trained from scratch on a supplied 6.5B-token OpenWebText stream. 搜索指标是在包含 4,873 个样例的受保护开发集上的下一 token 交叉熵（512 个上下文 token，另有一个留出的目标 token）；参考模型是在 1.3B 个 token 上训练的 305M RMT（开发集损失为 3.158）。 The search metric is next-token cross-entropy on the 4,873-example protected development set (512 context tokens, one withheld target token); the reference is a 305M RMT trained on 1.3B tokens (development loss 3.158). 最终的留出集损失（例如参考模型的 3.147）来自单独的留出评估。 Final held-out losses, such as the reference’s 3.147, come from a separate held-out evaluation. 该任务明确优先考虑根本性的架构变更，而非超参数或配置调优。 The task explicitly prioritizes fundamental architectural changes over hyperparameter or configuration tuning.

E.2.5 关于研究过程的发现E.2.5 Findings about the Research Process
小规模筛选在早期具有参考价值，在后期却产生了误导。 Small-scale screening was informative early and misleading late. 在 72 小时运行期间，从小型代理模型推广到完整规模的 17 个想法中，有 15 个带来了改进；在延长期内，8 个想法中仅有 1 个带来了改进，而且有几个想法在完整规模下的效果由正转负。 During the 72-hour run, 15 of 17 ideas promoted from the small proxy to full size helped; in the extension, only 1 of 8 did, and several ideas reversed sign at full size.
单独测得的增益在与领先模型结合后往往消失。 Gains measured in isolation often vanished when combined with the leader. 例如，一种对基础模型有益的记忆归一化方法却损害了最佳模型的性能。 For example, a memory normalization that helped the plain model hurt the best model.
噪声的影响不可忽视。 Noise matters. 一次随机种子复现实验使损失变化了 0.010，与解决方案演进路径中后期若干步骤带来的变化幅度相当。 A seed replication moved loss by 0.010, comparable to several of the later steps on the solution path.
E.3 循环 TransformerE.3 Looped Transformer
E.3.1 任务详情E.3.1 Task Details
架构。Architecture.
循环 Transformer（Looped Transformer）任务使用 Huginn (Geiping et al., 2025)，这是一种深度循环语言模型，将网络划分为前导模块、权重共享的循环核心和尾声模块。 The Looped Transformer task uses Huginn (Geiping et al., 2025), a depth-recurrent language model that splits the network into a prelude, a weight-tied recurrent core, and a coda. 前导模块对输入进行嵌入，核心以可变次数迭代，并在每次迭代时重新注入前导模块的输出——由一个适配器将当前状态与编码后的输入混合——尾声模块则对最终的潜在状态进行解码，因此可以通过展开更多迭代而非生成更多词元来扩展测试时计算量。 The prelude embeds the input, the core is iterated a variable number of times with the prelude output re-injected at every iteration—an adapter mixes the current state with the encoded input—and the coda decodes the final latent state, so test-time compute can be scaled by unrolling more iterations instead of generating more tokens.
任务规范。Task specification.
以作者的官方代码为起点，并将其缩放为一个 $\sim$ 308M 参数的参考模型（1,024 词元上下文，八次循环），智能体群必须开发一个架构经过改进的模型，保留真正的权重共享循环深度计算，独立参数量不超过 350M，并使用与参考模型相同的词元预算，在与 RMT 任务相同的 6.5B 词元 OpenWebText 数据流上从头训练（附录 E.2.1）。 Starting from the authors’ official code, scaled to a $\sim$ 308M-parameter reference (1,024-token context, eight recurrences), the swarm must develop an architecturally improved model that keeps genuine weight-tied recurrent-depth computation, has at most 350M unique parameters, and is trained from scratch with the reference’s token budget on the same 6.5B-token OpenWebText stream as the RMT task (Appendix E.2.1). 评估指标是在 4,873 个受保护开发集的 1,024 词元上下文上测得的保密下一词元损失，评估时严格采用八次循环（参考值为 3.265）；我们尚未报告该任务在留出集上的评估结果。 The metric is the withheld next-token loss on the 4,873 protected-development 1,024-token contexts, evaluated at exactly eight recurrences (reference 3.265); we do not yet report a held-out evaluation for this task.

候选方案先在一系列逐级增大的小模型（52M、124M、188M）上开发，再进行完整规模的训练。 Candidates are developed on a ladder of smaller models (52M, 124M, 188M) before full-size training. 工作智能体首先在小模型上并行筛选了全部十二类思路；两小时内，循环状态门控和前馈适配器成为最有前景的两个思路。 Workers first screened all twelve families in parallel on small models; within two hours the recurrent-state gate and the feed-forward adapter were the two leading ideas. 在对适配器的最初否定被推翻后（见下文步骤），这两个方案沿模型规模阶梯并行推进：门控的优势在 124M 和 188M 规模下消失，而适配器在每个规模级别上都胜出，并在 9 小时后于完整规模下达到 3.187（图 5(b)）。 After the adapter’s initial rejection was reversed (see the steps below), the two were carried up the ladder side by side: the gate’s advantage vanished at 124M and 188M, while the adapter won at every rung and reached 3.187 at full size after 9 hours (Figure 5(b)). 随后，工作智能体开展了容量对照实验，并在适配器的基础上构建第二代机制，例如对输入的注意力和并行前馈分支，其中若干机制在小模型上超越了适配器，但在完整规模下尚未做到。 Workers then ran capacity controls and built second-generation mechanisms on top of the adapter, such as attention to the input and parallel feed-forward branches, several of which beat it on small models but not yet at full size. 自 9 小时起，尚无方案进一步改进最佳模型；后续向校准和诊断工作的转移见附录 E.3.4。 Nothing has improved on the best model since 9 hours; the later shift to calibration and diagnostics is described in Appendix E.3.4.
跨谱系继承。Cross-lineage inheritance.
与 RMT 运行不同，最终模型的代码几乎全部来自同一谱系中由六个工作智能体完成的六次提交；只有第一次提交修改了代码，而唯一从其他地方导入的代码是为另一个分支编写的损失计算修复。 Unlike in the RMT run, the final model’s code comes almost entirely from one lineage of six commits by six workers; only the first changes code, and the only code imported from elsewhere is a loss-computation fix written for another branch. 其他谱系则贡献了证据：竞争方案门控在完整集合上的得分确立了适配器必须超越的标准，而一个用于快速代理测量的共享工具（被引用次数第二多的提交）则被用于比较候选方案。 Other lineages contributed evidence instead: the rival gate’s full-set scores defined what the adapter had to beat, and a shared tool for fast proxy measurements (the second most-cited commit) was used to compare candidates. 若计入最佳模型通过 informed_by= 边引用为证据的提交，其声明的依赖关系涵盖了 89 个不同工作智能体的 89 次提交（若通过唯一前缀恢复误写的提交哈希，则为 98 次提交，完成时间介于 0.18 至 9.10 小时之间）。 Counting the commits the best model cites as evidence through informed_by= edges, its declared dependencies span 89 commits by 89 distinct workers (98 commits, made between 0.18 and 9.10 hours, if mistyped commit hashes are recovered by unique prefix).

E.3.4 关于研究过程的发现E.3.4 Findings about the Research Process
小规模评估会错误排列模型的优劣。 Small evaluations misranked models. 在 12 对可比较的模型中，使用 128 个样例的评估有 5 对的排序与完整评估集不一致；在 50 对模型中，有 15 对的排序与使用 512 个样例的评估不一致；一名工作智能体自行测量了这一现象，随后智能体群采用了 128 $\rightarrow$ 512 $\rightarrow$ 4,873 的漏斗式评估流程。 128-example evaluations disagreed with the full set on 5 of 12 comparable pairs, and with 512-example evaluations on 15 of 50; a worker measured this itself and the swarm adopted a 128 $\rightarrow$ 512 $\rightarrow$ 4,873 evaluation funnel.
性能增益往往无法跨规模迁移。 Gains often failed to transfer across scale. 循环状态门、专门化分支以及依赖迭代的控制机制，在更大的规模档位上或与参数量匹配的对照模型相比时，都失去了在小规模下的优势。 The recurrent-state gate, the specialist branches and iteration-dependent control all lost their small-scale advantage at larger rungs or against a parameter-matched control.
工作智能体相互核查。 Workers checked each other. 除了推翻最初对适配器的否定结论（附录 E.3.3）之外，后来还有一名工作智能体推翻了依赖迭代的控制机制在 128 个样例评估中胜出的结论，另有四名工作智能体独立运行了参数量匹配的对照实验。 Besides the reversal of the adapter’s initial rejection (Appendix E.3.3), a later worker overturned a 128-example win for iteration-dependent control, and four workers independently ran parameter-matched controls.
共同遵循的实验规程逐渐形成。 Shared protocols emerged. 257 次提交使用了一组固定的代理上下文，187 次提交讨论了参数量匹配；构建测量工具和对照实验的提交位列引用次数最多的提交之中。 A fixed set of proxy contexts was used by 257 commits and parameter matching was discussed in 187; commits that built measurement tools and controls were among the most cited.
研究工作逐渐集中，随后转向诊断。 Work converged, then shifted to diagnostics. 在架构相关提交中，基于该适配器的提交占比从最初三小时的 17% 上升到九小时后的约 90%，一名工作智能体指出这表明研究过度集中。 The share of architectural commits building on the adapter rose from 17% in the first three hours to about 90% after nine, which one worker flagged as over-concentration. 评估预算耗尽后（20.8 小时），大多数提交都涉及校准和诊断，而在 136 次放弃行动中，有 128 次以工作重复或已有同类工作正在进行为由。 After the evaluation budget ran out (20.8 hours), most commits were calibrations and diagnostics, and 128 of 136 abstentions cited duplicate or already-running work.
本次运行中未观察到偏离任务的现象。 No off-task drift was observed in this run.

24 小时截止点时的架构。Architecture at the 24-hour cutoff.

G.4 自愿弃权与冗余G.4 Voluntary Abstention and Redundancy
当工作智能体计划作出的贡献已被已发布或正在进行的工作覆盖，或已不存在有用且不重复的改动时，它们可以明确选择弃权；自愿弃权的工作智能体会被替换，且不消耗计费预算，但其在弃权前进行检查和推理仍会产生 token 成本（第 2.3 节）。 Workers may explicitly abstain when their intended contribution is already covered by published or in-flight work, or when no useful nonredundant change remains; voluntary abstainers are replaced without consuming the charged budget but still incur token costs for the inspection and reasoning they perform before abstaining (Section 2.3). 相比之下，无效操作、无效提名、无操作退出和系统故障确实会消耗一个名额；无效和无操作的执行过程归入图 22 的“无效 / 无操作”类别，与自愿弃权分开列示。 By contrast, invalid actions, invalid nominations, no-action exits, and system failures do consume a slot; invalid and no-action episodes are shown in the Invalid / no action class of Figure 22, separate from voluntary abstentions. 第 3.5 节概述了有关冗余的主要发现；本小节报告其基础统计数据以及对弃权判断的校准。 Section 3.5 summarizes the main redundancy findings; this subsection reports the underlying statistics and the calibration of abstention judgments.

解读与适用范围。Interpretation and scope.
这些共性模式和任务特有模式表明，工作器进行的是选择性导航，而非穷尽式复查，并提示仓库被用作可检索的记忆，而非每个工作器都要完整重读的记录。 These shared and task-specific patterns indicate selective navigation rather than exhaustive reinspection, and suggest that the repository is used as a searchable memory rather than a transcript that every worker rereads in full. 当前预算下的结果尚不能证明，在图规模显著增大时，这种行为仍将有效，或能够持续而不发生退化。 The present budgets do not establish that this behavior will remain effective, or persist without degradation, at substantially larger graph sizes. 结合提名和弃权分析（附录 G.3 和 G.4），这些模式表明，工作器通过共享状态实现协调，而无需固定角色。 Taken together with the nomination and abstention analyses (Appendices G.3 and G.4), these patterns show coordination through shared state without fixed worker roles. 这种协调既包括将已有工作综合进后续解答，也包括比较、避免冗余和选择性导航，而这些行为的影响可能不会体现在所选解答的祖先谱系中。 This coordination includes synthesis into later solutions, but also comparison, redundancy avoidance, and selective navigation whose influence may not appear in the selected solution’s ancestry.
G.6 架构权衡G.6 Architectural Tradeoffs
第 3.5 节概述了在 ProgramBench 开发集上进行的两项 GitSwarm 设计比较。 Section 3.5 summarizes two GitSwarm design comparisons on the ProgramBench development set. 此处我们描述所比较的配置；表 13 报告了完整结果和实验设置。 Here we describe the compared configurations; Table 13 reports the full results and experimental settings.
异步执行与同步执行。Asynchronous versus synchronous execution.
默认调度器会在每当有工作器槽位空出时启动一个替补工作器。 The default scheduler launches a replacement worker whenever a worker slot becomes available. 同步变体则以五个工作器为一批，批次之间设置同步屏障：它等待一批中的五个工作器全部完成后，才启动下一批。 The synchronous variant instead executes barriers of five workers: it waits for every worker in a five-worker wave to finish before launching the next wave. 同步执行使平均得分变化了 $+1.05$ 分，但将平均任务运行时间增加至原来的 1.30 倍。 Synchronization changes the mean score by $+1.05$ points but increases the mean task runtime by a factor of 1.30. 由于每个同步批次都要等待其中最慢的工作器，这一结果与异步执行能够减少慢工作器所致延迟的解释一致。 Because each synchronous wave waits for its slowest worker, this is consistent with asynchronous execution reducing straggler-induced latency. 因此，在这些条件下，异步执行降低了延迟，且观测到的平均得分差异较小；该实验并未证明两种调度方式在统计上等效。 Under these conditions, asynchronous execution therefore reduces latency with a small observed difference in mean score; the experiment does not establish statistical equivalence between the two schedules.
去中心化读出与中心化读出。Decentralized versus centralized readout.
默认情况下，提交的候选方案由工作器的去中心化提名决定（第 2.5 节）。 By default, the submitted candidate is determined by decentralized worker nominations (Section 2.5). 我们将这种读出方式与两种变体进行比较；两种变体都将 50 个回合中的一个预留给具有特殊权限的最终工作器：一种是中央选择器，负责选择一个已有候选方案；另一种是中央聚合器，负责综合生成一个新候选方案。 We compare this readout with two variants that reserve one of the 50 episodes for a privileged final worker: a central selector, which chooses an existing candidate, and a central aggregator, which synthesizes a new candidate. 相较于去中心化提名，中央选择器将平均得分提高了 2.34 分，且平均运行时间更短；中央聚合器则将平均得分降低了 3.87 分，耗时增加了 16%。 Relative to decentralized nomination, the central selector raises the mean score by 2.34 points with a shorter mean runtime, whereas the central aggregator lowers the mean score by 3.87 points and takes 16% longer. 因此，在本研究中，强制执行最终综合步骤既未比分散式提名更准确，也未更高效。 In this study, forcing a final synthesis step was thus neither more accurate nor more efficient than decentralized nomination. 在此次开发集比较中，中央选择器的观测均值更高，但随机种子数量有限，无法据此确立任何一种结果读出方式具有普遍优势，也无法确立二者在统计上等效。 The central selector has the higher observed mean in this development-set comparison, but the limited number of seeds does not establish a general advantage of either readout or their statistical equivalence.

Gemini-3.1-Pro 工作智能体会在其系统提示词末尾收到以下扩展内容。 Gemini-3.1-Pro workers receive the extension below at the end of their system prompt. 在未加入该扩展的试运行中，Gemini 工作智能体经常在单次响应中发出整个贡献工作流程（检查、声明工作范围、gs_fork、写入文件和 git commit），有时还会预测命令输出，并从猜测的提交 SHA 创建分支。 In pilot runs without it, Gemini workers often issued an entire contribution workflow (inspection, scope announcement, gs_fork, file writes, and git commit) in a single response, sometimes predicting command outputs and branching from a guessed commit SHA. 当 gs_fork 随后失败时，其余命令仍会继续运行，并将新文件提交到工作智能体的占位分支上，最终结果因无效而被拒绝。 When gs_fork then failed, the remaining commands still ran and committed the new files on the worker’s placeholder branch, and the result was rejected as invalid. 该扩展要求工作智能体在发出依赖于某条命令的后续命令之前，先等待该命令的输出；将 gs_fork 作为独立步骤运行；并在成功创建分支之前，仅使用只读检查命令和协调命令。 The extension asks workers to wait for each command’s output before issuing commands that depend on it, to run gs_fork as a standalone step, and to use only read-only inspection and coordination commands before branching succeeds. 对于这些运行，测试框架还会以 set -e 模式运行每个 shell 代码块，在某个代码块失败后跳过该响应中的其余代码块，并拒绝在创建分支之前执行除只读检查命令、协调命令、独立的 gs_fork 或独立的 gs_abstain 之外的任何命令。 For these runs, the harness also runs each shell block with set -e, skips the remaining blocks of a response once a block fails, and rejects any pre-branch command other than read-only inspection, coordination, a standalone gs_fork, or a standalone gs_abstain. 这些新增规定限制了 shell 命令的运行方式和时机（例如，脚本和测试只能在创建分支之后运行）；图、作用域、依赖关系和提名规则保持不变。 These additions constrain how and when shell commands run (for example, scripts and tests can run only after branching); the graph, scope, dependency, and nomination rules are unchanged.
