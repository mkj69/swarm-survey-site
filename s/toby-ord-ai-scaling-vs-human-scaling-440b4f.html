一句话

Ord 提醒：增加 agent 数量与延长单个 agent 的推理，都可能存在收益递减；评估 swarm scaling 时，需要同时考虑这两层折损。

主要内容

  • 文章质疑“给 AI 更多 token，等于给人更多时间”的类比。额外资源能否带来同等进步，需要测量，不能直接假定。
  • Ord 根据英国 AISI 的内部 CTF 攻防任务图，采用关系式 \(H_{80}\propto T^\gamma\)：\(T\) 为 token 预算，\(H_{80}\) 为 AI 以 80% 成功率完成的任务所对应的人类耗时。若 \(\gamma<1\)，时间跨度随 token 次线性增长。
  • 作者估计，较早模型将时间跨度提高十倍需要约一万倍 token，较新模型约需二十倍。模型有所改善，但数据不足以判断是否停在 \(\gamma\approx2/3\)，或仍会继续上升。
  • 对递归自我改进，作者提出把反馈强度从 \(r=\lambda/\beta\) 调整为 \(r=\lambda\gamma/\beta\)，纳入推理扩展相对人类时间扩展的效率差异。

证据与可信度

  • 这些数字属于对已有实验图表的二次估算。作者披露使用 Claude Opus 5.5 估计曲线斜率并辅助核查；材料未提供可复算的原始数据，也未展示独立核验。
  • “十倍跨度所需 token 倍数”由 \(10^{1/\gamma}\) 得到，并非直接测量所有对应预算下的表现。
  • AISI 数据仅涉及一套任务，且推理长度超过上下文窗口、需要多次压缩，可能影响斜率。时间跨度也是人类表现的间接代理，不能等同于直接比较双方投入时间后的成绩。
  • METR 的早期结果混合了长推理与多次尝试取最佳结果，人类长时段数据也包含并行劳动，因此不能据此分离纯粹的串行扩展效应。作者明确将整体结论定位为提示性证据。

对 swarm scaling 的意义

若并行扩展满足 \(T\propto N^\lambda\)，再结合上述关系，就得到 \(H_{80}\propto N^{\lambda\gamma}\)。这意味着，即使 swarm 将人数转化为推理能力的效率尚可，最终转化为人类等效任务跨度时仍可能再次折损。

文中的假设例子取 \(\lambda=\gamma=0.5\)：匹配人类时间增加十倍的收益，需要单 agent 的 token 增加一百倍，或 agent 数量增加一万倍。这是公式示例，并非实测 swarm 结果。其调研价值在于要求同时追踪并行效率与串行推理效率，而不能只凭 agent 数量推断能力增幅。
