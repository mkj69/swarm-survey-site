一句话

这份文档说明，swarm 扩容同时受组织预算、请求速率和输入输出吞吐约束；但它不能证明“花费一定先于速率成为瓶颈”。

主要内容

  • 限制分为月度花费上限与速率上限。Start、Build、Scale 的月度上限分别为 500、1,000、200,000 美元；Custom 由客户团队协商。
  • Messages API 按模型类别分别限制每分钟请求数、输入 token 和输出 token。部分模型共享额度，组织内多个工作区仍受组织总额约束。
  • 速率采用令牌桶机制，短时突发也可能触限；流量骤增还可能触发加速限制。文档列出的额度是允许上限，并非吞吐保证。
  • 多数模型的缓存读取不计入输入速率额度，但写入缓存仍计入。Haiku 3.5 是文档注明的例外。输出额度按实际生成量计算。
  • 月度上限耗尽会暂停调用，返回没有 retry-after 的 429；持续重试无效。普通速率限制若附有该字段，应按指定时间等待。
  • 批处理和 Managed Agents 端点另有额度，因此推理调用、任务提交与管理操作需要分别核算。

证据与可信度

材料是 Anthropic 官方产品文档，数字属于厂商公布的配额与计费规则，不是独立性能测量。本次仅依据提供的抓取文本，未独立核验线上配置或实际执行效果；具体组织额度仍需查看控制台。

文档举例：输入额度为每分钟 200 万 token、缓存命中率为 80% 时，可对应每分钟 1,000 万总输入 token。这是缓存读取不占额度条件下的算术示例，并非实测吞吐，也不代表输出、请求数或预算限制同步解除。

材料没有给出任务成本、运行时长或实际用量，无法判断预算与速率哪个先耗尽。

对 swarm scaling 的意义

  • 增加 agent 数量不会自动增加组织额度。并发收益取决于每个任务的请求频率、上下文规模和输出长度，不能仅凭 RPM 推算可运行的 agent 数。
  • 共享系统提示、工具定义和重复上下文有机会通过缓存缓解输入瓶颈，但输出密集型任务仍受输出额度约束。
  • 调度器应结合响应头控制节奏、逐步放量，并区分暂时限流与预算耗尽，避免无效重试。
  • 工作区限额可用于约束不同任务的资源占用，但不能突破组织总额。扩容评估应同时检查持续运行成本与瞬时吞吐。
