一句话

这项框架比较表明，多智能体系统的可用性可能先受上下文、重试与终止机制限制；但它并未证明增加智能体数量能提高推理能力。

主要内容

  • 作者从 1,200 个 GitHub 仓库中筛出 22 个框架，在 BBH、GSM8K、ARC 上比较准确率、耗时、成本及表现一致性。
  • 实验统一使用 GPT-5.2，并采用双智能体配置，控制提示、温度等条件。预实验发现，四智能体配置会明显增加交互时间和 API 成本，因此正式实验选择双智能体。
  • 摘要报告，19 个框架完成全部基准；其中 12 个表现较稳定，平均准确率为 74.6%–75.9%，每题耗时 4–6 秒，成本为 0.14–0.18 美分。
  • 失败案例集中在编排：Camel 因上下文持续增长，运行 11 天仍未完成 BBH；Upsonic 因提取失败、反复重试及提示增长，单日花费 1,434 美元；AutoGen、Mastra 的迭代交互耗尽 API 配额，却未改善答案。
  • 完成全部基准的框架在 GSM8K 上平均准确率为 44.35%，低于 BBH 的 89.80% 和 ARC 的 89.56%。作者据此认为，框架没有消除底层模型的数学推理弱点。

对 swarm scaling 的意义

这篇材料更适合作为扩展过程中的系统风险证据：交互可能不断累积上下文，提取失败可能触发重试，最终放大延迟、费用和配额消耗。扩展群体前，应先约束记忆增长、重试次数与终止条件。

其边界也很明确：正式评测固定为双智能体，四智能体仅有预实验的定性描述，没有随群体规模变化的收益曲线。因此，它支持重视编排质量，不能据此判断 swarm 的最佳规模，或断言多智能体普遍优于单智能体。
