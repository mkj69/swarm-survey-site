什么是上下文图谱？What is a Context Graph?
**上下文图谱**是由实体、关系和事实构成的时序图谱——例如 *“Kendra 喜欢 Adidas 鞋（截至 A **context graph** is a temporal graph of entities, relationships, and facts — like *"Kendra loves Adidas shoes (as of
2026 年 3 月）。”* 与传统知识图谱不同，上下文图谱中的每条事实都有一个有效时间窗口：它何时开始 March 2026)."* Unlike traditional knowledge graphs, each fact in a context graph has a validity window: when it became
成立，以及何时（如果有）被取代。 true, and when (if ever) it was superseded. 实体随时间演变，其摘要也会更新。 Entities evolve over time with updated summaries. 所有内容都可追溯至 Everything traces back to
**情节（episodes）**——产生这些内容的原始数据。 **episodes** — the raw data that produced it.
Graphiti 的独特之处在于，它能够自主地从非结构化和结构化数据中构建上下文图谱， What makes Graphiti unique is its ability to autonomously build context graphs from unstructured and structured data,
在处理不断变化的关系的同时，保留完整的时间历史。 handling changing relationships while preserving full temporal history.
上下文图谱包含： A context graph contains: 
| Component | What it stores |
| **Entities** (nodes) | People, products, policies, concepts — with summaries that evolve over time |
| **Facts / Relationships** (edges) | Triplets (Entity → Relationship → Entity) with temporal validity windows |
| **Episodes** (provenance) | Raw data as ingested — the ground truth stream. Every derived fact traces back here |
| **Custom Types** (ontology) | Developer-defined entity and edge types via Pydantic models |

为什么选择 Graphiti？Why Graphiti?
传统的 RAG 方法通常依赖批处理和静态数据摘要，因此在处理 Traditional RAG approaches often rely on batch processing and static data summarization, making them inefficient for
频繁变化的数据时效率低下。 frequently changing data. Graphiti 通过提供以下功能来应对这些挑战： Graphiti addresses these challenges by providing:
**时态事实管理：**事实具有有效时间区间。 **Temporal Fact Management:** Facts have validity windows. 当信息发生变化时，旧事实会被 When information changes, old facts are
标记为失效，而非删除。 invalidated — not deleted. 可以查询当前成立的事实，或任意历史时点成立的事实。 Query what's true now, or what was true at any point in time.
**事件片段与溯源：**每个实体和关系都可追溯到产生它的事件片段（episodes，即原始数据）。 **Episodes & Provenance:** Every entity and relationship traces back to the episodes (raw data) that produced it.
提供从派生事实到源数据的完整血缘链路。 Full lineage from derived fact to source.
**预定义与学习得到的本体：**通过 Pydantic 模型预先定义实体和边的类型（预定义），或让 **Prescribed & Learned Ontology:** Define entity and edge types upfront via Pydantic models (prescribed), or let
结构从数据中自然形成（学习得到）。 structure emerge from your data (learned). 从简单结构开始，随着模式的出现逐步演化。 Start simple, evolve as patterns appear.
**增量图构建：**新数据可立即集成，无需进行批量重新计算。 **Incremental Graph Construction:** New data integrates immediately without batch recomputation. 图会 The graph evolves
随着事件片段的摄入而实时演化。 in real-time as episodes are ingested.
**混合检索：**结合语义嵌入、关键词（BM25）检索和图遍历，实现低延迟、 **Hybrid Retrieval:** Combines semantic embeddings, keyword (BM25), and graph traversal for low-latency,
高精度的查询，无需依赖 LLM 生成摘要。 high-precision queries without reliance on LLM summarization.
**可扩展性：**借助并行处理和可插拔的图后端高效管理大型数据集，适用于 **Scalability:** Efficiently manages large datasets with parallel processing, pluggable graph backends, suitable
企业工作负载。 for enterprise workloads.
Graphiti 与 GraphRAG 对比Graphiti vs. GraphRAG
| Aspect | GraphRAG | Graphiti |
| **Primary Use** | Static document summarization | Dynamic, evolving temporal knowledge graphs |
| **Data Handling** | Batch-oriented processing | Continuous, incremental updates |
| **Knowledge Structure** | Entity clusters & community summaries | Temporal context graph — entities, facts with validity windows, episodes, communities |
| **Retrieval Method** | Sequential LLM summarization | Hybrid semantic, keyword, and graph-based search |
| **Adaptability** | Low | High |

| **Contradiction Handling** | LLM-driven summarization judgments | Automatic fact invalidation with temporal history preserved |

| **Custom Entity Types** | No | Yes, customizable via Pydantic models |
| **Scalability** | Moderate | High, optimized for large datasets |
Graphiti 专为应对动态且频繁更新的数据集所带来的挑战而设计，因此 Graphiti is specifically designed to address the challenges of dynamic and frequently updated datasets, making it
尤其适用于需要实时交互和精确历史查询的应用。 particularly suitable for applications requiring real-time interaction and precise historical queries.

遥测Telemetry
Graphiti 收集匿名使用统计信息，以帮助我们了解该框架的使用情况，并加以改进，使其惠及 Graphiti collects anonymous usage statistics to help us understand how the framework is being used and improve it for
所有人。 everyone. 我们认为透明度很重要，因此下面明确说明我们收集哪些信息及其原因。 We believe transparency is important, so here's exactly what we collect and why.
我们收集的信息What We Collect
当您初始化 Graphiti 实例时，我们会收集： When you initialize a Graphiti instance, we collect:
**匿名标识符**：随机生成的 UUID，存储在本地的 `~/.cache/graphiti/telemetry_anon_id` 中 **Anonymous identifier**: A randomly generated UUID stored locally in `~/.cache/graphiti/telemetry_anon_id`
**系统信息**：操作系统、Python 版本和系统架构 **System information**: Operating system, Python version, and system architecture
**Graphiti 版本**：您使用的版本 **Graphiti version**: The version you're using
**配置选项**： **Configuration choices**:
LLM 提供商类型（OpenAI、Azure、Anthropic 等） LLM provider type (OpenAI, Azure, Anthropic, etc.)
数据库后端（Neo4j、FalkorDB、Kuzu、Amazon Neptune Database 或 Neptune Analytics） Database backend (Neo4j, FalkorDB, Kuzu, Amazon Neptune Database or Neptune Analytics)
嵌入模型提供商（OpenAI、Azure、Voyage 等） Embedder provider (OpenAI, Azure, Voyage, etc.)
我们不收集的信息What We Don't Collect
我们致力于保护您的隐私。 We are committed to protecting your privacy. 我们**绝不**收集： We **never** collect:
个人信息或标识符 Personal information or identifiers
API 密钥或凭据 API keys or credentials
您的实际数据、查询或图内容 Your actual data, queries, or graph content
IP 地址或主机名 IP addresses or hostnames
文件路径或特定于系统的信息 File paths or system-specific information
您的事件片段（episodes）、节点或边中的任何内容 Any content from your episodes, nodes, or edges
我们为什么收集这些数据Why We Collect This Data
这些信息有助于我们： This information helps us:
了解哪些配置最受欢迎，以优先安排支持和测试工作 Understand which configurations are most popular to prioritize support and testing
确定应重点投入开发工作的 LLM 和数据库提供商 Identify which LLM and database providers to focus development efforts on
跟踪采用模式，以指导我们的发展路线图 Track adoption patterns to guide our roadmap
确保在不同 Python 版本和操作系统之间的兼容性 Ensure compatibility across different Python versions and operating systems
通过分享这些匿名信息，您可以帮助我们改进 Graphiti，使社区中的每个人都能受益。 By sharing this anonymous information, you help us make Graphiti better for everyone in the community.

如何禁用遥测How to Disable Telemetry
遥测采用**默认启用、可选择退出**的方式，可随时禁用。 Telemetry is **opt-out** and can be disabled at any time. 要禁用遥测数据收集： To disable telemetry collection:
**选项 1：环境变量** **Option 1: Environment Variable** 
export GRAPHITI_TELEMETRY_ENABLED=false
**选项 2：在 shell 配置文件中设置** **Option 2: Set in your shell profile** 
# For bash users (~/.bashrc or ~/.bash_profile)
echo 'export GRAPHITI_TELEMETRY_ENABLED=false' >> ~/.bashrc

# For zsh users (~/.zshrc)
echo 'export GRAPHITI_TELEMETRY_ENABLED=false' >> ~/.zshrc
**选项 3：为特定 Python 会话设置** **Option 3: Set for a specific Python session** 
import os

os.environ['GRAPHITI_TELEMETRY_ENABLED'] = 'false'

# Then initialize Graphiti as usual
from graphiti_core import Graphiti

graphiti = Graphiti(...)
在运行测试期间（检测到 `pytest` 时），遥测会自动禁用。 Telemetry is automatically disabled during test runs (when `pytest` is detected).
