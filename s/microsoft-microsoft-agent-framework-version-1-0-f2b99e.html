一句话

微软宣布 Agent Framework 的 .NET 与 Python 版本进入 1.0，重点是稳定多智能体编排与生产运行接口，并未证明增加 agent 数量能带来性能收益。

主要内容

  • 框架整合 Semantic Kernel 的工程基础与 AutoGen 的编排能力，提供统一的开源 SDK，并承诺稳定 API、长期支持与向后兼容。
  • 稳定编排模式包括顺序、并发、交接、群聊和 Magentic-One；支持流式输出、检查点、人工审批及暂停恢复。
  • 图工作流可混合智能体与普通函数，执行条件分支、并行展开和结果汇合；检查点与状态恢复用于应对长流程中断。
  • 通过模型连接器、可插拔记忆和 YAML 配置组织系统；MCP 用于发现与调用外部工具，A2A 用于跨运行时协作。文中明确说 A2A 1.0 支持尚未到来。
  • DevUI、托管部署集成、评估面板、Skills、编码 agent SDK 接入及 Agent Harness 属于预览功能，不能一概视为稳定承诺。

对 swarm scaling 的意义

材料的价值在于展示多智能体系统的工程支撑：并行与汇合负责组织任务，检查点与恢复支撑长流程，人工审批提供干预入口，协议与连接器便于组合异构组件。

但“具备编排能力”与“规模扩大后更有效”之间仍缺证据。研究中可将它归为生产化基础设施进展；若要论证 swarm scaling，仍需比较不同 agent 数量下的质量、成本、延迟与协调开销。
