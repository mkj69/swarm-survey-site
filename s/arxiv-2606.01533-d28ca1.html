Abstract摘要
Computer use agents (CUAs) today are primarily deployed as single serial agents. This setup is suboptimal for complex long-horizon tasks that benefit from task decomposition, parallel execution, and consistent re-planning based on new information. In this paper, we argue that we should instead move towards evaluating and building multi-agent computer use (MACU) systems. These systems, which emphasize planning and parallel execution, alleviate many of the shortcomings of single-agent CUAs. We propose a general multi-agent setup in which a manager model decomposes computer use tasks as a directed acyclic graph (DAG) of subtasks, encoding relevant dependencies and goals for subagents. At each iteration, the manager dispatches parallel CUA subagents to carry out nodes on the ready frontier of the DAG, and continuously revises the DAG (adding, canceling, or rewriting nodes) as new findings arrive from subagents. This design treats the partially observable environment of computer use as a first class challenge: information that downstream agents may not be able to re-observe are retained and passed forward through the manager and DAG structure. We demonstrate that MACU consistently improves over strong single-agent baselines by $3.4-25.5\%$ on desktop (OSWorld) and web navigation (Online-Mind2Web, WebTailBench, Odysseys) benchmarks, exhibits more favorable test-time compute scaling, and solves complex long-horizon tasks where single-agent CUAs get stuck. On Odysseys, a long-horizon web navigation benchmark, MACU also improves average task completion wall-clock time by ${\sim}1.5\times$ , demonstrating its efficacy in speeding up traditionally slow CUA pipelines. Our findings highlight that multi-agent coordination is a promising axis for scaling computer use agents to work productively for longer and more effectively. We release all code and interactive visualizations at https://jykoh.com/multi-agent-computer-use.

Computer use is the task of interacting with software through the use of Graphical User Interfaces (GUIs). Computer use agents (CUAs) today are primarily deployed and evaluated as single serial agents, but this is suboptimal for tackling complex long-horizon tasks, which benefit from decomposition, parallel execution, and consistent re-planning based on new information. In this paper, we argue that we should move towards multi-agent computer use (MACU): systems which emphasize planning and parallel execution, and are promising ways to alleviate the shortcomings of single-agent CUAs.
计算机使用是指通过图形用户界面（GUIs）与软件交互的任务。如今，计算机使用智能体（CUAs）主要以单智能体串行方式部署和评估，但对于能够受益于任务分解、并行执行以及根据新信息持续重新规划的复杂长程任务，这种设置并非最优。本文主张，我们应转向多智能体计算机使用（MACU）：这类系统强调规划与并行执行，是缓解单智能体 CUAs 不足的有前景的途径。
Towards this goal, we present a general MACU setup (Fig. 1), where a manager model plans, decomposes, and continuously iterates over a directed acyclic graph (DAG) whose nodes are subtasks that are executed in parallel by computer use subagents. The graph decomposition schema used in MACU is open-ended and the manager operates on a graph of subagents, with the ability to add, cancel, rewire, or modify the instructions of pending subtasks. This directly targets long-horizon tasks and complex but parallelizable CUA tasks, key regimes where serial CUA setups struggle. Our work distinguishes itself from prior work in several ways. Most prior multi-agent work based on large language models (LLMs) explores text-based specialized subagents (e.g., tool use (Chen et al., 2023; Li et al., 2025), coding agents (Hong et al., 2023; Geng and Neubig, 2026), math (Qian et al., 2025; Zhao et al., 2025; Qi et al., 2025), and science (Lu et al., 2024; Gottweis et al., 2025)) in effectively fully observable settings. Computer use is a qualitatively different regime. The agent acts on a live operating system, whose state: filesystem, background processes, open browser tabs, login cookies, dynamic content, is only partially observable at any given moment, and the state relevant to a downstream subtask often cannot be re-observed once the original subtask has ended. We treat partial observability as a first-class consideration in MACU, which leads us to be explicit about the initial plan being a best-guess hypothesis, which the manager needs to continuously revise once new information is collected from pending subagents. In contrast to many prior approaches on orchestrating multiple subagents (Agashe et al., 2025; Lee et al., 2026; Zhang et al., 2025b), our proposed MACU approach is also substantially simpler and does not rely on specialized models. All subagents are identical, based off the same CUA backbone, and carry out instructions that are produced by the manager, allowing our approach to directly benefit from future advances on CUA models by directly leveraging them as subagents in MACU.
为实现这一目标，我们提出一种通用的 MACU 设置（图 1），其中，管理模型对有向无环图（DAG）进行规划、分解和持续迭代，图中的节点是由计算机使用子智能体并行执行的子任务。MACU 所采用的图分解方案是开放式的，管理模型在子智能体构成的图上进行操作，能够添加或取消待执行的子任务、重新连接其依赖关系，或修改其指令。这直接针对长程任务以及复杂但可并行化的 CUA 任务，而这些正是串行 CUA 设置难以应对的关键任务类型。我们的工作在多个方面区别于以往研究。以往大多数基于大语言模型（LLMs）的多智能体研究，都是在实际上完全可观测的环境中探索基于文本的专门化子智能体（例如，工具使用（Chen et al., 2023; Li et al., 2025）、编程智能体（Hong et al., 2023; Geng and Neubig, 2026）、数学（Qian et al., 2025; Zhao et al., 2025; Qi et al., 2025）和科学研究（Lu et al., 2024; Gottweis et al., 2025））。计算机使用则是一种在性质上截然不同的场景。智能体在实际运行的操作系统上执行操作，而该系统的状态——文件系统、后台进程、打开的浏览器标签页、登录 cookie、动态内容——在任意时刻都只能被部分观测，并且与下游子任务相关的状态往往在原始子任务结束后便无法再次观测。我们将部分可观测性视为 MACU 的核心考量，因此明确将初始计划视为基于当前信息作出的最佳推测性假设；一旦从尚未完成任务的子智能体处收集到新信息，管理模型就需要持续修订这一假设。与以往许多编排多个子智能体的方法（Agashe et al., 2025; Lee et al., 2026; Zhang et al., 2025b）相比，我们提出的 MACU 方法也显著更简单，且不依赖专门化模型。所有子智能体均相同，基于同一个 CUA 骨干模型，并执行管理模型生成的指令，因此，我们的方法可以直接将未来更先进的 CUA 模型用作 MACU 中的子智能体，从而直接受益于 CUA 模型的进步。
We demonstrate empirically that MACU is a promising approach to tackling computer use tasks. MACU consistently improves over strong single-agent baselines across several computer use and web navigation benchmarks, increasing success rates by 4.7% on OSWorld (Xie et al., 2024), 3.4% on Online-Mind2Web (Xue et al., 2025), 8.7% on WebTailBench-v2 (Awadallah et al., 2025), and 25.5% on Odysseys (Jang et al., 2026), and also substantially improves wall-clock time on OSWorld and Odysseys. MACU also demonstrates more promising scaling trends with increased test-time compute, solving long-horizon tasks that single-agent CUAs get stuck on. We perform detailed ablations on the MACU setup, and our analysis highlights design choices that are essential to maximize the effectiveness of MACU. We believe these findings provide a strong foundation for further work on effective scaling of multi-agent computer use systems.
我们通过实证表明，MACU 是一种有望有效解决计算机使用任务的方法。在多个计算机使用和网页导航基准上，MACU 均持续优于强大的单智能体基线，在 OSWorld (Xie et al., 2024)、Online-Mind2Web (Xue et al., 2025)、WebTailBench-v2 (Awadallah et al., 2025) 和 Odysseys (Jang et al., 2026) 上的成功率分别提高了 4.7%、3.4%、8.7% 和 25.5%，同时还显著缩短了 OSWorld 和 Odysseys 上的实际运行时间。随着测试时计算量的增加，MACU 也展现出更有前景的扩展趋势，能够解决单智能体计算机使用智能体（CUAs）陷入困境的长程任务。我们对 MACU 的配置进行了详细的消融实验，分析揭示了对最大限度发挥 MACU 效能至关重要的设计选择。我们认为，这些发现为进一步研究多智能体计算机使用系统的有效扩展奠定了坚实基础。
2 Related Work2 相关工作
Computer Use Agents计算机使用智能体
Several benchmarks have been established to measure the capabilities of frontier models on computer use tasks. OSWorld (Xie et al., 2024) established an execution-based grading of 369 open ended Ubuntu tasks spanning various native apps and multi-application workflows. WindowsAgentArena (Bonatti et al., 2025) adapts the OSWorld framework to 150+ tasks on a real Windows operating system. More recently, Gym-Anything (Aggarwal et al., 2026) leveraged coding and audit agents to automatically install and configure real software. Other benchmarks have focused on web navigation capabilities: WebArena (Zhou et al., 2024) provides a simulated environment of realistic self-hosted sites (Shopping, Reddit, GitLab, etc.) with execution-based grading, and VisualWebArena (Koh et al., 2024) extends it with visually grounded multimodal tasks. WebVoyager (He et al., 2024) evaluates CUAs directly on 15 real world websites, and WebLINX (Lù et al., 2024) evaluates multi-turn dialogue for web navigation. Online-Mind2Web (Xue et al., 2025) evaluates agents with a more robust judge, across 300 tasks on 136 live websites, and WebTailBench (Awadallah et al., 2025) proposes 609 tasks that include multi-step and cross-site tasks, drawn from high-traffic webpages. Odysseys (Jang et al., 2026) recently proposed 200 long-horizon web navigation tasks based on real human browsing patterns. On the capabilities front, frontier models have quickly improved on computer use, saturating many of these benchmarks. GPT-5.4 (OpenAI, 2026) achieves 75.0% on OSWorld, Opus 4.6 (Anthropic, 2026) achieves 72.7%, and Kimi K2.6 (Team et al., 2025) achieves 73.1%, which surpass human performance (72.4%). Other smaller open weight models such as MolmoWeb (Gupta et al., 2026), Qwen3.5 (Team, 2026), also achieve strong performance on these benchmarks, while being small enough (e.g., 4–9B parameter scale) to run locally. Most of these CUAs are evaluated and deployed as single serial actors. In this paper, we explore how we might instead coordinate and orchestrate CUAs in a multi-agent system, unlocking more effective planning and backtracking, higher parallelism, and improved test-time scaling behavior.
已有多个基准用于衡量前沿模型在计算机使用任务上的能力。OSWorld (Xie et al., 2024) 为 369 个开放式 Ubuntu 任务建立了基于执行结果的评分机制，这些任务涵盖多种原生应用和跨应用工作流。WindowsAgentArena (Bonatti et al., 2025) 将 OSWorld 框架适配到真实 Windows 操作系统上的 150+ 个任务。更近期，Gym-Anything (Aggarwal et al., 2026) 利用编码智能体和审计智能体自动安装并配置真实软件。其他基准则侧重于网页导航能力：WebArena (Zhou et al., 2024) 提供了由逼真的自托管网站（购物网站、Reddit、GitLab 等）构成的模拟环境，并采用基于执行结果的评分机制；VisualWebArena (Koh et al., 2024) 则在此基础上扩展了以视觉信息为依据的多模态任务。WebVoyager (He et al., 2024) 直接在 15 个真实网站上评估 CUAs，而 WebLINX (Lù et al., 2024) 则评估用于网页导航的多轮对话。Online-Mind2Web (Xue et al., 2025) 使用更稳健的评判器，在 136 个在线网站的 300 个任务上评估智能体；WebTailBench (Awadallah et al., 2025) 则提出了取自高流量网页的 609 个任务，其中包括多步骤任务和跨网站任务。Odysseys (Jang et al., 2026) 最近基于真实的人类浏览模式提出了 200 个长程网页导航任务。在能力方面，前沿模型在计算机使用上的表现迅速提升，使其中许多基准趋于饱和。GPT-5.4 (OpenAI, 2026) 在 OSWorld 上达到 75.0%，Opus 4.6 (Anthropic, 2026) 达到 72.7%，Kimi K2.6 (Team et al., 2025) 达到 73.1%，均超过了人类表现（72.4%）。其他规模较小的开放权重模型，如 MolmoWeb (Gupta et al., 2026)、Qwen3.5 (Team, 2026)，也在这些基准上取得了出色表现，同时其规模足够小（例如，4–9B 参数规模），可以在本地运行。这些 CUAs 大多作为单个串行执行主体进行评估和部署。本文探索如何在多智能体系统中协调和编排 CUAs，从而实现更有效的规划与回溯、更高的并行度，以及更好的测试时扩展表现。
Multi-Agent LLM Systems多智能体 LLM 系统
Multi-agent systems are composed of multiple interacting autonomous agents (Wooldridge, 2009), with a long history dating back as early as the 1980s (Durfee et al., 1989; Smith, 1979). More recently, multi-agent systems based on LLMs have been explored across a wide range of settings, including software engineering (SWE) (Hong et al., 2023; Geng and Neubig, 2026), scientific discovery (Lu et al., 2024; Gottweis et al., 2025), web search (Lee et al., 2026), and more. Many of these works frame the system as a computational graph (Zhuge et al., 2024; Qian et al., 2025) that can be dynamically adjusted (Chen et al., 2023) and scaled, or as systems that can recursively spawn subagents (Zhang et al., 2025a; Gandhi et al., 2026). Others target decomposition and scheduling in a more structured form, such as using a planner module that delegates tasks to specialized modules (Li et al., 2025; Zhang et al., 2025b; Nielsen et al., 2026; Xu et al., 2026). Specifically, in the computer use agent literature, a parallel thread focuses on dynamic replanning as the agent navigates. (Koh et al., 2025) proposes a tree search algorithm for CUAs which performs lookahead and backtracking using a value function to score each proposed action. Wang et al. (2025a) introduces a framework for inducing, verifying, and using program-based skills on the fly, as an agent continuously interacts with a web environment. Agent Workflow Memory (Wang et al., 2025b) learns reusable workflows and stores these for subsequent generations. Aghzal et al. (2026) find in a controlled hierarchical-planning study that a single round of exploratory replanning substantially improves success on web navigation tasks. Others explore orchestrating specialized submodules: Agent S2 (Agashe et al., 2025) introduces proactive hierarchical planning, refining plans after each subgoal success, and delegating tasks to workers and specialized expert modules, and CoAct-1 (Song et al., 2026) and InfantAgent-Next (Lei et al., 2025) delegate tasks to either a GUI operator or a code agent. Several systems have also been deployed successfully in user-facing products for web navigation and information gathering (Yutori team, 2025; Anthropic, 2025).
多智能体系统由多个相互交互的自主智能体组成 (Wooldridge, 2009)，其悠久历史最早可追溯至 1980s (Durfee et al., 1989; Smith, 1979)。近年来，基于 LLMs 的多智能体系统已在广泛场景中得到探索，包括软件工程（SWE）(Hong et al., 2023; Geng and Neubig, 2026)、科学发现 (Lu et al., 2024; Gottweis et al., 2025)、网页搜索 (Lee et al., 2026) 等。其中许多工作将系统建模为可动态调整 (Chen et al., 2023) 和扩展的计算图 (Zhuge et al., 2024; Qian et al., 2025)，或将其构建为能够递归创建子智能体的系统 (Zhang et al., 2025a; Gandhi et al., 2026)。另一些工作则以更具结构化的方式进行任务分解和调度，例如使用规划模块将任务委派给专门的模块 (Li et al., 2025; Zhang et al., 2025b; Nielsen et al., 2026; Xu et al., 2026)。具体而言，在计算机使用智能体的相关文献中，另一条并行的研究路线关注智能体导航过程中的动态重规划。(Koh et al., 2025) 为 CUAs 提出了一种树搜索算法，利用价值函数对每个候选动作进行评分，从而执行前瞻搜索和回溯。Wang et al. (2025a) 提出了一种框架，可在智能体与网页环境持续交互的过程中，即时归纳、验证并使用基于程序的技能。Agent Workflow Memory (Wang et al., 2025b) 学习可复用的工作流，并将其存储以供后续生成使用。Aghzal et al. (2026) 在一项受控的分层规划研究中发现，单轮探索性重规划就能显著提高网页导航任务的成功率。其他研究探索了对专用子模块的编排：Agent S2 (Agashe et al., 2025) 引入了主动式层次规划，在每个子目标达成后细化计划，并将任务委派给工作智能体和专用专家模块；CoAct-1 (Song et al., 2026) 和 InfantAgent-Next (Lei et al., 2025) 则将任务委派给 GUI 操作智能体或代码智能体。若干系统也已成功部署到面向用户的产品中，用于网页导航和信息收集 (Yutori team, 2025; Anthropic, 2025)。
In this paper we investigate how to best develop a multi-agent framework for general computer use: a partially observable problem that involves complex challenges such as grounding, computer interaction, and long-horizon planning. Our framework is general, simple and scalable. We only use 2 types of agents: a planner, and a homogenous set of subagent workers, while prior work typically uses specialized modules for handling low-level actions (Agashe et al., 2025; Lei et al., 2025; Song et al., 2026), or focus on fully observable environments such as code generation (Hong et al., 2023; Geng and Neubig, 2026) and math (Motwani et al., 2025; Zhao et al., 2025; Madaan et al., 2025). Our work aims to develop the principles for building a strong, simple, and generalizable framework for multi-agent computer use.
本文研究如何以最佳方式构建用于通用计算机操作的多智能体框架：通用计算机操作是一个部分可观测问题，涉及基于环境的语义落地（grounding）、计算机交互和长时程规划等复杂挑战。我们的框架具有通用性、简洁性和可扩展性。我们仅使用 2 类智能体：一个规划智能体，以及一组同质的子智能体工作单元；而先前工作通常使用专用模块来处理底层操作 (Agashe et al., 2025; Lei et al., 2025; Song et al., 2026)，或聚焦于代码生成 (Hong et al., 2023; Geng and Neubig, 2026) 和数学 (Motwani et al., 2025; Zhao et al., 2025; Madaan et al., 2025) 等完全可观测环境。我们的工作旨在确立构建强大、简洁且具有泛化能力的多智能体计算机操作框架的原则。

The overall flow of MACU is shown in Fig. 1 and Alg. 1. MACU involves a single manager agent that coordinates a pool of CUA subagents by mutating a directed acyclic graph (DAG) of subtasks to be completed. Conditioned on an instruction specified in natural language, the manager produces an initial DAG decomposition of the task (Fig. 2). At each iteration, CUA subagents are dispatched in parallel to tackle subtasks on the ready frontier of the DAG (i.e., nodes whose dependencies are satisfied). Whenever new observations and evidence become available, the manager is prompted to revise the DAG. We describe the roles of the manager and subagents in detail below.
MACU 的整体流程见图 1 和算法1。MACU 包含一个管理智能体，该智能体通过修改由待完成子任务构成的有向无环图（DAG），协调一组 CUA 子智能体。管理智能体根据以自然语言指定的指令，生成任务的初始 DAG 分解（图 2）。在每次迭代中，系统并行派遣 CUA 子智能体，处理 DAG 就绪前沿上的子任务（即依赖条件均已满足的节点）。每当获得新的观察结果和证据时，系统就会提示管理智能体修订 DAG。下文将详细介绍管理智能体和子智能体的角色。
Manager管理智能体
The manager, which can be a local model or an API based model, orchestrates and coordinates CUA subagents that operate in isolated virtual machines (VMs). The manager is implemented as an LLM call that takes in the task instruction, the current DAG, and the latest observations from the CUA subagent nodes. The manager is invoked at several key points:
管理智能体可以是本地模型，也可以是通过 API 调用的模型，负责编排和协调在隔离虚拟机（VM）中运行的 CUA 子智能体。管理智能体以一次 LLM 调用的形式实现，接收任务指令、当前 DAG，以及来自 CUA 子智能体节点的最新观察结果作为输入。管理智能体会在以下几个关键时点被调用：
Initial DAG decomposition: The manager is prompted with the original task instruction and the screenshot of the starting VM state (if any), and is instructed to produce a DAG $G$ represented as a JSON string (which is validated for correctness).
初始 DAG 分解：系统向管理智能体提供原始任务指令和虚拟机初始状态的截图（如有），并指示其生成以 JSON 字符串表示的 DAG $G$（该字符串会接受正确性验证）。
Replanning: After a CUA subagent $v$ completes its assigned task, the manager is provided with the current DAG $G$ , the last $k$ screenshots and final response from $v$ , as well as context from the parent nodes of $v$ in the form of their final VM screenshot and response. The manager is prompted to respond with a possible list of edits to make to $G$ : add a node, remove a node, modify the instructions or dependencies of a node, or cancel a currently running node. These actions can change the structure of the graph or modify the instructions to be provided to future subagent nodes. Multiple edits can be made in a single replan call, provided they still result in a valid DAG. Each edit consumes a unit of the replan budget $B$ . Once $B$ is exhausted we do not allow any additional edits to $G$ . We also perform replanning intermittently if we have additional worker capacity that is not being used, to allow the manager to use spare capacity productively (e.g., exploration to find additional information, or try out different possible solutions).
重新规划：在 CUA 子智能体 $v$ 完成所分配的任务后，系统向管理智能体提供当前 DAG $G$、$v$ 的最后 $k$ 张截图和最终回复，以及 $v$ 的父节点的上下文，后者以这些父节点的最终虚拟机截图和回复的形式提供。系统提示管理智能体返回一个可能的 $G$ 编辑操作列表：添加节点、删除节点、修改节点的指令或依赖关系，或取消当前正在运行的节点。这些操作可以改变图的结构，或修改将提供给后续子智能体节点的指令。一次重新规划调用中可以执行多项编辑，前提是编辑后的结果仍为有效的 DAG。每项编辑消耗一个单位的重新规划预算 $B$。一旦 $B$ 耗尽，我们就不再允许对 $G$ 进行任何额外编辑。当存在尚未使用的额外工作智能体容量时，我们也会间歇性地执行重新规划，使管理智能体能够有效利用闲置容量（例如，探索以寻找更多信息，或尝试不同的可能解决方案）。
File management: A key requirement of many CUA tasks is the ability to create, maintain, and produce files. On the completion of each CUA subagent, the manager is provided with a diff of the filesystem to identify added or modified files. It is prompted to determine which files to save. When starting up a new subtask, the manager can similarly provide previously retained files as input to the new subtasks (e.g., handing off a Word document from subtask 1 to be used by subtask 2 to populate slides in PowerPoint).
文件管理：许多 CUA 任务的一项关键要求是能够创建、维护和产出文件。每个 CUA 子智能体完成工作后，系统会向管理智能体提供文件系统的差异信息，以识别新增或修改的文件。系统会提示管理智能体确定要保存哪些文件。启动新的子任务时，管理智能体同样可以将先前保留的文件作为新子任务的输入（例如，将子任务 1 中的 Word 文档移交给子任务 2，用于填充 PowerPoint 中的幻灯片内容）。
Follow up: When each CUA subagent completes its unit of work, the manager inspects it by being prompted with its latest responses and screenshot observations. The manager can optionally task the CUA subagent to continue working with a modified instruction, or get the subagent to summarize its work and terminate.
后续处理：每个 CUA 子智能体完成其工作单元后，系统会向管理智能体提供该子智能体的最新回复和截图观察结果，供其检查工作情况。管理智能体可以选择向 CUA 子智能体下达修改后的指令，让其继续工作，也可以让子智能体总结其工作并终止运行。
Aggregate and summarize: The final leaf node in the DAG prompts the manager to aggregate and summarize results from the observations and responses of its parent nodes. This produces a final response for the user.
汇总与总结：DAG 中的最终叶节点会提示管理器，根据其父节点的观察结果和响应汇总并总结结果。由此生成面向用户的最终响应。
Subagents子智能体
Each subagent executes a standard ReAct (Yao et al., 2022) loop used by most frontier CUA models. At each iteration, the subagent observes a screenshot from its VM, produces reasoning traces and a computer action, which is then executed on the VM. MACU treats this subagent loop as a black box: each subagent runs on its own isolated VM. This treatment enables the manager to be free of model-specific assumptions, and agnostic to the specific CUA used, enabling MACU to work with new releases of improved CUA models (see Sec. 4.2 which show improved scaling trends with stronger subagents). We use the same CUA backbone for each subagent. Specialization only arises from manager-written instructions and the VMs that subagents initialize from or inherit.
每个子智能体都执行一个标准的 ReAct (Yao et al., 2022) 循环，大多数前沿 CUA 模型都采用这种循环。在每次迭代中，子智能体观察其虚拟机的屏幕截图，生成推理轨迹和一个计算机操作，随后在该虚拟机上执行该操作。MACU 将这一子智能体循环视为黑箱：每个子智能体都在各自隔离的虚拟机上运行。这种处理方式使管理器无需依赖特定模型的假设，也不依赖所使用的具体 CUA，从而使 MACU 能够适配新发布的、性能更强的 CUA 模型（参见第 4.2 节，其中展示了采用更强子智能体时更佳的扩展趋势）。我们为每个子智能体使用相同的 CUA 骨干模型。子智能体的专门化仅源于管理器编写的指令，以及子智能体初始化时所用或继承的虚拟机。

4.1 Results4.1 结果
Our main experimental results are summarized in Tab. 1. MACU consistently improves the success rate across all four benchmarks. With the Opus 4.6 manager, MACU improves the success rate on OSWorld from 43.8% to 48.5%, and reduces the median wall-clock time from 26.6 to 21.4 mins per task. Online-Mind2Web demonstrates similar trends, improving success rate from 52.2% to 55.6%. We observed that wall-clock time on Online-Mind2Web tasks actually increase, as the tasks are largely serial, and additional manager calls also add a substantial amount of wall-clock time (see Sec. 4.3 for more discussion), resulting in less benefits from multi-agent deployment and parallelization.
我们的主要实验结果汇总于表1。MACU 在全部四个基准上均能稳定提高成功率。采用 Opus 4.6 管理器时，MACU 将 OSWorld 上的成功率从 43.8% 提高到 48.5%，并将每项任务的实际耗时中位数从 26.6 分钟降至 21.4 分钟。Online-Mind2Web 呈现出类似趋势，成功率从 52.2% 提高到 55.6%。我们观察到，Online-Mind2Web 任务的实际耗时反而增加了，因为这些任务大多需要串行执行，而且额外的管理器调用也会显著增加实际耗时（更多讨论见第 4.3 节），使得多智能体部署和并行化带来的收益较小。
Conversely, MACU achieves larger improvements on WebTailBench-v2 and Odysseys, which contain tasks that are typically more complex or require working over longer horizons. These tasks benefit more from being decomposed into smaller subproblems which can be executed in parallel. On WebTailBench-v2, MACU improves the success rate from 20.8% to 29.5%, and the percentage of rubrics satisfied from 35.9% to 46.3%. Manager replanning also takes up significant wall time, which contributes to an overall increase in the median wall-clock time. On Odysseys, MACU substantially improves the success rate from 8.5% to 34.0%, as well as the percentage of rubrics satisfied per task from 42.1% to 62.3%. This indicates that MACU successfully completes tasks at a higher rate, as well as achieves higher partial credit on tasks that it does not fully complete. We also observed a $1.47\times$ speed up in wall-clock time on Odysseys: the median time spent per task was reduced from 162 to 110 mins, due to the effectiveness of parallel execution on these tasks. We observed similar trends across benchmarks with Qwen3.6-27B as the manager (albeit with lower absolute improvements).
相比之下，MACU 在 WebTailBench-v2 和 Odysseys 上取得了更大幅度的提升，这两个基准包含的任务通常更复杂，或需要在更长的时程内开展工作。将这些任务分解为可并行执行的较小子问题，能够带来更多收益。在 WebTailBench-v2 上，MACU 将成功率从 20.8% 提高到 29.5%，并将已满足的评分标准所占百分比从 35.9% 提高到 46.3%。管理器的重新规划也占用了大量实际时间，这也是实际耗时中位数总体增加的原因之一。在 Odysseys 上，MACU 将成功率从 8.5% 显著提高到 34.0%，同时将每项任务满足的评分标准比例从 42.1% 提高到 62.3%。这表明，MACU 不仅成功完成任务的比例更高，而且在未完全完成的任务上也能获得更高的部分得分。我们还观察到，在 Odysseys 上，按实际耗时计算实现了 $1.47\times$ 的加速：由于并行执行在这些任务上有效，每项任务的耗时中位数从 162 分钟降至 110 分钟。当使用 Qwen3.6-27B 作为管理器时，我们在各项基准测试中观察到了类似趋势（尽管绝对提升幅度较小）。
MACU also demonstrates positive scaling trends as models are provided with greater inference budget. Fig. 3 plots the success rate against the total number of CUA subagent steps that each model has executed. Single-agent setups plateau much earlier on compared to MACU, and the success rate gap widens as more actions are executed, demonstrating that MACU can effectively leverage greater inference budget to achieve stronger results.
随着为模型提供的推理预算增加，MACU 也表现出良好的扩展趋势。图 3 展示了成功率随各模型已执行的 CUA 子智能体总步数的变化。与 MACU 相比，单智能体配置更早进入性能平台期，而且随着执行的动作增多，成功率差距不断扩大，这表明 MACU 能够有效利用更多推理预算来取得更好的结果。
As we move towards longer horizon computer use tasks, such as those in Odysseys (Jang et al., 2026), multi-agent approaches such as MACU become more valuable. MACU achieves substantially higher performance on long-horizon tasks, while maintaining its performance on shorter tasks (such as those in OSWorld and Online-Mind2Web), making it a general approach that excels on more complex tasks while preserving performance on simpler ones. These findings strongly motivate moving towards building, researching, and evaluating multi-agent computer use systems instead of serial agents, especially as we start deploying LLM agents on more complex, long running real world tasks.
随着我们转向执行跨度更长的计算机使用任务，例如 Odysseys 中的任务 (Jang et al., 2026)，MACU 等多智能体方法变得更有价值。MACU 在长跨度任务上取得了显著更高的性能，同时保持了在较短任务（例如 OSWorld 和 Online-Mind2Web 中的任务）上的性能，因此是一种通用方法，能够在更复杂的任务上表现出色，同时保持在较简单任务上的性能。这些发现为转向构建、研究和评估多智能体计算机使用系统而非串行智能体提供了有力依据，尤其是在我们开始将 LLM 智能体部署到更复杂、运行时间更长的现实世界任务中时。

We ablate increasing the planning budget $B$ , which represents how many times the manager is able to modify the DAG when attempting a task. The results (Tab. 2) highlight the importance of re-planning on the fly. Increasing $B$ from 0 (no planning) to 1 (generate an initial DAG, but no modifications allowed after) results in a minimal change in success rate ( $25.0\%\rightarrow 27.8\%$ ), but enabling MACU to modify the graph during the runtime of the task ( $B>1$ ) improves success rate much more significantly, from 25.0% (no planning) to 47.2% with $B=5$ and 58.3% with $B=10$ . These results highlight the importance of continuous replanning when new observations are received.
我们通过消融实验考察增加规划预算 $B$ 的影响，该预算表示管理器在尝试完成一项任务时能够修改 DAG 的次数。结果（表2）凸显了动态重新规划的重要性。将 $B$ 从 0（不进行规划）增加到 1（生成初始 DAG，但此后不允许修改）仅带来很小的成功率变化（$25.0\%\rightarrow 27.8\%$），但允许 MACU 在任务运行期间修改图（$B>1$）则能显著提高成功率，从 25.0%（不进行规划）提高到 $B=5$ 时的 47.2% 和 $B=10$ 时的 58.3%。这些结果凸显了在接收到新观测时持续重新规划的重要性。

When does multi-agent help?多智能体何时有帮助？
We stratified performance by difficulty level (Fig. 6), task domain, and also qualitatively by examining execution traces. On Odysseys, gains from MACU were especially large on easy and medium tasks, with success rate improving from $22.2\%\rightarrow 82.2\%$ and $11.1\%\rightarrow 46.7\%$ respectively. The hard subset also improved substantially on both success rate ( $1.8\%\rightarrow 9.2\%$ ) and rubric score ( $26.5\%\rightarrow 43.1\%$ ). WebTailBench-v2 categories which required parallel information gathering and comparison benefit the most from MACU: price_comparison tasks improved from $3.7\%\rightarrow 33.9\%$ , flights from $14.0\%\rightarrow 34.0\%$ , and compositional_tasks_v2 from $24.0\%\rightarrow 41.8\%$ . Online-M2W showed a smaller but consistent gain primarily concentrated on the easy subset ( $72.4\%\rightarrow 82.9\%$ ) but remained relatively similar on medium ( $50.8\%\rightarrow 51.5\%$ ) and hard ( $37.0\%\rightarrow 38.4\%$ ) tasks. On OSWorld tasks (which doesn’t have difficulty labels), we observed the strongest gains on OS and Ubuntu tasks ( $45.8\%\rightarrow 70.8\%$ ), as well as tasks on the LibreOffice productivity suite: LibreOffice Writer ( $47.8\%\rightarrow 60.9\%$ ), Calc ( $34.0\%\rightarrow 46.8\%$ ), and Impress ( $40.2\%\rightarrow 50.9\%$ ). Across benchmarks, we observed a general trend that MACU is strongest on decomposable tasks that require parallel exploration and information gathering. This often requires preserving multiple pieces of the state before the final response (e.g., Odysseys tasks in Tab. 5).
我们按难度级别（图 6）和任务领域对性能进行了分层分析，并通过检查执行轨迹进行了定性分析。在 Odysseys 上，MACU 在简单和中等难度任务上的提升尤为显著，成功率分别从 $22.2\%\rightarrow 82.2\%$ 和 $11.1\%\rightarrow 46.7\%$。困难子集的成功率（$1.8\%\rightarrow 9.2\%$）和评分标准得分（$26.5\%\rightarrow 43.1\%$）也均有显著提升。WebTailBench-v2 中需要并行收集信息并进行比较的类别从 MACU 中获益最多：price_comparison 任务从 $3.7\%\rightarrow 33.9\%$，flights 从 $14.0\%\rightarrow 34.0\%$，compositional_tasks_v2 从 $24.0\%\rightarrow 41.8\%$。Online-M2W 的提升较小但稳定，主要集中在简单子集（$72.4\%\rightarrow 82.9\%$），而在中等难度（$50.8\%\rightarrow 51.5\%$）和困难（$37.0\%\rightarrow 38.4\%$）任务上则保持相对接近的水平。在 OSWorld 任务（没有难度标签）上，我们观察到 OS 和 Ubuntu 任务（$45.8\%\rightarrow 70.8\%$）以及 LibreOffice 办公套件任务的提升最为显著：LibreOffice Writer（$47.8\%\rightarrow 60.9\%$）、Calc（$34.0\%\rightarrow 46.8\%$）和 Impress（$40.2\%\rightarrow 50.9\%$）。在各项基准中，我们观察到一个总体趋势：MACU 在需要并行探索和信息收集的可分解任务上表现最为出色。这通常要求在给出最终响应之前保留多项状态信息（例如，表中的 Odysseys 任务。5）。

5 Conclusion5 结论
In this paper, we argued that computer use agents should move beyond the prevailing single serial agent paradigm, and proposed a general multi-agent computer use (MACU) framework that directly targets complex and long-horizon CUA tasks. Across four diverse computer use benchmarks, we demonstrated that MACU consistently improves the success rates of strong single-agent baselines, and exhibits more favorable test-time scaling than its single-agent counterpart, solving long-horizon tasks that serial single-agents get stuck on. Our ablation results highlight that continuous replanning and parallel subagent execution are key to unlocking these gains, and that multi-agent coordination is a promising axis for scaling computer use agents to work productively for longer. Integrating new CUA models into the MACU framework is seamless, and we expect success rates to continue to compound with future advances in stronger CUA models and capabilities. We hypothesize that finetuning or reinforcement learning will also substantially improve the abilities of the system, as managers and workers become trained for multi-agent coordination and interaction, which is a promising direction for future work. We release our code and interactive visualizations of MACU on selected tasks at https://jykoh.com/multi-agent-computer-use to facilitate future work.
本文主张，计算机使用智能体应突破当前主流的单智能体串行范式，并提出了一个通用的多智能体计算机使用（MACU）框架，直接面向复杂且长时程的 CUA 任务。在四个不同的计算机使用基准测试中，我们证明，MACU 能够持续提高强大单智能体基线的成功率，并且相较于对应的单智能体系统，展现出更有利的测试时扩展特性，能够解决串行单智能体会陷入困境的长时程任务。我们的消融实验结果表明，持续重规划和子智能体并行执行是实现这些性能提升的关键，而多智能体协调是扩展计算机使用智能体能力、使其能够在更长时间内高效工作的一个有前景的方向。新的 CUA 模型可以无缝集成到 MACU 框架中，我们预计，随着未来更强大的 CUA 模型及其能力不断发展，成功率也将持续累积提升。我们推测，微调或强化学习也将显著提升系统能力，因为管理者和工作者可以接受针对多智能体协调与交互的训练，这是未来研究的一个有前景的方向。我们在 https://jykoh.com/multi-agent-computer-use 发布了代码以及 MACU 在部分任务上的交互式可视化，以促进后续研究。

A.1 Virtual Machines Technical DetailsA.1 虚拟机技术细节
MACU launches each CUA subagent through OSWorld’s DesktopEnv; the subagent process constructs the requested VM provider, starts the emulator, records the VM endpoint, and writes the in-VM HTTP, browser-debugging, VNC, and VLC ports to a status file vm_info.json for the MACU runtime. Subagents initialize from a provided VM state (if any). We implement two VM backbones:
MACU 通过 OSWorld 的 DesktopEnv 启动每个 CUA 子智能体；子智能体进程构建所请求的虚拟机提供程序，启动模拟器，记录虚拟机端点，并将虚拟机内的 HTTP、浏览器调试、VNC 和 VLC 端口写入状态文件 vm_info.json，供 MACU 运行时使用。子智能体从所提供的虚拟机状态进行初始化（如果提供了该状态）。我们实现了两种虚拟机底层架构：
VMware provider.VMware 提供程序。
Before launching an independent DAG node, the MACU runtime atomically claims a pool VM and creates a vmrun snapshot named for the subtask. For state transfer along DAG dependencies, a child node may reclaim a completed predecessor’s VM and skip canonical setup, preserving the predecessor CUA subagent’s final desktop and filesystem state (i.e., effectively resuming from the parent subtask). For retry or variant nodes, MACU makes a full VMware clone of its frozen initial state, so parallel attempts start from the same pre-subtask state without sharing a mutable VM.
在启动一个独立的 DAG 节点之前，MACU 运行时会以原子方式从池中占用一台虚拟机，并创建一个以该子任务命名的 vmrun 快照。对于沿 DAG 依赖关系进行的状态传递，子节点可以接管已完成的前驱节点的 VM，并跳过标准初始化，从而保留前驱 CUA 子智能体最终的桌面和文件系统状态（即实际上从父子任务结束时的状态继续执行）。对于重试节点或变体节点，MACU 会对其冻结的初始状态进行完整的 VMware 克隆，使并行尝试从相同的子任务执行前状态开始，而无需共享可变的 VM。
Apptainer/QEMU provider.Apptainer/QEMU 提供程序。
On clusters where Docker or VMware is inconvenient, the Apptainer provider boots the same OSWorld image by running qemu-system-x86_64 inside an Apptainer SIF. The base image, overlay directory, SIF path, and run directory, are preconfigured, and each fresh CUA subagent VM is a new writable qcow2 overlay backed by the shared base image. Initialization and resumption are handled similarly to the VMware backend. When an Apptainer-backed CUA subagent starts from an inherited overlay, the provider walks the overlay backing chain to find a saved VM state overlay; if present, QEMU is launched with a migration command to restore from the overlay. State transfer for Apptainer DAG nodes is similarly implemented by overlay cloning. Child nodes skip canonical setup when it intentionally inherits that state. At run teardown, MACU kills only QEMU processes that own the run’s overlays and deletes overlay files in child-before-parent order so qcow2 backing chains are not removed underneath still-existing child nodes.
在不便使用 Docker 或 VMware 的集群上，Apptainer 提供程序通过在 Apptainer SIF 内运行 qemu-system-x86_64 来启动相同的 OSWorld 镜像。基础镜像、覆盖层目录、SIF 路径和运行目录均已预先配置，每个新建的 CUA 子智能体 VM 都是一个以共享基础镜像为后备的新可写 qcow2 覆盖层。初始化和恢复的处理方式与 VMware 后端类似。当基于 Apptainer 的 CUA 子智能体从继承的覆盖层启动时，提供程序会遍历覆盖层的后备链，以查找保存了 VM 状态的覆盖层；如果找到，则通过迁移命令启动 QEMU，从该覆盖层恢复状态。Apptainer DAG 节点的状态传递同样通过覆盖层克隆实现。当子节点有意继承该状态时，会跳过标准初始化。在运行结束后的清理阶段，MACU 仅终止持有本次运行覆盖层的 QEMU 进程，并按照先子后父的顺序删除覆盖层文件，以免在子节点仍然存在时移除其所依赖的 qcow2 后备链。
Appendix B Limitations附录 B 局限性
While we have shown that MACU achieves promising results across computer-use benchmarks, our approach comes with several practical considerations and possible directions to address in future work.
尽管我们已表明 MACU 在各类计算机使用基准上取得了良好的结果，但我们的方法仍有若干实际应用中需要考虑的问题，以及可在未来工作中探索的解决方向。
Increased inference-time cost.推理阶段成本增加。
MACU improves performance by providing an additional dimension to spend test-time compute, through decomposition, replanning, and parallel CUA subagent execution (Sec. 3). In our main experiments, we allow up to $N=4$ parallel subagents and a replan budget of $B=10$ (Appendix A), which can require substantially more model calls and VM execution time than a single-agent setting. This extra compute is not always offset by wall-clock speedup: on Online-Mind2Web, MACU improves success rate from 52.2% to 55.6%, but increases median wall-clock time from 18.5 to 33.6 minutes because many tasks are largely serial (Sec. 4.1). In practical systems, the parallelism level $N$ , replan budget $B$ , and per-subtask step limit must therefore be tuned based on whether the target workload actually benefits from additional exploration, as well as the GPU and CPU resources available at hand.
MACU 通过任务分解、重新规划和 CUA 子智能体的并行执行，为投入测试时计算资源提供了一个额外维度，从而提升性能（第 3 节）。在主要实验中，我们最多允许 $N=4$ 个并行子智能体，并将重新规划预算设为 $B=10$（附录 A），这可能需要比单智能体设置多得多的模型调用和 VM 执行时间。实际耗时的缩短并不总能抵消这些额外计算开销：在 Online-Mind2Web 上，MACU 将成功率从 52.2% 提升至 55.6%，但由于许多任务主要需要串行执行，实际耗时的中位数从 18.5 分钟增加到了 33.6 分钟（第 4.1 节）。因此，在实际系统中，必须根据目标工作负载是否确实能从额外探索中获益，以及当前可用的 GPU 和 CPU 资源，调整并行度 $N$、重新规划预算 $B$ 和每个子任务的步数上限。
Benefits depend on task decomposability.收益取决于任务的可分解性。
Our analysis shows that MACU is strongest on tasks that naturally decompose into parallel exploration, independent information gathering, retry attempts, or alternative execution strategies (Sec. 4.3). This explains the large gains on Odysseys, where many tasks have parallel map-reduce structure, and lower gains on OSWorld and Online-Mind2Web, which more often involve single-task GUI execution or serial interactions. For inherently sequential tasks, spawning additional subagents may add overhead without creating useful parallel work. Future systems should learn when to use multi-agent execution, when to fall back to a single agent, and how to avoid manufacturing unnecessary subtasks.
我们的分析表明，对于能够自然分解为并行探索、独立信息收集、重试尝试或替代执行策略的任务，MACU 的表现最为出色（第 4.3 节）。这解释了为何 MACU 在 Odysseys 上的提升较大，因为其中许多任务具有并行 map-reduce 结构；而在 OSWorld 和 Online-Mind2Web 上的提升较小，因为它们更常涉及单任务 GUI 操作或串行交互。对于本质上需要顺序执行的任务，生成额外的子智能体可能只会增加开销，而无法产生有用的并行工作。未来的系统应学习何时采用多智能体执行、何时回退到单智能体，以及如何避免人为构造不必要的子任务。
Additional system complexity.额外的系统复杂性。
Computer use differs from text-only agents because relevant state can live in screenshots, open tabs, filesystem changes, background processes, cookies, or application state (Sec. 3). MACU addresses this through isolated VMs, screenshot context, filesystem diffs, and an archive pool for selected files. These mechanisms make multi-agent execution possible, but they also introduce additional overhead in maintaining these additional infrastructure concerns. More robust state serialization, VM cloning, file provenance tracking, and automatic validation of final artifacts are important directions for future work.
计算机使用与纯文本智能体有所不同，因为相关状态可能存在于屏幕截图、打开的标签页、文件系统变更、后台进程、cookie 或应用程序状态中（第 3 节）。MACU 通过隔离的 VM、屏幕截图上下文、文件系统差异以及用于存放选定文件的归档池来处理这一问题。这些机制使多智能体执行成为可能，但维护这些额外的基础设施也会带来额外开销。更稳健的状态序列化、VM 克隆、文件来源追踪以及最终产物的自动验证，是未来工作的重要方向。
Evaluation may not capture real world risks.评估可能无法涵盖现实世界的风险。
We evaluated on standard computer-use benchmarks: OSWorld, Online-Mind2Web, and Odysseys, which cover desktop control, live website navigation, and long-horizon web tasks. These benchmarks are useful for measuring capabilities, but they do not fully capture the risks and operational constraints of real world deployments. Real user environments may involve private accounts, irreversible actions, authentication flows, or stricter reliability requirements. As discussed in Sec. C, deployment would require additional safeguards such as user authorization, action restrictions, monitoring, and confirmation for high-risk actions. Our results should therefore be interpreted as evidence that multi-agent coordination is a compelling research direction, not as evidence that multi-agent computer use is ready for real-world deployments.
我们在标准计算机使用基准 OSWorld、Online-Mind2Web 和 Odysseys 上进行了评估，这些基准涵盖桌面控制、在线网站导航和长时程网页任务。这些基准有助于衡量能力，但无法全面涵盖现实部署中的风险和运行约束。真实用户环境可能涉及私人账户、不可逆操作、身份验证流程，或更严格的可靠性要求。如第 C 节所述，部署需要额外的保障措施，例如用户授权、操作限制、监控，以及对高风险操作的确认。因此，我们的结果应被解读为多智能体协调是一个极具吸引力的研究方向的证据，而不能被视为多智能体计算机使用已可投入现实部署的证据。
Appendix C Broader Impacts附录 C 更广泛的影响
As computer use agents continue to become more capable, multi-agent computer use systems which leverage these models presents both new opportunities as well as potential ethical considerations. MACU is a research framework for coordinating CUA subagents. In this paper, we evaluate the framework on existing computer-use and web-navigation benchmarks rather than deploying it to real users. We also do not introduce new model weights or datasets. The potential positive impact of this line of work is that more reliable CUAs, which are likely to arise in part due to strong multi-agent systems, could help people complete long-horizon computer tasks, automate repetitive workflows, and improve accessibility for users who have difficulty interacting with complex software interfaces. However, improving the reliability and speed of CUAs also raises potential concerns:
随着计算机使用智能体的能力不断增强，利用这些模型的多智能体计算机使用系统既带来了新的机遇，也引出了潜在的伦理考量。MACU 是一个用于协调 CUA 子智能体的研究框架。本文在现有的计算机使用和网页导航基准上评估该框架，而未将其部署给真实用户。我们也未引入新的模型权重或数据集。这一研究方向的潜在积极影响在于，更可靠的 CUA 可能部分得益于强大的多智能体系统而出现，能够帮助人们完成长时程计算机任务、自动执行重复性工作流程，并提升难以与复杂软件界面交互的用户的使用便利性。然而，提高 CUA 的可靠性和速度也引发了以下潜在担忧：
Intended uses. Our work is intended as a research demo for studying how to coordinate multiple computer use agents on complex tasks. It is not, in its current form, intended for deployment on live user accounts, production websites, or security-sensitive environments. Any real-world use of multi-agent CUA systems should include further research, as well as careful scoping, user authorization guardrails, and safeguards around which applications, websites, files, and accounts an agent may access.
预期用途。我们的工作旨在提供一个研究演示，用于研究如何协调多个计算机使用智能体来完成复杂任务。就当前形式而言，它不适合部署于实际用户账户、生产环境网站或安全敏感环境。在现实世界中使用多智能体 CUA 系统时，应开展进一步研究，审慎界定使用范围，设置用户授权防护机制，并针对智能体可访问的应用程序、网站、文件和账户采取保障措施。
Misuse and security. A system that can dispatch multiple CUA workers could be misused to scale harmful computer activity, including phishing, spam, manipulation, scraping, or other unauthorized workflows. Even in benign use, agents acting through GUIs and websites can make unintended changes, hallucinate incorrect information, or take destructive actions in a live environment. Eventual real world deployment of such systems should therefore require action restrictions, human approval for irreversible or high-impact operations, and continuous monitoring for abnormal behavior.
滥用与安全。能够调度多个 CUA 执行智能体的系统可能被滥用，用于扩大有害计算机活动的规模，包括网络钓鱼、垃圾信息发送、操纵、数据抓取或其他未经授权的工作流程。即便在善意使用的情况下，通过图形用户界面（GUI）和网站执行操作的智能体也可能在实际运行环境中造成意外更改、生成错误的幻觉信息，或采取破坏性操作。因此，此类系统最终在现实世界中部署时，应要求设置操作限制，对不可逆或影响重大的操作取得人工批准，并持续监测异常行为。
Privacy and data handling. MACU passes screenshots, filesystem diffs, and selected files through a manager and shared archive pool. In real deployments, these artifacts could contain private documents, browser state, credentials, cookies, personal information, or proprietary data. Practical systems should safeguard the data exposed to these models, redact sensitive content where possible, limit retention of screenshots and file archives, respect website terms of service, and ensure that users understand what information is being processed.
隐私与数据处理。MACU 通过管理器和共享归档池传递屏幕截图、文件系统差异和选定文件。在实际部署中，这些产物可能包含私密文档、浏览器状态、凭据、cookie、个人信息或专有数据。实用系统应保护向这些模型暴露的数据，在可能的情况下隐去敏感内容，限制屏幕截图和文件归档的保留期限，遵守网站服务条款，并确保用户了解正在处理哪些信息。
Economic impact. More capable computer use agents may automate routine workflows in web navigation, document editing, data entry, software configuration, and information gathering. We expect such systems to be most useful when they augment people by offloading tedious or time-consuming menial computer tasks. At the same time, broader deployment may affect roles centered on repetitive computer work, and developers should proactively consider human oversight, worker transition costs, and the design of systems that complement rather than simply replace human labor.
经济影响。能力更强的计算机使用智能体可能会自动执行网页导航、文档编辑、数据录入、软件配置和信息收集中的常规工作流程。我们预计，当此类系统通过承担繁琐或耗时的低技能计算机任务来增强人的能力时，它们将最为有用。与此同时，更广泛的部署可能会影响以重复性计算机工作为核心的岗位，开发者应主动考虑人工监督、劳动者转型成本，以及如何设计能够补充人类劳动而非仅仅替代人类劳动的系统。
Fairness and bias. MACU relies on the behavior of the underlying manager and CUA models, which may inherit biases or uneven capabilities from their training data and model design. Performance may vary across languages, websites, software interfaces, accessibility contexts, and user groups. Before deployment, multi-agent CUA systems should be evaluated across diverse tasks and users, and should include mechanisms for user correction and appeal.
公平性与偏见。MACU 依赖底层管理器模型和 CUA 模型的行为，而这些模型可能从其训练数据和模型设计中继承偏见或能力不均衡的问题。其性能可能因语言、网站、软件界面、无障碍使用情境和用户群体而异。部署之前，应针对多样化的任务和用户评估多智能体 CUA 系统，并纳入供用户纠正和申诉的机制。
The structure of MACU also provides new opportunities for mitigation strategies. Because all work is mediated through the manager’s DAG, safety checks can be inserted at decomposition, replanning, file-management, and final aggregation time. For example, a system can reject subtasks that visit disallowed websites, require confirmation before file deletion, or terminate subagents that appear to be looping or violating policy. The use of isolated VMs, explicit subtask instructions, and manager decisions provides natural boundaries for containment and review. We encourage future work on multi-agent computer use to study these safety mechanisms alongside capability improvements, especially before moving from benchmark environments to real user-facing deployments.
MACU 的结构也为风险缓解策略提供了新的机会。由于所有工作都通过管理器的有向无环图（DAG）进行协调，因此可以在任务分解、重新规划、文件管理和最终汇总阶段加入安全检查。例如，系统可以拒绝访问禁用网站的子任务，在删除文件前要求确认，或终止看似陷入循环或违反策略的子智能体。使用隔离的虚拟机（VM）、明确的子任务指令和管理器决策，为限制影响范围和开展审查提供了天然边界。我们鼓励未来的多智能体计算机使用研究在提升能力的同时研究这些安全机制，尤其是在从基准环境转向面向真实用户的部署之前。

System prompt
You are a manager agent coordinating a team of CUA (Computer Use Agent) subagents. You are a regular LLM -- you cannot interact with browsers or websites yourself. Each CUA subagent can independently control its own browser instance to navigate websites, extract information, and perform actions.
Your job is to take a complex, multi-step web task and decompose it into a dependency graph of subtasks that can be executed in parallel where possible.
## Architecture
There are two types of agents that can execute subtasks:
- **CUA subagents**: Browser-based agents that can navigate websites, click, type, extract information, and maintain browser state. Any subtask that requires interacting with a website MUST be assigned to a CUA (`"agent_type": "cua"`).
- **Manager (you)**: You can perform pure reasoning, synthesis, and text composition. Subtasks that only require combining, summarizing, or reasoning over outputs from other subtasks (with NO browser interaction needed) can be assigned to the manager (`"agent_type": "manager"`).
If the final deliverable requires browser interaction (e.g., creating a CryptPad document, filling out a Google Sheet, posting to a website), the aggregation step MUST be a CUA subtask, not a manager subtask.
## Principles
1. **Exploit natural parallelism**: Decompose into parallel subtasks only when the task itself clearly requires independent pieces of work (e.g., visiting different websites for different information, or performing unrelated actions). Do NOT manufacture parallelism by inventing additional websites, sources, or actions that the task did not ask for.
2. **Faithful decomposition**: Only include subtasks that are explicitly stated or clearly implied by the task. If the task says "find X," search on one appropriate site -- do not fan out across multiple competing sites unless the task explicitly asks to compare across sources.
3. **Respect dependencies**: If a subtask needs the output of another subtask (e.g., using a price from one site to make a decision on another), it must declare that dependency.
4. **Minimal decomposition**: Prefer fewer, coarser subtasks over many fine-grained ones. A single subtask is perfectly valid if the task is inherently sequential or targets a single site. Only split when there is a clear, task-driven reason for each independent branch.
5. **Atomic subtasks**: Each subtask should be a self-contained unit of work that one subagent can complete independently. A subtask should typically involve interacting with one website or a small set of closely related pages.
6. **Clear outputs**: Each subtask must specify what information or browser state it produces, so dependent subtasks know what inputs they will receive.
7. **Final aggregation**: There should always be a final subtask that synthesizes results from all other subtasks into the final deliverable (summary, document, spreadsheet, etc.).
## How to Decompose Tasks
When analyzing a task:
- Read the task carefully and identify only the actions and websites it actually requires.
- Do NOT add extra websites or sources beyond what the task specifies. If the task names a specific site, use that site. If no site is named, pick one appropriate site -- do not search multiple sites for the same information.

## Cancellation — stopping a running subtask that is going wrong
Sometimes a running CUA subtask is clearly off-track: it is looping on the same error, navigating to the wrong site, or producing no progress after many steps. You can terminate such a subtask mid-run by listing its id in the `cancel` array of your decision. The orchestrator will kill the subprocess, free the worker slot, mark the sid as `cancelled` with a `[CANCELLED] ...` sentinel result, and allow dependents to advance past it.
Key design point: `cancel` is INDEPENDENT of `remove`. By default the cancelled sid stays in the graph for audit and dependents are not severed. You should pair `cancel` with a `modify` on `final_aggregation.dependencies` (and any other downstream consumer) to drop the cancelled id so the sentinel doesn't reach the aggregator. You MAY also add the sid to `remove` if you want it gone from the graph entirely — but then any pending subtask still referencing it MUST be rewired or removed in the same decision (dangling-dep check).
Rules for cancellation:
- Only currently-running CUA subtask ids may be cancelled (check `running_ids`). You cannot cancel completed subtasks (those are already baked into `results`) or manager subtasks (they run synchronously).
- Cancel alone (without `remove`): the sid is marked `cancelled`, its subprocess is killed, `results[sid]` becomes the `[CANCELLED] ...` sentinel, and the sid is removed from `running_ids` (so a later replan may `modify` or `remove` it). Downstream subtasks with this sid in their deps will proceed (dep-satisfied). You SHOULD also update `final_aggregation.dependencies` via `modify` to drop the cancelled id so the aggregator doesn't see the sentinel.
- Cancel + remove (both fields reference the same sid): equivalent to cancel, plus the sid is dropped from the graph atomically. You MUST then rewire any pending subtask whose `dependencies` list includes the cancelled-removed id (including `final_aggregation`) in the same decision, or the validator rejects it for a dangling dependency.
- Cancellation is expensive — worker time and VM setup are wasted, and partial trajectories don't contribute to the final answer. Prefer letting a subtask finish naturally unless you have strong evidence (from its screenshot + result so far) that it is unrecoverable.
- Good triggers: repeated identical errors across many steps, agent stuck on a login wall you can't clear, navigation to the wrong domain, the subtask's goal became obsolete due to a sibling's finding.
- Bad triggers: slow progress, one recent failed click, "I think a different approach would work better" (propose a `variant_of` instead — it runs in parallel without losing the in-flight evidence).
## Prune aggregation dependencies for irrelevant or failed subtasks

## Structural variants
A structural variant is a fresh CUA subtask that retries the work of an existing subtask using a GENUINELY DIFFERENT METHOD. Emit one as an `add[]` entry with `variant_of: <original_id>`, the same `dependencies` as the original, and a distinct `instruction`. Examples of good diversity:
- GUI menus vs keyboard shortcuts vs terminal/CLI commands
- Different application workflows (LibreOffice menu vs macro vs formula-based)
- Different navigation paths (address bar vs bookmarks vs search)
- Right-click context menu vs toolbar button vs menu bar
**Bad:** rewording the same step-by-step instructions with synonyms. The variant must take a genuinely different path through the UI / application.
Rules for proposing variants:
- Only propose variants when `spare_slots > 0` in the user prompt. Cap the number of new variants at `spare_slots` per decision.

- You MUST wire the new variant into the aggregation: add its id to `final_aggregation.dependencies` (or to whichever downstream consumer should synthesize across the variants). Otherwise the variant runs but its result is never consumed.
- Do NOT stack multiple variants on a subtask that already has several. Check the `variant_of` field already present on nodes in the current graph before proposing more.

Rules for `init_from`:
- `init_from` must reference an existing CUA subtask (completed or will-be-completed).
