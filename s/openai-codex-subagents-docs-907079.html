一句话

OpenAI 将子智能体定位为可并行分工、隔离中间上下文的工作机制，但明确提醒：增加代理会增加 token 消耗，并行修改代码还会带来冲突与协调成本。

主要内容

  • 优先拆分读密集工作：代码探索、测试、问题分诊、日志分析和摘要适合交给不同子智能体，主智能体负责需求、决策与最终整合。
  • 收益不仅是并行提速：探索记录、命令输出等留在子线程，主线程接收提炼结果，以减少无关信息挤占上下文。
  • 任务边界决定分工质量：文档建议明确每个代理的职责、是否等待全部结果，以及返回什么内容；自定义代理应职责集中、工具配置匹配任务。
  • 支持异构配置：不同代理可采用不同模型和推理强度，以权衡能力、速度与成本；未指定时通常继承父代理配置。
  • 写操作需要更强协调：多个代理同时改代码可能产生冲突。子代理继承父会话的权限与沙箱，仅靠“不要编辑”的提示不能建立独立的只读隔离。
  • 编排有集中管理能力：主智能体可以派发、追问、等待和关闭子线程，并汇总结果；并发上限可配置。

对 swarm scaling 的意义

这份材料支持一种有条件的扩展思路：先寻找能够独立执行、结果容易压缩汇总的子任务，再增加代理。上下文隔离提供了速度之外的潜在收益，但这种收益尚未在材料中量化。

它也指出扩展的约束：代理越多，独立推理与工具调用的消耗越大；共享代码上的写入冲突会增加协调负担。因此，评估 swarm scaling 应同时检查任务独立性、汇总质量和总成本，不能仅以并发数量作为能力提升的证据。
