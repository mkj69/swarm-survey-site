一句话

这篇论文把 scaling 的单位从“同一团队增加 agent”扩展到“跨开发者组合互补能力”，但收益取决于专精程度与协调成本，并非 agent 越多越好。

主要内容

  • 区分三种组织方式：单开发者系统（SDA）；把整项任务交给一个系统的路由方案（rSDA）；拆分任务、跨开发者调用并汇总结果的 MDA。SDA 本身也可以包含多个 agent。
  • 实验中的“开发者”由元 agent 模拟，自动生成能力规格、工具和系统提示，再迭代改进。不同池保持相同的总开发预算，但预算以改进轮数计量。
  • GAIA 上，54 个专精开发者组成的池中，单体准确率最高为 35%；组合后约为 70%，比最佳单开发者系统高约 3 个百分点。只用中低档 agent，MDA 仍达到 67%。
  • 单体成绩不能充分代表协作价值：迁移到 GAIA 的池加入一个独立准确率仅 19.1% 的互补 agent 后，整体从 40.4% 升至 53.2%。
  • 反例同样关键：在通用型 agent 池，以及主要依赖网页搜索的 SealQA 上，MDA 相比整任务路由准确率更低、成本更高。作者认为，能力差异不足时，拆分和多层转交的损失会压过组合收益。
  • 理论模型尝试说明：整任务竞争可能鼓励通才化，按技能路由则可能激励专精；这些结论依赖模型设定。

数字属于作者报告的基准实验测量，并非真实开发者生态的部署结果。图五、图六注明为四次运行的均值，误差条为均值标准误；不能据此认定所有数字都采用相同统计口径。准确率衡量答题表现，执行成本按 API 费用计算，默认包含协调费用；相同“开发预算”也不等于相同人力或资金投入。

路由器通过包含标准答案的交互记录学习，GAIA 验证集被分为训练和评估两部分。因此收益还依赖可获得反馈的路由学习条件。所给材料没有提供独立复现或外部核验，理论结论也不应直接当作现实生态规律。

对 swarm scaling 的意义

它支持的是“互补能力的组合扩展”，尚不能证明扩大群体数量本身带来稳定增益。实验同时改变了开发者专精方式、系统组成与协调机制，不能据此提炼通用的数量扩展规律。

评估 swarm 应同时看整体准确率、含协调的成本，以及新增成员带来的边际贡献。低独立分数的 agent 可能补齐关键短板；强通才系统也可能因重复能力和多层协调而拖累整体。开放生态的核心问题因此包括能力发现、可靠路由与专精激励，而不只是通信协议或并发规模。
