Abstract摘要
Existing multi-agent benchmarks primarily test in competitive settings, short-horizon interactions under 20 steps, or simply aggregate individual performance, failing to isolate and highlight genuine collaboration capabilities of LLM-based agents. We introduce AgentWorld, a benchmark of 100 human-annotated tasks (with 100 augmented variants) for evaluating long-horizon, multi-agent collaboration. Tasks span 50+ interaction rounds across a rich MMORPG sandbox and require 3–20 agents with asymmetric roles and abilities to coordinate through communication, joint planning, and resource sharing under a blackbox setting where each agent acts independently without access to others’ internal states. To quantify collaboration effectiveness in addition to conventional binary task success, we propose Causal Collaboration Effectiveness (CCE), a graph-based metric that traces causal dependencies between agent actions and measures what fraction of a team’s effort actually contributed to the outcome. Experiments with Gemini 3 Flash, Claude Haiku 4.5, GPT-5 Mini, and DeepSeek R1-70B show that even the best model achieves only 52.0% task success, with systematic failure modes including communication breakdowns, role confusion, and inability to maintain shared plans across rounds. AgentWorld is fully open-source.[fn1]
现有多智能体基准主要在竞争场景、少于 20 步的短程交互中进行测试，或仅仅汇总个体表现，未能单独识别并突出基于大语言模型的智能体真正的协作能力。我们提出 AgentWorld，这是一个用于评估长期多智能体协作的基准，包含 100 项人工标注任务（以及 100 个增强变体）。这些任务在内容丰富的大型多人在线角色扮演游戏（MMORPG）沙盒中跨越 50+ 轮交互，要求 3–20 个角色和能力不对称的智能体通过通信、联合规划和资源共享进行协调；任务采用黑箱设置，每个智能体独立行动，无法访问其他智能体的内部状态。为在传统的二元任务成功指标之外量化协作成效，我们提出因果协作有效性（Causal Collaboration Effectiveness，CCE），这是一种基于图的指标，通过追踪智能体动作之间的因果依赖关系，衡量团队投入中实际对结果作出贡献的比例。使用 Gemini 3 Flash、Claude Haiku 4.5、GPT-5 Mini 和 DeepSeek R1-70B 进行的实验表明，即使表现最好的模型也仅达到 52.0% 的任务成功率，并存在通信中断、角色混淆以及无法跨轮次维持共同计划等系统性失败模式。AgentWorld 完全开源。[fn1]

1 Introduction1 引言
As LLM-based agents advance from single-turn reasoning to autonomous tool use, planning, and multi-step execution, collaboration between agents becomes a critical capability. Many real-world tasks, from software development to scientific research to complex operations, require multiple specialized agents to coordinate toward shared goals. Systematically evaluating this collaboration capability is essential for understanding the strengths and limitations of current models and guiding future progress.
随着基于大语言模型的智能体从单轮推理发展到自主工具使用、规划和多步执行，智能体之间的协作成为一项关键能力。从软件开发、科学研究到复杂运营，许多现实世界任务都需要多个专门化智能体围绕共同目标进行协调。系统评估这种协作能力，对于理解当前模型的优势与局限并指导未来发展至关重要。
Multi-agent collaboration (MAC) involves multiple agents with diverse roles working together in a shared environment to achieve a common goal. LLMs enable these agents to communicate precisely through natural language, opening new possibilities for coordination. Researchers have developed a range of tasks and environments for MAC, spanning social simulations (Park et al., 2023; Chen et al., 2023; Piao et al., 2025), embodied reasoning benchmarks (Mandi et al., 2023; Sun et al., 2025), and Minecraft-based platforms (Fan et al., 2022; Gong et al., 2024; Yu et al., 2024). However, existing benchmarks fall short in evaluating collaboration for three reasons. First, most involve short task horizons of 10 steps or fewer, insufficient for evaluating sustained coordination (Table 1). Second, many conflate low-level action control with collaboration: agents must spend significant effort on fine-grained control (e.g., precise 3D navigation, block placement) rather than on collaboration itself, making it difficult for collaboration capability to meaningfully influence benchmark scores. Third, large-scale simulations like Project Sid (AL et al., 2024) focus on emergent social behavior rather than concrete tasks with measurable outcomes.
多智能体协作（MAC）是指多个具有不同角色的智能体在共享环境中共同工作，以实现共同目标。大语言模型使这些智能体能够通过自然语言进行精确沟通，为协调开辟了新的可能性。研究人员已为 MAC 开发了一系列任务和环境，涵盖社会模拟 (Park et al., 2023; Chen et al., 2023; Piao et al., 2025)、具身推理基准 (Mandi et al., 2023; Sun et al., 2025)，以及基于 Minecraft 的平台 (Fan et al., 2022; Gong et al., 2024; Yu et al., 2024)。然而，现有基准在评估协作方面存在不足，原因有三点。首先，大多数基准的任务跨度较短，仅为 10 步或更少，不足以评估持续协调能力（表 1）。其次，许多基准将底层动作控制与协作混为一谈：智能体必须将大量精力投入精细控制（例如精确的 3D 导航、方块放置），而非协作本身，这使得协作能力难以对基准得分产生实质性影响。第三，Project Sid (AL et al., 2024) 等大规模模拟侧重于涌现的社会行为，而非具有可衡量结果的具体任务。
To this end, we propose AgentWorld, a benchmark consisting of a rich MMORPG simulator and a long-horizon, collaboration-focused benchmark built on top of it. The simulator supports up to 1,000 concurrent agents in a blackbox environment where agents cannot observe each other’s internal states, and provides a complex world with 380+ items, 144 mob types, 70+ NPCs, and 13 high-level API tools that abstract away low-level game mechanics (e.g., combat, crafting, navigation) so that benchmark scores reflect collaboration quality rather than action-control proficiency. This combination of blackbox interaction and world complexity enables a new class of long-horizon collaboration tasks spanning 25–55 rounds and requiring 3–20 agents with asymmetric roles. AgentWorld features 100 human-annotated tasks across 8 categories (combat, crafting, gathering, trading, exploration, survival, construction, and coordination), with 100 LLM-augmented variants. Tasks require joint planning, resource sharing, and temporal coordination that cannot be achieved by any single agent alone. We propose Causal Collaboration Effectiveness (CCE), a graph-based metric that traces causal dependencies between agent actions to measure how much of a team’s effort actually contributed to the outcome. Experiments across four frontier models (Gemini 3 Flash, Claude Haiku 4.5, GPT-5 Mini, and DeepSeek R1-70B) reveal that even the best model achieves only 52.0% task success, with a CCE of just 0.320 (i.e., less than a third of all agent actions causally contribute to task completion), indicating that the vast majority of agent actions do not advance the shared objective. Qualitative analysis reveals systematic failure patterns including communication breakdowns where agents fail to share critical information, role confusion where agents duplicate work or act outside their designated roles, and inability to maintain shared plans across rounds. 3 AgentWorld Benchmark3 AgentWorld 基准
AgentWorld provides a RPG-style simulation environment for evaluating multi-agent collaboration alongside a curated benchmark of collaboration-centered tasks. The simulator abstracts away low-level control complexity so that benchmark performance reflects collaboration capability rather than fine-grained action proficiency. Tasks are designed to be diverse, challenging, and inherently collaborative: they cannot be solved by any single agent and require sustained coordination over multiple rounds.
AgentWorld 提供了一个用于评估多智能体协作的角色扮演游戏（RPG）风格仿真环境，以及一套经过精心筛选、以协作为核心的任务基准。该模拟器通过抽象屏蔽底层控制的复杂性，使基准表现反映协作能力，而非细粒度动作的熟练程度。这些任务在设计上具有多样性、挑战性和内在的协作需求：任何单个智能体都无法独立解决，必须在多轮交互中持续协调。
3.1 Simulation Environment3.1 仿真环境
A key challenge in designing a multi-agent collaboration benchmark is choosing the right environment. Existing simulators fall into two extremes. Complex environments like Minecraft offer rich worlds but burden agents with low-level control (precise 3D navigation, block placement, inventory management), making it difficult to isolate collaboration capability from action-control proficiency. Simpler environments like Werewolf or Overcooked provide clean interfaces but lack the world complexity needed for diverse, long-horizon collaboration tasks. Our design targets the middle ground: an environment that is complex enough to support diverse collaboration scenarios while abstracting away low-level control so that benchmark scores primarily reflect the quality of joint planning and coordination decisions.
设计多智能体协作基准的一项关键挑战是选择合适的环境。现有模拟器分为两个极端。Minecraft 等复杂环境提供了丰富的世界，但也让智能体承担了底层控制的负担（精确的 3D 导航、方块放置、物品栏管理），使得协作能力难以与动作控制的熟练程度区分开来。Werewolf 或 Overcooked 等较简单的环境提供了简洁的接口，却缺乏支持多样化、长时域协作任务所需的世界复杂性。我们的设计旨在寻求折中：环境既要足够复杂，能够支持多样化的协作场景，又要通过抽象屏蔽底层控制，使基准分数主要反映联合规划与协调决策的质量。
Sandbox.沙盒。
We build upon Kaetram[fn2], an open-source MMORPG engine that provides the world complexity we need: a persistent 2D world spanning $1056\times 768$ tiles across 9 biome types, with 380+ items, 144 mob types (Level 1 to 250+), 70+ NPCs, and 1,531 harvestable resource nodes across 8 skills (lumberjacking, mining, fishing, foraging, crafting, smithing, fletching, and cooking). This rich content enables diverse task categories (combat, crafting, trading, exploration, etc.) without requiring us to build a game world from scratch.

Agent-Environment Interface.智能体与环境的接口。
To ensure that benchmark performance reflects collaboration rather than low-level control, we built a custom abstraction layer on top of Kaetram that exposes 13 high-level API tools (e.g., move, attack, harvest, craft, transfer, chat). Each tool encapsulates complex multi-step game mechanics into a single function call. For instance, attack_entity handles the entire combat sequence (pathfinding to the target, initiating attack, completing combat, and collecting loot) rather than requiring agents to manage each step individually. Similarly, harvest_resource handles navigation to the resource node, performing the gathering action, and collecting the result. This design means agents spend their decision budget on what to do and who to coordinate with, not on how to execute low-level actions. Each turn, agents also receive (1) a structured text observation of nearby tiles, entities, and their own status, and (2) a task-specific guideline document describing relevant crafting recipes, monster attributes, and resource locations.
为确保基准表现反映的是协作能力而非底层控制能力，我们在 Kaetram 之上构建了一个自定义抽象层，提供 13 个高层 API 工具（例如 move、attack、harvest、craft、transfer、chat）。每个工具都将复杂的多步骤游戏机制封装为一次函数调用。例如，attack_entity 负责处理整个战斗流程（寻路至目标、发起攻击、完成战斗并收集战利品），无需智能体逐步管理各个环节。类似地，harvest_resource 负责导航至资源节点、执行采集动作并收集采集所得。这种设计使智能体将决策预算用于决定做什么以及与谁协调，而非如何执行底层动作。在每个回合中，智能体还会收到 (1) 关于附近地块、实体及自身状态的结构化文本观测，以及 (2) 一份针对当前任务的指导文档，描述相关的制作配方、怪物属性和资源位置。
Agent Orchestration.智能体编排。
Although Kaetram runs in real time, we convert it into a turn-based environment for reproducible evaluation. Each round, every agent sequentially receives a fresh observation, selects one API tool call, and waits for the action to resolve before the next agent acts. This round-robin protocol ensures deterministic turn order. Under the blackbox setting used in all our experiments, agents have no access to other agents’ internal states, observations, or action histories. Coordination relies solely on explicit chat messages routed through the environment.
尽管 Kaetram 实时运行，我们仍将其转换为回合制环境，以实现可复现的评估。在每一轮中，各智能体依次接收最新观测，选择调用一个 API 工具，并等待该动作执行完毕，然后下一个智能体才开始行动。这种轮询协议确保了确定的回合顺序。在我们所有实验采用的黑箱设置下，智能体无法访问其他智能体的内部状态、观测或动作历史。协调完全依赖通过环境传递的显式聊天消息。

3.3 Task Annotation3.3 任务标注
Five human annotators design tasks following a pre-defined category distribution. For each task, annotators define agent configurations with complementary roles, specify a primary objective with intermediate checkpoints, write a Python verifier that programmatically checks success against the final game state, and curate task-specific game documentation for each agent. Tasks must require genuine multi-agent collaboration (no single agent can succeed alone) and cover diverse collaboration patterns. Each task is verified through pilot experiments with two LLMs; failures are classified as system, task, or agent errors, and tasks are revised until only agent errors remain. The round budget for each task (ranging from 25 to 55) is calibrated from these pilot runs: annotators set an initial estimate, observe how many rounds successful completions require, and adjust the budget to be challenging but feasible. We additionally generate 100 augmented variants using Claude Opus with variations in objectives, spawn locations, and initial items. See Appendix for the full annotation protocol.
五名人工标注员按照预先定义的类别分布设计任务。对于每项任务，标注员设定角色互补的智能体配置，明确主要目标及中间检查点，编写 Python 验证器以通过程序检查最终游戏状态是否满足成功条件，并为每个智能体整理任务专用的游戏文档。任务必须要求真正的多智能体协作（任何单个智能体都无法独自成功），并涵盖多种协作模式。每项任务都通过两个 LLM 的预实验进行验证；失败被归类为系统错误、任务错误或智能体错误，并持续修订任务，直至只剩下智能体错误。每项任务的轮数预算（范围为 25 至 55）根据这些预实验进行校准：标注员先给出初步估计，观察成功完成任务所需的轮数，再调整预算，使任务既具有挑战性又切实可行。此外，我们使用 Claude Opus 生成了 100 个增强变体，对目标、生成位置和初始物品进行变化。完整标注规程见附录。

3.5 Evaluation Metrics3.5 评估指标
Conventionally, the success of multi-agent systems is often evaluated with task success rate (SR), and in the case of AgentWorld, each task couples with its own Python-based function for judging the success. However, as achieving the task success does not always entail a successful collaboration, we propose a new quantitative metric (i.e., causal collaboration effectiveness) for evaluating the quality of cross-agent collaboration.
通常，多智能体系统的成功表现常用任务成功率（SR）评估；在 AgentWorld 中，每项任务都配有专属的 Python 函数来判定是否成功。然而，任务成功并不总是意味着协作成功，因此我们提出一种新的定量指标（即因果协作有效性），用于评估跨智能体协作的质量。
Task Success Rate (SR)任务成功率（SR）
Based on the primary objective, the success of a task is determined by a Python-based verifier script written for each task. The verifier programmatically checks the final game state (e.g., counting items in inventories, checking kill counts, verifying agent survival). Optionally, the verifier can also check the trajectory if determining the success requires information further than the final game state. A task is successful if and only if all success criteria are met at the end of the trajectory.
根据主要目标，由为每项任务编写的 Python 验证脚本判定任务是否成功。验证器通过程序检查最终游戏状态（例如，统计物品栏中的物品数量、检查击杀数、验证智能体是否存活）。如果判定成功需要最终游戏状态之外的信息，验证器也可以选择检查执行轨迹。当且仅当轨迹结束时所有成功条件均得到满足，任务才算成功。
For each task, we also report partial success rate (PSR) as a soft metric using individual checkpoints reported by the verifiers (e.g., “Logs: 3/5, Kills: 0/3, All alive: True”). PSR is the fraction of checkpoint items achieved, averaged across all tasks. Successful tasks receive PSR = 100%.
对于每项任务，我们还利用验证器报告的各个检查点（例如，“Logs: 3/5, Kills: 0/3, All alive: True”）计算部分成功率（PSR），并将其作为一项软性指标进行报告。PSR 是已达成检查点项所占的比例，并在所有任务上取平均。成功任务的 PSR = 100%。
Causal Collaboration Effectiveness (CCE)因果协作有效性（Causal Collaboration Effectiveness，CCE）
SR and PSR measure what agents achieved but not how collaboratively they achieved it. A task can succeed with high SR yet poor collaboration if a single agent does all the work while others idle. Some existing works adopted LLM-as-judge approaches that score collaboration quality holistically (e.g., “rate coordination 1–5”), but such judgments are subjective and shift when the judge model is updated, making results difficult to reproduce.
SR 和 PSR 衡量智能体取得了什么成果，却不衡量它们在取得这些成果的过程中如何开展协作。如果一个智能体承担了所有工作，而其他智能体处于闲置状态，那么即使 SR 很高、任务成功完成，协作质量也可能很差。一些现有研究采用 LLM 作为评判者的方法，对协作质量进行整体评分（例如，“对协调程度打 1–5 分”），但这类判断具有主观性，且会随着评判模型的更新而发生变化，导致结果难以复现。
We propose CCE, a graph-based metric that quantifies collaboration quality by constructing a Causal Action Graph over task trajectories as illustrated in Figure 5. The algorithm works by iterative backward tracing: we first identify the action(s) that directly achieved the task objective (the success actions), then sweep backward round by round, querying an LLM at each round to determine which actions causally enabled any already-identified contributing action. This BFS-like process accumulates a contributing set $\mathcal{C}$ of all actions on a causal path to success. CCE is then the ratio of contributing actions to total actions: $\text{CCE}=|\mathcal{C}|/|\mathcal{T}|$ , where $\mathcal{T}$ is the set of all actions taken by all agents across all rounds. For failed tasks, CCE $=0$ by definition. Crucially, the LLM judge makes only relatively objective binary causal judgments (“did fishing for shrimp enable the later transfer of shrimp?”), not subjective quality assessments (“rate the collaboration 1–5”), making CCE substantially more reproducible across judge model versions. See Appendix F for the full formalization.
我们提出了 CCE，这是一种基于图的指标，通过在任务轨迹上构建因果动作图来量化协作质量，如图 5 所示。该算法通过迭代式反向追溯运行：我们首先识别直接达成任务目标的动作（即成功动作），然后逐轮向前回溯，在每一轮查询 LLM，以确定哪些动作在因果上促成了任何已被识别为有贡献的动作。这一类似广度优先搜索（BFS）的过程逐步累积贡献动作集合 $\mathcal{C}$，其中包含通向成功的因果路径上的所有动作。随后，CCE 定义为贡献动作数与动作总数之比：$\text{CCE}=|\mathcal{C}|/|\mathcal{T}|$，其中 $\mathcal{T}$ 是所有智能体在所有轮次中执行的全部动作的集合。对于失败的任务，按定义 CCE $=0$。关键在于，LLM 评判者仅作出相对客观的二元因果判断（“捕虾是否促成了后续的虾转交？”），而不进行主观的质量评估（“对协作打 1–5 分”），这使得 CCE 在不同版本的评判模型之间具有显著更高的可复现性。完整的形式化定义见附录 F。

在四个主要模型中，GPT-5 Mini 每个任务发送的聊天消息最多（44.1），但 SR 排名第三（36.0%）。DeepSeek R1-70B 发送的消息最少（7.5），排名也最低（20.0%）。Gemini 3 Flash 的通信量适中（11.0），却取得了最高的 SR。在失败的任务中，GPT-5 Mini 将 26% 的动作用于聊天，表明它过度沟通，挤占了实际行动。DeepSeek 平均直到第 5 轮才发送第一条聊天消息（其他所有模型均在第 1–2 轮），很可能因此错过了关键的早期协调窗口。这些模式表明，存在一种最优的沟通方式：沟通应足以实现协调，但又不能过多，以免挤占富有成效的行动。
Task difficulty varies sharply by category and augmentation.任务难度因类别和是否经过增强而存在显著差异。
Across the four primary models on the main set, survival tasks are the easiest (50–100% SR across models) while coordination (0–50%), construction (0–60%), and trading (8–46%) are the hardest, reflecting the difficulty of tight multi-agent synchronization and negotiation. On the augmented set, all models show substantial SR drops (Gemini: 52 $\rightarrow$ 24%, Claude: 45 $\rightarrow$ 26%, GPT-5: 36 $\rightarrow$ 21%, DeepSeek: 20 $\rightarrow$ 10%), confirming that augmented tasks are genuinely harder. Augmented tasks also require more rounds and actions, with GPT-5 Mini averaging 152 actions per task vs. 131 on the main set.
在主数据集上的四个主要模型中，生存任务最容易（各模型的成功率（SR）为 50–100%），而协调（0–50%）、建造（0–60%）和交易（8–46%）任务最难，反映出多智能体之间紧密同步与协商的难度。在增强数据集上，所有模型的 SR 均大幅下降（Gemini：52 $\rightarrow$ 24%，Claude：45 $\rightarrow$ 26%，GPT-5：36 $\rightarrow$ 21%，DeepSeek：20 $\rightarrow$ 10%），证实增强任务确实更难。增强任务还需要更多轮次和动作，GPT-5 Mini 在增强数据集上每项任务平均执行 152 个动作，而在主数据集上为 131 个。
4.3 Causal Collaboration Effectiveness4.3 因果协作有效性
We apply the CCE metric defined in §3 to all trajectories (Table 2, Figure 5).
我们将 §3 中定义的 CCE 指标应用于所有轨迹（表 2、图 5）。
The vast majority of agent actions do not contribute to success.绝大多数智能体动作对成功没有贡献。
Even the best model (Gemini, CCE = 0.320) has less than a third of its total actions on a causal path to task completion. For DeepSeek (CCE = 0.125), nearly 88% of all actions are wasted. This reveals a fundamental inefficiency: agents spend most of their effort on actions that neither directly achieve objectives nor enable other agents’ progress.
即使是表现最好的模型（Gemini，CCE = 0.320），其处于任务完成因果路径上的动作也不到总动作数的三分之一。对于 DeepSeek（CCE = 0.125），近 88% 的动作都被浪费了。这揭示了一种根本性的低效：智能体将大部分精力用于既不能直接实现目标、也不能推动其他智能体取得进展的动作。
CCE tracks SR but adds nuance.CCE 与 SR 的变化趋势一致，但提供了更细致的信息。
The CCE ranking (Gemini 0.320 $>$ Claude 0.294 $>$ GPT-5 0.206 $>$ DeepSeek 0.125) broadly follows SR, since failed tasks contribute CCE = 0. However, conditioning on successful tasks reveals a different picture: Claude achieves the highest per-task collaboration efficiency (0.653 on successes vs. Gemini’s 0.609), meaning Claude wastes fewer actions when it does succeed. GPT-5 Mini has the lowest efficiency even on successful tasks (0.571), consistent with its high action count and excessive chatting.
CCE 排名（Gemini 0.320 $>$ Claude 0.294 $>$ GPT-5 0.206 $>$ DeepSeek 0.125）大体遵循 SR 排名，因为失败任务的 CCE = 0。然而，仅考察成功任务会呈现出不同的情况：Claude 的单任务协作效率最高（成功任务中为 0.653，而 Gemini 为 0.609），这意味着 Claude 在成功完成任务时浪费的动作更少。即使在成功任务中，GPT-5 Mini 的效率也最低（0.571），这与其动作数量多、聊天过度的表现一致。
CCE agrees with human causal judgments.CCE 与人类的因果判断一致。
A natural concern is that CCE still relies on an LLM to make the underlying causal judgments. To test whether these judgments are well-posed, we compare the judge against a human annotator. We sample 84 action–contribution judgments drawn from the trajectories of two agent models (Gemini 3 Flash and Claude Haiku 4.5) across 11 tasks. A human annotator independently labels each action as contributing or not, following the same policy given to the judge. The annotator agrees with the GPT-4.1 judge on 69 of 84 judgments (82% raw agreement), corresponding to a Cohen’s $\kappa$ of 0.64 (“substantial” on the Landis–Koch scale). For reference, two independent judge models agree at a comparable level: recomputing CCE with Claude Sonnet 4 instead of GPT-4.1 yields action-level agreement of $\kappa=0.66$ (84% raw) over 7,298 decisions. In other words, humans agree with the judge about as strongly as two different judges agree with each other, indicating that the binary causal judgment is well-posed rather than an artifact of a particular model. We adopt an intentionally inclusive labeling policy (§F): marginally helpful actions are counted as contributing, so CCE is best read as an upper bound on the fraction of genuinely useful actions.
一个自然的疑虑是，CCE 仍然依赖大语言模型（LLM）作出底层的因果判断。为检验这些判断是否具有明确、合理的判定依据，我们将评判模型与一名人工标注员进行比较。我们从两个智能体模型（Gemini 3 Flash 和 Claude Haiku 4.5）在 11 项任务中的轨迹中抽取了 84 项动作贡献判断。一名人工标注员遵循提供给评判模型的相同规则，独立标注每个动作是否有贡献。在 84 项判断中，标注员有 69 项与 GPT-4.1 评判模型一致（原始一致率为 82%），对应的 Cohen’s $\kappa$ 为 0.64（在 Landis–Koch 量表上属于“高度一致”）。作为参考，两个独立评判模型之间的一致性也处于相近水平：使用 Claude Sonnet 4 替代 GPT-4.1 重新计算 CCE，在 7,298 次判定中得到的动作层面一致性为 $\kappa=0.66$（原始一致率为 84%）。换言之，人类与评判模型之间的一致程度，与两个不同评判模型之间的一致程度大致相当，表明这种二元因果判断具有明确、合理的判定依据，而非特定模型造成的假象。我们有意采用宽松的标注规则（§F）：略有帮助的动作也被计为有贡献，因此，最好将 CCE 理解为真正有用动作所占比例的上界。
CCE rankings are robust to the choice of judge model.CCE 排名对评判模型的选择具有稳健性。
A key advantage of CCE over direct LLM-as-judge scoring is that the LLM makes binary causal judgments rather than subjective quality assessments, which is more stable across judge models. To verify this, we recompute CCE with three judges from different families (GPT-4.1, our primary judge; Claude Sonnet 4; and Llama-4 Maverick) and report the results in Table 6 (Appendix A). The relative ordering of agent models is fully preserved under all three judges (Gemini $>$ Claude $>$ GPT-5 $>$ DeepSeek). Absolute CCE values shift by at most $\sim$ 0.05 (e.g., Claude Haiku moves from 0.294 to 0.241 between GPT-4.1 and Claude Sonnet 4), which does not affect any pairwise comparison. This stability supports our claim that reducing the judge’s role to binary causal decisions yields a more reproducible metric than holistic collaboration scoring.
相较于直接使用 LLM 作为评判者进行评分，CCE 的一个关键优势在于，LLM 作出的是二元因果判断，而非主观质量评估，因此在不同评判模型之间更为稳定。为验证这一点，我们使用来自不同模型家族的三个评判模型（GPT-4.1，即我们的主要评判模型；Claude Sonnet 4；以及 Llama-4 Maverick）重新计算 CCE，并在表 6（附录 A）中报告结果。在所有三个评判模型下，智能体模型的相对排序均完全保持不变（Gemini $>$ Claude $>$ GPT-5 $>$ DeepSeek）。CCE 绝对值的变化最多约为 $\sim$ 0.05（例如，将评判模型从 GPT-4.1 换为 Claude Sonnet 4 时，Claude Haiku 的数值从 0.294 变为 0.241），这不会影响任何两两比较的结果。这种稳定性支持了我们的主张：将评判模型的作用限定为作出二元因果判定，可以得到比整体协作评分更具可复现性的指标。

This suggests that the value of planning in AgentWorld depends on the ability to revise it during execution, which is consistent with the gains from communication discussed below. Furthermore, oracle communication improves over the vanilla blackbox setting (52.0% $\rightarrow$ 60.0%), showing that better communication helps, yet the 40% residual failure rate even with oracle communication indicates that much of the difficulty is intrinsic to long-horizon planning and resource allocation, not merely decentralization.

5 Conclusion5 结论
We presented AgentWorld, a benchmark for evaluating long-horizon multi-agent collaboration. Built on an MMORPG sandbox tailored for agents to play through 13 tools, the benchmark contains 100 human-annotated tasks (with 100 augmented variants) requiring 3–20 agents with asymmetric roles to coordinate through natural language under a blackbox setting where no agent can observe others’ internal states. For evaluation, in addition to success rates, we propose Causal Collaboration Effectiveness (CCE), a metric that constructs causal action graphs via backward tracing and measures what fraction of a team’s effort actually contributed to the outcome.
我们提出了 AgentWorld，一个用于评估长时程多智能体协作的基准。该基准基于一个专为智能体通过 13 个工具进行游戏而定制的大型多人在线角色扮演游戏（MMORPG）沙盒构建，包含 100 项人工标注任务（另有 100 个增强变体），要求 3–20 个具有非对称角色的智能体在黑箱设置下通过自然语言进行协调，其中任何智能体都无法观察其他智能体的内部状态。在评估方面，除成功率外，我们还提出了因果协作有效性（Causal Collaboration Effectiveness，CCE），该指标通过反向追踪构建因果动作图，并衡量团队投入中实际对结果作出贡献的比例。
Experiments across four frontier models (Gemini 3 Flash, Claude Haiku 4.5, GPT-5 Mini, DeepSeek R1-70B) reveal several key findings: (1) even the best model achieves only 52.0% task success, with 27% of tasks unsolved by any model; (2) CCE analysis shows that less than a third of all agent actions causally contribute to success (CCE = 0.320 for the best model), indicating massive inefficiency in collaboration; (3) a persistent gap between partial and full success (e.g., 71.5% PSR vs. 52.0% SR for Gemini) shows that agents can start collaborating but fail at late-stage coordination; and (4) communication quantity does not predict success, with the highest-chatting model ranking third and the most efficient model communicating moderately. These results suggest that collaboration remains a common gap in current foundational models, distinct from and harder than single-agent reasoning.
对四个前沿模型（Gemini 3 Flash、Claude Haiku 4.5、GPT-5 Mini、DeepSeek R1-70B）的实验揭示了几项关键发现：(1) 即使表现最好的模型，任务成功率也仅为 52.0%，且有 27% 的任务未被任何模型解决；(2) CCE 分析表明，所有智能体行动中，在因果上对成功有所贡献的不足三分之一（最佳模型的 CCE = 0.320），表明协作存在严重的效率问题；(3) 部分成功与完全成功之间持续存在差距（例如，Gemini 的 PSR 为 71.5%，而 SR 为 52.0%），表明智能体能够开始协作，却在后期协调中失败；(4) 通信量无法预测成功与否，通信最多的模型排名第三，而效率最高的模型通信量适中。这些结果表明，协作仍是当前基础模型普遍存在的能力短板，它不同于单智能体推理，且难度更高。

Appendix F Causal Collaboration Effectiveness (CCE)附录 F 因果协作有效性（CCE）
F.1 Formal DefinitionsF.1 形式化定义
F.1.1 BackgroundF.1.1 背景
Let there be $N$ agents $\{a_{1},\ldots,a_{N}\}$ acting over $R$ rounds in a task trajectory.
设有 $N$ 个智能体 $\{a_{1},\ldots,a_{N}\}$，在一条任务轨迹中经过 $R$ 轮行动。
Action set $\mathcal{T}=\{(a_{i},r,d)\mid a_{i}\in\{a_{1},\ldots,a_{N}\},\;r\in\{1,\ldots,R\},\;d\in\mathcal{D}\}$ : the complete set of all actions taken by all agents across all rounds, where $d$ is the action description (a tool use or chat message).
动作集合 $\mathcal{T}=\{(a_{i},r,d)\mid a_{i}\in\{a_{1},\ldots,a_{N}\},\;r\in\{1,\ldots,R\},\;d\in\mathcal{D}\}$：所有智能体在所有轮次中执行的全部动作的集合，其中 $d$ 为动作描述（一次工具使用或一条聊天消息）。
Agent action set $\mathcal{T}_{i}\subseteq\mathcal{T}$ : the subset of actions taken by agent $a_{i}$ . We have $\mathcal{T}=\bigcup_{i=1}^{N}\mathcal{T}_{i}$ .
智能体动作集合 $\mathcal{T}_{i}\subseteq\mathcal{T}$：智能体 $a_{i}$ 执行的动作所构成的子集。有 $\mathcal{T}=\bigcup_{i=1}^{N}\mathcal{T}_{i}$。
Success actions $\mathcal{S}\subseteq\mathcal{T}$ : the subset of actions that directly achieve (part of) the task’s success criteria. These are the terminal nodes of interest.
成功动作 $\mathcal{S}\subseteq\mathcal{T}$：直接达成任务成功标准（的一部分）的动作子集。这些动作是我们关注的终端节点。
F.1.2 Causal Action Graph (CAG)F.1.2 因果动作图（CAG）
We construct a directed acyclic graph $G=(\mathcal{T},E)$ where:
我们构建一个有向无环图 $G=(\mathcal{T},E)$，其中：
Nodes are all actions in $\mathcal{T}$ .
节点为 $\mathcal{T}$ 中的所有动作。
Directed edges $E=\{(x,y)\mid x\text{ causally enables }y\}$ : action $x$ is a causal prerequisite for action $y$ .
有向边 $E=\{(x,y)\mid x\text{ causally enables }y\}$：动作 $x$ 是动作 $y$ 的因果前提。
The graph is a DAG because causal influence flows forward in time: an action in round $r$ can only enable actions in rounds $r^{\prime}\geq r$ .
该图是一个有向无环图（DAG），因为因果影响沿时间向前传递：第 $r$ 轮中的动作只能促成第 $r^{\prime}\geq r$ 轮中的动作。
Edge construction. For each action $y$ , we ask: “Which prior actions $x$ were necessary for $y$ to occur or succeed?” This is where the LLM is used, but the judgment is relatively objective and binary: either fishing for shrimp was necessary for transferring shrimp, or it was not. This is far more reliable than asking “rate the collaboration quality on a scale of 1–5.” We adopt a loose inclusion policy: if an action is even somewhat helpful to a downstream contributing action, it is marked as contributing. False positives (marking a marginally helpful action as contributing) only slightly inflate the metric by one action, while false negatives (missing a genuinely contributing action) systematically undercount collaboration.
边的构建。对于每个动作 $y$，我们会问：“哪些先前的动作 $x$ 是 $y$ 得以发生或成功的必要条件？”此处使用了大语言模型（LLM），但判断相对客观，且为二元判断：捕虾要么是转交虾的必要条件，要么不是。这比要求“按 1–5 的量表为协作质量评分”可靠得多。我们采用宽松的纳入策略：只要一个动作对下游的贡献动作有哪怕一定程度的帮助，就将其标记为有贡献。假阳性（将帮助甚微的动作标记为有贡献）只会因多计入一个动作而使指标略微偏高，而假阴性（漏掉真正有贡献的动作）则会系统性地低估协作。
F.1.3 Contributing SetF.1.3 贡献集合
Starting from the success actions $\mathcal{S}$ , we compute the contributing set $\mathcal{C}$ by backward traversal:
从成功动作 $\mathcal{S}$ 出发，我们通过反向遍历计算贡献集合 $\mathcal{C}$：
$$\mathcal{C}=\mathcal{S}\cup\text{ancestors}(\mathcal{S})$$
where $\text{ancestors}(\mathcal{S})$ is the set of all nodes that have a directed path to any node in $\mathcal{S}$ within $G$ . In other words, $\mathcal{C}$ contains every action that directly or transitively contributed to the task’s success. All actions not in $\mathcal{C}$ are non-contributing: $\mathcal{T}\setminus\mathcal{C}$ .
其中，$\text{ancestors}(\mathcal{S})$ 是在 $G$ 中存在一条通往 $\mathcal{S}$ 中任意节点的有向路径的所有节点的集合。换言之，$\mathcal{C}$ 包含所有直接或间接为任务成功作出贡献的动作。所有不属于 $\mathcal{C}$ 的动作均为无贡献动作：$\mathcal{T}\setminus\mathcal{C}$。
F.1.4 MetricsF.1.4 指标
Causal Collaboration Effectiveness (CCE).因果协作有效性（CCE）。
The primary metric, measuring what fraction of all actions contributed to success:
主要指标，用于衡量所有动作中对成功作出贡献的动作所占的比例：
$$\text{CCE}=\frac{|\mathcal{C}|}{|\mathcal{T}|}$$
$\text{CCE}=1.0$ : every action taken by every agent contributed to the outcome (perfect efficiency).
$\text{CCE}=1.0$：每个智能体执行的每个动作都对结果作出了贡献（完全高效）。
$\text{CCE}\approx 1/N$ : only one agent’s actions contributed (no real collaboration).
$\text{CCE}\approx 1/N$：只有一个智能体的动作作出了贡献（没有真正的协作）。
$\text{CCE}\approx 0$ : almost no actions contributed (chaotic failure).
$\text{CCE}\approx 0$：几乎没有动作作出贡献（混乱的失败）。
If a task fails entirely (no success criteria met), $\text{CCE}=0$ .
如果任务完全失败（未达成任何成功标准），则 $\text{CCE}=0$。
Per-Agent Contribution (PAC).单智能体贡献（PAC）。
How much of each agent’s effort was useful:
每个智能体付出的努力中有多少是有用的：
$$\text{PAC}_{i}=\frac{|\mathcal{C}\cap\mathcal{T}_{i}|}{|\mathcal{T}_{i}|}$$
This reveals which agents were effective (high PAC) versus which were unproductive (low PAC). A task with high CCE but highly skewed PAC values indicates that success was driven by a subset of agents rather than genuine collaboration.
这揭示了哪些智能体是有效的（PAC 高），哪些智能体未能有效产出（PAC 低）。如果一项任务的 CCE 较高，但 PAC 值的分布高度偏斜，则表明任务的成功是由部分智能体推动的，而非源于真正的协作。
F.2 Backward Causal Tracing AlgorithmF.2 反向因果追踪算法
Identify success actions. From the trajectory and task outcome, identify the set $\mathcal{S}$ of actions that directly achieved the success criteria.
识别成功动作。根据轨迹和任务结果，识别直接达成成功标准的动作集合 $\mathcal{S}$。
Initialize. Set $\mathcal{C}\leftarrow\mathcal{S}$ , frontier $\leftarrow\mathcal{S}$ , $E\leftarrow\emptyset$ .
初始化。设置 $\mathcal{C}\leftarrow\mathcal{S}$，frontier $\leftarrow\mathcal{S}$，$E\leftarrow\emptyset$。
Backward tracing. While the frontier is non-empty:
反向追踪。当 frontier 非空时：
Pick action $y$ from the frontier.
从 frontier 中选取动作 $y$。
For each prior action $x$ in the trajectory (where $\text{round}(x)\leq\text{round}(y)$ ):
对于轨迹中每个先前的动作 $x$（其中 $\text{round}(x)\leq\text{round}(y)$）：
Query the LLM: “Given the task context, did action $x$ causally enable or contribute to action $y$ ?”
向 LLM 提问：“根据任务上下文，动作 $x$ 是否在因果上促成了动作 $y$，或对其有所贡献？”
If yes: add $(x,y)$ to $E$ ; if $x\notin\mathcal{C}$ , add $x$ to $\mathcal{C}$ and to the frontier.
如果是：将 $(x,y)$ 加入 $E$；如果 $x\notin\mathcal{C}$，则将 $x$ 加入 $\mathcal{C}$ 和 frontier。
Compute metrics. $\text{CCE}=|\mathcal{C}|/|\mathcal{T}|$ and $\text{PAC}_{i}=|\mathcal{C}\cap\mathcal{T}_{i}|/|\mathcal{T}_{i}|$ for each agent $i$ .
计算指标。$\text{CCE}=|\mathcal{C}|/|\mathcal{T}|$，且对于每个智能体 $i$，$\text{PAC}_{i}=|\mathcal{C}\cap\mathcal{T}_{i}|/|\mathcal{T}_{i}|$。
Optimizations. To avoid querying all $O(|\mathcal{T}|^{2})$ action pairs: (1) prune by relevance, only considering actions involving the same resource type, location, or communication channel; (2) batch multiple causal queries into a single LLM call; (3) apply temporal windowing, only considering actions within a reasonable time window before each frontier action.
优化措施。为避免对全部 $O(|\mathcal{T}|^{2})$ 个动作对进行查询：(1) 按相关性剪枝，仅考虑涉及相同资源类型、地点或通信渠道的动作；(2) 将多个因果查询批量合并到一次 LLM 调用中；(3) 应用时间窗口，仅考虑每个 frontier 动作之前合理时间窗口内的动作。
Design decisions. Each tool use (API call) or chat message is treated as one action; no grouping is applied. All contributing actions are weighted equally regardless of distance from the success node. Communication actions (chat messages) are included as first-class actions, since coordination through communication is a core mechanism of collaboration.
设计决策。每次工具使用（API 调用）或每条聊天消息均视为一个动作，不进行分组。所有有贡献的动作均赋予相同权重，无论其与成功节点的距离如何。通信动作（聊天消息）被作为一等动作纳入，因为通过通信进行协调是协作的核心机制。
