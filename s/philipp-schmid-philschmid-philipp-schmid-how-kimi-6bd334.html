一句话

这篇跨三份技术报告的解读提出：agent 扩展的关键，是训练任务编排、上下文管理和奖励机制，而非单纯增加并发数量。

主要内容

  • Kimi 把协调能力作为训练对象。 PARL 冻结子 agent，只优化编排者如何拆任务、派任务和汇总结果，使奖励更容易归因到协调策略。
  • 并发必须产生有效工作。 并行奖励鼓励模型探索分工，子任务完成奖励抑制“只创建、不干活”；辅助奖励逐步归零，最终以任务表现为目标。
  • 成本取决于最长分支。 Kimi 用各阶段最长执行链累加得到“关键步数”，促使编排者平衡任务，而非追求更多子 agent。
  • 三种上下文策略可以互补。 Kimi 将信息分散到独立子 agent；Cursor 用自摘要延续长程编码；Chroma 主动删除检索片段，为后续搜索腾出空间。
  • 训练环境也是扩展条件。 三家都强调在接近部署的工具环境中做强化学习，并通过结果奖励及针对性约束纠正退化行为。

证据与可信度

这是作者对厂商技术报告的二次整理，所给文本覆盖完整论述，但本次未独立核验底层报告或复现实验。

材料转述 Kimi：BrowseComp 从单 agent 的 60.6% 提高到 swarm 的 78.4%，相差 17.8 个百分点；WideSearch 的条目级 F1 从 72.8% 升至 79.0%；推理延迟最高改善 4.5 倍。这些属于厂商报告的实验结果，不能将最高加速幅度推广到所有任务。文中未给出足以核算总算力、总 token 或等预算收益的细节。

Cursor 约五小时的更新周期、Chroma 每步 128 个查询各采样 8 次、合计 1,024 条轨迹，均为材料转述的训练流程数据，不代表 swarm 扩展收益。点赞、转发和浏览量只能反映传播度。

对 swarm scaling 的意义

材料支持把 scaling 看作“学会何时并行、如何分工、怎样控制信息量”的联合问题。评估时应同时观察任务质量、最长执行链和总体资源消耗；仅凭子 agent 数量无法判断收益。

适用边界也很明确：Kimi 的训练任务强调广泛搜集与多分支推理，不能据此认定任意任务都适合 swarm。Cursor 和 Chroma 提供的是长程执行与检索管理的补充经验，并非多 agent 数量扩展的直接证据。
