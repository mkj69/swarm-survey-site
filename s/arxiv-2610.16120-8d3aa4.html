Abstract摘要
Existing large language model (LLM) based multi-agent systems have been shown to scale poorly, and we identify three problems: reading burden that grows with the group, useful information diluted by shared work of unknown quality, and fragility to failed agents. We argue that the problems are largely due to agent-centric designs: the coordination structure is wired into fixed workflows, central coordinators, or peer-to-peer messaging, and recent blackboard-style methods that move the coordination into a shared medium relieve only the last problem. To close the gaps, we build ScaleMAS, where asynchronous agents interact with a shared datastore of linked messages via three operations: publishing messages with optional references to earlier ones that they build on, searching for messages by content, and visiting messages by address. Search returns at most $k$ messages, so an agent’s read stays bounded at any group size; results are ranked by relevance and by how often they are cited, which we find to be an effective proxy for quality; and messages persist after their producers leave, so the group carries on when individual agents fail. Across four agentic tasks, ScaleMAS outperforms agent-centric and blackboard-style baselines at lower inference compute, continues to scale up to 128 agents, and tolerates losing agents midway.

1 Introduction1 引言
Scaling a group of cooperative agents should increase its collective capability, but this benefit is not automatic in current large language model (LLM) based multi-agent systems (MAS). Empirical studies report superlinearly increased inference compute, diminishing or negative returns from additional agents, and settings in which a group underperforms a single agent given the same inference budget (Smit et al., 2023; Zhang et al., 2026; Kim et al., 2026b; Zheng et al., 2026).
扩大协作智能体群体的规模理应增强其集体能力，但在当前基于大语言模型（LLM）的多智能体系统（MAS）中，这种收益并不会自动实现。实证研究报告了推理计算量超线性增长、增加智能体所带来的收益递减甚至为负，以及在相同推理预算下群体表现不如单个智能体的情形（Smit et al., 2023; Zhang et al., 2026; Kim et al., 2026b; Zheng et al., 2026）。
We identify three major problems that grow with the number of agents and that many of the current designs leave unsolved. First, what each agent must read increases with the group: message-passing systems deliver all senders’ outputs to a receiver agent (Du et al., 2023; Liu et al., 2026), and coordinator-based systems route every sub-agent’s result into a central agent’s context (Su et al., 2025; Ruan et al., 2026), thus a larger group floods its readers with input that could exceed context limits. Second, the useful information dilutes as the group grows: even with bounded reading, an agent must find the few relevant results in an ever larger body of partial work shared by others, and it is hard to tell the quality of the shared information. Third, failure becomes the routine rather than the exception: the more agents run, the more likely some of them stall or crash, yet workflow-based systems fix each agent’s role and successor at design time (Hong et al., 2024; Qian et al., 2024) and coordinator-based systems route everything through one agent (Cemri et al., 2026), so a lost agent could easily cause the system to crash.
我们指出了三个随智能体数量增加而加剧、且当前许多设计尚未解决的主要问题。首先，每个智能体必须阅读的内容随群体规模增加：消息传递系统将所有发送者的输出传给接收智能体（Du et al., 2023; Liu et al., 2026），基于协调器的系统则将每个子智能体的结果汇入中央智能体的上下文（Su et al., 2025; Ruan et al., 2026），因此，更大的群体会使负责阅读的智能体接收到大量输入，可能超出上下文限制。其次，有用信息随群体规模扩大而被稀释：即使阅读量有上限，智能体也必须从其他智能体共享的、不断增多的部分工作成果中找出少数相关结果，而且难以判断共享信息的质量。第三，失效成为常态而非例外：运行的智能体越多，其中一些停滞或崩溃的可能性就越高，然而，基于工作流的系统在设计时就固定了每个智能体的角色及其后继智能体（Hong et al., 2024; Qian et al., 2024），基于协调器的系统则让所有信息都经由一个智能体传递（Cemri et al., 2026），因此，损失一个智能体就很容易导致系统崩溃。
What these methods share is that they adopt agent-centric designs by wiring coordination structures into agents’ instructions and loops. Another design principle has been adopted for decades since early blackboard systems (Newell, 1962; Nii, 1986; Erman et al., 1980): rather than engineering agents for better coordination, one can design the substrate[fn1] where agents only interact with a shared environment and self-coordinate (Figure 2). Recent work in LLM-based multi-agent systems has been trying to adopt this principle by giving LLM agents either a shared context (Mao and Mirhoseini, 2026; Park et al., 2026; Qi et al., 2026) or a shared filesystem (Qu et al., 2026; Kim et al., 2026a). This could alleviate the third problem: no agent waits on a particular peer, so a stalled agent blocks no one; and results persist after their producers leave, so a failed agent loses only its unfinished work. However, it leaves the first two problems unsolved. A shared context grows linearly with the group size, which still could cause context overflow; a shared filesystem bounds nothing, and leaves each agent to search a growing pile of files with no signal of their quality. A scalable substrate for LLM agents therefore needs more than a shared medium: it must bound each agent’s reading as the group’s output grows, while maintaining effective information discovery for every agent.
这些方法的共同点在于，它们采用以智能体为中心的设计，将协调结构固化在智能体的指令和运行循环中。自早期黑板系统以来，另一种设计原则已沿用数十年（Newell, 1962; Nii, 1986; Erman et al., 1980）：与其通过设计智能体来改善协调，不如设计一种基底（substrate）[fn1]，使智能体仅与共享环境交互并自主协调（图 2）。近期，基于 LLM 的多智能体系统研究一直在尝试采用这一原则，为 LLM 智能体提供共享上下文（Mao and Mirhoseini, 2026; Park et al., 2026; Qi et al., 2026）或共享文件系统（Qu et al., 2026; Kim et al., 2026a）。这可以缓解第三个问题：没有智能体需要等待某个特定的同伴，因此，一个智能体停滞不会阻塞其他智能体；而且，结果在其生成者退出后仍会保留，因此，智能体失效只会损失其尚未完成的工作。然而，前两个问题仍未得到解决。共享上下文随群体规模线性增长，仍可能导致上下文溢出；共享文件系统则不设任何上限，每个智能体都必须自行搜索不断堆积的文件，且没有任何信号可供判断这些文件的质量。因此，面向 LLM 智能体的可扩展底座（substrate）需要的不仅是共享媒介：它必须在群体产出不断增长时限制每个智能体的阅读量，同时确保每个智能体都能有效发现信息。

Both requirements have a working precedent at the scale of billions of readers and writers: the Web. Its scalability comes in part from avoiding readers having to read everything: search bounds attention by returning a small set of relevant results, while hypertextual links make information navigable on demand and also provide signals of its importance (Brin and Page, 1998; Page et al., 1999). Drawing on these principles, we build ScaleMAS, a task-agnostic substrate on which LLM agents self-coordinate at scale. The agent substrate maintains a datastore of persistent messages interconnected through references, and a search engine indexed over them. Agents run asynchronously, and each interacts only with the substrate through three operations: it publishes messages to the datastore, optionally referencing earlier ones; it searches for messages by content and gets at most $k$ returned results; and it visits messages for details by address. When a new message references earlier ones, the referenced messages gain importance weight, which combines with lexical relevance to rank subsequent search results. Every message is displayed with its references and with the later messages that reference it, but never with its author or its weight.
这两项要求在数十亿读者和写作者的规模上已有成功运行的先例：万维网。其可扩展性部分源于避免要求读者阅读全部内容：搜索通过返回少量相关结果来限定注意力范围，而超文本链接既使信息能够按需导航访问，也提供了反映其重要性的信号 (Brin and Page, 1998; Page et al., 1999)。借鉴这些原则，我们构建了 ScaleMAS，这是一个与任务无关的底座，LLM 智能体可在其上实现大规模自主协调。该智能体底座维护着一个数据存储，其中的持久化消息通过引用相互连接，并配备了一个为这些消息建立索引的搜索引擎。智能体异步运行，每个智能体仅通过三种操作与底座交互：向数据存储发布消息，并可选择引用先前的消息；按内容搜索消息，最多获得 $k$ 条返回结果；以及通过地址访问消息以获取详细信息。当一条新消息引用先前的消息时，被引用消息的重要性权重会增加，该权重与词汇相关性相结合，用于对后续搜索结果进行排序。每条消息在展示时都会附带其引用的消息和后来引用它的消息，但绝不展示其作者或权重。
Several properties follow from the design. First, an agent takes in bounded messages per read operation, regardless of how many agents are writing or how large the datastore has grown. Second, the importance of shared information is earned through reuse: weight accumulates only when others build on a message, so search surfaces what the group has actually relied on, and the signal is enhanced as the datastore grows. Third, membership is flexible to change. Because messages outlive their producers, a newcomer reads the datastore and can catch up by searching for and visiting messages, and an agent that leaves takes nothing with it. Moreover, lineage of shared results is inspectable, as each message carries references and its citers, and a reader can check what a claim rests on before building on it.
这一设计带来了若干特性。首先，无论有多少智能体正在写入，也无论数据存储已增长到多大规模，智能体每次读取操作接收的消息数量都有上限。其次，共享信息的重要性通过复用获得：只有当其他智能体在某条消息的基础上开展工作时，该消息才会积累权重，因此搜索会呈现群体实际依赖过的内容，而且这一信号会随着数据存储的增长而增强。第三，成员构成可以灵活变化。由于消息的存续时间长于其生成者，新加入的智能体可以读取数据存储，通过搜索和访问消息了解当前进展，而退出的智能体不会带走任何内容。此外，共享结果的来源脉络可供检查，因为每条消息都附带其引用的消息及引用它的消息，读者可以先核查某项论断的依据，再在其基础上开展工作。
We evaluate ScaleMAS on four agentic tasks spanning deep research (Chen et al., 2025b), theorem proving (Jiang et al., 2026), software engineering (Jimenez et al., 2024), and contradiction audit, a benchmark we construct in which agents identify contradictions in large document corpora. We use two LLMs as backbones and compare against multi-agent debate (all-to-all message-passing) (Du et al., 2023), DeLM (blackboard-style shared context) (Mao and Mirhoseini, 2026), AOrchestra (coordinator-based delegation) (Ruan et al., 2026), and parallel ReAct agents without communication (Yao et al., 2022). Our experiments examine how collective performance and inference compute change with group size, with additional scaling studies extending to $128$ agents. We also evaluate resilience to unreliable membership and ablate citation-based ranking to assess its contribution. A group of $N$ agents with one failed agent performs comparably to $N-1$ healthy agents, indicating that the remaining agents can continue cooperating despite the loss of individual participants. These results suggest that multi-agent systems scale further when coordination is designed into the substrate the agents share rather than wired into the agents themselves.
我们在四项智能体任务上评估 ScaleMAS，涵盖深度研究 (Chen et al., 2025b)、定理证明 (Jiang et al., 2026)、软件工程 (Jimenez et al., 2024) 和矛盾审查；矛盾审查是我们构建的一项基准，要求智能体识别大型文档语料库中的矛盾。我们使用两种 LLM 作为骨干模型，并与多智能体辩论（全互连消息传递）(Du et al., 2023)、DeLM（黑板式共享上下文）(Mao and Mirhoseini, 2026)、AOrchestra（基于协调者的任务委派）(Ruan et al., 2026)，以及不进行通信的并行 ReAct 智能体 (Yao et al., 2022) 进行比较。我们的实验考察了群体表现和推理计算量如何随群体规模变化，并通过额外的扩展性研究将规模扩大至 $128$ 个智能体。我们还评估了系统对成员不可靠性的韧性，并对基于引用的排序进行消融实验，以评估其贡献。包含一个失效智能体的 $N$ 个智能体群体，其表现与 $N-1$ 个正常智能体相当，这表明其余智能体能够在个别参与者退出后继续协作。这些结果表明，将协调机制设计到智能体共享的底座中，而非内置于智能体本身，可以使多智能体系统扩展到更大规模。

ScaleMAS is an agent substrate with three parts: 1) a datastore of messages, 2) three operations that agents use to write to it and read from it, and 3) deterministic rules that decide what is written and what a read returns. $N$ agents run the same harness under the same prompt. Each is an ordinary tool-using LLM agent that keeps the tools of its task and gains the three extra operations, which are its only access to the datastore. No agent holds a role, sends messages to another agent, or assigns work to other agents, and the agents run asynchronously. Figure 3 shows an example that traces two agents through the substrate.
ScaleMAS 是一个由三部分组成的智能体底座：1) 消息数据存储，2) 智能体用于向其中写入和从中读取的三种操作，以及 3) 决定写入内容和读取返回内容的确定性规则。$N$ 个智能体在相同提示词下运行同一套执行框架（harness）。每个智能体都是一个常规的、使用工具的 LLM 智能体，保留其任务所需的工具，并额外获得三种操作；这三种操作是其访问数据存储的唯一途径。所有智能体均不担任特定角色，不向其他智能体发送消息，也不向其他智能体分配工作，并且各智能体异步运行。图 3 展示了一个示例，追踪两个智能体通过该底层支撑系统开展工作的过程。
2.1 The datastore2.1 数据存储
The datastore $D$ is an append-only sequence of messages. A message $m=(u,a,r,R)$ records one piece of completed work: the sub-task $u$ the agent carried out, stated in the words someone about to do the same work would search for; the artifact $a$ that the work produced; a short rationale $r$ ; and a set $R$ of references to what the work built on. A reference names either an earlier message or a resource exposed by the task’s own tools, such as a corpus snippet or a repository file. Each message receives the next address when it is written and is never edited or deleted, so a reference always resolves to the text it was written against, and the references form a directed acyclic graph over $D$ that grows only at its newest end. Each message also carries a citation weight $s_{m}\in[0,1)$ , which the rules maintain and which search uses for ranking. The sub-task and artifact together are limited to $256$ or $1{,}024$ tokens depending on the benchmark (Table 6), and a message carries at most $32$ references.
数据存储 $D$ 是一个仅可追加的消息序列。一条消息 $m=(u,a,r,R)$ 记录一项已完成的工作：智能体执行的子任务 $u$，其表述采用即将开展同类工作的人会用于搜索的措辞；该工作产生的成果 $a$；简短的理由说明 $r$；以及一组指向该工作所依赖内容的引用 $R$。每条引用指向一条更早的消息，或任务自身工具所提供的资源，例如语料库片段或代码仓库文件。每条消息在写入时获得下一个地址，此后永不编辑或删除，因此引用始终解析到创建该引用时所依据的文本，而这些引用在 $D$ 上构成一个仅在最新端增长的有向无环图。每条消息还带有一个引用权重 $s_{m}\in[0,1)$，该权重由规则维护，并由搜索操作用于排序。根据基准测试的不同，子任务与成果合计限制为 $256$ 或 $1{,}024$ 个词元（表 6），且每条消息最多包含 $32$ 条引用。
2.2 The operations2.2 操作
publish $(u,a,r,R)$ appends a message and makes it readable by every agent from that moment on. The two read operations match the two ways a reader can know what it wants. search $(q)$ takes a free-text description of what the agent needs and returns the $k$ highest-ranked messages. visit $(m_{1},\dots,m_{j})$ returns the named messages, for an agent that a search result or a message’s references has already pointed somewhere specific. Both return each message as its four fields, the messages it references, and the most recent of the messages that reference it, up to eight. The author and the citation weight are never shown, so a reader judges a message by its content and its links. An agent ends by submitting its answer together with references and a rationale in the same form as a message, except on SWE-bench Verified, where the answer is a patch. The messages an answer cites, followed transitively through their references, form the answer’s evidence chain, which Section 3.4 uses to trace where correct answers come from.
publish $(u,a,r,R)$ 追加一条消息，并使所有智能体从该时刻起都能读取它。两种读取操作分别对应读取者确定所需内容的两种方式。search $(q)$ 接收一段自由文本，用于描述智能体所需的内容，并返回排名最高的 $k$ 条消息。visit $(m_{1},\dots,m_{j})$ 返回指定的消息，适用于搜索结果或消息中的引用已将智能体引向某个具体位置的情况。两种操作都会返回每条消息的四个字段、该消息引用的消息，以及引用该消息的最新消息，后者最多八条。作者和引用权重始终不予显示，因此读取者根据消息的内容及其链接来判断消息。智能体在结束时提交答案以及引用和理由说明，其形式与消息相同；SWE-bench Verified 除外，在该基准测试中，答案是一个补丁。答案所引用的消息，以及沿这些消息的引用传递追溯到的消息，共同构成答案的证据链；第 3.4 节利用该证据链追踪正确答案的来源。
A walk-through.流程示例。
Figure 3 shows how the operations combine on a deep research query. Agent 0 publishes Message 0, a candidate answer with the background it has gathered, then browses further, searches the datastore, and publishes Message 1, which verifies one clue of the query and cites Message 0. Agent 1 has meanwhile browsed on its own; it searches the datastore, finds Message 1, follows its reference to Message 0 with visit, and publishes Message 2, which combines the two into a conclusion and cites both. Neither agent addresses the other or waits for it: Agent 1 learns of Agent 0’s work only by reading the datastore, and its final message rests on evidence it did not gather itself.
图 3 展示了这些操作如何组合起来处理一个深度研究查询。智能体 0 发布消息 0，其中包含一个候选答案及其收集的背景信息，随后继续浏览、搜索数据存储，并发布消息 1，以验证查询中的一条线索，同时引用消息 0。与此同时，智能体 1 一直在独立浏览；它搜索数据存储，找到消息 1，通过 visit 沿其引用访问消息 0，然后发布消息 2，将这两条消息的内容整合为一个结论，并同时引用二者。两个智能体都不向对方发出信息，也不等待对方：智能体 1 仅通过读取数据存储得知智能体 0 的工作，而其最终消息所依据的证据并非全部由其自行收集。
2.3 The rules2.3 规则
What is written.写入的内容。
publish accepts a message only if every reference names something that exists and the rationale names every reference and states what it contributed. A message that breaks either rule is rejected with the offending reference named, and nothing is written. The first rule keeps references pointing backward in time. The second turns a reference into a stated dependency that a reader can check against the cited text, rather than an incidental mention. These are the only constraints ScaleMAS places on what an agent writes.
只有当每条引用都指向已存在的内容，且理由说明逐一指明每条引用并说明其贡献时，publish 才接受该消息。违反任一规则的消息都会被拒绝，并指出有问题的引用，且不写入任何内容。第一条规则确保引用在时间上指向过去。第二条规则使引用成为明确陈述的依赖关系，读取者可以对照被引文本加以核查，而非仅仅是顺带提及。这些是 ScaleMAS 对智能体写入内容施加的全部约束。
How weight is assigned.权重的分配方式。
A new message starts at weight $s_{0}=0$ . When a message references $m$ , the weight of $m$ moves a fraction $\alpha$ of the way toward one, $s_{m}\leftarrow s_{m}+\alpha(1-s_{m})$ , once per citing message, and at every step of the group all weights decay, $s_{m}\leftarrow\gamma s_{m}$ . A message that later work builds on therefore gains weight, and one that the group stops building on loses it. References to task resources carry no weight.
新消息的初始权重为 $s_{0}=0$。当一条消息引用 $m$ 时，$m$ 的权重会向一增加，增量为其与一之差的 $\alpha$，即 $s_{m}\leftarrow s_{m}+\alpha(1-s_{m})$，每条引用它的消息触发一次更新；在群体运行的每一步，所有权重都会衰减，即 $s_{m}\leftarrow\gamma s_{m}$。因此，后续工作所依赖的消息会获得更高权重，而群体不再据以开展工作的消息则会失去权重。对任务资源的引用不计入权重。
What a read returns.读取返回的内容。
The search index ranks messages by
搜索索引按以下方式对消息排序
$$\mathrm{score}(q,m)=s_{m}+\frac{\mathrm{Rel}(q,m)}{\max_{m^{\prime}\in D}\mathrm{Rel}(q,m^{\prime})}.$$
The citation weight plus a retrieval score normalized to $[0,1]$ ; any retrieval function can serve as $\mathrm{Rel}$ , and we use BM25 (Robertson and Zaragoza, 2009). Only messages with a positive retrieval score are ranked, ties go to the earlier message, and the top $k$ are returned, so the weight reorders relevant messages but cannot surface an unrelated one. The citation weight follows the idea of PageRank (Brin and Page, 1998; Page et al., 1999), with links written by the agents as they work. visit likewise accepts at most $k$ addresses per call. Every read therefore adds at most $k$ messages of bounded length to an agent’s context, however many agents are writing and however large $D$ has grown: an agent’s intake grows with how often it reads, which the agent decides, and not with the size of the group.
引用权重加上归一化至 $[0,1]$ 的检索得分；任何检索函数都可用作 $\mathrm{Rel}$，我们采用 BM25（Robertson and Zaragoza, 2009）。仅对检索得分为正的消息进行排序，得分相同时优先选择更早的消息，并返回排名前 $k$ 的消息，因此权重会重新排列相关消息，但无法使不相关的消息出现在结果中。引用权重沿用 PageRank（Brin and Page, 1998; Page et al., 1999）的思想，其中的链接由智能体在工作过程中写入。visit 同样在每次调用中最多接受 $k$ 个地址。因此，无论有多少智能体在写入，也无论 $D$ 已增长到多大，每次读取都至多向一个智能体的上下文添加 $k$ 条长度有界的消息：智能体接收的信息量随其读取频率增长，而读取频率由智能体自行决定，并不随群体规模增长。
3 Experiments3 实验
3.1 Contradiction Audit3.1 矛盾审查
Few existing tasks allow multi-agent systems to be studied at different scales under control. Also, on many existing agentic benchmarks a single agent already performs well, which leaves little room to measure how performance changes with group size. We therefore construct a new task, Contradiction Audit, which is designed to reward combining information spread across agents: The agents receive a large software documentation corpus with injected factual contradictions, and are tasked with reporting as many pairs of contradicting passages as they can find. The corpus can grow while the injected contradictions stay fixed, so difficulty can be varied without changing the task. More details are given in Appendix B.
现有任务中，很少有任务允许在受控条件下研究不同规模的多智能体系统。此外，在许多现有的智能体基准测试中，单个智能体就已表现良好，因此留给衡量性能如何随群体规模变化的空间很小。因此，我们构建了一项新任务——矛盾审查（Contradiction Audit），旨在奖励对分散在不同智能体之间的信息进行整合：智能体接收一个注入了事实性矛盾的大型软件文档语料库，其任务是报告尽可能多的相互矛盾的段落对。语料库可以不断扩充，而注入的矛盾保持不变，因此可以在不改变任务的情况下调整难度。更多细节见附录 B。
Benchmark construction.基准构建。
We source the Markdown and reStructuredText documentation files from 16 open-source software projects, including CPython, the Linux kernel, and PyTorch, and exclude files that disagree with the rest by design (changelogs, release notes, deprecation notices). We use GPT-5.6 to select pairs of document snippets on a common subject and rewrite the prose of one to contradict the other. An edit is kept only if a diff against the original snippet shows that it changes a few sentences and leaves the rest intact, and a second round of LLM judge (also with GPT-5.6) confirms that the edited snippet reads naturally, is not trivial (so that LLMs will not find it by memorization), is self-consistent, and truly conflicts with its partner. The LLM judge will run four times, and a snippet will be accepted iff. all four judges are positive. Each corpus receives twenty injected contradictions over forty distinct snippets, ten within one file and ten across files.
我们从 16 个开源软件项目中收集 Markdown 和 reStructuredText 文档文件，其中包括 CPython、Linux 内核和 PyTorch，并排除那些因其用途而与其余文档存在差异的文件（变更日志、发行说明、弃用通知）。我们使用 GPT-5.6 选择讨论同一主题的文档片段对，并改写其中一个片段的文字，使其与另一个片段相矛盾。只有在与原始片段的差异比较表明该编辑仅改动了少数几个句子、其余内容保持不变，且第二轮 LLM 评判（同样使用 GPT-5.6）确认编辑后的片段读起来自然、并非显而易见（从而使 LLM 无法凭记忆发现它）、内部自洽，并且确实与配对片段冲突时，该编辑才会被保留。LLM 评判将运行四次，当且仅当四次评判结果均为肯定时，片段才会被接受。每个语料库在四十个不同片段中注入二十处矛盾，其中十处位于同一文件内，十处跨越不同文件。
Difficulty and scoring.难度与评分。
Level x $n$ pads the forty contradiction snippets with seeded random distractors to $40n$ snippets, so the corpus grows while the answers stay fixed. For example, a x $8$ split means besides the 20 pairs of snippets that a system should really focus on, there are $40\times 8-40=280$ other irrelevant snippets as distractions. We use a relaxed metric for evaluation: A contradiction counts as found when a reported pair includes its edited snippet, and extra reports are not penalized. The score is the fraction of the twenty found, averaged over 16 corpora. In the example of Table 1, each passage reads naturally on its own and the two sit in different documents, so detecting the contradiction requires reading one snippet and locating the other.
难度等级 x $n$ 使用带固定随机种子的随机干扰片段，将四十个矛盾片段扩充至 $40n$ 个片段，从而使语料库增大，而答案保持不变。例如，x $8$ 数据划分意味着，除了系统真正应当关注的 20 对片段之外，还有 $40\times 8-40=280$ 个其他无关片段作为干扰。我们使用宽松的指标进行评估：只要报告的片段对包含某处矛盾中经过编辑的片段，就将该矛盾计为已发现，且不对额外报告予以惩罚。得分为二十处矛盾中已发现矛盾所占的比例，再对 16 个语料库取平均。在表 1 的示例中，每个段落单独读起来都很自然，且两者位于不同文档中，因此，检测该矛盾需要先阅读一个片段，再定位另一个片段。

3.2 Setup3.2 设置
Benchmarks.基准。
Beyond Contradiction Audit, we select three more benchmarks that stress a group of LLM agents in different ways. BrowseComp-Plus (Chen et al., 2025b) is search-intensive: the evidence for each question is scattered across a large corpus of web documents, reached through a search index. FATE (Jiang et al., 2026) is reasoning-intensive: each theorem proving problem asks for a complete Lean 4 proof that the compiler checks. SWE-bench Verified (Jimenez et al., 2024) measures the resolution of real GitHub issues, and requires multiple steps of verification and revision. ScaleMAS is harness-agnostic: we run it on a standard ReAct loop (Yao et al., 2022), implemented with the Hugging Face smolagents library[fn2], for BrowseComp-Plus, FATE, and Contradiction Audit, and on mini-SWE-agent (Yang et al., 2024) for SWE-bench Verified. More benchmark details are presented in Section C.3.
除 Contradiction Audit 外，我们还选择了另外三个基准，从不同方面考验一组 LLM 智能体。BrowseComp-Plus (Chen et al., 2025b) 是搜索密集型基准：每个问题的证据都分散在一个大型网页文档语料库中，需要通过搜索索引访问。FATE (Jiang et al., 2026) 是推理密集型基准：每个定理证明问题都要求给出一个由编译器检查的完整 Lean 4 证明。SWE-bench Verified (Jimenez et al., 2024) 衡量解决真实 GitHub 问题的能力，并要求进行多步验证和修订。ScaleMAS 不依赖于特定的执行框架：对于 BrowseComp-Plus、FATE 和 Contradiction Audit，我们在使用 Hugging Face smolagents 库[fn2]实现的标准 ReAct 循环 (Yao et al., 2022) 上运行它；对于 SWE-bench Verified，则在 mini-SWE-agent (Yang et al., 2024) 上运行它。更多基准细节见第 C.3 节。
Footnote: 2 https://github.com/huggingface/smolagents
脚注：2 https://github.com/huggingface/smolagents
Baselines and parity.基线与条件一致性。
We compare against the following methods: Parallel ReAct (Yao et al., 2022) runs $N$ agents without communication between them. Multi-Agent Debate (MAD) (Du et al., 2023) is agent-centric with all-to-all message passing: agents exchange their intermediate work, each reading what every other produced. AOrchestra (Ruan et al., 2026) is agent-centric with a central coordinator: a main agent decomposes the task and delegates to sub-agents, each of which reports back once. DeLM (Mao and Mirhoseini, 2026) is blackboard-style: agents write to a shared context that all of them read, without addressing one another. For parallel ReAct, MAD, DeLM, and ScaleMAS, an agent stops once it outputs a final answer, and the system stops when all agents stop. For AOrchestra, the system stops once the coordinator agent stops. Every method runs with Qwen3.5-9B on all four benchmarks and with Claude-5-Sonnet on all but SWE-bench Verified. The stronger model gets the harder benchmark splits (FATE-H and Contradiction Audit x8; Qwen3.5-9B gets FATE-M and x4). All methods share identical benchmark task prompts, per-benchmark limit on action steps, and the benchmark’s tools and evaluation harness.
我们与以下方法进行比较：Parallel ReAct (Yao et al., 2022) 运行 $N$ 个智能体，智能体之间不进行通信。Multi-Agent Debate (MAD) (Du et al., 2023) 以智能体为中心，采用全互连消息传递：智能体交换各自的中间工作成果，每个智能体都会读取其他所有智能体生成的内容。AOrchestra (Ruan et al., 2026) 以智能体为中心，设有一个中央协调者：主智能体分解任务并将其委派给子智能体，每个子智能体仅汇报一次。DeLM (Mao and Mirhoseini, 2026) 采用黑板式架构：智能体向所有智能体都会读取的共享上下文写入内容，而不直接向彼此发送消息。对于 parallel ReAct、MAD、DeLM 和 ScaleMAS，智能体一旦输出最终答案便停止，所有智能体都停止后，系统便停止。对于 AOrchestra，协调智能体一旦停止，系统便停止。每种方法都在全部四个基准上使用 Qwen3.5-9B 运行，并在除 SWE-bench Verified 之外的所有基准上使用 Claude-5-Sonnet 运行。能力更强的模型使用难度更高的基准数据划分（FATE-H 和 Contradiction Audit x8；Qwen3.5-9B 使用 FATE-M 和 x4）。所有方法均使用相同的基准任务提示、各基准规定的行动步数上限，以及基准提供的工具和评估框架。

Performance grows with group size.性能随群体规模增大而提升。
Figures 1 and 5 plot performance against the inference compute per example, one point per group size. With Qwen3.5-9B, scaling ScaleMAS from one agent to sixteen raises performance on every benchmark, from $38.1\%$ to $65.3\%$ on BrowseComp-Plus, from $24.0\%$ to $56.0\%$ on FATE-M, and from $4.1\%$ to $29.4\%$ on Contradiction Audit x4. On SWE-bench Verified, it levels off after eight agents, where parallel ReAct saturates as well, which points to the limit of the LLM’s capability. Parallel ReAct also improves with group size but stays below ScaleMAS at every group size on all four benchmarks. Part of this gap is present with a single agent, where the system degrades to a single agent with a private substrate; Table 2 separates this effect from the benefit of reading one another’s messages.
图 1 和图 5 展示了性能与每个样例的推理计算量之间的关系，每个点对应一种群体规模。使用 Qwen3.5-9B 时，将 ScaleMAS 从一个智能体扩展至十六个，可提升其在所有基准上的性能：在 BrowseComp-Plus 上从 $38.1\%$ 提升至 $65.3\%$，在 FATE-M 上从 $24.0\%$ 提升至 $56.0\%$，在 Contradiction Audit x4 上从 $4.1\%$ 提升至 $29.4\%$。在 SWE-bench Verified 上，其性能在八个智能体之后趋于平稳，并行 ReAct 在这一规模下也达到饱和，这表明瓶颈在于 LLM 的能力上限。并行 ReAct 的性能也随群体规模增大而提升，但在全部四个基准的所有群体规模下均低于 ScaleMAS。这一差距在单智能体情况下就已部分存在，此时系统退化为一个具有私有底层基座的智能体；表 2 将这一效应与读取彼此消息所带来的收益区分开来。
The baselines behave differently: on BrowseComp-Plus and Contradiction Audit, adding agents to MAD or DeLM helps little and sometimes hurts, and neither exceeds $7\%$ on Contradiction Audit at any group size. Both methods deliver the group’s outputs into each agent’s context, so adding agents enlarges the reading burden of every member. Experiments with Claude-5-Sonnet show similar patterns (Figure 5), most visibly on Contradiction Audit x8, where ScaleMAS rises from $10.6\%$ with one agent to $57.5\%$ with eight.
各基线方法的表现有所不同：在 BrowseComp-Plus 和 Contradiction Audit 上，为 MAD 或 DeLM 增加智能体几乎没有帮助，有时甚至会降低性能，而且二者在 Contradiction Audit 上的任何群体规模下均未超过 $7\%$。这两种方法都会将群体的输出送入每个智能体的上下文，因此增加智能体会加重每个成员的阅读负担。使用 Claude-5-Sonnet 的实验呈现出类似的模式（图 5），其中在 Contradiction Audit x8 上最为明显：ScaleMAS 的性能从一个智能体时的 $10.6\%$ 提升至八个智能体时的 $57.5\%$。
Scaling is more compute-efficient.扩展规模具有更高的计算效率。
At matched inference compute, ScaleMAS is ahead of baselines on every benchmark (Figures 1 and 5). For example, with Qwen3.5-9B (Figure 1), at a similar compute of about $20$ M tokens per example on BrowseComp-Plus, 8 ScaleMAS agents reach $60.0\%$ while 16 DeLM agents reach $26.0\%$ ; and on SWE-bench Verified, 4 ScaleMAS agents reach the same $80.0\%$ as 8 ReAct agents with about half the tokens ( $15.3$ M against $28.3$ M). The difference grows with the group: independent ReAct agents repeat each other’s searching and reading, so their tokens per example roughly double with every doubling of the group, whereas on BrowseComp-Plus and Contradiction Audit the tokens used by ScaleMAS grow more slowly than its size, because agents reuse what others have already published instead of rediscovering it. The pattern holds with Claude-5-Sonnet: at about $3.5$ M tokens per example on BrowseComp-Plus, eight ScaleMAS agents reach $79.8\%$ , against $73.0\%$ for eight MAD agents and $72.0\%$ for four ReAct agents. Adding agents to MAD, in contrast, increases tokens without improving accuracy: on BrowseComp-Plus with Qwen3.5-9B, its tokens per example grow from $5.6$ M with two agents to $48.5$ M with sixteen, while its accuracy stays between $28\%$ and $32\%$ .
在相同推理计算量下，ScaleMAS 在所有基准上均领先于基线方法（图 1 和图 5）。例如，使用 Qwen3.5-9B 时（图 1），在 BrowseComp-Plus 上，每个样例的计算量同为约 $20$ M 个 token 时，8 个 ScaleMAS 智能体达到 $60.0\%$，而 16 个 DeLM 智能体达到 $26.0\%$；在 SWE-bench Verified 上，4 个 ScaleMAS 智能体使用约一半的 token（$15.3$ M 对比 $28.3$ M），便达到了与 8 个 ReAct 智能体相同的 $80.0\%$。这一差异随群体规模增大而扩大：独立的 ReAct 智能体会重复彼此的搜索和阅读工作，因此群体规模每翻一倍，每个样例的 token 用量也大致翻一倍；而在 BrowseComp-Plus 和 Contradiction Audit 上，ScaleMAS 的 token 用量增长慢于其规模增长，因为智能体会复用其他智能体已发布的内容，而不是重新发现这些内容。使用 Claude-5-Sonnet 时，这一模式依然成立：在 BrowseComp-Plus 上，每个样例使用约 $3.5$ M 个 token 时，八个 ScaleMAS 智能体达到 $79.8\%$，而八个 MAD 智能体为 $73.0\%$，四个 ReAct 智能体为 $72.0\%$。相比之下，为 MAD 增加智能体会增加 token 用量，却不会提高准确率：在 BrowseComp-Plus 上使用 Qwen3.5-9B 时，其每个样例的 token 用量从两个智能体时的 $5.6$ M 增至十六个智能体时的 $48.5$ M，而准确率始终处于 $28\%$ 至 $32\%$ 之间。
Agents take fewer turns in larger groups.群体规模越大，智能体执行的轮次越少。
Figure 5 reports the mean number of turns an agent takes before it submits. It falls as the group grows, from $304$ with one agent to $205$ with eight on BrowseComp-Plus with Qwen3.5-9B and from $150$ to $94$ with Claude-5-Sonnet, and it also falls on Contradiction Audit with both backbones. The total work of the group therefore grows more slowly than its size: eight Qwen3.5-9B agents on BrowseComp-Plus take about $5.4$ times as many turns in total as a single agent. One reason is that an ScaleMAS agent that finds the result it needs already published can build on it instead of deriving it again; Section 3.4 further tests whether correct answers indeed draw on other agents’ work. The turns an agent saves are mostly calls to the task’s own tools: with Claude-5-Sonnet on BrowseComp-Plus, an agent calls them $80$ times per example in a group of eight against $134$ times alone. On Contradiction Audit x8, these calls fall from $131$ to $98$ while the agent’s searches of the datastore rise from $12$ to $65$ , so agents in larger groups explore the task less on their own and read more of what the others have found.
图 5 报告了智能体提交结果前执行的平均轮次数。该数值随群体规模增大而下降：在 BrowseComp-Plus 上使用 Qwen3.5-9B 时，从一个智能体时的 $304$ 降至八个智能体时的 $205$；使用 Claude-5-Sonnet 时，则从 $150$ 降至 $94$，且在 Contradiction Audit 上使用这两种骨干模型时也均有所下降。因此，群体总工作量的增长慢于其规模增长：在 BrowseComp-Plus 上，八个 Qwen3.5-9B 智能体的总轮次数约为单个智能体的 $5.4$ 倍。原因之一是，ScaleMAS 智能体若发现所需结果已被发布，就可以在此基础上继续工作，而无须重新推导；第 3.4 节进一步检验了正确答案是否确实利用了其他智能体的工作成果。智能体节省的轮次主要来自对任务自身工具的调用：在 BrowseComp-Plus 上使用 Claude-5-Sonnet 时，八个智能体组成的群体中，每个智能体针对每个样例调用这些工具 $80$ 次，而单独运行时为 $134$ 次。在 Contradiction Audit x8 上，这些调用从 $131$ 次降至 $98$ 次，而智能体对数据存储的搜索从 $12$ 次增至 $65$ 次，因此在更大的群体中，智能体会减少独自探索任务，更多地阅读其他智能体的发现。

Figure 7 extends the sweep to $N=128$ agents with Qwen3.5-9B. On FATE-M, ScaleMAS makes most of its improvement by $N=16$ and then levels off just below $60\%$ , whereas MAD peaks at $N=32$ and declines afterwards, and DeLM ends lower at $N=128$ than at $N=8$ . 图 7 将使用 Qwen3.5-9B 的规模扫描范围扩展至 $N=128$ 个智能体。在 FATE-M 上，ScaleMAS 在 $N=16$ 时已实现其大部分性能提升，随后趋于平稳，略低于 $60\%$；而 MAD 在 $N=32$ 时达到峰值，之后下降，DeLM 在 $N=128$ 时的最终表现则低于 $N=8$ 时。在 Contradiction Audit x4 上，智能体数量每翻一倍，ScaleMAS 的表现都会提升，并在 $N=128$ 时达到 $50.9\%$，而 DeLM 和 MAD 始终未超过 $7\%$。因此，这些基线呈现出既有研究所报告的现象：随着多智能体系统规模扩大，收益递减甚至转为负收益（Kim et al., 2026b）；我们将其归因于这些方法不受限制的读取。相应地，ScaleMAS 将智能体的读取负担保持在较低水平，并将新增智能体转化为更高的性能。
Peer citations automatically curate the datastore.同伴引用自动筛选整理数据存储中的内容。
The substrate never judges the quality of a message; the only quality-related signal is which messages the agents choose to cite. We test whether this signal is informative on all BrowseComp-Plus runs of ScaleMAS, using two complementary criteria. The first is use: whether a message lies on the evidence chain of a correct final answer, that is, whether the answer cites it directly or through a chain of references. Ranking the messages within each run by citation count, the fraction on such a chain increases monotonically from $29\%$ in the least-cited quintile to $85\%$ in the most-cited (Figure 9a). Because the evidence chain itself follows citations, this measure reflects connectivity as well as relevance.
底层基础设施从不评判消息的质量；唯一与质量相关的信号是智能体选择引用哪些消息。我们使用两个互补的标准，在 ScaleMAS 的所有 BrowseComp-Plus 运行中检验这一信号是否具有信息价值。第一个标准是使用情况：一条消息是否位于某个正确最终答案的证据链上，即该答案是否直接引用它，或通过一条引用链间接引用它。在每次运行内部按引用次数对消息排序后，位于此类证据链上的消息比例从被引用最少的五分位组中的 $29\%$ 单调递增至被引用最多的五分位组中的 $85\%$（图 9a）。由于证据链本身也是沿引用关系构建的，因此这一度量既反映相关性，也反映连接性。
The second criterion is independent of any answer: whether a message names a gold evidence document annotated by BrowseComp-Plus. Among messages that name a source, those naming gold evidence receive about twice as many citations from other agents as those naming other documents (Figure 9b). These results show that, without any central ranking, peer citations can effectively single out the messages that matter: those that final answers build on, and those that hold genuine evidence.
第二个标准独立于任何答案：一条消息是否提及了 BrowseComp-Plus 标注的某篇金标准证据文档。在提及来源的消息中，提及金标准证据文档的消息获得的其他智能体引用次数约为提及其他文档的消息的两倍（图 9b）。这些结果表明，在没有任何集中式排序的情况下，同伴引用能够有效识别出重要消息：即最终答案所依据的消息，以及包含真实证据的消息。
Correct answers are assembled across agents.正确答案通过跨智能体协作汇集而成。
Using BrowseComp-Plus runs with Qwen3.5-9B, we ask whether a correct answer’s evidence chain contains a message, written by another agent, that names a gold document the submitting agent never opened itself. The share of correct answers built this way grows with the group, from $9\%$ with two agents to $24\%$ with eight, and the trend holds under a stricter criterion that also excludes documents the submitter saw in its own search results (Figure 9). This indicates that a division of labor emerges although no agent is ever assigned a sub-task: agents increasingly answer by combining evidence that others found, and more correct answers rest on it as the group grows.
利用采用 Qwen3.5-9B 的 BrowseComp-Plus 运行，我们考察正确答案的证据链中是否包含这样一条消息：它由另一个智能体撰写，并提及了一篇提交答案的智能体自身从未打开过的金标准文档。以这种方式构建的正确答案所占比例随群体规模扩大而上升，从两个智能体时的 $9\%$ 增至八个智能体时的 $24\%$；即使采用更严格的标准，进一步排除提交者在自身搜索结果中见过的文档，这一趋势依然成立（图 9）。这表明，尽管从未向任何智能体分配子任务，分工仍会涌现：智能体越来越多地通过整合其他智能体找到的证据来作答，并且随着群体规模扩大，更多正确答案建立在这类证据之上。

Individual failures do not break the group.个体故障不会使群体失效。
Figure 11 adds one agent that fails on every step (i.e. it always returns error messages), holding the number of healthy agents fixed. For ScaleMAS, a group with one failing agent scores about as well as its healthy agents alone; with seven healthy agents, for instance, both reach $19.4\%$ . This is because ScaleMAS does not assign jobs to agents, and does not require an agent to finish anything: a failing agent simply publishes nothing, while the healthy agents keep finding and building on each other’s messages, so the group loses only the failing agent’s accumulated context. DeLM, in contrast, falls below $1\%$ when one of its members fails. This may be partially due to its task decomposition design, which could be susceptible to individual failures when the errors are injected in the decomposition step.
图 11 在保持正常智能体数量不变的情况下，加入了一个每一步都发生故障的智能体（即它始终返回错误消息）。对于 ScaleMAS，包含一个故障智能体的群体，其得分与仅由其中正常智能体组成的群体大致相同；例如，当有七个正常智能体时，两者均达到 $19.4\%$。这是因为 ScaleMAS 不向智能体分配任务，也不要求某个智能体完成任何工作：故障智能体只是不发布任何内容，而正常智能体继续寻找并利用彼此的消息，因此群体损失的只有故障智能体积累的上下文。相比之下，当 DeLM 的一个成员发生故障时，其得分会降至 $1\%$ 以下。这可能部分归因于其任务分解设计：当错误被注入分解步骤时，这种设计可能容易受到个体故障的影响。
Agents can leave and rejoin at any time.智能体可以随时离开并重新加入。
In Figure 7, each agent drops out of each step independently with probability $p$ , so agents keep leaving and returning over the course of a run; at $p=0.8$ , an agent is absent from four of every five steps on average and the group’s membership changes constantly. ScaleMAS keeps working throughout: even at $p=0.8$ , eight agents still solve $22.0\%$ of FATE-M problems, and on Contradiction Audit x8, eight agents that drop out of two of every five steps still score higher than every baseline without dropout. This is because nothing in ScaleMAS waits on a particular agent, and what an agent has published stays in the datastore while it is away, so a returning agent picks up the group’s progress and continues. Larger groups absorb dropout better (at $p=0.8$ on FATE-M, $22.0\%$ with eight agents against $2.0\%$ with one), whereas AOrchestra, which routes every result through a single coordinator, loses more than half of its score already at $p=0.2$ because it cannot tolerate the loss of the coordinator.
在图 7 中，每个智能体在每一步均以概率 $p$ 独立缺席，因此智能体在一次运行过程中不断离开和返回；当 $p=0.8$ 时，一个智能体平均每五步缺席四步，群体的成员构成不断变化。ScaleMAS 始终保持运行：即使在 $p=0.8$ 时，八个智能体仍能解决 $22.0\%$ 的 FATE-M 问题；而在 Contradiction Audit x8 上，八个每五步缺席两步的智能体，其得分仍高于所有无缺席情况下的基线。这是因为 ScaleMAS 中的任何环节都不等待某个特定智能体，且智能体已发布的内容在其离开期间仍保留在数据存储中，因此返回的智能体能够接续群体的进展并继续工作。规模更大的群体能更好地应对智能体退出（在 FATE-M 上，当 $p=0.8$ 时，八个智能体的得分为 $22.0\%$，而单个智能体为 $2.0\%$），而 AOrchestra 将每项结果都经由单一协调者传递，由于无法容忍协调者丢失，其得分在 $p=0.2$ 时就已下降一半以上。

4 Related Work4 相关工作
LLM-based multi-agent systems revisit three coordination structures from classic distributed problem solving: agents that address one another directly, a designated agent that mediates, and a shared blackboard. Agents address one another directly in Du et al. (2023) and along the edges of a topology in Qian et al. (2025); a designated agent mediates in Fourney et al. (2024) and Ruan et al. (2026); and the blackboard has been revived repeatedly, with Han and Zhang (2025) removing direct contact between agents entirely and Mao and Mirhoseini (2026) placing typed notes in a context every agent reads. A further line asks which agents should be connected: Zhuge et al. (2024) optimizes graph connectivity together with node prompts, and Zhang et al. (2024) generates a task-specific topology. These methods change who is connected to whom. What arrives in a reader’s context is still chosen by whoever sends along those edges, so the question of who selects is left where these structures put it. We discuss earlier work and further related lines in Appendix A.
基于 LLM 的多智能体系统重新采用了经典分布式问题求解中的三种协调结构：智能体彼此直接通信、由指定智能体居中协调，以及共享黑板。在 Du et al. (2023) 中，智能体彼此直接通信，在 Qian et al. (2025) 中则沿拓扑结构的边通信；在 Fourney et al. (2024) 和 Ruan et al. (2026) 中，由指定智能体居中协调；黑板结构也被多次重新采用，其中 Han and Zhang (2025) 完全移除了智能体之间的直接联系，而 Mao and Mirhoseini (2026) 则将带类型的笔记放入每个智能体都会读取的上下文中。另一条研究路线探讨应当连接哪些智能体：Zhuge et al. (2024) 联合优化图的连接关系与节点提示词，Zhang et al. (2024) 则生成针对特定任务的拓扑结构。这些方法改变的是谁与谁相连。进入读取者上下文的内容仍由沿这些边发送信息的一方选择，因此，由谁进行选择这一问题，仍沿袭了这些结构原有的安排。我们在附录 A 中讨论了早期工作和其他相关研究方向。
5 Conclusion5 结论
We identified three problems that grow with the number of agents: the reading burden on each agent, the dilution of useful shared work of unknown quality, and fragility to failing agents. ScaleMAS addresses them with an agent substrate: agents interact only through a shared datastore of linked messages, every read returns at most $k$ messages ranked by relevance and by how often they are cited, and messages persist after their producers leave. Across four benchmarks and two backbones, ScaleMAS improves with group size up to eight agents on every benchmark, and with Qwen3.5-9B up to sixteen on three of the four, while reaching higher performance than message-passing, coordinator-based, and blackboard-style baselines at matched inference compute. Our analysis shows the mechanisms at work: peer citations concentrate attention on messages that hold genuine evidence, correct answers increasingly draw on evidence found by other agents, and the group tolerates both a permanently failing agent and agents that drop out at any step.
我们识别出三个随智能体数量增加而加剧的问题：每个智能体的阅读负担、质量未知的共享工作成果中有用内容被稀释，以及对智能体失效的脆弱性。ScaleMAS 通过智能体底层支撑环境（agent substrate）解决这些问题：智能体仅通过存储相互链接消息的共享数据存储进行交互，每次读取最多返回 $k$ 条按相关性和被引用频次排序的消息，并且消息在其生成者离开后仍会保留。在四个基准和两种骨干模型上，当群体规模增加至八个智能体时，ScaleMAS 在每个基准上的性能均持续提升；使用 Qwen3.5-9B 时，在其中三个基准上，这一趋势持续至十六个智能体，同时，在相同的推理计算量下，其性能高于消息传递式、基于协调者的以及黑板式基线。我们的分析揭示了这些机制的作用：同伴引用将注意力集中到包含真实证据的消息上，正确答案越来越多地利用其他智能体发现的证据，而且群体既能容忍一个永久失效的智能体，也能容忍在任意步骤退出的智能体。
Limitations and future work.局限性与未来工作。
Due to limited compute, our experiments scale groups up to $128$ agents; larger groups are left to future work. ScaleMAS is also used only at inference time, and training agents to coordinate through the substrate is another direction for future work.
由于计算资源有限，我们的实验将群体规模扩展至最多 $128$ 个智能体；更大规模的群体留待未来研究。此外，ScaleMAS 仅用于推理阶段，训练智能体通过底层支撑环境进行协调是未来工作的另一个方向。

Appendix A Extended Related Work附录 A 扩展相关工作
Cooperative problem solving and coordination.协作式问题求解与协调。
How a group of problem solvers should divide work and share partial results is an old question, surveyed for the pre-LLM era in Durfee et al. (1989). The three structural answers this paper builds on were fixed in that period. The blackboard metaphor appears in Newell (1962), which already describes workers who each read everything on a shared surface, and was built in Erman et al. (1980), whose knowledge sources are activated by what appears on the blackboard rather than by calls from one another. Direct addressing was put to work for task allocation in Smith (1988), whose nodes exchange messages and share no memory, while Gelernter (1985) gives a shared medium in which writers do not name readers. The communication complexity of such structures was studied in parallel, from Yao (1979) to Dolev and Feder (1989), in terms of bits on a channel. The readers that literature assumes can scan a growing shared surface with little effort, so the amount of reading was never the binding constraint. It becomes one when the reader is a language model.
一组问题求解者应如何分工并共享部分结果，是一个由来已久的问题，Durfee et al. (1989) 对 LLM 出现之前这一领域的研究进行了综述。本文所依据的三种结构性方案在那一时期已基本定型。黑板隐喻出现在 Newell (1962) 中，该文已描述了各自读取共享板面上全部内容的工作单元；Erman et al. (1980) 则实现了这一隐喻，其中的知识源由黑板上出现的内容激活，而非通过彼此调用来激活。Smith (1988) 将直接寻址用于任务分配，其中各节点通过消息交换进行通信，不共享内存；Gelernter (1985) 则提供了一种共享媒介，写入者无需指定读取者。与此同时，从 Yao (1979) 到 Dolev and Feder (1989)，研究者以信道上传输的比特数为度量，研究了此类结构的通信复杂度。这些文献假定，读取者能够轻松扫描不断扩展的共享板面，因此阅读量从未成为制约因素。当读取者是语言模型时，阅读量就会成为制约因素。
Reducing what agents read.减少智能体的阅读量。
A second line accepts the delivery structure and makes each delivery smaller. Zeng et al. (2025) propagates only exchanges it judges novel, and Chen et al. (2025a) trains agents to communicate more compactly; a parallel effort operates inside a single agent, compressing or evicting accumulated history to keep a long run within the context window (Wu et al., 2026; Semenov and Dorofeev, 2026). Both reduce the size of what has already been routed to an agent. The bound studied here applies one step earlier, to how much is routed at all, and is set by the reader rather than by the sender. The two are complementary: every method in our experiments, ScaleMAS included, manages its own history in the same way (Section C.2).
第二条研究路线接受既定的传递结构，并缩减每次传递的内容量。Zeng et al. (2025) 仅传播其判定具有新颖性的交流内容，Chen et al. (2025a) 则训练智能体以更精简的方式通信；另一项并行开展的工作作用于单个智能体内部，通过压缩或移除累积的历史记录，使长时间运行所需的上下文保持在上下文窗口之内（Wu et al., 2026; Semenov and Dorofeev, 2026）。两者都缩减了已经路由至智能体的内容量。本文研究的界限作用于更早一步，即究竟有多少内容被路由，并且由读取者而非发送者决定。两者是互补的：我们实验中的每种方法，包括 ScaleMAS，都以相同的方式管理各自的历史记录（第 C.2 节）。
Retrieval, memory, and information access.检索、记忆与信息访问。
Shared stores for language agents are usually built to persist: Zhong et al. (2024) and Park et al. (2023) maintain per-agent stores across sessions, and Xu et al. (2026) links notes and rewrites older ones. The datastore studied here is not of this kind: it is created for one task and discarded with it, and exists so that agents working at the same time can reach each other’s results. Retrieval by an agent has also been studied where the corpus is fixed in advance (Singh et al., 2025); here the corpus is the group’s own output, so what an agent can find at any moment is what the others have published by that moment. The distinction our substrate rests on is older than either literature: Belkin and Croft (1992) separates systems in which profiles decide what reaches a reader from systems in which a reader expresses a need and initiates retrieval. The three families of Section 1 are of the first kind; the design of Section 2 is of the second, and takes its two access modes from the tradition of Bush et al. (1945) and Berners-Lee (1989), with ranking informed by reference structure as in Brin and Page (1998).
语言智能体的共享存储通常被设计为持久保存：Zhong et al. (2024) 和 Park et al. (2023) 为每个智能体维护跨会话的存储，而 Xu et al. (2026) 则将笔记相互关联，并改写较早的笔记。本文研究的数据存储并非此类存储：它为单个任务而创建，并随任务结束而丢弃，其存在是为了让同时工作的智能体能够访问彼此的结果。也有研究考察了语料库预先固定时智能体的检索行为（Singh et al., 2025）；而在这里，语料库是群体自身的输出，因此，智能体在任一时刻能够找到的内容，就是其他智能体截至该时刻已经发布的内容。我们的底层架构所依据的区分比上述两类文献都更早：Belkin and Croft (1992) 区分了两类系统，一类由用户画像决定哪些内容送达读取者，另一类则由读取者表达需求并发起检索。第 1 节中的三类方法属于前者；第 2 节的设计属于后者，其两种访问模式源自 Bush et al. (1945) 和 Berners-Lee (1989) 所开创的传统，并像 Brin and Page (1998) 那样，利用引用结构为排序提供依据。

This section describes details about how Contradiction Audit (Section 3.1) is built and scored. The pipeline has four stages: collecting documentation, splitting it into snippets, injecting contradictions, and deriving difficulty levels.
本节详细介绍矛盾审计（第 3.1 节）的构建和评分方式。该流程分为四个阶段：收集文档、将文档切分为片段、注入矛盾，以及确定难度等级。

B.2 Splitting into snippetsB.2 切分为片段
Each file is split into paragraphs, that is, runs of non-blank lines, and the paragraphs are packed greedily into snippets of about $1024$ tokens (tiktoken o200k_base). A paragraph is never split, so every snippet ends at a paragraph boundary and may run slightly over the target to complete one; a file containing a single paragraph longer than twice the target is skipped. Snippets keep the order of their files, and each snippet begins with a line naming the file it comes from, which the agents see.
每个文件先被切分为段落，即连续的非空行，再以贪心方式将段落装入约含 $1024$ 个 token 的片段中（tiktoken o200k_base）。段落始终保持完整，因此每个片段都在段落边界处结束，并可能为了容纳一个完整段落而略微超过目标长度；如果文件中的某个段落长度超过目标长度的两倍，则跳过该文件。片段保留其在文件中的顺序，每个片段开头都有一行注明其来源文件，智能体可以看到这一行。
B.3 Injecting contradictionsB.3 注入矛盾
Contradictions are injected into pairs of snippets by GPT-5.6, one pair at a time, in five steps.
GPT-5.6 每次处理一对片段，通过五个步骤向其中注入矛盾。
Candidate pairs.候选片段对。
Random pairs of snippets almost never discuss the same subject, so candidates are drawn from lexical overlap. A term is a lowercased word of at least four characters or one containing a digit; a pair is a candidate if the two snippets share at least two terms that each occur in at most eight snippets of the corpus. Candidates are visited in decreasing order of shared terms, with ties broken by a fixed random seed.
随机配对的片段几乎从不讨论同一主题，因此我们根据词汇重叠来选取候选片段对。术语是指转换为小写后至少包含四个字符的单词，或包含数字的单词；如果两个片段共享至少两个术语，且每个术语在语料库中均至多出现在八个片段中，则这两个片段构成一个候选对。按共享术语数量从多到少的顺序遍历候选对，数量相同时使用固定的随机种子确定顺序。
Shared subject.共同主题。
The model is shown the two snippets inside their full files, so that names and references can be resolved, and asked for up to three subjects that both snippets discuss and that are central to what their files document, rather than passing mentions. Pairs without such a subject are skipped.
向模型展示两个片段及其所在的完整文件，以便解析名称和引用，并要求模型找出至多三个主题：这些主题须是两个片段都讨论的内容，且是各自文件所记录内容的核心，而非仅被顺带提及。没有此类主题的片段对将被跳过。
Edit.编辑。
The model rewrites the prose of one of the two snippets so that it can no longer be true together with the other, and explains why the two now conflict. It may only edit natural-language prose, never code, tables, list entries or headings, and must copy the rest of the snippet unchanged.
模型改写两个片段中某一个片段的正文，使其与另一个片段无法同时为真，并解释两者现在为何存在冲突。模型只能编辑自然语言正文，绝不能编辑代码、表格、列表条目或标题，并且必须原样复制片段的其余部分。
Mechanical checks.机械检查。
The edited snippet is compared with the original. The edit is rejected if it changes more than $30\%$ of the snippet, if its changes are spread over more than eight separate places, or if it changes only formatting. Each sentence containing an edit must also occur exactly once in the corpus, so that the injected claim can be located without ambiguity.
将编辑后的片段与原始片段进行比较。如果编辑改动了片段中超过 $30\%$ 的内容、改动分布在超过八个独立位置，或仅改变了格式，则该编辑将被拒绝。每个包含改动的句子还必须在语料库中恰好出现一次，以便能够无歧义地定位注入的断言。
Judges.评审。
Four independent GPT-5.6 judges then check that the edited snippet reads naturally on its own, that the contradiction is not trivial, so that a model cannot find it from memorized knowledge of the project, that the edited snippet does not contradict itself, and that the two snippets truly cannot both be true. A contradiction is kept only if all four judges accept it.
随后，四个相互独立的 GPT-5.6 评审检查以下各点：编辑后的片段单独阅读时是否自然；矛盾是否并非显而易见，以使模型无法凭借记忆中的项目知识发现它；编辑后的片段是否不存在自相矛盾；以及两个片段是否确实不可能同时为真。只有四个评审全部接受时，才保留该矛盾。
The walk over candidates stops once each corpus holds twenty contradictions: ten whose two snippets come from the same file and ten whose snippets come from different files. Every snippet takes part in at most one contradiction, so the twenty contradictions occupy forty distinct snippets.
当每个语料库都包含二十个矛盾时，停止遍历候选对：其中十个矛盾的两个片段来自同一文件，另外十个矛盾的片段来自不同文件。每个片段至多参与一个矛盾，因此这二十个矛盾涉及四十个不同的片段。
B.4 Difficulty levelsB.4 难度级别
Level x $n$ keeps the forty contradiction snippets and adds $40(n-1)$ distractor snippets drawn at random with a fixed seed, for $40n$ snippets in total. Distractors are drawn first from snippets that form a whole file on their own, so that the reduced corpus consists of complete files as far as possible. The kept snippets stay in their original corpus order and are renumbered from zero. The contradictions are identical at every level, so a higher level differs only in how much unrelated text surrounds them. The main experiments use x4 ( $160$ snippets per corpus) with Qwen3.5-9B and x8 ( $320$ snippets) with Claude-5-Sonnet.
x $n$ 级别保留这四十个矛盾片段，并使用固定种子随机抽取 $40(n-1)$ 个干扰片段加入其中，共计 $40n$ 个片段。优先从自身即构成一个完整文件的片段中抽取干扰片段，以使缩减后的语料库尽可能由完整文件组成。保留的片段维持其在原始语料库中的顺序，并从零开始重新编号。所有级别中的矛盾完全相同，因此，更高级别的区别仅在于矛盾周围无关文本的数量。主要实验对 Qwen3.5-9B 使用 x4（每个语料库包含 $160$ 个片段），对 Claude-5-Sonnet 使用 x8（$320$ 个片段）。
B.5 Tools and reportingB.5 工具与报告
Every method receives the same two corpus tools. fetch_snippet returns the full text of a snippet given its index. search_snippet is an exact, case-insensitive text search over the corpus, which returns up to ten matching snippets with the surrounding context of each match. Each agent is told the number of snippets and a starting position; the starting positions of a group are randomly set. A contradiction is reported as a pair of snippet indices with a short reason, and an agent’s final answer is the list of pairs it is confident of. In ScaleMAS, a reported contradiction is also published as a message whose rationale quotes the conflicting text of both snippets; a quote that is not verbatim text of the cited snippets is rejected.
每种方法都获得相同的两个语料库工具。fetch_snippet 根据给定索引返回片段的完整文本。search_snippet 对语料库执行不区分大小写的精确文本搜索，返回至多十个匹配片段，并附上每处匹配的上下文。每个智能体都会获知片段数量和一个起始位置；同一组智能体的起始位置随机设置。报告矛盾时，需提供一对片段索引及简短理由；智能体的最终答案是其有把握的片段对列表。在 ScaleMAS 中，所报告的矛盾还会以消息形式发布，消息中的理由会引用两个片段中相互冲突的文本；如果引文并非所引用片段中的逐字原文，则会被拒绝。
B.6 ScoringB.6 评分
A contradiction counts as found when some reported pair includes its edited snippet. Reported pairs that match no injected contradiction are not penalized. The score of a run is the fraction of the twenty contradictions found by the pairs its agents report, and the score of a method is this fraction averaged over the sixteen corpora.
只要某个报告的片段对包含某个矛盾中经过编辑的片段，该矛盾就算被发现。对于未匹配任何注入矛盾的报告片段对，不予惩罚。一次运行的得分是其智能体所报告的片段对发现的矛盾占二十个矛盾的比例，一种方法的得分则是该比例在十六个语料库上的平均值。

C.2 Agent harnessC.2 智能体运行框架
ScaleMAS shares the identical agent harness with all baselines: ReAct, DeLM, AOrchestra, and MAD. For Contradiction Audit, FATE, and BrowseComp-Plus, the agent summarizes its own history periodically: once the history reaches ten turns, all but the three most recent turns are replaced by a summary of at most $1{,}024$ tokens written by the same model, and an earlier summary is rewritten together with the newly summarized turns. The mini-SWE-agent harness used on SWE-bench Verified keeps the full history instead.
ScaleMAS 与所有基线（ReAct、DeLM、AOrchestra 和 MAD）使用完全相同的智能体运行框架。对于 Contradiction Audit、FATE 和 BrowseComp-Plus，智能体会定期总结自身的历史记录：当历史记录达到十轮时，除最近三轮外的所有轮次都会被替换为由同一模型撰写、长度不超过 $1{,}024$ 个 token 的摘要，已有摘要也会与本次新纳入总结的轮次一起重新总结。而 SWE-bench Verified 使用的 mini-SWE-agent 运行框架会保留完整的历史记录。
C.3 Evaluation detailsC.3 评估细节
For the three third-party benchmarks, we report Pass@N accuracy (where N is the number of agents), following other multi-agent systems work (Park et al., 2026; Mao and Mirhoseini, 2026). This evaluation protocol is shared across all methods we tested. Pass@N measures what the group finds rather than which answer it would commit to; we treat answer selection as orthogonal, and single out the benefit of coordination by comparing with parallel ReAct agents.
对于三个第三方基准，我们遵循其他多智能体系统研究（Park et al., 2026; Mao and Mirhoseini, 2026），报告 Pass@N 准确率（其中 N 为智能体数量）。我们测试的所有方法均采用这一评估协议。Pass@N 衡量的是群体找到了什么答案，而非其最终会选定哪个答案；我们将答案选择视为一个独立问题，并通过与并行运行的 ReAct 智能体比较，单独考察协调带来的收益。
Every method submits a final answer when its action limit is reached: ReAct and MAD through the forced final step of their agent loop, DeLM and AOrchestra by submitting the answer recorded so far. Each baseline follows its released design, adapted to the shared benchmark adapter.
每种方法都会在达到动作次数上限时提交最终答案：ReAct 和 MAD 通过其智能体循环中强制执行的最终步骤提交，DeLM 和 AOrchestra 则提交截至当时记录的答案。各基线均遵循其已发布的设计，并作出适配以使用统一的基准适配器。
BrowseComp-Plus.BrowseComp-Plus。
We use the questions and the document corpus of BrowseComp-Plus (Chen et al., 2025b), served through the search service and browser tools of OpenResearcher. Agents have three tools: browser_search returns the top $20$ documents of a BM25 search over the corpus; browser_open opens a document or a link on the current page and shows a window of about $1{,}024$ tokens, which the agent can move; and browser_find searches for a text pattern in an open page. Each agent’s final answer is graded by an LLM judge (Qwen3.5-flash) with OpenResearcher’s grading prompt, which extracts the final answer from the response and compares it with the gold answer. Experiments use the first $100$ questions.
我们使用 BrowseComp-Plus（Chen et al., 2025b）的问题和文档语料库，并通过 OpenResearcher 的搜索服务和浏览器工具提供访问。智能体有三种工具：browser_search 返回对语料库执行 BM25 搜索后排名前 $20$ 的文档；browser_open 打开一个文档或当前页面上的一个链接，并显示一个约含 $1{,}024$ 个 token 的窗口，智能体可以移动该窗口；browser_find 则在已打开的页面中搜索文本模式。每个智能体的最终答案均由 LLM 评判器（Qwen3.5-flash）使用 OpenResearcher 的评分提示词进行评判，该提示词要求从响应中提取最终答案，并将其与标准答案比较。实验使用前 $100$ 个问题。
FATE.FATE。
FATE (Jiang et al., 2026) poses problems in abstract algebra as formal statements in Lean 4 with Mathlib, at increasing levels of difficulty; we use FATE-M ( $150$ problems) and FATE-H ( $100$ problems). Agents have two tools: search_mathlib returns the $10$ best-matching declarations from an index of Mathlib, and check_lean compiles a candidate proof and returns the compiler’s messages, at most $10$ times per agent with a limit of $900$ seconds per compilation. A final proof is compiled with Lean 4 (v4.28.0) and counts as correct only if it proves the stated theorem, compiles without errors, and contains no sorry. Experiments use the first $100$ questions of FATE-M, and use all questions of FATE-H.
FATE（Jiang et al., 2026）使用 Lean 4 和 Mathlib，将抽象代数问题表述为形式化命题，并设置逐渐递增的难度等级；我们使用 FATE-M（$150$ 道题）和 FATE-H（$100$ 道题）。智能体有两种工具：search_mathlib 从 Mathlib 索引中返回匹配程度最高的 $10$ 个声明；check_lean 编译候选证明并返回编译器消息，每个智能体最多可调用 $10$ 次，每次编译的时限为 $900$ 秒。最终证明使用 Lean 4（v4.28.0）编译，只有在证明了所述定理、编译无错误且不包含 sorry 时，才被判定为正确。实验使用 FATE-M 的前 $100$ 个问题，以及 FATE-H 的全部问题。
SWE-bench Verified.SWE-bench Verified。
We run SWE-bench Verified (Jimenez et al., 2024) on the mini-SWE-agent scaffold (Yang et al., 2024). Each agent works in its own container holding the repository at the base commit of the issue, runs shell commands with a limit of $60$ seconds per command, and submits the diff of its changes as a patch. A patch is graded with the benchmark’s tests: it is applied to a fresh copy of the repository, and the instance counts as resolved only if all tests that the fix must make pass (FAIL_TO_PASS) and all tests that must keep passing (PASS_TO_PASS) pass. Experiments use the first $100$ instances of the test split.
我们在 mini-SWE-agent 框架（Yang et al., 2024）上运行 SWE-bench Verified（Jimenez et al., 2024）。每个智能体都在各自的容器中工作，容器中的代码仓库处于对应问题的基准提交版本；智能体运行 shell 命令，每条命令的时限为 $60$ 秒，并将其更改的差异以补丁形式提交。补丁通过该基准的测试进行评判：将其应用于代码仓库的全新副本，只有在修复后必须通过的所有测试（FAIL_TO_PASS）以及必须继续通过的所有测试（PASS_TO_PASS）均通过时，该实例才被视为已解决。实验使用测试集划分中的前 $100$ 个实例。

Selection by citation weight.按引用权重选择。
When the datastore holds competing or redundant results, the one that others have built on is ranked first. Replaying each search on the datastore as it stood at that step reproduces the logged ranking exactly, so the effect of the weight can be measured by removing it. In Case 1, the citation weight puts the cited right answer first in three of four searches, where the uncited wrong answer would otherwise rank first. In Case 7, it places the filed contradiction within the eight returned results of two later searches, which would otherwise not return it.
当数据存储中存在相互竞争或冗余的结果时，其他智能体曾据以开展工作的结果会排在首位。在每一步当时的数据存储状态下重放各次搜索，可以精确复现日志中的排名，因此可以通过移除权重来衡量其影响。在案例 1 中，引用权重使被引用的正确答案在四次搜索中的三次排在首位；若无这一权重，未被引用的错误答案原本会排在首位。在案例 7 中，引用权重使已存入的矛盾出现在随后两次搜索各自返回的八条结果之内；若无这一权重，这两次搜索均不会返回该矛盾。

Agents prove different pieces of a theorem, and one agent assembles them. In Case 5, all agents start on the same route, and the work divides by lemma instead: one agent checks a skeleton with three open lemmas, and another fills them with lemmas published by two other agents. In Case 6, an agent reaches a proved lemma by following the “referenced by” links that the datastore attaches to each message.
多个智能体分别证明一个定理的不同部分，再由一个智能体将其整合起来。在案例 5 中，所有智能体起初都沿着同一路径展开工作，随后工作转而按引理分工：一个智能体检查了一个尚有三个引理未获证明的证明框架，另一个则用另外两个智能体发布的引理填补了这些空缺。在案例 6 中，一个智能体沿着数据存储为每条消息附加的“被引用”（referenced by）链接，找到了一个已获证明的引理。
Matching across agents.跨智能体匹配。
In Contradiction Audit, the two halves of a contradiction are often read by different agents at different times. A summary that one agent publishes lets another agent recognize the conflict when it reads the other half. In Case 7, a message written at step 2 is matched at step 219; in Case 8, an agent recalls a summary by its address after reading the edited page.
在 Contradiction Audit 中，构成矛盾的两部分往往由不同智能体在不同时间读到。一个智能体发布的摘要，使另一个智能体在读到另一部分时能够识别出冲突。在案例 7 中，第 2 步写下的一条消息直到第 219 步才被匹配上；在案例 8 中，一个智能体在阅读编辑后的页面后，通过摘要的地址将其调取出来。
Adoption.采纳。
Once a result is published, later agents answer from it without redoing the work, often after checking it. Adoption accounts for most of the correct final answers in Cases 3, 4, 7 and 8, and in Case 5 the late agents re-verify the assembled proof before submitting it.
一旦结果发布，后续智能体便据此作答，无须重复开展工作，而且往往会先加以核查。案例 3、4、7 和 8 中的大多数正确最终答案都来自对已有结果的采纳，而在案例 5 中，后期参与的智能体在提交整合后的证明之前，会再次验证该证明。
Across the cases, search by content is the channel through which agents first meet each other’s work. The other parts of the substrate each appear in at least one case: links between messages (Cases 6 and 8), persistence after the author stops or moves on (Cases 4 and 7), and citation weight (Cases 1 and 7).
在这些案例中，按内容搜索是智能体首次接触彼此工作成果的渠道。这一底层基础设施的其他组成部分也各自在至少一个案例中出现：消息之间的链接（案例 6 和 8）、作者停止工作或转向其他工作后消息仍持续保留（案例 4 和 7），以及引用权重（案例 1 和 7）。
D.2 Case 1: citation weight settles a splitD.2 案例 1：引用权重消解分歧
BrowseComp-Plus, Qwen3.5-9B, eight agents. The task is to name the author behind six clues about a set of papers; the answer is Jacek Rojowski. Two candidates enter the datastore one step apart: Muszyńska (Message 1, wrong) and Rojowski (Message 2). Agent 4 cites Message 5 of Agent 1 for Rojowski at step 33, and Agent 1 cites its own Messages 4 and 5, so their weight rises while no Muszyńska message is ever cited. Four agents working on Muszyńska then switch after one search each. With the citation weight, a Rojowski message ranks first in three of these searches; without it, Message 1 ranks first in all four. All eight agents answer Rojowski, while in groups of two and four agents every agent answers Muszyńska.
BrowseComp-Plus，Qwen3.5-9B，八个智能体。任务是根据关于一组论文的六条线索确定作者姓名；答案是 Jacek Rojowski。两位候选人相隔一步进入数据存储：Muszyńska（消息 1，错误）和 Rojowski（消息 2）。智能体 4 在第 33 步引用了智能体 1 关于 Rojowski 的消息 5，而智能体 1 又引用了自己的消息 4 和 5，因此这些消息的权重上升，而关于 Muszyńska 的消息始终未被引用。随后，四个正在追查 Muszyńska 的智能体各自搜索一次后便改变了判断。有引用权重时，一条关于 Rojowski 的消息在这些搜索中的三次排在首位；没有引用权重时，消息 1 在全部四次搜索中都排在首位。所有八个智能体都回答 Rojowski，而在两个和四个智能体组成的组中，每个智能体都回答 Muszyńska。

All four agents first pursue the same wrong actor. Building on Message 3 of Agent 3, which a search returns at step 98, Agent 2 traces the clue about releasing the wrong inmate to another actor (Message 6) and confirms his background (Messages 7 and 8).
