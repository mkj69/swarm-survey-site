架构Architecture
Agent Canvas 由 [OpenHands Agent Server](https://github.com/OpenHands/software-agent-sdk/tree/main/openhands-agent-server/openhands/agent_server) 提供支持，后者是一个用于在单台机器上运行多个智能体的 REST API。 Agent Canvas is powered by the [OpenHands Agent Server](https://github.com/OpenHands/software-agent-sdk/tree/main/openhands-agent-server/openhands/agent_server), a REST API for running multiple agents on a single machine. 每个 Agent Server 都在单一主机/端口上运行；Agent Canvas 可以连接多个 Agent Server，并在它们之间轻松切换。 Each Agent Server runs on a single host/port; the Agent Canvas can connect to multiple Agent Servers and easily flip between them.
你可以在任何地方运行 Agent Server： You can run an Agent Server anywhere:
直接在你的笔记本电脑上运行（请谨慎！） Directly on your laptop (be careful!)
在 Mac Mini 这样的专用机器上 On a dedicated machine like a Mac Mini
在云端的虚拟机上 On a virtual machine in the cloud
在 OpenHands Cloud（我们的商业产品）中 Inside OpenHands Cloud (our commercial offering)
Agent Server 通常与 [Automation Server](https://github.com/OpenHands/automation) 配合使用，后者允许你设置按计划运行或响应事件运行的智能体。 The Agent Server is often paired with an [Automation Server](https://github.com/OpenHands/automation), which lets you set up agents that run on a schedule or in response to events.
仓库边界Repository boundaries
Agent Canvas 是由多个仓库组成的 OpenHands 系统的一部分。 Agent Canvas is part of a multi-repository OpenHands system. 更改应提交到负责相应行为的仓库： Changes should go to the repository that owns the behavior: 
| Repository                                                                        | Responsibility                                                                                            |
| [`OpenHands/OpenHands`](https://github.com/OpenHands/OpenHands)                   | Agent Canvas frontend, user-facing control center, backend selection, and local-stack orchestration.      |

| [`OpenHands/automation`](https://github.com/OpenHands/automation)                 | Automation definitions, scheduling, webhooks, run history, and dispatching.                               |
