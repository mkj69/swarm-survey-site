智能体网络协议（Agent Network Protocol，ANP）Agent Network Protocol (ANP)
ANP 旨在成为智能体 Web（Agentic Web）时代的 HTTP：一套涵盖智能体身份、命名、发现、协商、安全消息传递和应用层协作的协议。 ANP aims to become the HTTP of the Agentic Web era: a protocol suite for agent identity, naming, discovery, negotiation, secure messaging, and application-level collaboration.
> **注意：** 本项目未在任何平台或区块链上发行任何数字货币。 > **Note:** This project has not issued any digital currency on any platform or blockchain.
愿景与定位Vision and Positioning
智能体网络协议（Agent Network Protocol，ANP）是一种面向智能体的开源通信协议。 Agent Network Protocol (ANP) is an open-source communication protocol for intelligent agents. 其目标是定义智能体之间的连接方式，并为数十亿个智能体构建开放、安全、高效的协作网络。 Its goal is to define how agents connect with each other and to build an open, secure, and efficient collaboration network for billions of agents.
我们认为，智能体互联网是继以人为中心的互联网之后的下一代信息基础设施。 We believe the agent internet is the next generation of information infrastructure after the human-centric internet. 在这一愿景中： In this vision:
**从以平台为中心转向以协议为中心：** 数据和服务不应继续被封闭在彼此孤立的平台中。 **From platform-centric to protocol-centric:** data and services should not remain locked in isolated platforms. 智能体需要通过开放协议实现直接连接。 Agents need open protocols for direct connection.
**连接就是力量：** 每个智能体都可以同时作为信息消费者和服务提供者，能够发现其他节点、与之连接并开展协作。 **Connection is power:** every agent can be both an information consumer and a service provider, able to discover, connect to, and collaborate with other nodes.
**AI 原生网络：** 智能体应通过语义清晰、机器可读且可调用的协议进行交互，而非仅通过面向人类的网页进行交互。 **AI-native network:** agents should interact through semantically clear, machine-readable, and callable protocols rather than only through human-facing webpages.
为什么需要 ANPWhy We Need ANP
当前的互联网基础设施已经成熟，但仍缺少专为大规模智能体网络设计的通信与连接层。 Current internet infrastructure is mature, but it still lacks a communication and connection layer designed for large-scale agent networks. ANP 聚焦于三项挑战： ANP focuses on three challenges:
🌐 **互联互通：** 使来自不同平台和域的智能体能够相互认证、发现和通信。 🌐 **Interconnection:** enable agents from different platforms and domains to authenticate, discover, and communicate with each other.
🖥️ **原生接口：** 让 AI 使用 API、协议文档、结构化描述和经协商确定的接口，而不是模仿人类浏览网页。 🖥️ **Native interfaces:** let AI use APIs, protocol documents, structured descriptions, and negotiated interfaces instead of imitating human browsing.
🤝 **高效协作：** 使智能体能够自主组织、自主协商，并构建成本更低的协作网络。 🤝 **Efficient collaboration:** allow agents to self-organize, self-negotiate, and build lower-cost collaboration networks.
协议架构Protocol Architecture
ANP 基于现有互联网基础设施构建，将已发布的协议能力组织为两个核心协议层以及特定领域的应用协议： ANP is built on existing Internet infrastructure and organizes the released protocol capabilities into two core protocol layers plus domain-specific application protocols:
🌐 **开放互联网基础设施：** ANP 复用 HTTP、CA、DNS、CDN、Search 和 TLS，而非重新构建网络协议栈。 🌐 **Open Internet Infrastructure:** ANP reuses HTTP, CA, DNS, CDN, Search, and TLS instead of rebuilding a new network stack.
🔒 **身份与加密通信层：** 基于 W3C DID 和 Web 基础设施。 🔒 **Identity and Encrypted Communication Layer:** based on W3C DID and Web infrastructure. ANP-02 将通用身份认证与 DID 方法验证分离，后者包括 `did:wba` 和原生 `did:web`，而消息传递配置文件（Profiles）则定义了 DID 寻址和设备绑定的端到端加密（E2EE）。 ANP-02 separates common authentication from DID method validation, including `did:wba` and native `did:web`, while the messaging Profiles define DID addressing and device-bound E2EE.
📡 **应用协议层：** 包括智能体描述、智能体发现和智能体应用协议。 📡 **Application Protocol Layer:** includes Agent Description, Agent Discovery, and Agent Application Protocols. 智能体支付、授权、身份认证和交易协议等领域协议构建于该层之上。 Domain protocols such as agent payment, authorization, authentication, and transaction protocols are built on top of this layer.
🧪 **元协议状态：** ANP-06 仍为草案，不属于当前已发布架构的一部分。 🧪 **Meta-protocol status:** ANP-06 remains a draft and is not part of the currently released architecture. 更新后的草案将其定位为由智能体描述驱动的语义协商层，使用 `MetaProtocolInterface`、`anp.get_capabilities` 和 `anp.negotiate` 来选择后续使用的接口、配置文件（Profile）、安全配置文件和模式（schema）。 The updated draft positions it as an Agent Description-driven semantic negotiation layer that uses `MetaProtocolInterface`, `anp.get_capabilities`, and `anp.negotiate` to select the subsequent interface, Profile, security profile, and schema.
