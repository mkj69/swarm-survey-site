一句话

Symphony 把 Linear 工单变成 Codex 的任务调度入口，扩展重点是减少人工盯会话的负担，而非展示智能体数量优势。

主要内容

  • 编排器轮询任务板，以工单状态驱动执行，为任务分配独立工作区，并重启崩溃或停滞的智能体。
  • 工单不必对应单个 PR：可跨仓库产生多个 PR，也可只做调查分析；工程师负责审查产出。
  • 系统基于 Codex App Server，通过动态工具调用访问 Linear，避免向子智能体容器暴露令牌。
  • Symphony 是供研究、修改的最小参考实现，OpenAI 不计划将其维护为独立产品；采用前需具备适合智能体的仓库、测试与护栏。

证据与可信度

这是 Help Net Security 对 OpenAI 信息的二手报道。文中称部分内部团队使用前三周，已合入 PR 数增长 500%；按通常口径即原来的六倍，但未给基数、样本量、对照组或质量指标，属于厂商自报，无独立核验。手机完成三项重要代码修改也是公司提供的个案；Linear 工作区增长仅为创始人的观察。

对 swarm scaling 的意义

材料提示，规模化瓶颈可能从执行能力转向任务分配、故障恢复和人工审查。工单状态机与独立工作区提供了可复用的编排思路，但 PR 增长不能证明并行数量与收益成比例，也不能证明多智能体协作提高了代码质量。
