一句话

Yegge 主张用权限受限的 TPM 类 agent 推动跨团队项目，并为企业积累组织上下文。

主要内容

  • Builder agent 仍受软件开发流程约束，可能加重合并队列与代码审查瓶颈；operator agent 则职责较窄，依赖工程师维护。
  • TPM agent 通过询问、观察、记录、汇报和催办推进项目，不直接执行变更。
  • 作者称其 Wheelhouse 中的此类 agent 已持续数月推动数十个项目，并在过程中整理隐性知识、依赖与工作流。
  • 他设想将各 agent 的发现汇入共享知识，并让员工逐步适应与 agent 协作。

证据与可信度

“数月”“数十个项目”均为作者个人自报，未提供项目清单、对照或独立核验。低成本、低风险和企业普及潜力属于判断，材料没有成本或效果测量；不能据此认定只询问和记录便没有风险。

对 swarm scaling 的意义

它把扩展重点从增加执行者转向增加协调与上下文采集能力，提示更多 builder 可能把压力转移到审查环节。但跨 agent 知识合并被描述得过于轻松，文中没有验证其准确性、冲突处理或规模收益。
