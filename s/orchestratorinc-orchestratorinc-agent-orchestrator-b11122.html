为什么选择 Orchestrator.incWhy Orchestrator.inc
一个编码智能体可以处理一项任务。 One coding agent can handle a task. 同时运行多个智能体意味着需要拆分工作、避免分支相互冲突，并跟踪每项变更完成 CI、审查和合并的全过程。 Running several means splitting the work, keeping branches from colliding, and following every change through CI, review, and merge. Orchestrator.inc 是为此而设计的本地桌面工作空间：每项任务都有独立的智能体、分支和工作树（worktree），而代码始终保留在你的机器上。 Orchestrator.inc is a local desktop workspace for that: every task gets its own agent, branch, and worktree, and your code stays on your machine.
功能Features
由编排器管理智能体集群The orchestrator runs the fleet
告诉项目的主智能体你想构建什么。 Tell a project's main agent what you want built. 它会规划工作，为每个部分启动一个在独立工作树中运行的工作智能体，并且只在需要你介入时才回来联系你。 It plans the work, starts a worker for each piece in its own worktree, and comes back only when something needs you.
用一个看板管理所有会话One board for every session
会话会根据智能体、其拉取请求（PR）、CI 和审查的状态自动归入相应的泳道，因此需要你处理的事项总会排在最上方。 Sessions sort themselves into lanes from the agent, its PR, CI, and reviews, so whatever needs you is on top.
CI 失败时，由对应的智能体修复CI fails, the right agent fixes it
失败的检查、审查意见和合并冲突都会反馈给负责该分支的工作智能体处理，直至 PR 获得批准。 Failed checks, review comments, and merge conflicts go back to the worker that owns the branch until the PR is approved. 审查智能体可以在人工审查之前阅读每个 PR。 A reviewer agent can read every PR before a person does.
使用你已经信赖的智能体Use the agent you already trust
为每项任务选择智能体和模型，然后通过结构化聊天或智能体自身的终端界面开展工作。 Pick the agent and model per task, then work in structured chat or the agent's own terminal UI. 每个工作智能体还配有浏览器，用于预览和测试其应用。 Each worker also gets a browser to preview and test its app.
支持的智能体Supported agents
不同智能体对工作智能体、聊天和审查功能的支持有所不同；[智能体设置指南](https://docs.orchestrator.inc/plugins/agents)提供了最新的支持矩阵。 Worker, Chat, and reviewer support differ by agent; the [agent setup guides](https://docs.orchestrator.inc/plugins/agents) have the current matrix.

**持续运行。**即使合上笔记本电脑，任务也会继续执行。 **Keep running.** Tasks keep going with your laptop closed.

产品遥测Product telemetry
Orchestrator.inc 会收集有限的使用情况和可靠性遥测数据，绝不会收集你的代码、提示词、智能体对话或凭据。 Orchestrator.inc collects limited usage and reliability telemetry, never your code, prompts, agent conversations, or credentials. 这些数据包括安装 ID 和你的 GitHub 用户名；如果你登录 AO Cloud，还会包括你的 AO Cloud 用户 ID 以及该账户的电子邮件地址，这些信息会一次性设置为 PostHog 人员属性（绝不会从 git config 中读取）。 It includes an installation ID and your GitHub username; if you sign in to AO Cloud it also includes your AO Cloud user ID and the email address of that account, set once as a PostHog person property (never read from git config). 在“设置 > 常规 > 隐私 > 共享使用情况分析”中可关闭全部遥测，该设置适用于桌面应用、守护进程和已配对的手机。 Turn it all off in Settings > General > Privacy > Share usage analytics, which covers the desktop, the daemon, and a paired phone. [详细了解我们收集哪些数据以及如何退出数据收集](docs/telemetry.md)。 [Learn exactly what we collect and how to opt out](docs/telemetry.md).
