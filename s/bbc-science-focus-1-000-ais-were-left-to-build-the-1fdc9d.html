一句话

千个 AI 在 Minecraft 中形成分工与社会行为，但也需要外部机制打破停滞；这篇报道更能说明大规模协作的治理难题，尚不能证明增加 agent 就能提升生产力。

主要内容

  • BBC Science Focus 的 Tom Howarth 于 2025 年 12 月 16 日报道 FRL（原 Altera AI）的 Project Sid：让约 1,000 个 agent 在 Minecraft 中持续活动数日，观察共同生活与协作。
  • 报道描述了农业、交易、建设等分工，以及治理、宗教和群体规范。但系统也出现反复附和、追逐无法完成的目标等问题，团队必须加入机制打断循环。
  • 开放服务器后，部分 agent 优先执行自身长期目标，忽视用户请求。研究所追求的自主性因此成为产品可用性的障碍。
  • FRL 随后转向办公工具，以 Excel agent Shortcut 为代表，主张先提高专用 agent 的能力，再组织成团队。报道将这一转向与游戏实验中的协调经验联系起来。

证据与可信度

  • 这是媒体报道，核心实验与产品效果主要来自公司及创始人 Robert Yang 的介绍，文中未提供足以复核的实验方法、日志或独立验证。
  • “1,000 个”“数日”描述部署规模与运行时间，不是协作效率指标。文章没有给出不同规模下的成功率、成本或吞吐量对比。
  • OSWorld 成功率约 50%、同期模型约 20–25%、人类约 60–70%，均为报道转述；未交代模型版本、评测配置及具体时间。“翻倍”是对这些近似数值的概括。
  • Shortcut 接近九成胜过初级分析师、挑战得分超过 80%等，也是报道中的产品试验说法，缺少样本量与完整协议，不能直接作为 swarm scaling 的证据。
  • “未来 24 个月”发生转变，以及个人管理上百个专家 agent，属于 Yang 的预测。

对 swarm scaling 的意义

材料提示，规模扩大后的难点包含循环附和、目标失控和对用户指令响应不足；增加数量之外，还需要停滞检测、纠偏与目标协调机制。但报道未说明这些机制的实现及效果。

它也揭示了两种目标的差别：模拟社会中的丰富涌现行为，与办公系统中的可靠执行并不等价。千个 agent 能持续共存，不代表千个 agent 能高效完成任务。本文适合作为失败模式与研究方向的线索，不能据此推导规模收益曲线或最佳团队规模。
