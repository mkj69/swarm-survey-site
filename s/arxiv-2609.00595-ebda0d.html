Abstract摘要
Safe agents can fail together. Multi-agent LLM systems (MAS) move information, state, decisions, and authority across principal boundaries, creating failures that local checks may miss. Without an execution-level view, a multi-agent setting can easily be mistaken for evidence of a genuinely multi-agent security effect. We thus systematize MAS security through an execution-centered analysis of 197 works, covering six interaction interfaces, four adversary positions, seven system-level risks, and eight recurring attack paths. We introduce an A-I-R framework that organizes attacks by adversary position, interaction interface, and resulting system-level risk, unifying otherwise fragmented attack mechanisms across MAS. We organize defenses through a five-part contract covering path target, observation, intervention, trust boundary, and recovery, and identify path closure and recovery as key challenges. We audit 44 evaluation and benchmark works and identify open challenges in isolating interaction effects, designing comparable and diagnostic metrics, supporting reuse across MAS designs, and evaluating open-system operation. Together, these findings motivate an interaction-aware view of MAS security: trace attacks end to end, test whether defenses close those paths, and evaluate system-level effects with appropriate counterfactuals.
安全的智能体也可能共同失效。多智能体 LLM 系统（MAS）使信息、状态、决策和权限跨越主体边界流转，从而引发局部检查可能遗漏的失效。如果缺乏执行层面的视角，就很容易将多智能体场景误认为确实存在多智能体安全效应的证据。因此，我们通过对 197 项工作开展以执行为中心的分析，系统梳理 MAS 安全，涵盖六类交互接口、四类对抗者位置、七类系统级风险和八条反复出现的攻击路径。我们提出 A-I-R 框架，按照对抗者位置、交互接口及所导致的系统级风险来组织攻击，将 MAS 中原本零散的攻击机制统一起来。我们通过一套由五部分组成的契约来组织防御，涵盖目标路径、观测、干预、信任边界和恢复，并将路径阻断和恢复确定为关键挑战。我们审查了 44 项评估与基准研究，并指出以下尚待解决的挑战：分离交互效应、设计可比较且具有诊断能力的指标、支持跨 MAS 设计复用，以及评估开放系统的运行。这些发现共同促使我们采用一种关注交互的 MAS 安全视角：端到端追踪攻击，检验防御能否阻断这些路径，并利用适当的反事实对照评估系统级效应。
1 Introduction1 引言
Agents that are safe when used individually can fail when used together in a MAS. Benign prompt fragments can become harmful when combined [11]; truthful reports can steer a group toward a false belief [55]; and attacker-controlled content can pass through honest specialists to a privileged tool [62]. These failures arise through interactions among the separately addressable participants of the MAS, which we call principals. Messages propagate influence between principals, a shared state preserves propagated influence, aggregation combines local outputs from different principals, and delegation transfers authority across boundaries [79, 95, 93, 62]. We therefore study the end-to-end execution of MAS, where interactions may leave a failure largely unchanged, amplify it, create a failure through composition, or require defining a security property that exists only when principals interact.
单独使用时安全的智能体，在 MAS 中协同使用时也可能失效。无害的提示片段在组合后可能变得有害 [11]；真实的报告可能将群体引向错误信念 [55]；攻击者控制的内容也可能经由诚实的专用智能体传递至具有特权的工具 [62]。这些失效源于 MAS 中可分别寻址的参与者之间的交互，我们将这些参与者称为主体（principals）。消息在主体之间传播影响，共享状态保留已传播的影响，聚合将不同主体的局部输出组合起来，而委派则使权限跨越边界转移 [79, 95, 93, 62]。因此，我们研究 MAS 的端到端执行；在这一过程中，交互可能使失效基本保持不变、放大失效、通过组合产生失效，或者要求定义一种仅在主体交互时才存在的安全属性。

Existing surveys cover many important threats, approaching from different perspectives. Agent-security surveys organize risks around models, prompts, memory, tools, workflows, interfaces, and environments [34, 50, 181, 71], while MAS-focused surveys emphasize communication, trust, topology, governance, and collective behavior [49, 139, 72, 132]. What remains unclear is how an attack moves through a multi-agent system: where it enters, which interaction interfaces it uses, and what system-level security failure it finally causes. Without this execution view, simply observing a failure in a multi-agent setting can be mistaken for evidence that the failure depends on interaction. This distinction is increasingly important as the field grows, because closely related studies still use different threat models, units of analysis, metrics, and evidence standards. A common way to describe and evaluate these security effects is therefore needed.
现有综述从不同视角涵盖了许多重要威胁。智能体安全综述围绕模型、提示、记忆、工具、工作流、接口和环境来组织风险 [34, 50, 181, 71]，而聚焦 MAS 的综述则强调通信、信任、拓扑、治理和集体行为 [49, 139, 72, 132]。尚不清楚的是，攻击如何在多智能体系统中推进：从何处进入，利用哪些交互接口，以及最终导致何种系统级安全失效。如果缺乏这种执行视角，仅仅在多智能体场景中观察到失效，就可能被误认为是该失效依赖交互的证据。随着该领域不断发展，这一区分日益重要，因为密切相关的研究仍在使用不同的威胁模型、分析单位、指标和证据标准。因此，需要一种共同的方法来描述和评估这些安全效应。
We address this gap by treating the complete multi-agent execution as the unit of analysis. Our core representation traces adversarial influence from its starting position (A), through one or more interaction interfaces (I), to a system-level security failure (R), yielding the $A\rightarrow I\rightarrow R$ framework. Eight configuration dimensions (C1–C8) describe the conditions under which such an execution occurs; they condition a path. Across the corpus, we group recurring $A\rightarrow I\rightarrow R$ executions into eight non-exclusive attack paths (P1–P8). These paths are synthesis shorthands for recurring execution patterns, not an additional taxonomy of security outcomes. The same execution view is then used to analyze where defenses can intervene and how security claims should be evaluated. Figure 1 summarizes this organization. Our contributions are therefore fourfold:

2 Overview2 概述
This section defines the scope of the SoK, positions our analysis relative to prior surveys, and summarizes the evidence base used for the synthesis.
本节界定本知识系统化研究（SoK）的范围，说明我们的分析与既有综述之间的关系，并概述用于综合分析的证据基础。
2.1 Scope2.1 范围
System boundary. We define an MAS by separately addressable principals: at least two participants whose outputs can affect one another through messages, shared state, collective decisions, or delegated actions [178, 56]. We call each such participant a principal. Principals may share the same LLM backend or use multiple models internally, so the system boundary is defined by interaction rather than model count [178, 71]. Debate systems, orchestrated teams, swarms, hierarchies, and A2A networks are therefore in scope when their participants act as separate principals [46, 86, 111]. Routing, ensembling, repeated sampling, and planner–critic–verifier pipelines are out of scope when all steps remain within one principal [71].
系统边界。我们以可独立寻址的主体（principal）来界定多智能体系统（MAS）：系统至少包含两个参与者，其输出能够通过消息、共享状态、集体决策或委托行动相互影响 [178, 56]。我们将每个这样的参与者称为一个主体。不同主体可以共享同一个 LLM 后端，也可以在内部使用多个模型，因此系统边界由交互而非模型数量来界定 [178, 71]。因此，当参与者作为独立主体行动时，辩论系统、编排式团队、群体、层级结构和 A2A 网络均属于研究范围 [46, 86, 111]。当所有步骤均处于同一主体内部时，路由、集成、重复采样以及规划器–批评器–验证器流水线不属于研究范围 [71]。
Security boundary. For the synthesis, we treat a result as evidence of a MAS-specific security effect when interaction changes a security-relevant outcome or when the protected property itself depends on interaction. Prompt injection, for example, may remain local, propagate across principals, persist in shared state, influence a collective decision, or gain authority through delegation [79, 95, 93, 62]. Authentication and authorization are likewise interaction-level concerns when trust or authority crosses principal boundaries [140, 173, 62]. Changes in accuracy, agreement, or behavior, including behavioral drift, count as security failures only when they violate a stated protected property or boundary. Results that reproduce an agent vulnerability in an MAS without a material interaction effect may be retained as comparative context, but they do not by themselves establish a MAS-specific causal claim.
安全边界。在综合分析中，当交互改变了与安全相关的结果，或受保护属性本身依赖于交互时，我们将该结果视为 MAS 特有安全效应的证据。例如，提示注入可能局限于局部，也可能跨主体传播、持久留存于共享状态、影响集体决策，或通过委托获得权限 [79, 95, 93, 62]。同样，当信任或权限跨越主体边界时，身份认证和授权也属于交互层面的问题 [140, 173, 62]。准确率、一致程度或行为的变化，包括行为漂移，只有在违反明确规定的受保护属性或边界时，才算作安全失效。在 MAS 中复现智能体漏洞、但未体现实质性交互效应的结果，可以保留为比较背景，但其本身不足以确立 MAS 特有的因果论断。
Interaction can play four roles in a security result. An inherited effect remains largely unchanged when the relevant relation is removed; we use this as a comparison label, not evidence of interaction dependence. An interaction-amplified effect remains possible, but interaction changes likelihood, reach, persistence, privilege, or impact [48, 182, 95, 151]. A composition-induced effect appears only when principals or steps are combined [11, 75, 124]. A structurally multi-agent effect concerns a property defined by relations among principals, such as collusion, coalition formation, or quorum manipulation [111, 105, 178]. For inherited, amplified, and composition-induced effects, relation-removal counterfactuals can distinguish whether the effect persists, changes in magnitude, or disappears when the protected property remains meaningful. Structurally multi-agent effects require comparisons that preserve the relation. These labels describe how interaction contributes to a security effect and what evidence is needed to support that claim.
交互可以在安全结果中发挥四种作用。继承性效应在移除相关关系后基本保持不变；我们将其用作比较标签，而非依赖交互的证据。交互放大型效应在没有交互时仍可能发生，但交互会改变其发生概率、波及范围、持久性、权限或影响 [48, 182, 95, 151]。组合诱发型效应仅在主体或步骤组合起来时才会出现 [11, 75, 124]。结构性多智能体效应涉及由主体间关系所定义的属性，例如合谋、联盟形成或法定人数操纵 [111, 105, 178]。对于继承性效应、交互放大型效应和组合诱发型效应，在受保护属性仍有意义的前提下，可以通过移除关系的反事实比较，区分该效应是持续存在、程度发生变化，还是消失。结构性多智能体效应需要采用保留相关关系的比较。这些标签描述了交互如何促成安全效应，以及支持该论断需要哪些证据。

2.2 Related Work2.2 相关工作
Prior surveys, reviews, and synthesis-style studies cover complementary parts of agent and multi-agent security. Broad agent-security surveys organize threats and defenses around models, prompts, memory, tools, workflows, interfaces, and environments [34, 50, 71, 181]. MAS-focused syntheses study communication, trust, topology, coordination, authorization, governance, and system-level risks [49, 139, 144, 72, 73, 140, 132]. More focused or adjacent studies examine orchestration and verification, trustworthy coordination, privacy-preserving retrieval, governed risk analysis, and the coverage of existing security frameworks [129, 153, 68, 148, 133, 115].
既有综述、评述和综合性研究涵盖了智能体及多智能体安全中相互补充的不同方面。综合性的智能体安全综述围绕模型、提示、记忆、工具、工作流、接口和环境来组织威胁与防御措施 [34, 50, 71, 181]。聚焦 MAS 的综合研究探讨通信、信任、拓扑、协调、授权、治理以及系统层面的风险 [49, 139, 144, 72, 73, 140, 132]。范围更聚焦或涉及相邻领域的研究则考察编排与验证、可信协调、隐私保护检索、受治理约束的风险分析，以及现有安全框架的覆盖范围 [129, 153, 68, 148, 133, 115]。
These works have different goals and scopes, and we do not treat the comparison as a ranking of their quality. Our distinction is the unit of analysis. Rather than organizing security primarily by component, attack name, design pattern, or governance concern, we organize it around cross-principal execution. The same execution model connects where adversarial influence enters, which interaction interfaces it crosses, which protected system-level effect it reaches, where a defense can intervene and under what assumptions, and what evidence supports the claim. Table 1 compares prior syntheses along these analytical dimensions. We code a dimension as systematic only when it is used as an explicit organizing or evaluation axis, as partial when it is substantively discussed or illustrated but not applied systematically, and as not systematically treated otherwise. These markers describe analytical coverage, not the quality of the cited work.
这些工作的目标和范围各不相同，我们并不将这种比较视为对其质量的排名。我们的区别在于分析单位。我们围绕跨主体执行来组织安全分析，而非主要依据组件、攻击名称、设计模式或治理问题。同一个执行模型将以下方面联系起来：对抗性影响从何处进入、跨越哪些交互接口、最终产生何种涉及系统级受保护属性的效应、防御能够在何处以及何种假设下介入，以及哪些证据支持相关论断。表 1 沿这些分析维度比较了既有综合研究。只有当某个维度被用作明确的组织或评估轴时，我们才将其编码为“系统性处理”；当该维度得到实质性讨论或示例说明，但未被系统应用时，将其编码为“部分处理”；其余情况则编码为“未系统处理”。这些标记描述的是分析覆盖情况，而非所引用工作的质量。
Literature Selection. We assembled the corpus through searches across major security, AI, and NLP venues and scholarly indexes, supplemented by backward and forward citation chasing. After deduplication and review against Section 2.1, the final corpus contains 197 works. We divide the corpus into two evidence sets with different roles in the synthesis. Set 1 contains 115 works that were peer reviewed or had received at least ten citations by the frozen review cutoff. We use these works to characterize the current MAS-security landscape and to support the main synthesis in the paper. Set 2 contains 82 additional in-scope works that point to emerging mechanisms, system settings, and security questions that may shape the next stage of the field. We use these works more selectively, primarily to highlight extensions of established attack paths, defenses, and evaluation settings. The literature corpus and associated artifacts will be released publicly with the final version of the paper.
文献筛选。我们通过检索安全、AI 和 NLP 领域的主要会议、期刊及学术索引，并辅以前向和后向引文追踪，构建了该文献集。经过去重并依据第 2.1 节进行审查后，最终文献集包含 197 项工作。我们将文献集划分为两个证据集，它们在综合分析中发挥不同作用。集合 1 包含 115 项工作，这些工作在本次综述确定的截止日期前已通过同行评审，或已获得至少十次引用。我们使用这些工作来刻画当前 MAS 安全领域的整体状况，并支撑本文的主要综合分析。集合 2 包含另外 82 项符合研究范围的工作，这些工作揭示了可能影响该领域下一阶段发展的新兴机制、系统设置和安全问题。我们更有选择性地使用这些工作，主要用于突出既有攻击路径、防御措施和评估设置的扩展。文献语料库及相关研究产物将随论文最终版本公开发布。
3 System Model and Interaction Surface3 系统模型与交互面
Building on the scope above, we separate the conditions around an execution from the transitions within it. Configuration dimensions (C1–C8) describe how the system is arranged and therefore condition the reach, persistence, and impact of an attack. Interaction interfaces (I1–I6) identify the security-relevant transitions through which information, state, decisions, authority, or security controls cross boundaries. The interfaces later form the middle of the $A\rightarrow I\rightarrow R$ execution path; the configuration dimensions provide context for interpreting that path.
基于上述范围，我们将一次执行所处的条件与执行内部的转换区分开来。配置维度（C1–C8）描述系统的组织方式，因此会制约攻击的波及范围、持续性和影响。交互接口（I1–I6）标识与安全相关的转换，信息、状态、决策、权限或安全控制通过这些转换跨越边界。这些接口随后构成 $A\rightarrow I\rightarrow R$ 执行路径的中间部分；配置维度则为解释该路径提供背景。
3.1 Configuration Dimensions3.1 配置维度
The eight configuration dimensions describe the conditions that shape an MAS execution. The same attack may therefore have different reach, persistence, or impact across configurations, and several dimensions may matter at once.
这八个配置维度描述了塑造 MAS 执行过程的条件。因此，同一种攻击在不同配置下可能具有不同的波及范围、持续性或影响，而且多个维度可能同时起作用。
C1: Communication topology. Communication topology describes which principals can communicate directly and which paths connect them. MAS studies commonly consider complete, chain or line, ring or circle, tree, and star topologies, as well as other system-specific communication graphs [48, 182, 166]. Topology changes path length, connectivity, and centrality, shaping how far adversarial influence can travel and which principals become important intermediaries.
C1：通信拓扑。通信拓扑描述哪些主体（principal）可以直接通信，以及哪些路径将它们连接起来。MAS 研究通常考虑全连接、链式或线性、环形或圆环、树形和星形拓扑，以及其他系统特定的通信图 [48, 182, 166]。拓扑会改变路径长度、连通性和中心性，从而影响对抗性影响能够传播多远，以及哪些主体会成为重要的中介。
C2: Protocol semantics. Protocol semantics describe how principals exchange information and what security context is preserved across each exchange. MAS communication ranges from free-form natural-language messages to messages with fixed roles or formats and agent-to-agent protocols [86, 52, 62]. Security depends on whether identity, origin and provenance, task context, and authorization information remain available across principal boundaries. End-to-end enforcement may require the security context needed by downstream checks to remain available across the protocol chain. Each exchange may be valid on its own, yet the full execution can still become unsafe if translation, summarization, state updates, or delegation lose the origin, purpose, provenance, or authority needed by a later decision [62, 1].
C2：协议语义。协议语义描述主体如何交换信息，以及每次交换过程中保留了哪些安全上下文。MAS 的通信形式涵盖自由形式的自然语言消息、具有固定角色或格式的消息，以及智能体间协议 [86, 52, 62]。安全性取决于身份、来源与溯源信息、任务上下文以及授权信息在跨越主体边界后是否仍然可用。端到端的安全执行可能要求下游检查所需的安全上下文在整个协议链中始终可用。每次交换本身可能都是有效的，但如果翻译、摘要、状态更新或委派过程丢失了后续决策所需的来源、目的、溯源信息或权限，整个执行过程仍可能变得不安全 [62, 1]。
C3: Principal composition. Principal composition describes which principals participate, what roles they play, and how independent they are. Systems may use homogeneous or heterogeneous models and generalist or specialist roles. Shared models, prompts, or evidence sources can create correlated behavior even when several principals participate [48, 105].
C3：主体构成。主体构成描述哪些主体参与其中、它们扮演什么角色，以及它们的独立程度。系统可以使用同构或异构模型，并采用通才或专家角色。即使有多个主体参与，共享的模型、提示或证据来源也可能导致行为相关性 [48, 105]。
C4: Coordination mechanism. Coordination mechanisms describe how principals combine their contributions into a system-level decision or action. Common mechanisms include debate, voting, judge or aggregator models, consensus, and orchestrator-mediated coordination [93, 111, 55]. Their security depends on how malicious or correlated contributions affect the collective outcome.
C4：协调机制。协调机制描述主体如何将各自的贡献整合为系统层面的决策或行动。常见机制包括辩论、投票、裁判或聚合器模型、共识，以及由编排器介导的协调 [93, 111, 55]。这些机制的安全性取决于恶意或相互关联的贡献如何影响集体结果。
C5: State architecture. State architecture describes where state is stored, who can access it, and how long it persists. Distinctions include principal-local versus shared state, ephemeral versus persistent state, and whether state is copied or inherited across principals [95, 187, 21]. These choices determine which principals can read or modify state and whether derived state can later be traced, revoked, or repaired.
C5：状态架构。状态架构描述状态存储在何处、谁可以访问，以及状态持续存在多长时间。相关区分包括主体本地状态与共享状态、临时状态与持久状态，以及状态是否在主体之间复制或继承 [95, 187, 21]。这些选择决定了哪些主体可以读取或修改状态，以及派生状态日后能否被追溯、撤销或修复。
C6: Membership and trust. Membership and trust describe which principals may participate and which relationships the system treats as trusted. Membership may be closed or open, static or dynamic, with persistent or ephemeral identities [86, 21, 89]. Dynamic systems must update admission, trust, and revocation as principals join, leave, or change roles. Membership is part of the system’s security state. In open or self-spawning systems, the population can change during execution, so the fraction of malicious principals is not necessarily fixed. Robustness claims based on that fraction therefore depend on how admission, identity, spawning, and revocation define who counts as a participant [21, 89].
C6：成员资格与信任。成员资格与信任描述了哪些主体可以参与，以及系统将哪些关系视为可信关系。成员资格可以是封闭或开放的、静态或动态的，并采用持久或临时身份 [86, 21, 89]。动态系统必须随着主体的加入、退出或角色变化，更新准入、信任和撤销机制。成员资格是系统安全状态的一部分。在开放或可自行生成主体的系统中，主体群体可能在执行期间发生变化，因此恶意主体的比例不一定固定。因此，基于该比例的鲁棒性主张取决于准入、身份、主体生成和撤销机制如何界定哪些主体算作参与者 [21, 89]。
C7: Authority placement. Authority placement describes which principals hold or can delegate privileged capabilities. Relevant authority includes tool permissions, credentials, resource budgets, delegation rights, and routing or control-plane privileges [62, 173, 1]. Security impact depends not only on which principals are reachable, but also on what authority is reachable through them.
C7：权限配置。权限配置描述了哪些主体持有特权能力，或能够将这些能力委托给其他主体。相关权限包括工具权限、凭据、资源预算、委托权，以及路由或控制平面特权 [62, 173, 1]。安全影响不仅取决于哪些主体可达，还取决于通过这些主体能够触及哪些权限。
C8: Oversight architecture. Oversight architecture describes who can observe an execution and how much of it they can see. Monitoring may be local, distributed across principals, or centralized with graph or trace visibility. Broader visibility can improve detection and attribution, but it may also concentrate sensitive state and control in the oversight plane. A defense can only make claims about interactions that fall within its view. A local observer may miss behavior that spans edges, principals, shared state, or a long execution trace, while a broader observer may recover more of the path at the cost of stronger trust and privacy assumptions [162, 40, 193].
C8：监督架构。监督架构描述了谁能够观察一次执行，以及能够看到其中多少内容。监控可以在本地进行、分布于多个主体之间，或以集中方式进行，并具备对图结构或执行轨迹的可见性。更广的可见范围可以改善检测和归因，但也可能使敏感状态与控制权集中于监督平面。防御机制只能对其可见范围内的交互作出保证。局部观察者可能遗漏跨越多条边、多个主体、共享状态或较长执行轨迹的行为，而观察范围更广的观察者可能还原更多路径，但代价是需要更强的信任与隐私假设 [162, 40, 193]。
Limitations and Open Challenges. Configuration dimensions often change together. An architectural change may simultaneously alter topology, protocol behavior, state sharing, authority, and oversight [48, 95]. Security results should therefore state which C1–C8 dimensions vary across configurations. Controlled comparisons should isolate one dimension when possible and report coupled changes otherwise. More broadly, interaction does not always make a system less secure. The same architecture may increase or reduce risk under different models, protocols, roles, or protected properties.
局限性与开放挑战。配置维度往往会一同变化。一次架构变更可能同时改变拓扑结构、协议行为、状态共享、权限和监督方式 [48, 95]。因此，安全性研究结果应说明，不同配置之间的哪些 C1–C8 维度发生了变化。受控比较应尽可能单独考察一个维度，否则应报告相互耦合的变化。更广泛地说，交互并不总会降低系统的安全性。在不同模型、协议、角色或受保护属性下，同一架构可能增加风险，也可能降低风险。
3.2 Interaction Interfaces3.2 交互接口
The six interaction interfaces mark security-relevant transitions during an MAS execution. I1–I5 describe how inputs, messages, state, authority, and collective decisions move through the system. I6 captures how the system observes and intervenes in those transitions.
这六个交互接口标示了 MAS 执行过程中与安全相关的转换环节。I1–I5 描述了输入、消息、状态、权限和集体决策如何在系统中流转。I6 刻画了系统如何观察和干预这些转换。
I1: Admission. Admission covers what is allowed to enter the MAS boundary, including users, new principals, external data, messages, and artifacts. Relevant context includes identity, provenance, role, initial trust, and participation rules [62, 86, 79]. An input that is safe at entry may still become harmful after later interactions give it more reach, persistence, or authority.
I1：准入。准入涵盖哪些对象获准进入 MAS 边界，包括用户、新主体、外部数据、消息和制品。相关上下文包括身份、来源、角色、初始信任和参与规则 [62, 86, 79]。某个输入在进入时可能是安全的，但后续交互赋予其更广的影响范围、更强的持久性或更多权限后，它仍可能变得有害。
I2: Message transfer. Message transfer begins once information moves between admitted principals. Security depends on who receives the message, in what order and context, and whether sender identity, provenance, and task purpose remain clear across the transfer [52, 176, 79]. Routing can therefore change which principals a message can influence.
I2：消息传递。一旦信息在已获准加入的主体之间流动，消息传递便开始了。安全性取决于谁接收消息、接收的顺序和上下文，以及发送者身份、来源和任务目的在传递过程中是否始终清晰 [52, 176, 79]。因此，路由可以改变一条消息能够影响哪些主体。
I3: State propagation. State propagation occurs when information from one interaction is written into state and later affects another principal or execution. This includes memories, summaries, plans, histories, and derived artifacts [95, 187, 21]. Unlike direct message transfer at I2, I3 can preserve and reintroduce influence after the original interaction has ended.
I3：状态传播。当一次交互中的信息被写入状态，并在之后影响另一个主体或另一次执行时，就发生了状态传播。这包括记忆、摘要、计划、历史记录和派生制品 [95, 187, 21]。与 I2 中的直接消息传递不同，I3 能够在原始交互结束后保留并重新引入影响。
I4: Authority transfer and action. Authority transfer and action cover delegation and use of privileged capabilities. A message, state update, or decision may lead a principal to use a tool, credential, resource, or delegated capability [62, 1, 36]. Security depends on whether the action stays within the authority, purpose, resource, and scope that were originally allowed. I4 therefore marks the transition from information or delegated authority to a privileged action; attacks exploit this interface when adversarial influence reaches that action.
I4：权限转移与行动。权限转移与行动涵盖特权能力的委托与使用。消息、状态更新或决策可能促使某个主体使用工具、凭据、资源或受委托的能力 [62, 1, 36]。安全性取决于该行动是否始终处于最初获准的权限、目的、资源和范围之内。因此，I4 标志着从信息或受委托权限向特权行动的转变；当对抗性影响触及该行动时，攻击便会利用这一接口。
I5: Collective commitment. Collective commitment occurs when local outputs become a group-level decision, such as a vote, consensus, final answer, termination decision, or action trigger. Security depends on whether that decision is based on valid and sufficiently independent evidence [111, 55, 178]. Shared models, context, sources, or attacker influence can make agreement overstate the evidence.
I5：集体承诺。当局部输出转化为群体层面的决策时，就形成了集体承诺，例如投票、共识、最终答案、终止决策或行动触发。安全性取决于该决策是否基于有效且具有充分独立性的证据 [111, 55, 178]。共享的模型、上下文、信息来源或攻击者影响，可能使一致意见夸大证据的支持力度。
I6: Detection and intervention. Detection and intervention cover security checks and responses applied during an execution. These include monitoring, blocking, isolation, revocation, rollback, and recovery across I1–I5 [162, 40, 141]. A defense can act only on the information it can observe and the parts of the execution it can control. Intervention must also occur before the protected effect becomes irreversible when prevention is the goal.
I6：检测与干预。检测与干预涵盖执行过程中实施的安全检查与响应。这些措施包括贯穿 I1–I5 的监控、阻断、隔离、撤销、回滚和恢复 [162, 40, 141]。防御只能依据其能够观察到的信息，对其能够控制的执行环节采取行动。当目标是预防时，干预还必须在所要防止的后果变得不可逆之前发生。
In short, C1–C8 are conditioning descriptors, whereas I1–I6 are transitions within an execution. Section 4 completes the execution record by adding the adversary position A and resulting risk R, forming $A\rightarrow I\rightarrow R$ . We reuse this single representation for attacks, defenses, and evaluation.
简言之，C1–C8 是条件描述符，而 I1–I6 是一次执行过程中的状态转变。第 4 节通过加入对手位置 A 及其导致的风险 R，补全执行记录，形成 $A\rightarrow I\rightarrow R$。我们将这一统一表示复用于攻击、防御和评估。
4 Attack Landscape4 攻击态势
Attacks become system-level failures when adversarial influence crosses interaction boundaries under a particular system configuration. We first define adversary positions and seven system-level risks, then synthesize eight recurring attack paths. We close with cross-cutting findings and the evidence gaps that remain for interaction-dependent harm.
在特定系统配置下，当对抗性影响跨越交互边界时，攻击就会演变为系统层面的失效。我们首先定义对手位置和七类系统层面风险，然后归纳八条反复出现的攻击路径。最后，我们总结跨领域的发现，以及在依赖交互的危害方面仍然存在的证据缺口。
4.1 Threat Model4.1 威胁模型
An MAS threat model must state the adversary’s position, capabilities, persistence, and the protected party and property. Figure 1 distinguishes four starting positions. An A1 external adversary controls content or services outside the MAS. An A2 user-level adversary acts through an authorized user interface. An A3 member adversary controls one or more participating principals. An A4 infrastructure adversary controls shared components such as the coordinator, state store, router, telemetry service, or defense plane. Adversary position alone does not determine capability. Attackers at the same position may differ in whether they can alter messages, routing, shared state, aggregation, membership, tools, or delegated authority [52, 176, 46, 93, 62]. Coalition size and persistence further shape how far that influence can propagate or coordinate [111, 105, 143]. A complete threat model must therefore specify not only where the adversary is, but also what it can control and which security property is protected.
MAS 的威胁模型必须明确对手的位置、能力、持续性，以及受保护方和受保护的属性。图 1 区分了四种初始位置。A1 外部对手控制 MAS 之外的内容或服务。A2 用户级对手通过获授权的用户界面采取行动。A3 成员对手控制一个或多个参与主体。A4 基础设施对手控制协调器、状态存储、路由器、遥测服务或防御平面等共享组件。仅凭对手位置无法确定其能力。处于同一位置的攻击者，在能否修改消息、路由、共享状态、聚合、成员构成、工具或受委托权限方面可能有所不同 [52, 176, 46, 93, 62]。攻击联盟的规模和持续性进一步决定了这种影响能够传播多远，或能在多大范围内得到协调 [111, 105, 143]。因此，完整的威胁模型不仅必须说明对手位于何处，还必须说明其能够控制什么，以及所保护的是哪项安全属性。
Limitations and Open Challenges. Many evaluated settings keep these variables fixed throughout a run, while deployed MAS may spawn principals, reroute communication, update trust, and delegate or revoke authority during execution. Threat models for such systems should track changes in membership, communication, state lineage, and reachable authority, rather than describe only the initial attacker state. In open or self-spawning systems, membership is itself part of the security state. Fraction-based robustness claims are incomplete unless admission and identity mechanisms define who counts toward the population and how spawned or ephemeral principals inherit trust [86, 21, 89, 173].
局限性与开放挑战。许多接受评估的设置在整个运行过程中都将这些变量保持不变，而实际部署的 MAS 可能在执行期间生成主体、重新路由通信、更新信任，以及委托或撤销权限。此类系统的威胁模型应跟踪成员构成、通信、状态谱系和可获得权限的变化，而不应仅描述攻击者的初始状态。在开放系统或能够自行生成主体的系统中，成员构成本身就是安全状态的一部分。除非准入和身份机制明确规定哪些主体计入总体，以及生成的主体或临时主体如何继承信任，否则基于比例的鲁棒性论断就是不完整的 [86, 21, 89, 173]。
4.2 System-Level Risk Families4.2 系统层面风险类别
Risk families describe the system-level security failure reached by an attack. We group consequences into seven non-exclusive families. The same risk may arise through different interfaces, and one execution may trigger several risks.
风险类别描述攻击最终导致的系统层面安全失效。我们将后果归为七类，这些类别并不互斥。同一种风险可能通过不同接口产生，而一次执行可能触发多种风险。
R1. Containment failure. Containment fails when adversarial influence escapes the principal or context in which it entered and remains effective elsewhere. Agent Smith, Prompt Infection, and the Wolf Within show spread across principals, while Flooding shows manipulated knowledge spreading and persisting through interaction and memory, and CORBA shows that blocking behavior can itself become contagious [46, 79, 147, 65, 195]. Topology and shared state determine how far that influence travels and whether it remains after the original source disappears [182, 95].
R1.遏制失效。当对抗性影响逸出其最初进入的主体（principal）或上下文，并在其他地方持续发挥作用时，就发生了遏制失效。Agent Smith、Prompt Infection 和 Wolf Within 展示了跨主体传播，而 Flooding 展示了被操纵的知识如何通过交互和记忆传播并持续存在，CORBA 则表明，阻断行为本身也可能具有传染性 [46, 79, 147, 65, 195]。拓扑结构和共享状态决定了这种影响能够传播多远，以及在原始来源消失后是否仍会持续存在 [182, 95]。
R2. Loss of independence. Loss of independence occurs when principals expected to provide independent evidence become strategically or statistically dependent. Secret Collusion and CoMet establish covert coordination channels, while hidden-role and steganographic studies show that such dependence may be difficult to observe [111, 172, 105, 170]. As illustrated in Fig. 2, protocol-valid messages can hide coordination between compromised principals, making their agreement unreliable as independent evidence. Dependence can also arise from a shared model, prompt, retriever, or poisoned source without explicit collusion. Agreement alone therefore does not establish independent support.
R2.独立性丧失。当本应提供独立证据的主体在策略上或统计上变得相互依赖时，就发生了独立性丧失。Secret Collusion 和 CoMet 建立了隐蔽的协调通道，而关于隐藏角色和隐写术的研究表明，这种依赖关系可能难以被观察到 [111, 172, 105, 170]。如图 2 所示，符合协议的消息可以隐藏受控主体之间的协调，使其达成的一致无法作为可靠的独立证据。即使不存在明确的串谋，共享的模型、提示、检索器或遭投毒的信息源也可能导致依赖关系。因此，仅凭一致性并不能确立独立的佐证。

R3. Collective-decision integrity failure. Collective-decision integrity fails when adversarial influence changes a protected vote, consensus, commitment, quorum, or other group decision. R4. Trajectory and goal integrity failure. Trajectory or goal integrity fails when interaction redirects a protected objective, policy, or execution trajectory beyond an authorized boundary. CRDA measures content-risk drift under adversarial multi-agent interaction, while persuasion studies provide more direct evidence that peer interaction can redirect later behavior [98, 76]. FlowSteer studies workflow steering, while the LLM Drift software artifact provides an evaluation framework for behavioral drift and latent-state studies examine longer or stateful changes in multi-agent execution [82, 138, 19]. These forms of evidence do not all establish the same trajectory-security claim. Unlike ordinary accuracy degradation, an R4 claim needs an explicit protected objective and a boundary after which the deviation becomes unauthorized. Direct evidence for this risk remains thinner than for propagation or collective manipulation.
R4.轨迹与目标完整性失效。当交互使受保护的目标、策略或执行轨迹发生偏转并超出授权边界时，就发生了轨迹或目标完整性失效。CRDA 衡量对抗性多智能体交互下的内容风险漂移，而说服研究则提供了更直接的证据，表明同伴交互能够改变后续行为的方向 [98, 76]。FlowSteer 研究工作流引导，LLM Drift 软件制品提供了行为漂移的评估框架，而潜在状态研究则考察多智能体执行中持续时间更长或涉及状态的变化 [82, 138, 19]。这些不同形式的证据并不能全部确立同一种轨迹安全论断。与普通的准确率下降不同，R4 论断需要明确受保护的目标，以及一条界定偏离从何处起不再获得授权的边界。与传播或集体操纵相比，这一风险的直接证据仍然较为薄弱。
R5. Cross-principal confidentiality breach. A cross-principal confidentiality breach occurs when protected information reaches an unauthorized principal, coalition, service, or observer. MASLeak studies extraction of multi-agent intellectual property, including prompts, tools, and architecture, while AgentLeak measures privacy leakage across internal coordination channels; CIA shows that communication topology itself can be inferred [160, 174, 166]. Compositional privacy further shows that several locally permissible views may reveal protected information when combined [124]. The protected object therefore extends beyond user secrets to internal context, state, workflow information, and system structure.
R5.跨主体机密性泄露。当受保护的信息到达未经授权的主体、联盟、服务或观察者时，就发生了跨主体机密性泄露。MASLeak 研究多智能体知识产权的提取，包括提示、工具和架构；AgentLeak 衡量经由内部协调通道发生的隐私泄露；CIA 则表明，通信拓扑本身也可以被推断出来 [160, 174, 166]。组合隐私研究进一步表明，若干在局部各自被允许的视图在组合后可能泄露受保护的信息 [124]。因此，受保护的对象不仅包括用户秘密，还涵盖内部上下文、状态、工作流信息和系统结构。
R6. Transitive authorization failure. A transitive authorization failure occurs when state, instructions, or delegated authority cross principal boundaries and produce effects outside their original purpose or scope. Control-flow hijacking follows attacker-controlled influence through trusted handoffs into privileged tools, while cascading instruction and software-team attacks show similar composition across roles and artifacts [62, 1, 152, 163]. The central failure is loss of origin, purpose, or scope along the delegation chain [173].
R6.传递性授权失效。当状态、指令或委托权限跨越主体边界，并产生超出其原始目的或范围的影响时，就发生了传递性授权失效。控制流劫持追踪攻击者控制的影响如何经由可信交接进入特权工具，而级联指令攻击和软件团队攻击则展示了跨角色与制品的类似组合过程 [62, 1, 152, 163]。核心失效在于，来源、目的或作用范围信息在委托链中丢失 [173]。
R7. Availability and resource-isolation failure. Availability or resource isolation fails when shared communication, execution, or control resources allow one adversarial path to degrade the service available to other principals. CORBA provides direct evidence through contagious blocking [195]. Other studies expose resource and control-plane coupling, but systematic evidence for adversarial resource isolation remains limited. The defining property is cross-principal loss of availability or resource isolation, not ordinary latency, lower accuracy, or efficiency loss.
R7.可用性与资源隔离失效。当共享的通信、执行或控制资源使某条对抗性路径能够降低其他主体可获得的服务水平时，可用性或资源隔离就会失效。CORBA 通过传染性阻塞提供了直接证据 [195]。其他研究揭示了资源与控制平面之间的耦合，但有关对抗条件下资源隔离的系统性证据仍然有限。其界定性特征是跨主体的可用性或资源隔离丧失，而非普通的延迟、准确率下降或效率损失。
Risk interactions. The risks can form chains rather than isolated outcomes. Propagation or persistent influence (R1) may redirect later behavior (R4), become accepted as collective evidence (R3), acquire delegated authority (R6), and eventually cross a confidentiality boundary (R5). Loss of independence (R2) can accelerate this chain, while resource interference (R7) can weaken observation or intervention at I6. This is a cross-paper synthesis rather than a claim that one study demonstrates the full chain.
风险之间的相互作用。这些风险可能形成链条，而非孤立的结果。传播或持续性影响（R1）可能改变后续行为的方向（R4），被接纳为集体证据（R3），获得委托权限（R6），并最终跨越机密性边界（R5）。独立性丧失（R2）可能加速这一链条，而资源干扰（R7）可能削弱 I6 处的观测或干预。这是跨论文的综合分析，并非声称某一项研究展示了完整链条。
Limitations and Open Challenges. Risk labels identify consequences, not causes, and they should not be inferred from attack names alone. The same risk can arise through several interaction paths, while one execution can violate several protected properties at once. Evaluations should therefore state the protected property and verify the downstream consequence before assigning a system-level risk.
局限性与开放挑战。风险标签标识的是后果，而非原因，不应仅凭攻击名称推断风险标签。同一种风险可能通过多条交互路径产生，而一次执行也可能同时违反多项受保护属性。因此，评估应明确受保护属性，并在判定系统级风险之前验证下游后果。
4.3 Attack Paths from Adversary to Risk4.3 从对手到风险的攻击路径
Attack paths connect an adversary’s starting position to a security consequence through one or more interaction interfaces. Across the corpus, we identify eight recurring $A\rightarrow I\rightarrow R$ paths, summarized in Table 2. These paths describe recurring mechanisms, so one execution may contain several paths.
攻击路径通过一个或多个交互接口，将对手的起始位置与安全后果连接起来。在所收集的文献中，我们识别出八条反复出现的 $A\rightarrow I\rightarrow R$ 路径，汇总于表 2。这些路径描述的是反复出现的机制，因此一次执行可能包含多条路径。
Running example. Control-flow hijacking shows why the full execution matters. In our coding of CFH-Hard, the core path is A1 $\rightarrow$ I1 $\rightarrow$ I2 $\rightarrow$ I4: external content enters the system, is relayed through trusted principals, and reaches a privileged coder or emailer, causing an R6 authorization failure [62]. Replanning may also involve I3 when an intermediate plan or execution state persists into downstream execution. Each step may appear valid on its own: the input may be allowed, the intermediate task may look reasonable, and the delegated action may be valid for its immediate sender. The violation becomes clear only when provenance and authority are traced across the full execution.
贯穿示例。控制流劫持说明了为何需要考察完整执行过程。在我们对 CFH-Hard 的编码分析中，核心路径为 A1 $\rightarrow$ I1 $\rightarrow$ I2 $\rightarrow$ I4：外部内容进入系统，经由受信任主体转发，最终到达具有特权的编码智能体或邮件发送智能体，导致 R6 授权失效 [62]。当中间计划或执行状态持续保留到下游执行中时，重新规划也可能涉及 I3。每一步单独来看都可能显得有效：输入可能是允许的，中间任务可能看似合理，而受委托的操作对于其直接发送者而言也可能是有效的。只有在完整执行过程中追溯来源与权限，违规才会显现。
P1. Admission and compositional injection. Locally acceptable inputs can become unsafe when combined. Prompt Infection and the Wolf Within show malicious influence crossing principal boundaries, while conjunctive and semantic-intent fragmentation split unsafe intent across pieces that appear less suspicious on their own [79, 147, 11, 7]. Similar effects appear in software teams, RAG-based debate, and ACIARena, where prompts, retrieved content, or generated artifacts are combined later in the execution [152, 163, 75, 9]. Recent work extends this pattern to debate jailbreaks, distributed backdoors, multimodal injection, poisoned retrieval, and workflow steering [127, 197, 74, 82, 92, 118]. The common problem is that harmful meaning or authority may emerge only after several locally acceptable steps. Conjunctive Prompt Attacks directly isolates this compositional effect with single-fragment and combined-fragment controls [11].
P1.准入与组合式注入。局部可接受的输入在组合后可能变得不安全。Prompt Infection 和 the Wolf Within 展示了恶意影响如何跨越主体边界，而合取式碎片化和语义意图碎片化则将不安全意图拆分到多个片段中，使各片段单独看来不那么可疑 [79, 147, 11, 7]。类似效应也出现在软件团队、基于 RAG 的辩论以及 ACIARena 中，其中提示、检索内容或生成产物会在执行的后续阶段被组合起来 [152, 163, 75, 9]。近期研究将这一模式扩展到辩论越狱、分布式后门、多模态注入、检索投毒和工作流引导 [127, 197, 74, 82, 92, 118]。共同的问题在于，有害含义或权限可能只有在多个局部可接受的步骤之后才会出现。Conjunctive Prompt Attacks 通过设置单片段与组合片段对照，直接分离出这种组合效应 [11]。
P2. Propagation and persistence. Interaction can turn a local compromise into a system-wide or persistent failure. Agent Smith, Troublemaker, Flooding, Prompt Infection, the Wolf Within, and CORBA spread malicious influence or disruption through communication, retrieval, generated content, or agent state [46, 107, 65, 79, 147, 195, 183, 125]. NetSafe and memory studies further show that topology affects reach, while shared state affects persistence [182, 95, 185]. AgentWorm extends propagation across communication, state, and downstream actions, while When Child Inherits considers spawned principals and inherited state or authority [187, 21, 184, 104]. Propagation is therefore not only about message delivery. It also depends on what remains in the system after the original source is removed. Recovery is much less studied than spread, especially when memories, artifacts, delegations, or spawned principals remain after the initial compromise [95, 187, 21].
P2.传播与持久性。交互可能将局部失陷转化为全系统范围的失效或持续性失效。Agent Smith、Troublemaker、Flooding、Prompt Infection、the Wolf Within 和 CORBA 通过通信、检索、生成内容或智能体状态传播恶意影响或干扰 [46, 107, 65, 79, 147, 195, 183, 125]。NetSafe 和记忆相关研究进一步表明，拓扑结构影响传播范围，而共享状态影响持久性 [182, 95, 185]。AgentWorm 将传播扩展至通信、状态和下游操作，而 When Child Inherits 则考察派生主体及其继承的状态或权限 [187, 21, 184, 104]。因此，传播不仅关乎消息传递。它还取决于原始来源被移除后，系统中仍然留存着什么。与传播相比，恢复受到的研究要少得多，尤其是在初始失陷后仍留有记忆、产物、委派关系或衍生主体的情况下 [95, 187, 21]。
P3. Routing and role manipulation. The communication path itself can become an attack surface. Communication red teaming and MAST intercept or rewrite messages between principals without compromising endpoint models, while CIA treats topology itself as protected information [52, 176, 166, 188]. NetSafe shows how topology changes attack reach, A2ASecBench exposes protocol-stage attack surfaces, and PEAR highlights security effects of role separation [182, 86, 36]. Router hijacking, FlowSteer, and insider studies make routing and role placement explicit attack variables, while MESA identifies security-critical communication edges [10, 82, 143, 83, 168, 192]. Together, these studies show that routing and role placement can directly change decision influence and reachable authority. Many studies evaluate fixed membership, topology, and roles, leaving runtime admission, rerouting, and role reassignment less studied [86, 10, 82, 21].
P3.路由与角色操纵。通信路径本身也可能成为攻击面。通信红队测试和 MAST 在不攻陷端点模型的情况下拦截或改写主体之间的消息，而 CIA 则将拓扑本身视为受保护的信息 [52, 176, 166, 188]。NetSafe 展示了拓扑如何改变攻击的可达范围，A2ASecBench 揭示了协议各阶段的攻击面，PEAR 则强调了角色分离对安全性的影响 [182, 86, 36]。路由器劫持、FlowSteer 和内部攻击者研究将路由与角色配置明确列为攻击变量，而 MESA 则识别出对安全至关重要的通信边 [10, 82, 143, 83, 168, 192]。这些研究共同表明，路由与角色配置能够直接改变对决策的影响力以及可触及的权限范围。许多研究在成员构成、拓扑和角色固定的条件下开展评估，对运行时准入、重新路由和角色重新分配的研究则较少 [86, 10, 82, 21]。
P4. Adversarial coordination and collective manipulation. Collective security depends on independence, not only agreement. Secret Collusion and CoMet show covert coordination channels; Among Us measures malicious contributions; Lying with Truths shows how individually truthful statements can produce a misleading group conclusion; and persuasion and hidden role studies show how strategic members can steer a group [111, 172, 178, 55, 93, 76, 105, 57, 2, 110]. Other work studies adversarial majorities, coordinated insiders, debate jailbreaks, Byzantine communication, and consensus traps [15, 143, 127, 37, 94, 134]. Byzantine fault-tolerance studies further show that collective outcomes depend on assumptions about faulty membership and aggregation [191]; Fig. 3 illustrates the classical fault-bound intuition. A group may therefore agree strongly even when its evidence is compromised or not independent. It can also be hard to separate strategic coordination from common causes such as shared models, prompts, retrievers, or evidence sources [111, 55, 105, 135, 30]. This also limits content-only defenses: individually harmless messages can still create dependence through the communication channel, so message content alone cannot establish contributor independence [111, 172, 105].
P4.对抗性协调与集体操纵。集体安全取决于独立性，而不仅是意见一致。Secret Collusion 和 CoMet 展示了隐蔽的协调通道；Among Us 衡量恶意贡献；Lying with Truths 展示了单独来看真实的陈述如何产生误导性的群体结论；说服研究和隐藏角色研究则展示了采取策略性行动的成员如何引导群体 [111, 172, 178, 55, 93, 76, 105, 57, 2, 110]。其他工作研究了对抗性多数、协同行动的内部攻击者、辩论越狱、拜占庭通信和共识陷阱 [15, 143, 127, 37, 94, 134]。拜占庭容错研究进一步表明，集体结果取决于对故障成员构成和聚合方式的假设 [191]；图 3 直观展示了经典故障数量界限的含义。因此，即使群体所依据的证据已遭篡改或缺乏独立性，群体仍可能达成高度一致。此外，策略性协调也可能难以与共享模型、提示、检索器或证据来源等共同原因区分开来 [111, 55, 105, 135, 30]。这也限制了仅基于内容的防御：单独来看无害的消息仍可能通过通信通道造成依赖，因此，仅凭消息内容无法确立贡献者的独立性 [111, 172, 105]。

P5. Peer- and state-mediated steering. P5 has limited direct evidence in our current map. CRDA measures content-risk drift under adversarial multi-agent interaction, while persuasion studies provide more direct evidence that peer interaction can redirect later behavior [98, 76]. FlowSteer and latent-state studies extend this analysis over longer or stateful executions [82, 19]. The LLM Drift software artifact provides an additional framework for measuring behavioral drift in adversarial multi-agent simulations [138]. Lower accuracy, changed reasoning, or generic drift does not by itself constitute an R4 failure. A study must identify the protected objective or allowed trajectory and show that interaction causes an unauthorized deviation. Direct evidence remains limited on when peer or state influence causes persistent, security-relevant goal redirection rather than temporary behavioral change [98, 82].
P5.经由同伴与状态的引导。在我们当前的研究图谱中，P5 的直接证据有限。CRDA 衡量对抗性多智能体交互下的内容风险漂移，而说服研究则提供了更直接的证据，表明同伴交互能够改变后续行为的方向 [98, 76]。FlowSteer 和潜在状态研究将这一分析扩展至持续时间更长或具有状态的执行过程 [82, 19]。LLM Drift 软件产物提供了一个额外框架，用于衡量对抗性多智能体仿真中的行为漂移 [138]。准确率下降、推理发生变化或一般性的漂移，本身并不构成 R4 失效。研究必须明确受保护的目标或允许的轨迹，并证明交互导致了未经授权的偏离。关于同伴或状态的影响何时会导致持续且与安全相关的目标转向，而非暂时性的行为变化，直接证据仍然有限 [98, 82]。
P6. Cross-principal information leakage. Confidentiality can fail during execution even when the final answer appears safe. MASLeak studies extraction of multi-agent intellectual property, including prompts, tools, and architecture, while AgentLeak measures privacy leakage across internal coordination channels; CIA shows that communication topology itself can be inferred [160, 174, 166]. Compositional privacy shows that several acceptable local views can reveal more when combined, and collusion studies show that inter-principal channels can hide strategic information transfer [124, 111]. Recent work studies distinct extensions: OMNI-LEAK examines orchestrator-mediated leakage, WebWeaver targets topology confidentiality, CalBench measures coordination–privacy trade-offs, and SNEAK evaluates strategic communication and information leakage [112, 171, 198, 14]. The protected object is therefore the information available to a principal or coalition across the execution, not only secret strings in the final response. Existing work gives limited attention to how ownership, provenance, receiver constraints, and intended use survive summarization, replication, joint inference, and tool use [124, 174, 95]. We found limited controlled evidence on cross-principal tool-prompt theft or timing, I/O, and network side channels.
P6.跨主体信息泄露。即使最终答案看似安全，执行过程中仍可能发生保密性失效。MASLeak 研究多智能体知识产权的提取，包括提示、工具和架构；AgentLeak 衡量经由内部协调通道发生的隐私泄露；CIA 则表明，通信拓扑本身也可以被推断出来 [160, 174, 166]。组合隐私研究表明，多个各自可接受的局部视图在组合后可能揭示更多信息，而合谋研究则表明，主体间通道可以隐藏策略性的信息传递 [124, 111]。近期工作研究了不同的扩展方向：OMNI-LEAK 考察经由编排器发生的泄露，WebWeaver 针对拓扑保密性，CalBench 衡量协调与隐私之间的权衡，SNEAK 则评估策略性通信与信息泄露 [112, 171, 198, 14]。因此，受保护的对象是某个主体或联盟在整个执行过程中能够获取的信息，而不仅是最终响应中的秘密字符串。现有工作较少关注所有权、来源、接收方约束和预期用途如何在摘要生成、复制、联合推断和工具使用过程中得以保留 [124, 174, 95]。我们发现，关于跨主体工具提示窃取，以及时序、I/O 和网络侧信道的受控实验证据有限。
P7. Delegation and authority escalation. A locally valid handoff does not guarantee valid authority across the full execution. Control-flow hijacking traces attacker-controlled influence into privileged tools, while cascading instruction shows how upstream content can gain downstream authority. Multi-agent code-generation attacks show similar failures across specialized roles and generated artifacts [62, 1, 152, 163]. PEAR and A2ASecBench provide role- and protocol-aware views of these transitions [36, 86]. AgentWorm extends the path across communication, state, and downstream actions, while When Child Inherits considers spawned principals and inherited state or authority [187, 21]. The recurring failure is the loss of origin, purpose, or scope along the delegation chain. Defense work on Agentic JWT and SentinelAgent begins to address multi-hop delegation, but preserving intent, scope, and provenance across semantic transformation, and revoking authority after credentials, capabilities, or state have already propagated, remain open challenges [45, 123, 21].
P7.委托与权限升级。局部有效的交接并不能保证整个执行过程中的权限均有效。控制流劫持追踪攻击者控制的影响如何进入特权工具，而级联指令则展示上游内容如何获得下游权限。多智能体代码生成攻击表明，类似失效也会出现在专门化角色和生成的产物之间 [62, 1, 152, 163]。PEAR 和 A2ASecBench 从角色和协议感知的角度审视这些转变 [36, 86]。AgentWorm 将这一路径扩展至通信、状态和下游动作，而 When Child Inherits 则考察衍生主体及其继承的状态或权限 [187, 21]。反复出现的失效是委托链中来源、目的或范围信息的丢失。围绕 Agentic JWT 和 SentinelAgent 的防御研究开始处理多跳委托问题，但如何在语义转换过程中保留意图、范围和来源，以及如何在凭证、能力或状态已经传播后撤销权限，仍是尚未解决的挑战 [45, 123, 21]。
P8. Shared-resource and control-plane interference. Shared resources create availability risks across principals. CORBA provides direct evidence of communication-level availability loss through contagious blocking [195]. Architectural-resilience and defection studies show that malicious or uncooperative participation can degrade shared execution, although such degradation does not by itself establish an R7 resource-isolation failure [130, 77]. Capability-paradox and sabotage evaluations show that defensive components can themselves change system-level security outcomes [96, 106]. This suggests that the defense plane can become part of the interaction surface, but systematic evidence on adversarial resource exhaustion and control-plane failure remains limited. Centralized control may improve visibility while also increasing the impact of a control-plane failure. Our current map contains relatively little direct security evidence for P8 compared with propagation and collective manipulation [195, 96, 106].
P8.共享资源与控制平面干扰。共享资源会带来跨主体的可用性风险。CORBA 提供了直接证据，表明传染式阻塞会导致通信层面的可用性丧失 [195]。关于架构韧性和背离行为的研究表明，恶意或不合作的参与可能使共享执行过程退化，但这种退化本身并不足以证明存在 R7 资源隔离失效 [130, 77]。能力悖论和蓄意破坏评估表明，防御组件本身也可能改变系统层面的安全结果 [96, 106]。这表明防御平面可能成为交互面的一部分，但关于对抗性资源耗尽和控制平面失效的系统性证据仍然有限。集中式控制可能提高可见性，同时也可能扩大控制平面失效的影响。与传播和集体操纵相比，我们当前的图谱中与 P8 相关的直接安全证据相对较少 [195, 96, 106]。
Path composition. A single execution may combine several paths. For example, malicious influence may enter through P1, persist through P2, alter a collective decision through P4, and finally reach a privileged action through P7 [79, 1, 62]. This composition shows why attacks should be traced across the full execution.
路径组合。一次执行可能组合多条路径。例如，恶意影响可能通过 P1 进入，通过 P2 持续存在，通过 P4 改变集体决策，最终通过 P7 触达特权动作 [79, 1, 62]。这种组合说明了为何应当在整个执行过程中追踪攻击。
4.4 Cross-Cutting Findings4.4 跨领域发现
Across P1–P8, four findings cut across individual attack mechanisms. First, relations are themselves attack surfaces: routing, role placement, aggregation, and delegation can change security even when message content is unchanged [52, 176, 10, 62]. Second, security effects can outlive the interaction that created them: shared state, spawned principals, and inherited authority can preserve a compromise after the original source is removed [95, 187, 21]. Third, the protected object extends beyond the final output: independence, topology, private context, and delegated authority can fail even when the final answer appears correct [111, 166, 174, 62]. Finally, observing an attack path is not the same as attributing its cause. Execution traces can show where harm travels, but additional comparisons are needed to establish which interaction caused or amplified it [182, 86, 9].
在 P1–P8 中，有四项发现超越了单一攻击机制。首先，关系本身就是攻击面：即使消息内容保持不变，路由、角色配置、聚合和委托也可能改变安全性 [52, 176, 10, 62]。其次，安全影响可能比产生它们的交互持续更久：即使原始来源已被移除，共享状态、衍生主体和继承的权限仍可能使受侵害状态持续存在 [95, 187, 21]。第三，受保护对象超出了最终输出的范围：即使最终答案看似正确，独立性、拓扑结构、私有上下文和委托权限仍可能受到破坏 [111, 166, 174, 62]。最后，观察到攻击路径并不等同于确定其成因。执行轨迹可以显示危害沿何处传播，但要确定是哪种交互造成或放大了危害，还需要进行额外的比较 [182, 86, 9]。
Together, these findings shift the security unit from an isolated malicious message or agent to the execution path that carries influence across principals. This distinction also determines what a defense must interrupt and what an evaluation must observe or vary to support a system-level security claim.
这些发现共同将安全分析单元从孤立的恶意消息或智能体，转向在主体之间传递影响的执行路径。这一区别也决定了防御必须阻断什么，以及评估必须观察或改变什么，才能支撑系统层面的安全论断。

The attack paths in Section 4.3 show how adversarial influence moves through an MAS. A defense may interrupt such a path by constraining the system before execution, intervening during execution, or containing and repairing effects after they occur. We therefore ask which path the defense targets, what it can observe, where and when it can intervene, what it must trust, and what recovery remains possible. 第 4.3 节中的攻击路径展示了对抗性影响如何在多智能体系统（MAS）中传播。防御可以通过在执行前约束系统、在执行期间实施干预，或在影响发生后加以遏制和修复，来阻断这样的路径。因此，我们考察防御针对哪条路径、能够观察什么、可以在何处及何时介入、必须信任什么，以及还存在哪些恢复可能性。图 1 从防御视角展示了同一执行过程。
5.1 Defense Contract5.1 防御契约
We characterize each defense along five dimensions: path target, observation, intervention, trust boundary, and recovery. Because security effects may span several principals, a defense must account for how influence, state, and authority move through the execution.
我们从五个维度刻画每种防御：目标路径、观测、干预、信任边界和恢复。由于安全影响可能跨越多个主体，防御必须考虑影响、状态和权限如何在执行过程中流转。
Path target. Which system-level risk or attack path must the defense interrupt? A claim should identify the risk R1–R7 and the interaction or path segment that must be broken. Protecting one agent or filtering one message is insufficient if the same effect remains reachable through another route.
目标路径。防御必须阻断哪一种系统级风险或攻击路径？一项防御声明应明确指出风险 R1–R7，以及必须切断的交互或路径片段。如果仍可通过其他途径产生相同的效果，那么仅保护一个智能体或过滤一条消息是不够的。
Observation. What part of the cross-principal execution can the defender observe? A defense may see a message, principal, communication edge, shared state, subgraph, latent state, or full execution trace. Observation depends mainly on oversight architecture C8 and which interfaces I1–I6 are visible. A defense cannot reliably detect a failure whose relevant interaction lies outside this view. Observation also varies in scope and depth: a local monitor may have detailed neighbor history, while a global monitor may cover more of the system through coarser logs or metadata [40, 119].
观测。防御方能够观测到跨主体执行过程中的哪些部分？防御机制可能能够观测到消息、主体、通信边、共享状态、子图、潜在状态或完整的执行轨迹。观测主要取决于监督架构 C8，以及接口 I1–I6 中哪些是可见的。如果与某种失效相关的交互位于这一观测范围之外，防御机制就无法可靠地检测到该失效。观测在范围和深度上也存在差异：局部监控器可能掌握详细的邻居历史记录，而全局监控器则可能通过较粗粒度的日志或元数据覆盖系统的更多部分 [40, 119]。
Intervention. What can the defender change, and when? A defense may reshape topology, policy, or authority before execution; block or rewrite messages, reroute communication, or quarantine principals during execution; or revoke authority and roll back shared state afterward. Timing matters: blocking a message before I2 may prevent a state change at I3 that is difficult to undo later.
干预。防御方能够改变什么，以及何时进行改变？防御机制可以在执行前调整拓扑、策略或权限；在执行期间阻止或重写消息、重新路由通信或隔离主体；也可以在执行后撤销权限并回滚共享状态。时机很重要：在 I2 之前阻止一条消息，可能会防止 I3 处发生之后难以撤销的状态变化。
Trust boundary. Which principals, components, and system conditions must remain trustworthy? Examples include authenticated identities, trusted coordinators, preserved provenance, bounded membership, honest-neighbor or honest-majority conditions, stable topology, synchrony, and complete logs. Together, these assumptions define the defense’s effective trust boundary. Changes in membership, routing, delegation, or shared state can invalidate it during execution.
信任边界。哪些主体、组件和系统条件必须保持可信？例如，经认证的身份、可信的协调者、得到保留的来源信息、受限的成员规模、诚实邻居或诚实多数条件、稳定的拓扑、同步性以及完整的日志。这些假设共同界定了防御机制的有效信任边界。成员构成、路由、委托或共享状态的变化可能在执行期间使这一边界失效。
Recovery. What remains when prevention or containment fails? Harmful influence may already have reached another principal, shared state, delegated authority, or a collective decision. A complete defense claim should state what can still be contained, revoked, rolled back, or repaired, and how the system verifies that the protected property has been restored.
恢复。当预防或遏制失败时，还能采取哪些措施？有害影响可能已经波及另一个主体、共享状态、委托权限或集体决策。完整的防御声明应说明，哪些影响仍可遏制、哪些权限仍可撤销、哪些状态仍可回滚或修复，以及系统如何验证受保护属性已经恢复。
We use these five dimensions as a common comparison basis below. The control primitives describe what a defense acts on, while the contract describes how its protection claim is obtained and bounded.
下文中，我们将这五个维度作为共同的比较基础。控制原语描述防御机制作用于什么对象，而契约则描述其保护声明如何成立以及受到哪些限制。

These primitives are not mutually exclusive: one system may combine several of them. D1. Identity, policy, and authority enforcement. D1 primarily interrupts admission and delegation paths (P1/P7) by controlling who may participate, what actions they may perform, and what authority may cross principal boundaries. Provenance controls can also help limit leakage along P6. Set 1 evidence includes identity and local-authorization mechanisms such as BlockA2A, decentralized identity and credential systems, SPIFFE-based authentication, SAFEFLOW, and ConvPayMAS [199, 136, 121, 85, 29]. They reduce reliance on message content alone by making identity, policy, and authorization explicit.
D1。身份、策略与权限的强制执行。D1 通过控制谁可以参与、参与者可以执行哪些操作，以及哪些权限可以跨越主体边界，主要阻断准入和委托路径（P1/P7）。来源控制也有助于限制沿 P6 发生的泄露。Set 1 的证据包括 BlockA2A、去中心化身份与凭证系统、基于 SPIFFE 的认证、SAFEFLOW 和 ConvPayMAS 等身份与本地授权机制 [199, 136, 121, 85, 29]。这些机制通过显式表示身份、策略和授权，减少了仅依赖消息内容的程度。
Several Set 2 proposals extend these controls to multi-hop delegation, identity-aware routing, and context scoping. Agentic JWT binds authorization to user intent and workflow context, SentinelAgent targets intent-verified delegation chains, and LDP and Nexus add identity- or protocol-aware controls across principals [45, 123, 126, 47, 159, 122]. Set 1 control-flow work separately shows how downstream invocations can be restricted at execution time [62]. Recent work also broadens D1 with governance and context-level controls [27, 33, 165]. Across the defense contract, D1 observes identity, provenance, intent, and scope at admission and authorization boundaries, then constrains participation, actions, or delegated authority. Its guarantees depend on authenticated identities, mediated handoffs, and preservation of the security context needed by downstream checks. Revocation alone may not recover authority, credentials, or derived state that have already propagated.
Set 2 中的若干方案将这些控制扩展到多跳委托、身份感知路由和上下文范围限定。Agentic JWT 将授权与用户意图及工作流上下文绑定，SentinelAgent 针对经过意图验证的委托链，而 LDP 和 Nexus 则在主体之间引入身份感知或协议感知控制 [45, 123, 126, 47, 159, 122]。Set 1 中关于控制流的研究还单独展示了如何在执行时限制下游调用 [62]。近期研究还通过治理和上下文层面的控制拓展了 D1 [27, 33, 165]。在整个防御契约中，D1 在准入和授权边界处观察身份、来源、意图和作用范围，进而约束参与、操作或委托权限。其保障依赖于经过认证的身份、受中介机制管控的交接，以及对下游检查所需安全上下文的保留。仅靠撤销可能无法收回已经传播出去的权限、凭据或派生状态。
D2. Trust and interaction-structure control. D2 mainly targets routing and collective-manipulation paths (P3/P4) by changing who can influence whom and how collective evidence is combined. Topology control can also reduce propagation along P2. ResMAS and topology-linearization methods modify influence paths, while RoMa and trust-aware communication use credibility or trust signals to limit unreliable influence [196, 97, 84, 35]. AgentChain provides a separate coordination mechanism, while MIN-Trust restricts information disclosure across collaborating principals [25, 26]. Other Set 1 work studies faulty or Byzantine members and changes how collective evidence is aggregated [191, 24, 88].
D2。信任与交互结构控制。D2 主要针对路由和集体操纵路径（P3/P4），其方式是改变谁能够影响谁，以及如何组合集体证据。拓扑控制也可以减少沿 P2 的传播。ResMAS 和拓扑线性化方法修改影响路径，而 RoMa 和信任感知通信则利用可信度或信任信号来限制不可靠的影响 [196, 97, 84, 35]。AgentChain 提供了一种独立的协调机制，而 MIN-Trust 则限制协作主体之间的信息披露 [25, 26]。Set 1 中的其他研究考察故障成员或拜占庭成员，并改变集体证据的聚合方式 [191, 24, 88]。
D2 also includes dynamic-trust mechanisms such as DynaTrust, A-Trust, and Ev-Trust, which update influence from interaction history or message signals [89, 51, 157]. A separate line changes the collective-decision rule itself through local coordination, Byzantine protocols, conformal social choice, majority-resistant aggregation, or institutional controls [102, 22, 64, 161, 94, 16, 80, 18]. D2 therefore intervenes by changing communication, contributor influence, or aggregation. Its guarantees depend on assumptions about identity, membership, fault bounds, observability, and sometimes synchrony. Reconfiguring trust or topology can limit future influence, but does not by itself remove manipulated evidence already committed to persistent state or collective decisions.
D2 还包括 DynaTrust、A-Trust 和 Ev-Trust 等动态信任机制，这些机制根据交互历史或消息信号更新影响力 [89, 51, 157]。另一条研究路线通过局部协调、拜占庭协议、保形社会选择、抗多数操纵的聚合或制度性控制，改变集体决策规则本身 [102, 22, 64, 161, 94, 16, 80, 18]。因此，D2 通过改变通信、贡献者的影响力或聚合方式来实施干预。其保障依赖于有关身份、成员资格、故障数量上限、可观测性，有时还包括同步性的假设。重新配置信任或拓扑可以限制未来的影响，但其本身并不能移除已经写入持久状态或纳入集体决策的受操纵证据。
D3. Detection, attribution, and containment. D3 observes harmful influence and intervenes once suspicious behavior or propagation is identified. It applies across several attack paths, with much of the current evidence centered on propagation, routing, and collective manipulation (P2–P4). G-Safeguard, BlindGuard, XG-Guard, SentinelAgent, PeerGuard, GUARDIAN, and SentinelNet use communication structure, message or response signals, peer history, or anomaly scores to identify harmful participants [162, 109, 119, 53, 39, 193, 40].
D3。检测、归因与遏制。D3 观察有害影响，并在识别出可疑行为或传播后实施干预。它适用于多种攻击路径，目前的大部分证据集中于传播、路由和集体操纵（P2–P4）。G-Safeguard、BlindGuard、XG-Guard、SentinelAgent、PeerGuard、GUARDIAN 和 SentinelNet 利用通信结构、消息或响应信号、同伴历史记录或异常分数来识别有害参与者 [162, 109, 119, 53, 39, 193, 40]。
Several recent works consider propagation rather than only suspicious endpoints. Cross-Layer Semantic Flow Reconstruction, CASPIAN, From Spark to Fire, INFA-Guard, PropGuard, contribution-based methods, and related cascade defenses study how harmful influence moves across messages, principals, or communication paths [20, 154, 169, 194, 175, 164, 41]. Other mechanisms target narrower intervention points, including misinformation rectification, sentence-level repair, linguistic routing controls, stubborn-neighbor detection, and game-theoretic or machine-checkable controls [90, 99, 8, 3, 59, 60, 177, 61, 67]. SAIGuard moves intervention earlier by predicting the state change caused by a candidate message and intercepting it before delivery [141]. More broadly, D3 ranges from local message or peer history to graph- and trace-level observation, with guarantees bounded by the coverage and integrity of that telemetry [119, 40]. Detection and containment do not imply recovery: once P2 has changed downstream state, stopping further spread does not undo earlier effects.
近期的若干研究关注传播过程，而非仅关注可疑端点。Cross-Layer Semantic Flow Reconstruction、CASPIAN、From Spark to Fire、INFA-Guard、PropGuard、基于贡献的方法以及相关的级联防御研究了有害影响如何跨消息、主体或通信路径传播 [20, 154, 169, 194, 175, 164, 41]。其他机制针对更具体的干预点，包括错误信息纠正、句子级修复、语言层面的路由控制、顽固邻居检测，以及基于博弈论或可由机器检查的控制 [90, 99, 8, 3, 59, 60, 177, 61, 67]。SAIGuard 通过预测候选消息引起的状态变化，并在消息送达前将其拦截，从而将干预时机提前 [141]。更广泛地说，D3 的观察范围涵盖局部消息或同伴历史记录，直至图和执行轨迹层面，其保障受这些遥测数据的覆盖范围和完整性所限 [119, 40]。检测和遏制并不意味着恢复：一旦 P2 改变了下游状态，阻止进一步传播并不能消除先前的影响。
D4. State, provenance, and information-flow governance. D4 controls what information and derived state may cross principal boundaries, where they may persist, and what security context remains attached to them. It therefore most directly addresses propagation, leakage, and delegation (P2/P6/P7). Set 1 evidence includes differential-privacy and privacy-preserving systems that limit disclosure across collaborating principals, together with provenance-aware work on cross-agent information flows [180, 43, 4, 146]. Set 1 also includes memory-oriented defenses such as Self-Healing Memory Architectures [155].
D4。状态、来源与信息流治理。D4 控制哪些信息和派生状态可以跨越主体边界、它们可以在何处持久保存，以及哪些安全上下文会继续附随其上。因此，它最直接地应对传播、泄露和委托（P2/P6/P7）。Set 1 中的证据包括限制协作主体之间信息披露的差分隐私系统和隐私保护系统，以及关于跨智能体信息流的来源感知研究 [180, 43, 4, 146]。Set 1 还包括 Self-Healing Memory Architectures 等面向记忆的防御方法 [155]。
Set 2 work targets additional forms of shared and latent state, including Governed Shared Memory and EquiMem [103, 108]. PRISM models leakage that accumulates across multi-stage generation and intervenes before a complete secret is emitted, while LCGuard targets information carried through shared latent or KV state [149, 13]. Maris applies reference monitors and checked policies to declared cross-principal message and tool flows, while semantic-taint mechanisms attach tracking information to derived data [31, 142]. Other work combines information governance with prompt-injection controls, verifiable coordination, or contextual privacy mechanisms [44, 145, 167, 87]. D4’s guarantees are strongest when the relevant flow is mediated and its security context remains trustworthy. Maris, for example, assumes relevant message and tool flows pass through its reference monitors [31], while PRISM and latent-state defenses cover different leakage channels [149, 13]. Semantic rewriting, covert channels, and unmediated side effects remain harder to govern, and recovery requires tracing state that has already been copied or transformed.
Set 2 中的研究针对其他形式的共享状态和潜在状态，包括 Governed Shared Memory 和 EquiMem [103, 108]。PRISM 对多阶段生成过程中累积的泄露进行建模，并在完整秘密被输出前实施干预，而 LCGuard 则针对通过共享潜在状态或 KV 状态传递的信息 [149, 13]。Maris 将引用监视器和经过检查的策略应用于已声明的跨主体消息流和工具流，而语义污点机制则为派生数据附加跟踪信息 [31, 142]。其他研究将信息治理与提示注入控制、可验证协调或上下文隐私机制相结合 [44, 145, 167, 87]。当相关流程受到中介管控，且其安全上下文保持可信时，D4 的保障最为有力。例如，Maris 假定相关消息流和工具调用流均经过其引用监控器（reference monitors）[31]，而 PRISM 和潜在状态防御则覆盖不同的泄漏渠道 [149, 13]。语义改写、隐蔽信道和未经中介管控的副作用仍然更难治理，而恢复则需要追踪已被复制或转换的状态。
Adaptive defense allocation. The four primitives above describe what a defense controls. A smaller emerging literature asks where limited defensive capacity should be concentrated. SafeSieve progressively prunes communication, while MESA prioritizes communication edges according to estimated security relevance [186, 83]. Adjacent adaptive-hardening work uses randomized smoothing or adversarial co-evolution to improve robustness [54, 120]. These approaches can concentrate stronger protection on interactions that dominate propagation (P2), collective influence (P4), or downstream authority (P7), rather than applying the same control everywhere. We treat adaptive allocation as a cross-cutting strategy rather than a fifth control primitive because it selects where existing controls should be strengthened rather than defining a distinct object of enforcement. Its smaller evidence base also leaves open how well allocation signals transfer across tasks, models, topologies, and attack strategies.
自适应防御分配。上述四种原语描述了防御控制的对象。一部分规模较小的新兴研究则探讨，应将有限的防御能力集中于何处。SafeSieve 逐步裁剪通信，而 MESA 则根据估计的安全相关性确定通信边的优先级 [186, 83]。相关的自适应加固研究利用随机平滑或对抗性共同演化来提高鲁棒性 [54, 120]。这些方法可以将更强的保护集中于在传播（P2）、集体影响（P4）或下游权限（P7）中起主导作用的交互，而非在所有位置施加相同的控制。我们将自适应分配视为一种横贯各类控制的策略，而非第五种控制原语，因为它选择的是应在何处加强现有控制，而没有定义独立的强制执行对象。其证据基础也较为有限，因此，分配信号在不同任务、模型、拓扑和攻击策略之间的迁移效果如何，仍是一个开放问题。
5.3 Cross-Cutting Findings5.3 跨领域发现
Comparing the defense literature through the contract above reveals three cross-cutting limitations that are not specific to any one control primitive.
依据上述契约比较防御文献，可以发现三项并非特定于某一种控制原语的共性局限。
First, local protection does not imply path closure. Attack paths can compose: an attack may enter through P1, persist through P2, and gain authority through P7. A defense that blocks one transition therefore does not establish end-to-end protection when another route remains reachable. The mappings in Table 3 identify where a control may interrupt a path, not whether it closes every route to the protected effect.
首先，局部保护并不意味着路径闭合。攻击路径可以相互组合：攻击可能通过 P1 进入，通过 P2 持续存在，并通过 P7 获得权限。因此，当另一条路线仍然可达时，阻断某一次转移的防御并不能确立端到端保护。表 3 中的映射指出了控制可能在何处中断路径，而非它是否封闭了通向受保护效应的每一条路线。
Second, defense effectiveness depends on where and when control is applied. Some defenses constrain the system before execution, while runtime defenses must observe enough of the relevant execution to support their intervention. A global observer may cover more of the execution but rely on coarse or trusted telemetry, while a local observer may see detailed behavior along only a small part of the path [40, 119]. Timing also determines what can still be prevented or reversed: ResMAS changes interaction structure before execution, SAIGuard can block candidate messages before delivery, while other mechanisms intervene after suspicious influence has been observed [196, 141, 119]. Defense guarantees therefore depend on the intervention point and, for runtime mechanisms, on whether their observation and control are sufficient for the claimed protection, together with the trust assumptions on which those mechanisms rely.
其次，防御有效性取决于控制施加的位置和时机。某些防御在执行前约束系统，而运行时防御必须充分观测相关执行过程，才能为其干预提供依据。全局观测者可能覆盖更多执行过程，但依赖粗粒度或受信任的遥测数据，而局部观测者可能只能看到路径中一小部分的详细行为 [40, 119]。时机也决定了哪些情况仍可预防或逆转：ResMAS 在执行前改变交互结构，SAIGuard 可以在交付前阻断候选消息，而其他机制则在观测到可疑影响后进行干预 [196, 141, 119]。因此，防御保障取决于干预点；对于运行时机制，还取决于其观测和控制是否足以支撑所声称的保护，以及这些机制所依赖的信任假设。
Finally, containment is not recovery. Removing the source or stopping further propagation does not restore the system once its effects have been copied into memory, artifacts, credentials, delegated authority, or spawned principals [95, 187, 21]. Recovery requires identifying these descendants, revoking inherited authority, repairing state, and verifying that the protected property has been restored. In our map, recovery is evaluated less directly than prevention and containment.
最后，遏制并不等于恢复。一旦其影响已被复制到记忆、产物、凭据、委托权限或派生主体中，移除源头或阻止进一步传播并不能使系统恢复 [95, 187, 21]。恢复需要识别这些衍生实体、撤销继承的权限、修复状态，并验证受保护属性是否已恢复。在我们的映射中，相较于预防和遏制，对恢复的评估较少采用直接方式。
Together, these findings suggest that end-to-end MAS defense requires more than a strong local control: defenses must close the relevant attack paths, place interventions at points where they can affect those paths, provide adequate observation when runtime decisions depend on it, and account for residual effects that survive the original compromise.
这些发现共同表明，端到端 MAS 防御所需的不仅是强有力的局部控制：防御必须封闭相关攻击路径，在能够影响这些路径的位置实施干预，在运行时决策依赖观测时提供充分的观测，并考虑在最初的失陷事件之后仍然存在的残余影响。
6 Benchmarks and Evaluation6 基准与评估
Beyond mapping the attack and defense landscape, we examine how the security of multi-agent systems is evaluated. We first systematize existing benchmarks and their accompanying artifacts. We then identify four gaps in current evaluation practice and discuss the corresponding open challenges.
除了梳理攻击与防御的全貌，我们还考察多智能体系统的安全性是如何评估的。我们首先对现有基准及其配套产物进行系统化梳理。随后，我们指出当前评估实践中的四项不足，并讨论相应的开放挑战。
6.1 Existing Benchmarks and Artifacts6.1 现有基准与产物
Within the 197-work corpus, we identify 44 works whose main contribution is the security evaluation of multi-agent systems. These works test attacks, defenses, and security properties under different system designs and threat models. We reviewed the paper PDFs for 43 works and the software archive for one Zenodo record without an accompanying paper. For each work, we record its adversary position A1–A4, configuration dimensions C1–C8, interaction interfaces I1–I6, attack paths P1–P8, and system-level risks R1–R7. We also record their baselines, metrics, observation depth, and artifact availability. All counts below cover the full set of 44 works; the detailed per-work mapping is provided in Table 4.
在包含 197 项工作的文献集中，我们识别出 44 项以多智能体系统安全评估为主要贡献的工作。这些工作在不同的系统设计和威胁模型下测试攻击、防御及安全属性。我们审阅了 43 项工作的论文 PDF，以及一条没有配套论文的 Zenodo 记录中的软件归档。对于每项工作，我们记录其对手位置 A1–A4、配置维度 C1–C8、交互接口 I1–I6、攻击路径 P1–P8 和系统级风险 R1–R7。我们还记录其基线、指标、观测深度和产物可用性。下文所有计数均涵盖全部 44 项工作；逐项工作的详细映射见表 4。
The works provide broad coverage of both attacks and defenses. Forty-two evaluate an attack or failure, including 16 that also evaluate a defense. CalBench and MAGPIE evaluate privacy without an explicit attacker [198, 66]. The benchmarks also cover many MAS designs. All 44 report or vary principal composition (C3), 39 cover coordination (C4), and 38 cover communication topology (C1). Membership is fixed in 42 works, while two allow limited runtime spawning. Member adversaries (A3), message transfer (I2), detection (I6), peer or state steering (P5), and collective-decision failure (R3) are the most common settings [182, 95, 9, 69].
这些工作广泛覆盖了攻击和防御两个方面。42 项工作评估了攻击或失效，其中 16 项还评估了防御措施。CalBench 和 MAGPIE 在没有显式攻击者的情况下评估隐私 [198, 66]。这些基准还涵盖了多种 MAS 设计。全部 44 项工作都报告了主体组成（C3）或对其进行了变更，39 项涵盖协调机制（C4），38 项涵盖通信拓扑（C1）。42 项工作的成员固定不变，另有两项允许在运行时有限地生成新成员。成员对手（A3）、消息传递（I2）、检测（I6）、对其他成员或状态的引导（P5）以及集体决策失效（R3）是最常见的设置 [182, 95, 9, 69]。
The evaluations provide different depths of execution evidence. Classified by their deepest observation, 20 use full traces, 20 use principal-level messages or actions, two use episode outcomes, and two use final outputs. Thirty-one works identify code, data, logs, a test tool, or a project page, including 26 with an exact URL. The works also report communication topology for 38 works, model information for 32, and an exact principal count for 18.
这些评估提供了不同深度的执行证据。按其最深入的观测层级分类，20 项使用完整轨迹，20 项使用主体级消息或动作，两项使用回合结果，两项使用最终输出。31 项工作提供了代码、数据、日志、测试工具或项目页面的相关信息，其中 26 项提供了确切的 URL。此外，38 项工作报告了通信拓扑，32 项报告了模型信息，18 项报告了确切的主体数量。
6.2 Gaps and Open Challenges6.2 缺口与开放挑战
Our analysis identifies four gaps in current evaluation practice. First, evaluations often show that a failure occurs without isolating how multi-agent interaction affects it. Second, metric names may hide what is measured, while execution traces rarely support causal diagnosis. Third, comparisons within one benchmark do not by themselves provide configurable or extensible components for other MAS designs. Finally, current evaluations largely focus on fixed, closed systems rather than practical open settings.
我们的分析发现，当前评估实践存在四个方面的缺口。首先，评估往往只表明失效发生了，却没有单独辨明多智能体交互如何影响该失效。其次，指标名称可能掩盖实际测量的内容，而执行轨迹很少能够支持因果诊断。第三，单个基准内部的比较本身并不能为其他 MAS 设计提供可配置或可扩展的组件。最后，当前评估主要关注固定的封闭系统，而非实际的开放环境。
6.2.1 Isolating Multi-Agent Effects6.2.1 分离多智能体效应
Determining how interaction changes a security outcome remains an open evaluation challenge. As defined in Section 2.1, a failure may remain unchanged without interaction, become worse because of interaction, appear only because of interaction, or involve a security property that exists only among multiple principals. Distinguishing these four roles requires comparisons designed for the specific role being tested.
确定交互如何改变安全结果，仍然是一项尚未解决的评估挑战。如第 2.1 节所定义，一种失效可能在没有交互时保持不变，可能因交互而加重，可能仅因交互而出现，也可能涉及仅存在于多个主体之间的安全属性。区分这四种作用，需要针对所检验的具体作用设计比较。
When an attack has a single-principal counterpart, a matched single-principal comparison can distinguish an inherited effect from an interaction-amplified effect. Our audit identifies 21 works that evaluate at least one of these two effects. Six compare an MAS with a single-principal execution [12, 92, 58, 189, 174, 128]. The remaining 15 evaluate the attack in an MAS or compare different MAS configurations. These evaluations show that the attack succeeds under the tested conditions, but they do not determine whether the same failure would occur with one principal or become worse through interaction.
当一种攻击存在对应的单主体情形时，通过条件匹配的单主体比较，可以区分继承效应与交互放大效应。我们的审查发现，21 项工作至少评估了这两种效应中的一种。其中六项将 MAS 与单主体执行进行了比较 [12, 92, 58, 189, 174, 128]。其余 15 项在 MAS 中评估攻击，或比较不同的 MAS 配置。这些评估表明，攻击在所测试的条件下能够成功，但无法确定同样的失效是否会在仅有一个主体时发生，或是否会因交互而加重。
When no meaningful single-principal counterpart exists, the evaluation should preserve the MAS and vary the relation under study. Among 36 such works, 12 include a relation-focused comparison. The remaining 24 use another control or provide no clear relation-focused comparison. For example, MESA removes or masks communication edges, while CalBench compares models and coordination protocols under the same private-information constraints [83, 198].
当不存在有意义的对应单主体情形时，评估应保留 MAS，并改变所研究的关系。在 36 项此类工作中，12 项包含以关系为重点的比较。其余 24 项使用了其他对照，或未提供明确的以关系为重点的比较。例如，MESA 移除或屏蔽通信边，而 CalBench 在相同的私有信息约束下比较模型与协调协议 [83, 198]。
6.2.2 Comparable and Diagnostic Metrics6.2.2 可比较且具有诊断能力的指标
Current metrics are inadequate in two respects: their outcome-level measures are not comparable across benchmarks, and their trace-level measures do not explain how a compromise propagates across agents.
当前指标在两个方面存在不足：结果层面的度量无法跨基准比较，轨迹层面的度量也无法解释安全失陷如何在智能体之间传播。
Underspecified ASR.定义不充分的 ASR。
Attack Success Rate (ASR) is the most common security metric in our corpus. Thirteen of the 44 works compute ASR in their own evaluation, while ATAG additionally records ASR values reported by other sources [42]. Across these studies, ASR refers to different evaluation units and success conditions because the benchmarks study different attacks. The name “ASR” alone therefore does not identify what event is counted or over which eligible population. An ASR of 60% in one benchmark may therefore measure a different event from an ASR of 60% in another. The values cannot be directly compared, ranked, or aggregated unless these definitions match. When propagation is part of the claim, an end-to-end ASR also cannot distinguish an attack stopped at entry from one that spreads across several agents before being blocked.
攻击成功率（Attack Success Rate，ASR）是我们所收集文献中最常见的安全指标。44 项工作中有 13 项在自身评估中计算了 ASR，此外，ATAG 还记录了其他来源报告的 ASR 值 [42]。在这些研究中，由于各基准研究的攻击不同，ASR 所指的评估单位和成功条件也各不相同。因此，仅凭“ASR”这一名称，无法确定统计的是何种事件，以及统计所针对的符合条件的总体是什么。因此，一个基准中 60% 的 ASR 与另一个基准中 60% 的 ASR，可能衡量的是不同事件。除非这些定义一致，否则无法直接比较这些数值、据此排序或将其汇总。当所提出的论断涉及传播时，端到端 ASR 也无法区分攻击是在入口处被阻止，还是在多个智能体之间传播后才被阻断。
Future benchmarks should qualify ASR by its evaluation unit, using names such as per-principal ASR, per-message ASR, or per-run ASR, and define the counted success event. Each result should provide its taxonomy mapping, evaluation unit, execution protocol, and verification method. When propagation is part of the claim, stage-level measures should follow the relevant I1–I6 path to the verified R1–R7 consequence. These stages should be selected based on the attack rather than imposed on every risk. Existing work already measures individual dimensions such as harm amplification, topology-dependent leakage, and internal-channel exposure [131, 95, 174]. Benign task utility should be reported separately from security outcomes.
未来的基准应根据评估单位限定 ASR 的含义，使用诸如每主体 ASR、每消息 ASR 或每次运行 ASR 等名称，并定义所统计的成功事件。每项结果都应提供其在分类体系中的映射、评估单元、执行协议和验证方法。当所提出的论断涉及传播时，阶段级度量应沿相关的 I1–I6 路径，追踪至经验证的 R1–R7 后果。这些阶段应根据攻击来选择，而不应强加于每一种风险。现有研究已经对危害放大、依赖拓扑结构的信息泄露以及内部通道暴露等单独维度进行了度量 [131, 95, 174]。良性任务效用应与安全结果分开报告。
Missing Causal Provenance.因果溯源信息缺失。
Full execution traces provide more information than final-output evaluation, but they do not necessarily explain why a failure occurred. Twenty records use the full execution trace as their deepest observation. These traces may show that one principal received malicious information, another updated memory, and a third invoked a tool, without showing how these events depend on one another. Across the corpus, ATAG models attack dependencies and Agent-BOM reconstructs dependencies from executions [42, 81]. Agent-BOM is the only one of these 20 full-trace records coded as reporting an explicit dependency or provenance graph. This evidence is unnecessary for benchmarks that report only final outcomes, but it is needed for claims about propagation, responsibility, or defense placement.
完整执行轨迹比最终输出评估提供更多信息，但不一定能解释故障为何发生。有 20 条记录将完整执行轨迹作为其最深入的观测层次。这些轨迹可能显示，一个主体接收了恶意信息，另一个主体更新了记忆，第三个主体调用了工具，却未显示这些事件之间如何相互依赖。在整个文献集合中，ATAG 对攻击依赖关系进行建模，而 Agent-BOM 从执行过程中重建依赖关系 [42, 81]。在这 20 条完整轨迹记录中，Agent-BOM 是唯一被编码为报告了显式依赖图或溯源图的记录。对于仅报告最终结果的基准，这类证据并非必需；但对于涉及传播、责任归属或防御部署位置的论断，则需要这类证据。
Benchmarks that make such claims should represent the relevant execution path as a provenance graph. Its nodes should identify the principals and events at the I1–I6 interfaces, including attacker-controlled inputs, messages, memory operations, tool results, delegation decisions, and security-sensitive actions. Its edges should record data, control, and delegation dependencies. The path should begin with the first adversarially influenced event or violated trust boundary and end with a verified R1–R7 consequence. Because a dependency graph does not prove causation, the claimed path should also be tested through controlled replay or ablation.
提出此类论断的基准应将相关执行路径表示为溯源图。图中的节点应标明 I1–I6 接口处的主体和事件，包括攻击者控制的输入、消息、记忆操作、工具结果、委派决策以及安全敏感操作。图中的边应记录数据依赖、控制依赖和委派依赖关系。该路径应始于第一个受对抗性影响的事件或被突破的信任边界，并以经验证的 R1–R7 后果为终点。由于依赖图并不能证明因果关系，还应通过受控重放或消融实验来检验所声称的路径。
6.2.3 Configurable and Extensible Benchmarks6.2.3 可配置和可扩展的基准
Thirty-nine of the 44 works compare two or more evaluation conditions. These comparisons include component or attack controls, defense controls, single-principal baselines, and relation-focused MAS comparisons. They support controlled variation within each study, but do not show whether benchmark factors can be changed independently or reused elsewhere. We call a benchmark configurable when its supplied factors can be changed independently and extensible when new components can be added through a documented interface.
44 项研究中有 39 项比较了两种或更多评估条件。这些比较包括组件或攻击对照、防御对照、单主体基线，以及聚焦关系的 MAS 比较。这些比较支持在各项研究内部进行受控变化，但并未表明基准中的因素能否独立改变或在其他场景中复用。当基准所提供的因素可以独立改变时，我们称其为可配置；当可以通过有文档说明的接口添加新组件时，我们称其为可扩展。
ACIARena defines interfaces for MAS implementations, attacks, defenses, and evaluation modules [9]. RiskLab provides configurable experiment components and a registry for adding risk detectors [63]. A2ASecBench uses an LLM-based adapter to apply attack descriptions to different A2A scenarios [86]. These benchmarks expose useful extension points, but their task, trace, attack, and verifier formats differ. Transferring a component between them would therefore require an additional adapter. Similarly, the 31 works with identified artifacts may provide access to code or data without making their components reusable. Because our audit does not systematically record interface reuse, we do not quantify how often such reuse occurs.
ACIARena 为 MAS 实现、攻击、防御和评估模块定义了接口 [9]。RiskLab 提供可配置的实验组件，以及用于添加风险检测器的注册机制 [63]。A2ASecBench 使用基于 LLM 的适配器，将攻击描述应用于不同的 A2A 场景 [86]。这些基准提供了有用的扩展点，但其任务、轨迹、攻击和验证器格式各不相同。因此，在这些基准之间迁移组件需要额外的适配器。同样，已识别出研究产物的 31 项研究可能提供了代码或数据访问途径，却未使其组件具备可复用性。由于我们的审计未系统记录接口复用情况，因此我们不量化此类复用发生的频率。
Benchmarks intended for cross-system comparison should expose the factors named in their claims through documented interfaces. A paired test should change one factor while preserving the protected property and outcome definition. Differences between system interfaces should be handled through validated adapters. Each run should record four groups of information: the model specification, execution settings, environment state, and verifier version.
旨在进行跨系统比较的基准，应通过有文档说明的接口开放其论断中所涉及的因素。配对测试应改变一个因素，同时保持受保护属性和结果定义不变。系统接口之间的差异应通过经过验证的适配器来处理。每次运行都应记录四组信息：模型规格、执行设置、环境状态和验证器版本。
6.2.4 Open-System Evaluation6.2.4 开放系统评估
Current benchmarks primarily evaluate closed systems whose members and trust relationships are fixed before execution. Forty-two of the 44 works use fixed membership, while the other two allow limited runtime spawning under one administrator. Ten works use deception games or negotiation environments, and many others rely on synthetic tasks with predefined roles. These settings support controlled experiments but do not capture how practical MAS operate across changing trust boundaries.
当前基准主要评估封闭系统，其成员及信任关系在执行前就已固定。44 项研究中有 42 项采用固定的成员构成，其余两项则允许在单一管理员的管理下于运行时有限地创建新主体。10 项研究采用欺骗博弈或谈判环境，其他许多研究则依赖角色预先定义的合成任务。这些设置支持受控实验，但无法反映实际 MAS 如何跨越不断变化的信任边界运行。
Identity, trust, authority, and policy also matter in closed systems. However, they become more dynamic and consequential when previously unknown principals interact across administrative boundaries [72, 139]. Current benchmarks largely begin after these relationships have been established. They therefore provide little evidence about how principals enter the system, how trust changes during execution, or how access is removed.
身份、信任、权限和策略在封闭系统中同样重要。然而，当此前互不相识的主体跨管理边界交互时，这些因素会变得更加动态，影响也更加显著 [72, 139]。现有基准测试大多在这些关系已建立之后才开始。因此，它们几乎无法提供有关主体如何进入系统、信任如何在执行过程中变化，以及访问权限如何被撤销的证据。
Future benchmarks should evaluate deployed coordination protocols and frameworks with independently managed principals. Testbeds should include heterogeneous implementations, persistent state, external services, and changing membership. They should cover the lifecycle from discovery and admission through operation and removal. Security outcomes should reflect consequences across real trust boundaries rather than only success or failure in a synthetic task.
未来的基准测试应评估已部署的协调协议和框架，其中各主体由独立管理方管理。测试平台应涵盖异构实现、持久状态、外部服务以及成员变化。它们应覆盖从发现和准入到运行和移除的整个生命周期。安全结果应反映跨越真实信任边界所产生的后果，而不应仅体现合成任务中的成功或失败。
7 Conclusion7 结论
This SoK frames multi-agent LLM security around end-to-end execution. Across 197 works, we organize MAS security through system configuration, interaction interfaces, attack paths, defenses, and evaluation. Our analysis shows that security depends on how adversarial influence crosses principal boundaries, what state and authority remain reachable, whether defenses can close the path, and whether evaluations verify the resulting system-level effect. This execution-centered view provides a common basis for comparing security claims across MAS designs.
本知识系统化研究（SoK）围绕端到端执行来构建多智能体 LLM 安全的分析框架。我们基于 197 项研究，从系统配置、交互接口、攻击路径、防御和评估几个方面梳理 MAS 安全。我们的分析表明，安全性取决于对抗性影响如何跨越主体边界、哪些状态和权限仍然可达、防御能否阻断该路径，以及评估是否验证了由此产生的系统级影响。这种以执行为中心的视角，为比较不同 MAS 设计中的安全主张提供了共同基础。
Ethical Considerations伦理考量
This SoK synthesizes publicly available research on the security of multi-agent systems. It does not involve human-subject studies, private user data, or experiments against live or third-party systems. Our analysis is based on published papers, public artifacts, advisories, and bibliographic metadata. The topic is inherently dual use: organizing attack mechanisms and system weaknesses can help both defenders and attackers understand where multi-agent systems fail. We therefore emphasize security properties, interaction paths, threat assumptions, defenses, and evaluation evidence rather than operational payloads or step-by-step exploitation procedures. We do not disclose non-public vulnerabilities or unnecessary identifying details. Finally, we distinguish experimental evidence from deployment prevalence. A vulnerability demonstrated in a benchmark or controlled environment does not by itself imply that the same failure is common in deployed systems. We report claims within the scope and assumptions supported by the underlying studies.
本 SoK 综合整理了有关多智能体系统安全的公开研究。本研究不涉及以人为受试者的研究、私人用户数据，也不涉及针对在线系统或第三方系统开展的实验。我们的分析基于已发表的论文、公开研究产物、安全通告和文献元数据。这一主题本身具有双重用途：梳理攻击机制和系统弱点，既能帮助防御者，也能帮助攻击者理解多智能体系统在哪些环节会失效。因此，我们着重讨论安全属性、交互路径、威胁假设、防御措施和评估证据，而非可实际使用的攻击载荷或逐步漏洞利用流程。我们不披露非公开漏洞或不必要的身份识别细节。最后，我们区分实验证据与实际部署中的普遍程度。在基准测试或受控环境中得到验证的漏洞，本身并不意味着相同的失效在已部署系统中普遍存在。我们在原始研究所支持的范围和假设内报告相关主张。
