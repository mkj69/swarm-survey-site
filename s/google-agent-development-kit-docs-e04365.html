一句话

Google ADK 提供图工作流、多 agent 编排与 A2A 相关入口，但这份首页材料证明的是框架能力定位，不能证明 swarm 扩大后的性能收益。

主要内容

  • 首页宣布 TypeScript 2.0 GA 支持图工作流，强调把确定性代码与模型推理结合，通过显式执行路径组织复杂任务。
  • 导航列出多 agent 工作流、agent 路由和工作流模式，但没有展开具体模板、调度规则或执行语义。
  • A2A 部分列出协议、消费端快速入门和扩展入口；当前内容不足以确认互操作范围与实际运行效果。
  • 上下文管理被描述为结构化组装会话、记忆、工具输出和产物，并提供事件过滤、旧对话摘要、产物按需加载及 token 用量跟踪。
  • 框架还宣称支持并行任务、故障处理、任务恢复，以及评估、可观测性和多种部署方式。

证据与可信度

这是 Google 官方文档首页抓取内容，混有导航、示例代码和宣传文案；未读到全文，尤其未读到工作流模式与 A2A 子页。功能描述属于厂商自述，本材料没有独立核验。

“2.0”是版本号，不是性能指标。页面没有提供 agent 数量、吞吐、延迟、成本或成功率的对照测量，因此“企业规模”“可靠”等表述不能当作扩展性实验证据。

对 swarm scaling 的意义

ADK 展示了组织多 agent 系统所需的一组工程接口：显式流程、路由、上下文管理、恢复和观测。这些能力有助于控制协作过程，但不能直接推出增加 agent 就能提高任务质量或效率。

对调研仓库而言，它适合作为编排基础设施的能力线索。图工作流支持有明确首页声明；工作流模板细节和 A2A 支持深度仍需查阅子页，规模收益则需要另找实验数据。
