一句话

这份五周实践表明：把编码 agent 组织成分层团队，可能显著放大人类指令的产出，但瓶颈随之转向审批、质量收尾、共享资源与协调成本。

主要内容

  • 作者用总技术负责人统筹各功能负责人，再由后者分派编码任务；人类主要参与规划、反馈和审批。另有维护开发环境的团队，以及逐渐成为统一质量关卡的审查 agent R11。
  • 人类输入量仍约每周 500 条，但每条消息对应的 PR 从夏季约 0.3 增至十月约 1.4；合并 PR 的代码行数中位数前后均约 200 行。作者另称，每周 PR 数约为夏季的 14 倍。这些是不同口径，不能相互替代。
  • 产量增加没有体现为首轮审查评分明显恶化，但合并前的复核更薄弱：组织实验仓库以 5/5 合并的比例从夏季 75% 降至 55%，对照仓库为 64%；合并队列弹出约为对照的两倍。
  • 团队形成了跨组协作、测试资源锁、发布协调和责任归属规则，也出现重复调查、消息错位、把局部反馈推广成全局规则等问题。一个只顾轮询的中间管理层被直接撤掉。
  • 人类仍是关键依赖：首次审批等待中位数为 4.5 小时，最后一次审批后到合并为 23 分钟。作者同时报告 CI、审查费用大增，以及自己对技术细节的掌握变弱。

证据与可信度

  • 属于作者自报的单人实践，观察期为 9 月 23 日至 10 月 28 日；作者正在开发 AgentRun，存在产品推广利益。材料未提供可独立复算的原始日志。
  • 质量比较取自七月以来两个仓库的 3,300 个已合并 PR。Greptile 评分是自动审查代理指标，不能等同于真实缺陷率；作者认为评分下降源于审查趋严，也只是解释。
  • R11 报告植入 446 个缺陷，其中 39 个未被测试捕获并触发返工，说明测试存在盲区；不代表线上缺陷率。
  • 对照不是随机实验：实验仓库仅五周、仍是概念验证，生产仓库始于 2023 年且有六名贡献者；后者也局部尝试了多 agent。任务、成熟度和流程差异限制了因果判断。

对 swarm scaling 的意义

最有价值的信号是“人类注意力如何扩展”：总负责人吸收问题、团队内部消化约一半 agent 间通信，使人类消息能够驱动更多工作。但消息效率并不等于时间或成本效率。

规模扩大后，质量关卡、共享算力、唤醒机制和审批权限成为核心系统设计问题。R11 的晋升与无效管理层的撤除，提示组织结构需要随实际信息流调整；本案例尚不能证明层级越多、agent 越多就越好，也没有给出成本归一化的扩展曲线。
